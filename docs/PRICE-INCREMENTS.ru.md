# Ценовые шаги инструмента

[English version](PRICE-INCREMENTS.md). Английский текст является основным.

`glossary::PriceIncrements` из `qdcxx_ipf` интерпретирует поле инструмента `PRICE_INCREMENTS`, выбирает шаг, округляет и изменяет цену. Значение владеет текстом и неизменяемыми таблицами диапазонов. Копии разделяют неизменяемое владение; перемещённый источник становится пустым и пригодным для повторного использования. Константные запросы допускают параллельное выполнение; присваивание и уничтожение синхронизирует вызывающий код.

```cpp
#include <qd/glossary/price_increments.hpp>
#include <qd/ipf/instrument_profile.hpp>

namespace q = org::ttldtor::qdcxx;

int main() {
    q::ipf::InstrumentProfile instrument;
    if (!instrument.setPriceIncrements(u"0.01 1; 0.05")) {
        return 1;
    }
    auto rules = q::glossary::PriceIncrements::valueOf(instrument.getPriceIncrements());
    auto tick = rules.getPriceIncrement(1.0, +1);
    auto price = rules.roundPrice(1.023, q::glossary::PriceRoundingMode::HALF_EVEN);
    auto next = rules.incrementPrice(price, +1);
    return tick == 0.05 && price == 1.0 && next == 1.05 ? 0 : 1;
}
```

Пример читает точный текст поля IPF; профиль нужен только на время `valueOf`. Правило явно передаётся в проверку ордера или ввод цены. Получение профиля само по себе не меняет правила приложения.

## Создание и идентичность

Формат текста: `increment upperLimit; increment upperLimit; increment`, с одним ASCII-пробелом на месте каждого показанного разделителя. Диапазоны покрывают неотрицательную ось; для отрицательных цен они отражаются. Шаги и границы в нескольких диапазонах должны быть конечными и не меньше `1e-18`. Каждая следующая граница должна превосходить предыдущую более чем на `2e-18`. Единственный шаг из текста может быть меньше, включая ноль вследствие потери значимости.

Null, пустой текст и обычные десятичные записи нуля со знаком, например `-0.0`, дают пустое правило. Его текст пуст, шаги равны `{0}`, точность равна нулю, округление сохраняет вход. Другие допустимые записи сохраняют точный текст: `-0e0` хранит отрицательный ноль и отличается от пустого правила. Численное равенство не задаёт идентичность текста. `hashCode` использует знаковый32-битный Java-хеш UTF-16.

`valueOf(double)` отклоняет отрицательные и неконечные значения; любой знаковый ноль означает пустое правило. `valueOf(span<const double>)` принимает пустой массив либо чередующиеся шаги и границы нечётной длины. Единственный нулевой элемент означает пустое правило; остальные элементы должны быть конечными и не меньше `1e-18`. Числовое создание форматирует значения с эталонной политикой пятнадцати значащих цифр и разбирает текст заново; исходные binary64 могут измениться. Текстовое создание сохраняет производственную устаревшую десятичную грамматику, включая арифметику экспоненты и знаковый ноль; шестнадцатеричные Java-литералы не принимаются.

По умолчанию `PriceIncrementLimits` допускает 1 048 576 кодовых единиц UTF-16 и 16 384 диапазона. Ограничения проверяются до сохранения входа и выделения таблиц. Ноль диапазонов допускает только пустое правило. Превышение границы вызывает `std::length_error`, ошибки грамматики или значений — `std::invalid_argument`. Ошибки выделения памяти передаются без публикации частичного значения. Сообщения проверки массива не обязаны повторять встроенное Java-представление массива.

## Выбор, точность и округление

`getPriceIncrement(price, direction)` использует допуск `min(соседние шаги) * 1e-6` около границы. Положительное направление выбирает верхний шаг, отрицательное — нижний, нулевое — их минимум. Для отрицательной цены направление инвертируется с Java-переполнением signed32; NaN выбирает первый шаг. `getPricePrecision(price)` выбирает нижний диапазон около допустимой границы и возвращает от нуля до восемнадцати десятичных знаков.

`roundPrice(price, direction)` округляет вниз, вверх или к ближайшему чётному кратному для отрицательного, положительного или нулевого направления. `PriceRoundingMode` также поддерживает округление от/к нулю, half-up, half-down и `UNNECESSARY`. Последний режим вызывает `std::domain_error`, если округление изменило бы цену. NaN возвращается неизменным, включая payload; нулевой шаг сохраняет вход до проверки режима. Иное неизвестное значение enum вызывает `std::invalid_argument`.

`incrementPrice(price, direction, step)` требует ненулевое направление и неотрицательный конечный step, даже для движения вниз. Цена изменяется на максимум из шага диапазона и step, после чего округляется half-even. Приоритет знаковых нулей соответствует Java `Math.max`.

Десятичная коррекция соответствует численной политике precision15 HALF_UP с Java8-переходом к десятичному представлению на точных половинах; она отличается от форматирования количества дополнительного базового актива. Эталон гарантирует точные десятичные результаты для не более четырнадцати значащих и четырнадцати дробных цифр. Бесконечности binary64 и другие масштабы сохраняют наблюдаемое эталонное поведение; это не десятичная арифметика произвольной точности.

См. [контракт ценовых шагов](../spec/glossary/PRICE-INCREMENTS.ru.md) и API в `qd/glossary/price_increments.hpp`.
