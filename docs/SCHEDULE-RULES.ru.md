# Правила торговых расписаний

[English version](SCHEDULE-RULES.md). Английский текст является основным.

Необязательная библиотека `qdcxx_schedule` предоставляет владеющие identities `Schedule`, полный
разбор закреплённой грамматики trading hours, явные календарные контексты и типизированные обновления
defaults. Она возвращает имя и проверенную timezone identity. Построение Day/Session для конкретных
дат, запросы по моменту времени и фильтры остаются отдельными возможностями. Parser не загружает
timezone-провайдер и не запрашивает его.

## Явный контекст

Приложение создаёт `ScheduleDataContext`, затем непосредственно вызывает привычную фабрику:

```cpp
#include <qd/schedule/schedule.hpp>

int main() {
    using namespace org::ttldtor::qdcxx::schedule;
    auto context = ScheduleDataContext::create();
    if (!context) {
        return 1;
    }
    auto schedule = Schedule::getInstance(*context, u"XNYS()");
    if (!schedule) {
        return 1;
    }
    const auto name = schedule->getName();
    const auto zoneId = schedule->getTimeZoneId();
    return name == u"NYSE" && zoneId == u"America/New_York" ? 0 : 1;
}
```

Контекст использует встроенные [закреплённые defaults рынка](../resources/schedule/manifest.json).
Инициализация и getters не обращаются к файлам, окружению или сети, не вызывают callbacks и не
продвигают фоновую работу. Глобального контекста по умолчанию нет. Копии контекста разделяют один
домен; отдельные `create` независимы. Копии Schedule сохраняют identity и контекст, в том числе после
уничтожения исходного handle контекста. Move сохраняет исходный handle допустимым. Присваивание
одному handle требует внешней синхронизации, если другие потоки обращаются к тому же объекту.

`getName()` и `getTimeZoneId()` возвращают независимые владеющие копии UTF-16 из полностью
опубликованного поколения. Каждый вызов удерживает собственное поколение; между двумя отдельными
getters может произойти обновление. `getDefinition()` заимствует точное выбранное определение из
identity и остаётся допустимым, пока handle существует и не заменён. Выделение памяти для копии
результата может выбросить `std::bad_alloc`.

## Части инструмента и грамматика

`Schedule::getInstance(context, text)` выбирает первую часть по production-границе предыдущей `)`
или `;`. Перегрузка с последним аргументом `venue` выбирает первую точно совпавшую площадку либо
возвращает `MISSING_VENUE`. `getTradingVenues(text)` отдельно воспроизводит regex-find по ASCII-word,
сохраняет порядок и дубликаты и не валидирует найденные расписания. Эти три операции намеренно
не объединены новым более строгим tokenizer инструмента.

[Спецификация грамматики](../spec/schedule/RULES-AND-TIMEZONES.ru.md#текст-расписания-и-defaults)
описывает наследование площадки, chained/repeated properties, заполнение weekdays, минутные и
секундные группы, сдвиги дней, границы дня/reset, алгебру именованных списков дат и упорядоченные
стратегии. Parser строит владеющие локальные определения для всей закреплённой семьи исходника,
не сводя расписание к одному интервалу UTC. Неизвестные обычные свойства и source-fallback
неизвестных стратегий сохраняются. Некорректное распознанное свойство отклоняется как в production.

Корпус сравнения захватывает фактические
[фабрики Schedule и построенные модели](https://github.com/devexperts/QD/blob/0ddc0a09779fb61d74cc0b37c6449ff47dcb715f/dxfeed-api/src/main/java/com/dxfeed/schedule/Schedule.java),
включая необычные прямые поля `TimeDef`, нулевые длительности и порядок свойств. Нативные пределы
могут отказать дальнейшему построению с `RESOURCE_LIMIT`; они не нормализуют исходные значения
молча и не меняют принятое правило грамматики.

## Поколения календаря и обновления

`CalendarDefaults` содержит типизированную signed-версию в миллисекундах и полные упорядоченные
`CalendarDefaultsEntry`. Виды записей соответствуют `hd`, `sd`, `xd`, `tv`. Имена и значения
заимствуются только на время `setDefaults`; контекст копирует всё удерживаемое. Именованные списки
ссылаются только на предыдущие записи своего namespace. Дубликаты имён и неверные площадки
отклоняются. Версия baseline — `1774285200000`, дата исходника — `20260323-170000+0000`.

```cpp
using namespace org::ttldtor::qdcxx::schedule;
const CalendarDefaultsEntry entries[] = {
    {CalendarEntryKind::HOLIDAY_DAYS, u"Closed", u"20261225"},
    {CalendarEntryKind::VENUE, u"Local", u"name=Local market;tz=UTC;hd=Closed;0=09001700"}
};
auto result = context.setDefaults({1780000000000LL, entries});
```

Обновление проверяет полный кандидат и перестраивает каждую живую identity до единой публикации.
Неиспользуемый кеш может быть удалён в этой публикации. Неверные данные, пределы, ошибка выделения
или конфликт транзакций сохраняют опубликованные defaults и живые metadata. Проверенная более
старая версия возвращает `OLDER_IGNORED`; изменённые defaults с равной версией могут заменяться.
Старые неизменяемые reader pins сохраняют исходные модели и данные. Эта атомарная C++-граница
усиливает последовательную глобальную переинициализацию эталона.

API **не объявляет** Java-загрузчик `setDefaults(byte[])` или raw-byte parser date header
`TimeFormat.GMT`. Приложение передаёт типизированную версию явно. Встроенный baseline — отдельно
проверенный хешем ресурс, а не разрешающий runtime-загрузчик других файлов. Обновление календаря
не меняет данные timezone-провайдера. Его офлайн-развёртывание и перезапуск описаны в
[ADR-0008](decisions/ADR-0008-schedule-timezone-data-ownership.ru.md).

## Профиль identity и зависимости

Детерминированный профиль содержит все 631 именованных ID, принимаемых фактическим закреплённым
Java 8/TZDB 2024a `TimeUtil`, а также нормализованные пользовательские `GMT+HH:MM` и `GMT-HH:MM`
с часами 00–23 и минутами 00–59. Исходное написание и формы signed zero сохраняются. Неизвестные
ID, изменения регистра и сокращённые смещения отклоняются. Таблица проверяет identity; переходов
timezone в ней нет, и она не утверждает, что одни IANA aliases реализуют политику Java ID.

[Манифест](../resources/schedule/manifest.json) содержит хеши исходника/runtime/данных. Java runtime
не нужен для сборки или использования C++-библиотеки. Выбранные production-переходы остаются IANA
TZDB 2026f с отдельно квалифицированным приватным провайдером. Parser target не приобретает и не
линкует date/tz SDK, CURL или backend timezone-запросов. Будущая интеграция запросов по моментам
должна сохранять принятые границы совместимости и провайдера.

## Конечные ресурсы и concurrency

`ScheduleLimits` раздельно задаёт пределы входа, работы построения, staging и retention. Они
считают логические владеющие поля и моделируемую работу, а не точный heap/RSS. Overhead аллокатора,
control blocks/ёмкости контейнеров и принадлежащий caller вход/выход не входят в логические байты.
Скомпилированные ресурсы/identity имеют фиксированное общее backing для контекстов.

| Настройка | Default и граница |
| --- | --- |
| `inputUnits`, `defaultUnits` | 65 536 units инструмента/площадки; 1 048 576 суммарных UTF-16 units типизированных defaults |
| `defaultEntries`, `properties` | 4 096 именованных записей; 1 024 различных merged properties |
| `dateValues`, `dayDefinitions`, `sessionsPerDay` | 100 000 накопленных credits построения дат; 8 192 построения дней; 1 024 сессии абстрактного дня вместе с gaps |
| `work`, `stagingBytes` | 16 000 000 накопленных credits проверки/копирования; 33 554 432 логических байта построения за операцию |
| `retainedBytes` | 67 108 864 логических байта общего retention-домена |
| `retainedGenerations`, `retainedSchedules`, `retainedRuleModels`, `retainedBundles` | 4 поколения календаря; 256 identities; 1 024 модели identity/generation; 16 bundles вместе с кандидатами/reader pins |
| `inactiveCacheTarget` | 64 неактивных identity после явного сбора кеша; все записи всегда ограничены `retainedSchedules` |

Удалённое/заменённое построение не возвращает credits работы. Retained charges переживают handle
контекста, пока модели удерживаются. `getUsage()` показывает общий домен; дополнительные копии
уже удерживаемого handle не являются отдельными identities. Пределы должны вмещать встроенный
baseline до создания контекста. Обновлению также нужно место для полного staging-поколения при
живых старых значениях.

Фабрика может сначала собрать неактивный кеш отдельной полной публикацией, сохраняя календарь и
все живые identities. Последующая ошибка фабрики поэтому может уменьшить cache/resource accounting;
полный rollback кеша не обещается. Типизированное обновление defaults имеет более сильную
single-commit гарантию выше. Построение и уничтожение вытесненных моделей выполняются вне краткого
commit-lock; callbacks приложения и принадлежащие ему destructors под этим lock не вызываются.

Конкурирующие writers возвращают `CONCURRENT_CHANGE` после одной ограниченной транзакции вместо
скрытых бесконечных повторов. Независимые неизменяемые readers допустимы. Фоновых потоков,
автообновлений и application progress pumps нет.

## Сборка и установленное использование

Выберите `ORG_TTLDTOR_QDCXX_BUILD_SCHEDULE=ON`; default — OFF. Target — `qdcxx_schedule`.
Отдельный installed consumer использует:

```cmake
find_package(qdcxx CONFIG REQUIRED COMPONENTS schedule)
target_link_libraries(app PRIVATE qdcxx_schedule)
```

Приватные source/helper headers не нужны. OFF не генерирует schedule-ресурсы и не приобретает
зависимости. Пакет устанавливает проверяемые календарь/манифест identity и MPL2 notices рядом с
лицензией проекта. [Полный консольный пример](../examples/schedule_rules/README.ru.md) показывает
конечное клиентское приложение. [Production oracle](../tools/upstream/schedule-oracle/README.ru.md)
является необязательным инструментом разработчика.
