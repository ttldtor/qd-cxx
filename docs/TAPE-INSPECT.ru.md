# Инспекция tape, версия 1

[English version](TAPE-INSPECT.md). Английская версия является нормативной.

## Внешние нативные JSON-схемы и вывод версии 6

Используйте `--schema PATH` вместо `--profile BUILTIN`, чтобы передать владеющую локальную схему
без пересборки. Обязательны ровно один источник схемы и `--input PATH`.
[Нативный контракт версии 1](../spec/schema/NATIVE-JSON.ru.md) принимает `qdcxx-native` версии 1,
обычные записи с `hasTime:false`, точные полные типы 2/8/10/40/56/72/88/120, упорядоченные локальные
поля и явные lookup-ключи. Локальные ID — последовательные позиции в массиве, независимые от ID
отправителя. Сохраняются пользовательские записи, переставленные и дополнительные поля. Имена —
точный текст из Unicode scalar values, преобразуемый во владеющий UTF-16; aliases, property names
и Java slots не выводятся автоматически.

Соберите с [необязательным JSON-загрузчиком](CPP-BUILD.ru.md#нативный-загрузчик-json-схем).
Из корня репозитория эти команды используют повторно применимую нативную схему с неизменёнными
смешанными tapes, полученными от Java:

```text
.work/schema-json-msvc/Release/qdcxx-tape-inspect --input tests/fixtures/encoding/field-types/expected/mixed-stream.qtp --schema spec/schema/examples/native/field-types.json --output-format human
.work/schema-json-msvc/Release/qdcxx-tape-inspect --input tests/fixtures/encoding/field-types/expected/mixed-raw.qtp --schema spec/schema/examples/native/field-types.json --tape-mode raw-message-v1 --output-format tsv
```

Для сборки с одной конфигурацией используйте `.work/schema-json-linux/qdcxx-tape-inspect`.
JSON-файл не выбирает и не расширяет режим tape: по умолчанию остаётся `legacy`, а
`raw-message-v1` указывается явно. Оба внешних режима выводят версию **6**, профиль
`external-schema-v1`, с общими типизированными полями в локальном порядке. Тип 10 сохраняет null,
пустые и точные UTF-16 значения; скаляры сохраняют точное представление type/raw. Дополнительные
поля остаются видимыми, для неизвестных wire-записей сохраняется прежняя политика пропуска.
Имена Quote или Profile не запрашивают проекцию события; приложения используют
[подготовленные API](CPP-BUILD.ru.md#нативный-загрузчик-json-схем).
[Контракт](../spec/schema/NATIVE-JSON.ru.md) определяет строки TSV/human.

Схема читается один раз, конечные бюджеты действуют во время чтения и загрузки. Значения по
умолчанию совпадают с библиотечными; ноль — настоящий лимит, равенство допустимо. Эти лимиты
отдельны от прежних бюджетов декодированных записей/полей, строк, входного tape и вывода:

| Параметр | По умолчанию | Единица |
| --- | --- | --- |
| `--max-schema-bytes` | 1048576 | Все байты документа схемы, включая пробельные символы |
| `--max-schema-depth` | 16 | Вложенные объекты/массивы; глубина корня — 1 |
| `--max-schema-records` | 1024 | Локальные записи |
| `--max-schema-fields` | 16384 | Суммарное число локальных полей |
| `--max-schema-lookups` | 32768 | Суммарное число lookup-записей |
| `--max-schema-name-units` | 1024 | UTF-16 units в одном имени записи/lookup |
| `--max-schema-total-name-units` | 1048576 | Суммарные UTF-16 units всех имён записей/lookup |

Сначала проверяются аргументы, затем доступность загрузчика, затем файл схемы и схема целиком;
только после этого открывается tape. Поэтому ошибка схемы имеет приоритет над отсутствующим tape,
без перехода к встроенной схеме. Ошибки схемы не выводят в stdout заголовок или данные и создают
одну ограниченную строку stderr: `schema-error<TAB>1<TAB>CODE<LF>`. Представление одинаково для
TSV/human и версий диагностики 1/2. Внешний режим по умолчанию использует диагностику 2;
допустимы явные 1/2. Коды выхода: usage 2, I/O файла схемы 3, неподдерживаемые
профиль/версия/тип/индексная семантика или отключённый загрузчик 4, некорректные JSON/схема 5,
ошибка бюджета/выделения памяти 6. Контракт перечисляет стабильные коды; последующие ошибки tape
сохраняют прежнюю диагностику.

При `ORG_TTLDTOR_QDCXX_BUILD_SCHEMA_JSON=OFF` корректные внешние запросы сообщают
`LOADER_DISABLED` до открытия обоих файлов. Вызов без аргументов и отдельный `--help` остаются
идентичными и не выполняют файловый I/O: stdout, пустой stderr, выход 0 при успешной записи.
Встроенные вывод/диагностика по умолчанию неизменны. Не поддерживаются XML,
`qd-3.355-xml-captured`, imports, URLs, environment/Java properties, автоопределение, индексные
записи, новые wire-типы/преобразования, замена схемы во время работы и транспорт. Нативные примеры
определяют наш исходный формат; они не доказывают более широкую поддержку частного tape.

## Явный oracle-field-types-v1 и вывод версии 4

`--profile oracle-field-types-v1` выбирает фиксированную диагностическую локальную схему `FieldTypes`:
Text(10), Short(40), Sequence(72), Date(88), Count(8), Char(2), Seconds(56), Wide(120), Tail(10).
Она работает без параметра режима/с явным `--tape-mode legacy` и с явным `--tape-mode raw-message-v1`.
Локальная политика — `EXTENDED_FIELDS_V1`; выбор контейнера остаётся независимым. Этот адаптер
не обнаруживает схему и не отображает событие Profile. [FIELD-TYPES](../spec/encoding/FIELD-TYPES.ru.md)
определяет точные значения, lookup-имена схемы, грамматику строк, учёт и Java-доказательства.

TSV и human используют версию 4 для этого профиля. TSV-записи имеют семь ячеек:
`field-record`, индекс кадра, индекс выданной записи, локальный ID, UTF-16 hex имени, UTF-16 hex символа, значения.
Разделённые запятыми значения имеют вид `type:raw:payload`: payload скаляра — `-`; тип 10 использует
`null`, `empty` или точные UTF-16 units по четыре строчные hex-цифры с нулевым raw.
Human сохраняет те же tags/raw и безопасно заключает строки в кавычки, экранируя управляющие
символы и одиночные суррогаты. Преобразования ShortString, календаря или event-time не выполняются.
Время RAW-кадра остаётся отдельно от поля SEQUENCE. Строки descriptor/frame/timing/completion
сохраняют прежнюю грамматику своего режима. Версия диагностики по умолчанию — 2; явные 1/2 доступны.

Пять дополнительных беззнаковых десятичных лимитов ограничивают строки полей отдельно от символов и имён:

| Параметр | По умолчанию | Значение |
| --- | --- | --- |
| `--field-string-bytes` | 65536 | Исследованные байты префикса и тела одной строки |
| `--field-string-units` | 16384 | Допущенные UTF-16 units одной строки |
| `--max-field-bytes` | 16777216 | Исследованные байты строк всего файла |
| `--max-field-units` | 4194304 | Допущенные units декодирования всего файла |
| `--max-owned-field-units` | 4194304 | Units завершённого вывода, текущих и временных строк |

Ноль означает нулевой допуск. Работа декодирования учитывается для пропущенных/повторных/неуспешных
значений без возврата; владеющие units ограничивают логическое UTF-16 хранение, не расходы аллокатора.
Полная строка вывода должна помещаться в остаток байтового бюджета до аллокации и первой записи.
Обнаруженный сбой вывода подавляет последующий completion; ошибка финального flush может произойти
после уже записанного completion. Успех требует кода выхода 0.

```powershell
.work/field-types-msvc-024/Release/qdcxx-tape-inspect --input tests/fixtures/encoding/field-types/expected/mixed-stream.qtp --profile oracle-field-types-v1 --output-format human
.work/field-types-msvc-024/Release/qdcxx-tape-inspect --input tests/fixtures/encoding/field-types/expected/mixed-raw.qtp --profile oracle-field-types-v1 --tape-mode raw-message-v1 --output-format tsv
```

Существующие профили сохраняют версии вывода/диагностики и поведение, кроме расширенной справки tape.
Вызовы без аргументов и с отдельным `--help` остаются одинаковыми без входного IO. Неверные,
пропущенные или повторные аргументы профиля дают usage error до открытия входа.
[Покрытие](../tests/conformance/protocol/field-types/COVERAGE.ru.md) и
[авторская валидация](../tests/conformance/protocol/field-types/VALIDATION.ru.md) описывают проверки и ограничения;
независимое ревью ожидается. Исторические разделы ниже описывают свои исходные этапы.

## Явный raw-message-v1 и вывод времени версии 3

`--tape-mode raw-message-v1` выбирает ограниченный RAW_DATA/MESSAGE без сжатия независимо от
`--profile oracle-sre-v1|default-quote-v1`. Режим допускает только измеренное подмножество
options/заголовков, нулевые event flags и существующие точные полные типы. Отсутствующий режим
и явный `legacy` сохраняют прежние вывод, отказы и стандартную диагностику. Режим не выводится из входа.

[RAW-TAPE](../spec/protocol/RAW-TAPE.ru.md) определяет строки TSV/human версии 3: исходные границы
frames, точные options/time дескриптора, каждый heartbeat, включая последний, общее время data
frame, отсутствие исходного timestamp отдельно от нуля, packed cursor sequence и доставленное
event time. Бизнес-время Quote независимо; отображаемый eventTime в новом режиме отражает время
cursor. `--max-timing-events` ограничивает накопленные попытки metadata явных heartbeat/данных
(по умолчанию 4096). Прежние бюджеты и версии диагностики 1/2 доступны. Human-объяснение отказа
соответствует выбранному режиму; legacy-текст неизменен. Равенство no-argument/help и проверка
аргументов до IO обязательны. Новый режим не ожидает времени воспроизведения.

```powershell
.work/raw-msvc/Release/qdcxx-tape-inspect --input tests/fixtures/protocol/raw-tape/expected/connector-quote.qtp --profile default-quote-v1 --tape-mode raw-message-v1 --output-format human
```

Команда читает неизменённый production Java fixture. Частный tape имеет
[дополнительные ограничения полей/схем](REAL-TAPE-GAPS.ru.md); успех generated fixtures не
подтверждает полную поддержку. Исторические разделы ниже описывают прежние версии и их проверки.

## Явный default-quote-v1 и диагностика version 2

Имена и human-пояснения диагностики реализованы в tools/tape-inspect/diagnostics.hpp/.cpp
(qdcxx_tape_inspect_tool). Protocol сохраняет данные TapeRejection/TapeDiagnostic и точные checkpoints,
без имён CLI-профилей и советов по выбору. Перенос представления сохраняет байты stdout/stderr,
версии форматов и коды завершения. Авторские проверки исправления ревью
отделены от исторической валидации; повторное независимое ревью ожидается.

QDCXX-022 добавляет --profile default-quote-v1 со всеми восемью неизменными полями default composite
Quote. Транспорт остаётся BINARY/uncompressed/NONE/EMPTY_SET/STREAM_DATA. TSV по умолчанию и
--output-format human имеют отдельную version 2 для этого профиля: точные type:raw поля, mapped
binary64 биты и время в миллисекундах; human цены/размеры выводятся decimal text, не raw integers.
[Полная грамматика строк, безопасные объяснения и потери отображения](../spec/protocol/DEFAULT-QUOTE.ru.md).

--diagnostics-version 1|2 выбирает прежнюю диагностику из девяти ячеек или новую из десяти.
По умолчанию 1 для oracle-sre-v1 и 2 для default-quote-v1. Version 2 добавляет статическое имя
причины; human — фиксированное объяснение с сохранением точных offsets. Явная version 2 объясняет
также неподдержанный локальный профиль до открытия файла. Без opt-in весь прежний S/R/E вывод и
ошибки побайтно сохраняются; QTP inspector неизменен. Help перечисляет оба профиля, эквивалентность
вызова без аргументов/--help сохраняется. Прежние числовые бюджеты применяются с однократным
списанием typed поля. Автоопределения профиля нет.
API потоковой инспекции проверяет совместимость схемы/вывода до чтения или записи stdout;
несовпадение возвращает 4 со stage profile и причиной LOCAL_PROFILE в версии 2. Вывод Quote требует
одну запись Quote с восемью точными типами по порядку; явные lookup-связи остаются контрактом вызывающей стороны.

[Выполненные проверки](../tests/conformance/protocol/quote/VALIDATION.ru.md); независимое ревью ожидается.

[English version](TAPE-INSPECT.md). Английская версия является основной.

Необязательная qdcxx-tape-inspect читает [ограниченную tape](../spec/protocol/TAPE-READER.ru.md).
Обязательны --input PATH --profile oracle-sre-v1. Нет stdin, сети и автоопределения.
По умолчанию TSV; --output-format human использует прежнее безопасное представление записей
и version в кавычках UTF-8. Без аргументов и с отдельным --help вывод идентичен: stdout, пустой stderr,
код 0 при успешном выводе. Непустые неверные/неполные аргументы дают 2 до открытия файлов.

Лимиты — беззнаковые десятичные size_t, без повторов опций и без значения «неограниченно»;
ноль допустим, кроме chunk-size. --max-input, --max-frame, --max-frames, --max-descriptions,
--max-actions, --max-name-units, --max-total-name-units, --max-records, --max-fields, --max-values,
--max-symbol-units, --symbol-units, --max-output, --max-construction, --max-properties,
--max-messages, --max-descriptor-units и --max-text-units задают отдельные конечные лимиты.
Help перечисляет значения по умолчанию. Frame+9 и streamsize должны быть представимы.
Лимиты локальной схемы: 1024 записи, 65536 полей/lookup, 1024 единицы/имя, 1048576 единиц суммарно.
Встроенный профиль — диагностический S/R/E, не default Quote и не схема, выведенная из входа.
Оба инспектора можно собирать независимо с BUILD_TESTING=OFF без загрузки тестов и поиска Python.

Вывод LF/без BOM, канонические числа, точные UTF-16 единицы строчным hex в TSV, '-' для пустых
последовательностей. Грамматика frame/record и human-экранирование повторно используются без изменения
старого инспектора. Новый заголовок: `format<TAB>qdcxx-tape-inspect<TAB>1`; human-заголовок:
`qdcxx-tape-inspect human 1 profile=oracle-sre-v1 identities=local`.
После принятого дескриптора выводится `descriptor, version-present(0|1), version-hex-or--,
time(NONE|absent), send(15|-), receive(-)` с TAB-разделителями. Принятие гарантирует type=tape и пустое
opt. Human-дескриптор выводит version в кавычках либо absent, type=tape opt=EMPTY_SET,
time=NONE|absent и send=15|-. Version никогда не определяет поддержку.

Перед завершением выводится `markers<TAB>count` (human `Markers: count=N authenticated-footer=no`).
Это наличие пустых конвертов, не подлинность, физический EOF или полнота записи. Итоговая строка
complete использует прежнюю грамматику шести ячеек счётчиков под новым идентификатором формата.
Успех требует кода 0 после последнего flush; физическая ошибка вывода может усечь любую строку.
Каждая строка сначала проверяется по бюджету закодированных байтов до расширения/выделения/записи.
Завершённый префикс данных сохраняется после ошибки; частичная текущая запись не выдаётся.
После обнаруженной ошибки нет markers/complete. Ошибки чтения/flush дают ненулевой код.

Коды: 0 успех/help, 2 аргументы, 3 IO, 4 неподдерживаемое/порядок, 5 повреждение, 6 ресурсы/память.
Диагностика: `incomplete, code, stage, detail, frame-start, accepted-file-bytes, payload-start,
payload-consumed, payload-error` (9 ячеек с TAB); недоступные позиции '-'. Detail вложенного этапа —
порядковое значение существующего enum, иначе ноль. Принятая файловая позиция не подменяет потребление
payload. Абсолютная позиция его проверки равна payload-start плюс относительная. IO-диагностика
использует метку операции без выдуманных позиций парсера. Читаются ограниченные порции; на точном
лимите входа один peek отличает чистый EOF от превышения. Нет продолжения после ошибки,
удаления/перестановки входа и разбора протокола в представлении.

Настройка: -DORG_TTLDTOR_QDCXX_BUILD_TAPE_INSPECT=ON; target qdcxx_tape_inspect,
файл qdcxx-tape-inspect. [Авторская валидация](../tests/conformance/protocol/tape/VALIDATION.ru.md)
содержит завершённые проверки; независимое ревью ожидается.

Строки дескриптора в CLI также имеют фиксированный лимит тела 4096 байт; библиотека предоставляет
отдельный параметр этого лимита. Независимые вызовы tool API по умолчанию используют local-schema
и подписи field[index]; CLI явно выбирает oracle-sre-v1. При ошибке декодированного события строки
frame и завершённого префикса выводятся до сообщения ошибки парсера; ошибка записи этого префикса
имеет приоритет IO/бюджета вывода. Это не разрешает обработку последующего входа.
