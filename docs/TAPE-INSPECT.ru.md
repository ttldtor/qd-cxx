[English version](TAPE-INSPECT.md). Английская версия является нормативной.

## Проверка binary JSON конфигурации

При включённом необязательном JSON loader проверьте отдельно выбранный
[native binary profile](../spec/schema/NATIVE-BINARY-JSON.ru.md) без открытия tape:

```powershell
qdcxx-tape-inspect --schema spec/schema/examples/native-binary/pair.json --schema-format binary-v1 --validate-schema
```

Обязательны оба новых флага и непустой schema path, отличный от `-`. Режим принимает только эти
селекторы и известные числовые `--max-schema-*` limits. Input, profile, wire-schema, tape-mode,
source-profile и rendering/output options отклоняются как usage до файлового I/O. Три binary-only
лимита — `--max-schema-parser-bytes`, `--max-schema-work`, `--max-schema-model-bytes`; каждый имеет
default 67 108 864 в собственных единицах и пересекается с семью прежними schema limits. Work units —
логические кредиты; model bytes описывают две логические копии объявлений. Total heap/RSS cap нет.
Новые budget flags не выбирают и не изменяют ordinary mode без обоих явных селекторов.

Успех пишет ровно `schema-valid<TAB>1<TAB>qdcxx-native-binary<TAB>1<LF>` в stdout с пустым stderr;
возврат 0 возможен только после успешных write/flush. Ошибки используют ограниченную статическую
stderr-строку `schema-error<TAB>1<TAB>CODE<LF>` без повторения пути/содержимого. Exit 2 — неверные
аргументы; 3 — file/output I/O; 4 — неподдерживаемые profile/version/type/layout или `LOADER_DISABLED`;
5 — malformed JSON/invalid schema; 6 — resource/allocation failure. При корректных options JSON OFF
возвращает `LOADER_DISABLED` до попытки открыть отсутствующий schema file; неверные options дают usage 2.

Без аргументов и с отдельным `--help` выводится одинаковая справка без рабочих входов и file I/O;
ошибки вывода справки сохраняют ненулевой exit. Прежние tape defaults и output versions сохранены.
Режим проверяет только конфигурацию; HISTORY tape reading, subscription и transport facade не добавлены.

## Владеющие самодостаточные источники и вывод версии 9

Явный профиль `self-contained-segments-v1` владеет конечным упорядоченным списком локальных файлов.
Он реализует [контракт конечной последовательности](../spec/protocol/TAPE-SEQUENCE.ru.md): отдельные
состояния схемы/времени для каждого вхождения, проверку admission, физическое закрытие и финальный flush.
Прежние профили с заимствованным потоком и их версии вывода 1–8 сохраняются отдельно.

```powershell
qdcxx-tape-inspect --source-profile self-contained-segments-v1 --wire-schema binary-catalog-v1 --tape-mode binary-catalog-v1 --time-policy none --input first.qtp
qdcxx-tape-inspect --source-profile self-contained-segments-v1 --wire-schema binary-catalog-v1 --tape-mode binary-catalog-v1 --time-policy long --input first.qtp.gz --time-input first.time.gz --container gzip --time-container gzip
qdcxx-tape-inspect --source-profile self-contained-segments-v1 --wire-schema binary-catalog-v1 --tape-mode binary-catalog-v1 --time-policy field --input first.qtp --input second.qtp --aggregate-reservation-copies 2
```

Обязательны профиль источника, оба селектора binary-catalog и `--time-policy none|message|field|long|text`.
LONG/TEXT требуют ровно один `--time-input` на каждый `--input`; пары образуются по отдельному порядку
появления этих параметров. Повторные пути являются отдельными вхождениями; повторы остальных параметров
считаются ошибкой использования. NONE/MESSAGE/FIELD отклоняют все параметры спутника, даже явно заданный
контейнер `none`. Оба контейнера по умолчанию — `none`; вид общий для всех данных, отдельно — для спутников.
Библиотека допускает независимый выбор контейнеров для каждого вхождения. CLI не определяет имена по
расширению, не раскрывает wildcard, не сортирует и не ищет файлы, не использует stdin, follow, сеть,
replay или восстановление. Пустой путь и `-` недопустимы. Внешнюю/локальную схему с этим режимом не совмещают.

NONE разрешает отсутствие свойства времени в новом начальном дескрипторе, как в стандартном выводе
производителя; heartbeat с меткой MESSAGE отклоняется. MESSAGE требует первого heartbeat с меткой времени
до публикации записи; FIELD требует сырых метаданных FIELD у каждой записи. LONG/TEXT требуют применения
первой метки спутника до публикации записи. Остальные политики требуют явного совпадающего объявления
времени в начальном дескрипторе. Упакованный ноль не заменяет отсутствующее присваивание. Относительное
время спутника и смешанные наложения MESSAGE/спутника/FIELD остаются вне этого именованного профиля.

Здесь принимается только версия диагностики 3; при отсутствии параметра выбирается 3. По умолчанию
выводится TSV; HUMAN сохраняет ту же информацию с безопасным цитированием/hex. [Контракт output9](../spec/protocol/TAPE-SEQUENCE.ru.md)
определяет native-идентичность пути, строку политики сразу после каждого source-begin, все 27 ячеек записи,
различие сырых FIELD и внешнего/эффективного времени, строки ресурсов и единственный итоговый маркер.
Поколения схемы, ID отправителей и порядковые номера попыток FIELD локальны для сегмента; опубликованные
записи также имеют проверяемый сквозной индекс. Native-пути кодируются UTF-16LE hex в Windows и байтовым hex
в POSIX; преобразование локали и канонизация файловой системы не определяют идентичность.

### Ограничения и admission

Каждое ограничение — конечное беззнаковое десятичное число; ноль остаётся нулём. Прежние параметры
binary-catalog для parser/string/schema/construction/payload/snapshot сохраняют свои стандартные значения.
Ограничения размера документа JSON и глубины относятся только к внешнему загрузчику и здесь отклоняются.
`--max-owned-field-time-records` по умолчанию равен 1048576. До admission `prepareLimits` вычисляет pending
как frame+9, payload/symbol-input как frame, symbol-state как symbol-units, emitted-records как max-records.
После admission ограничения не меняются. `--help` перечисляет все параметры и фактические значения по умолчанию.

| Параметр источника | По умолчанию | Значение |
| --- | --- | --- |
| `--max-sources` | 256 | Вхождения, включая повторные пути |
| `--max-path-units` | 4096 | Native-кодовые единицы одного пути |
| `--max-total-path-units` | 1048576 | Native-единицы всех путей данных и спутников |
| `--max-path-output-bytes` | 4194304 | Байты hex-представления native-путей |
| `--aggregate-reservation-copies` | 1 | Явный множитель ёмкости, допустимо 1..256 |
| `--max-source-output` | 16777216 | Допуск кодированного вывода каждого вхождения |
| `--max-output` | 67108864 | Единый допуск кодированных байтов stdout+stderr команды |
| `--max-physical-probes` | 2 | Отдельные суммарные байты физической проверки превышения |
| `--max-inflated-probes` | 2 | Отдельные суммарные отброшенные логические байты проверки превышения |

Copies с проверкой переполнения умножает каждую разрешённую вложенную ёмкость parser/container/scanner,
рабочую память feed и допуск копирования событий. Общий вывод и проверки превышения не умножаются.
Полные объявленные резервы учитываются для каждого вхождения до открытия файлов, включая повторы;
неиспользованные ёмкости не возвращаются. Поэтому два источника со стандартными ограничениями требуют
явного copies>=2, даже если оба малы. Сумма допусков вывода всех источников, строк идентичности и итогового
резерва 65536 байт независимо должна помещаться в max-output. Одновременно принадлежит не более одной
пары/двух физических файлов.

До диагностики ошибок аргументов отдельный проход по позициям параметров разрешает бюджет вывода.
Учитываются только корректные операнды `--max-output`; при повторах берётся минимум корректных значений.
Некорректный операнд не задаёт допуск и остаётся ошибкой использования 2; если корректных значений нет,
действует конечное стандартное значение. Порядок параметров не позволяет превысить допуск диагностики.
Если целая строка не помещается, stderr остаётся пустым, а код завершения сохраняет первую ошибку.

Каждый член `ContainerLimits` имеет варианты с префиксами `--source-` и `--time-source-`:

| Суффикс | По умолчанию | Единица |
| --- | --- | --- |
| compressed-bytes / inflated-bytes | 67108864 / 67108864 | Физические / выданные логические байты |
| expansion-ratio / ratio-slack | 1000 / 65536 | Безразмерное отношение / байты одного member |
| gzip-members / zip-entries | 1024 / 64 | Начатые member / entries |
| header-bytes / total-header-bytes | 262144 / 4194304 | Байты одного / суммарных метаданных |
| work-bytes / inflate-calls | 268435456 / 262144 | Необратимая работа в байтах / фактические вызовы |
| retained-bytes / inflater-bytes | 4194304 / 1048576 | Рабочая память и метаданные / текущая память inflater |
| chunk-bytes | 4096 | Положительный размер физической входной рабочей памяти в байтах |

`--chunk-size` отдельно задаёт положительный размер выдаваемого parser-span. Параметры scanner спутника:
`--time-input-bytes` (4194304), `--time-line-bytes` (128), `--time-lines` (262144), `--time-marks` (262144),
`--time-work-bytes` (8388608) и `--time-retained-bytes` (128). Это логические входные байты, байты тела строки,
попытки строк, возвращённые метки, байтовая работа просмотра/разбора и память строки.
Контракты [контейнера](../spec/protocol/TAPE-CONTAINERS.ru.md) и [scanner](../spec/protocol/SIDECAR-TIME.ru.md)
определяют точные границы и разрешённые диагностические проверки EOF; резерв не является измерением работы или RSS.

При `ORG_TTLDTOR_QDCXX_BUILD_TAPE_COMPRESSION=OFF` явный gzip/zip возвращает unsupported4 на этапе
конфигурации до копирования имён, строк вывода и открытия источников; NONE работает без zlib. Для этого режима JSON и replay могут оставаться OFF;
при выполнении CLI зависимости не загружаются. Без аргументов и с отдельным --help вывод одинаков: только stdout,
exit0 при успешных записи/flush, без I/O источников и конфигурации. Непустой неверный список аргументов даёт2.

### Завершение и проверка

Коды: 0 завершение/help, 2 использование, 3 I/O, 4 неподдерживаемое, 5 повреждённое, 6 ресурсы/выделение
памяти, 7 STOPPED. Новый параметр отмены CLI или планировщик сигналов не устанавливается. Синхронная
владеющая библиотека принимает явный stop token. Она сохраняет первую причину, закрывает только текущую
собственную пару после уничтожения заимствующих адаптеров и не открывает/читает/подаёт новые источники после
ошибки или отмены.

Source-end требует parser finish, полного хвоста спутника, EOF/целостности контейнеров и физического
закрытия. После закрытия последнего источника flush данных должен пройти до вывода ресурсов/итога;
затем должен пройти финальный flush маркера. Видимые байты complete-v9 остаются предварительными при
ошибке последнего flush: COMPLETE подтверждает только успешный результат/exit0. Прежние полные строки
остаются полезным частичным префиксом. Diagnostics3 содержит статические stage/reason и необязательные
локальные координаты physical fetched/consumed, logical produced, parser accepted, начало frame/payload
и строку спутника; неизвестные значения — `-`. Сжатые смещения не задают обратного отображения в QTP.
Cleanup-диагностика сохраняет не более вторичных причин data-close, time-close и flush, не заменяя первую.

Фиксированные токены операции и причины ниже не содержат входных байтов или текста пути.

| stage | Набор staticReason |
| --- | --- |
| usage | invalid-arguments, duplicate-option, path-limits, zero-chunk |
| configuration | compression-disabled, path-limits, unrepresentable, allocation, arguments-unavailable, invalid-argument, invalid-presentation |
| admission | configuration-refused, identity-overflow, identity-output-limit |
| profile | empty-segment, missing-source-header, missing-time-declaration, mixed-time-declaration, message-time-overlay, missing-field-time, missing-time-assignment |
| schema / record | ordinal-overflow; для schema также missing-source-plan |
| open / close | data-open или time-open / source-close |
| parse / sidecar | parser-failure, parser-finish, no-progress / scanner-failure, scanner-finish |
| container | invalid-header, invalid-data, truncated, checksum, invalid-directory, unsupported-container, compressed-limit, inflated-limit, ratio-limit, header-limit, member-entry-limit, work-limit, source-io, allocation-failure, invalid-argument, not-finished, invalid-container-state |
| aggregate / allocation | counter-overflow / allocation-failure, length-limit |
| stop / io | cancelled / stream-failure |
| write / flush | output-limit, sink-io, diagnostic-output-limit, io-error / sink-io, diagnostic-io |
Native-регрессии `source_sequence_cli`, `source_sequence_io` и `source_sequence_large` проверяют реальную
границу CLI, ошибки владеющего жизненного цикла и ограниченный временный файл из 3000000 записей.
Большой тест использует не более256 записей в кадре и ограниченный sink, сравнивающий каждый канонический
байт schema/frame/record/time/source/complete с независимым ожидаемым представлением, строящимся по мере
работы, для parser chunks1 и4096. Полный вывод не удерживается; строки ресурсов проверяются отдельно,
поскольку зависящие от chunk наблюдения могут различаться. Логические резервы и отдельно измеренный OS RSS
описывают разные величины. Квалификация именованного production-корпуса отделена от общей поддержки QD,
живого транспорта и бизнес-событий.

## Явная wire-схема и вывод версии 7

Параметр `--input PATH --wire-schema ordinary-v1` явно строит
[схему с точными обычными полями](../spec/schema/WIRE-INVENTORY.ru.md) без внешней
схемы и бизнес-адаптера. Требуется ровно один источник: `--wire-schema ordinary-v1`,
`--schema PATH` или `--profile NAME`. Неверные сочетания, пропущенные и повторные
значения приводят к ошибке использования до открытия входного файла. По умолчанию
выводится диагностика версии 2; доступны оба прежних явных режима tape. Загрузчик
JSON можно отключить. Все ограничения `--max-schema-*` на число записей, полей,
ключей поиска и имён применяются ко всему объединению wire-описаний до создания
владеющей локальной формы. Ограничения размера и глубины JSON действуют только
при загрузке. Параметр `--max-construction` дополнительно учитывает временную
работу по обнаружению согласно WIRE-INVENTORY. Настройки окружения и вывод схемы
по содержимому источника не используются.

```powershell
qdcxx-tape-inspect --input tests/fixtures/encoding/field-types/expected/mixed-stream.qtp --wire-schema ordinary-v1
qdcxx-tape-inspect --input tests/fixtures/encoding/field-types/expected/mixed-raw.qtp --wire-schema ordinary-v1 --tape-mode raw-message-v1 --output-format human
```

TSV начинается строкой `format, qdcxx-tape-inspect, 7, ordinary-v1, MODE`, ячейки
разделяются TAB. Прежние строки frame/descriptor/heartbeat/timing/marker/completion
сохраняют грамматику выбранного режима. Версия 7 добавляет полные снимки схемы и
источников после каждого успешного DESCRIBE_RECORDS, перед последующими данными.
Поколение начинается с 1 и увеличивается один раз на каждое успешное событие,
включая пустой пакет описаний. Возвращённый, но отклонённый кадр не меняет
поколение и не выводит метаданные кандидата.

| Строка | Следующие ячейки, разделённые TAB |
| --- | --- |
| schema | frameIndex, generation, localRecordCount, sourceDescriptionCount |
| schema-record | generation, localId, recordNameHex, 0 (hasTime), localFieldCount |
| schema-field | generation, localId, localFieldId, fieldNameHex, fullTypeId |
| wire-record | generation, descriptionIndex, senderId, localId, recordNameHex, wireFieldCount |
| wire-field | generation, senderId, wireFieldIndex, fieldNameHex, fullTypeId, targetLocalFieldId |
| schema-end | generation |
| wire-data | frameIndex, recordIndex, generation, senderId, localId, recordNameHex, symbolHex, typedValues |

Индексы начинаются с нуля. Записи и поля схемы следуют локальному порядку
первого появления. Описания сохраняют исходный порядок добавления, их поля —
точный порядок в wire. Все имена и символы представлены строчными
четырёхзначными шестнадцатеричными кодами единиц UTF-16; `-` означает пустую
строку. Ячейка `typedValues` содержит значения `fullType:raw:units`, разделённые
запятыми, в текущем локальном порядке полей. Для типов, отличных от 10, `units`
равно `-`; тип 10 использует `null`, `empty` или точные шестнадцатеричные коды
UTF-16. Сырые десятичные значения со знаком не преобразуются в бизнес-значения.
В `raw-message-v1` строка `wire-data` дополнительно содержит `timestampMs`
(`-` при отсутствии), `eventTimeSequence` и `eventTimeMs`. Они сохраняют различие
точной метки времени wire и упакованного/доставленного времени; ноль отличается
от отсутствия. Прежние правила нулевых флагов, времени и параметров не расширяются.

Для каждой строки данных выберите привязку поколения и отправителя, чтобы
восстановить наличие и порядок исходных полей по локальным значениям.
Для `90:R(A,B)` и `7:R(B,C,A)` объединение A/B/C может содержать одинаковые
значения сырого нуля или null у обеих записей; целевые ID 0/1 и 1/2/0 в
`wire-field` различают отсутствие и первоначальный порядок источника. ID
отправителей берутся из декодированных wire-данных, а не выводятся обратно
из локального ID. Снимки содержат точные имена и полные типы; внешний JSON
для их понимания не нужен. Сохраняются логические исходные записи, а не
первоначальное байтовое кодирование примитивов и оболочки.

Каждая ограниченная группа строк метаданных учитывается в оставшемся бюджете
закодированного вывода до выделения памяти и записи; неограниченная история
снимков и буфер вывода не накапливаются. Короткая физическая запись может
оставить неполный снимок. `schema-end` завершает лишь этот снимок; полное чтение
по-прежнему требует финальной строки `completion` и кода завершения 0 после
сброса буферов. Ошибки парсера сохраняют прежние полные снимки и данные без
последующего `completion`. Человекочитаемый вывод содержит те же метаданные
с безопасными именами в кавычках; числовые строки метаданных сохраняют теги
строк и разделяются пробелами. Обычные `wire-data` показываются как `Fields`
с поколением, отправителем и точными типизированными полями, а не как
отображённое бизнес-событие.

Запуск без аргументов и отдельный `--help` по-прежнему дают одинаковый вывод
только в stdout и не выполняют ввод-вывод входных данных. Прежние профили
и вывод версии 6 для внешней схемы не меняются. Потоковая вспомогательная функция
`inspectWire(input, output, diagnostic, limits, format, diagnosticsVersion, mode)`
использует общий синхронный цикл проверки и возвращает прежние нативные коды
завершения. [Целевая проверка](../tests/conformance/protocol/wire-inventory/VALIDATION.ru.md)
разделяет специально разработанные случаи, производственные эталоны и
ограничения интеграционной проверки.

## Внешние нативные JSON-схемы и вывод версии 6

Используйте `--schema PATH` вместо `--profile BUILTIN`, чтобы передать владеющую локальную схему
без пересборки. Обязательны ровно один источник схемы и `--input PATH`.
[Нативный контракт версии 1](../spec/schema/NATIVE-JSON.ru.md) принимает `qdcxx-native` версии 1,
обычные записи с `hasTime:false`, точные полные типы 2/8/10/40/56/72/88/120, упорядоченные локальные
поля и явные lookup-ключи. Локальные ID — последовательные позиции в массиве, независимые от ID
отправителя. Сохраняются пользовательские записи, переставленные и дополнительные поля. Имена —
точный текст из Unicode scalar values, преобразуемый во владеющий UTF-16; aliases, property names
и Java slots не выводятся автоматически.

Соберите с [необязательным JSON-загрузчиком](CPP-BUILD.ru.md#нативный-загрузчик-json-схем).
Из корня репозитория эти команды используют повторно применимую нативную схему с неизменёнными
смешанными tapes, полученными от Java:

```text
.work/schema-json-msvc/Release/qdcxx-tape-inspect --input tests/fixtures/encoding/field-types/expected/mixed-stream.qtp --schema spec/schema/examples/native/field-types.json --output-format human
.work/schema-json-msvc/Release/qdcxx-tape-inspect --input tests/fixtures/encoding/field-types/expected/mixed-raw.qtp --schema spec/schema/examples/native/field-types.json --tape-mode raw-message-v1 --output-format tsv
```

Для сборки с одной конфигурацией используйте `.work/schema-json-linux/qdcxx-tape-inspect`.
JSON-файл не выбирает и не расширяет режим tape: по умолчанию остаётся `legacy`, а
`raw-message-v1` указывается явно. Оба внешних режима выводят версию **6**, профиль
`external-schema-v1`, с общими типизированными полями в локальном порядке. Тип 10 сохраняет null,
пустые и точные UTF-16 значения; скаляры сохраняют точное представление type/raw. Дополнительные
поля остаются видимыми, для неизвестных wire-записей сохраняется прежняя политика пропуска.
Имена Quote или Profile не запрашивают проекцию события; приложения используют
[подготовленные API](CPP-BUILD.ru.md#нативный-загрузчик-json-схем).
[Контракт](../spec/schema/NATIVE-JSON.ru.md) определяет строки TSV/human.

Схема читается один раз, конечные бюджеты действуют во время чтения и загрузки. Значения по
умолчанию совпадают с библиотечными; ноль — настоящий лимит, равенство допустимо. Эти лимиты
отдельны от прежних бюджетов декодированных записей/полей, строк, входного tape и вывода:

| Параметр | По умолчанию | Единица |
| --- | --- | --- |
| `--max-schema-bytes` | 1048576 | Все байты документа схемы, включая пробельные символы |
| `--max-schema-depth` | 16 | Вложенные объекты/массивы; глубина корня — 1 |
| `--max-schema-records` | 1024 | Локальные записи |
| `--max-schema-fields` | 16384 | Суммарное число локальных полей |
| `--max-schema-lookups` | 32768 | Суммарное число lookup-записей |
| `--max-schema-name-units` | 1024 | UTF-16 units в одном имени записи/lookup |
| `--max-schema-total-name-units` | 1048576 | Суммарные UTF-16 units всех имён записей/lookup |

Сначала проверяются аргументы, затем доступность загрузчика, затем файл схемы и схема целиком;
только после этого открывается tape. Поэтому ошибка схемы имеет приоритет над отсутствующим tape,
без перехода к встроенной схеме. Ошибки схемы не выводят в stdout заголовок или данные и создают
одну ограниченную строку stderr: `schema-error<TAB>1<TAB>CODE<LF>`. Представление одинаково для
TSV/human и версий диагностики 1/2. Внешний режим по умолчанию использует диагностику 2;
допустимы явные 1/2. Коды выхода: usage 2, I/O файла схемы 3, неподдерживаемые
профиль/версия/тип/индексная семантика или отключённый загрузчик 4, некорректные JSON/схема 5,
ошибка бюджета/выделения памяти 6. Контракт перечисляет стабильные коды; последующие ошибки tape
сохраняют прежнюю диагностику.

При `ORG_TTLDTOR_QDCXX_BUILD_SCHEMA_JSON=OFF` корректные внешние запросы сообщают
`LOADER_DISABLED` до открытия обоих файлов. Вызов без аргументов и отдельный `--help` остаются
идентичными и не выполняют файловый I/O: stdout, пустой stderr, выход 0 при успешной записи.
Встроенные вывод/диагностика по умолчанию неизменны. Не поддерживаются XML,
`qd-3.355-xml-captured`, imports, URLs, environment/Java properties, автоопределение, индексные
записи, новые wire-типы/преобразования, замена схемы во время работы и транспорт. Нативные примеры
определяют наш исходный формат; они не доказывают более широкую поддержку частного tape.

## Явный oracle-field-types-v1 и вывод версии 4

`--profile oracle-field-types-v1` выбирает фиксированную диагностическую локальную схему `FieldTypes`:
Text(10), Short(40), Sequence(72), Date(88), Count(8), Char(2), Seconds(56), Wide(120), Tail(10).
Она работает без параметра режима/с явным `--tape-mode legacy` и с явным `--tape-mode raw-message-v1`.
Локальная политика — `EXTENDED_FIELDS_V1`; выбор контейнера остаётся независимым. Этот адаптер
не обнаруживает схему и не отображает событие Profile. [FIELD-TYPES](../spec/encoding/FIELD-TYPES.ru.md)
определяет точные значения, lookup-имена схемы, грамматику строк, учёт и Java-доказательства.

TSV и human используют версию 4 для этого профиля. TSV-записи имеют семь ячеек:
`field-record`, индекс кадра, индекс выданной записи, локальный ID, UTF-16 hex имени, UTF-16 hex символа, значения.
Разделённые запятыми значения имеют вид `type:raw:payload`: payload скаляра — `-`; тип 10 использует
`null`, `empty` или точные UTF-16 units по четыре строчные hex-цифры с нулевым raw.
Human сохраняет те же tags/raw и безопасно заключает строки в кавычки, экранируя управляющие
символы и одиночные суррогаты. Преобразования ShortString, календаря или event-time не выполняются.
Время RAW-кадра остаётся отдельно от поля SEQUENCE. Строки descriptor/frame/timing/completion
сохраняют прежнюю грамматику своего режима. Версия диагностики по умолчанию — 2; явные 1/2 доступны.

Пять дополнительных беззнаковых десятичных лимитов ограничивают строки полей отдельно от символов и имён:

| Параметр | По умолчанию | Значение |
| --- | --- | --- |
| `--field-string-bytes` | 65536 | Исследованные байты префикса и тела одной строки |
| `--field-string-units` | 16384 | Допущенные UTF-16 units одной строки |
| `--max-field-bytes` | 16777216 | Исследованные байты строк всего файла |
| `--max-field-units` | 4194304 | Допущенные units декодирования всего файла |
| `--max-owned-field-units` | 4194304 | Units завершённого вывода, текущих и временных строк |

Ноль означает нулевой допуск. Работа декодирования учитывается для пропущенных/повторных/неуспешных
значений без возврата; владеющие units ограничивают логическое UTF-16 хранение, не расходы аллокатора.
Полная строка вывода должна помещаться в остаток байтового бюджета до аллокации и первой записи.
Обнаруженный сбой вывода подавляет последующий completion; ошибка финального flush может произойти
после уже записанного completion. Успех требует кода выхода 0.

```powershell
.work/field-types-msvc-024/Release/qdcxx-tape-inspect --input tests/fixtures/encoding/field-types/expected/mixed-stream.qtp --profile oracle-field-types-v1 --output-format human
.work/field-types-msvc-024/Release/qdcxx-tape-inspect --input tests/fixtures/encoding/field-types/expected/mixed-raw.qtp --profile oracle-field-types-v1 --tape-mode raw-message-v1 --output-format tsv
```

Существующие профили сохраняют версии вывода/диагностики и поведение, кроме расширенной справки tape.
Вызовы без аргументов и с отдельным `--help` остаются одинаковыми без входного IO. Неверные,
пропущенные или повторные аргументы профиля дают usage error до открытия входа.
[Покрытие](../tests/conformance/protocol/field-types/COVERAGE.ru.md) и
[авторская валидация](../tests/conformance/protocol/field-types/VALIDATION.ru.md) описывают проверки и ограничения;
независимое ревью ожидается. Исторические разделы ниже описывают свои исходные этапы.

## Явный raw-message-v1 и вывод времени версии 3

`--tape-mode raw-message-v1` выбирает ограниченный RAW_DATA/MESSAGE без сжатия независимо от
`--profile oracle-sre-v1|default-quote-v1`. Режим допускает только измеренное подмножество
options/заголовков, нулевые event flags и существующие точные полные типы. Отсутствующий режим
и явный `legacy` сохраняют прежние вывод, отказы и стандартную диагностику. Режим не выводится из входа.

[RAW-TAPE](../spec/protocol/RAW-TAPE.ru.md) определяет строки TSV/human версии 3: исходные границы
frames, точные options/time дескриптора, каждый heartbeat, включая последний, общее время data
frame, отсутствие исходного timestamp отдельно от нуля, packed cursor sequence и доставленное
event time. Бизнес-время Quote независимо; отображаемый eventTime в новом режиме отражает время
cursor. `--max-timing-events` ограничивает накопленные попытки metadata явных heartbeat/данных
(по умолчанию 4096). Прежние бюджеты и версии диагностики 1/2 доступны. Human-объяснение отказа
соответствует выбранному режиму; legacy-текст неизменен. Равенство no-argument/help и проверка
аргументов до IO обязательны. Новый режим не ожидает времени воспроизведения.

```powershell
.work/raw-msvc/Release/qdcxx-tape-inspect --input tests/fixtures/protocol/raw-tape/expected/connector-quote.qtp --profile default-quote-v1 --tape-mode raw-message-v1 --output-format human
```

Команда читает неизменённый production Java fixture. Частный tape имеет
[дополнительные ограничения полей/схем](REAL-TAPE-GAPS.ru.md); успех generated fixtures не
подтверждает полную поддержку. Исторические разделы ниже описывают прежние версии и их проверки.

## Явный default-quote-v1 и диагностика version 2

Имена и human-пояснения диагностики реализованы в tools/tape-inspect/diagnostics.hpp/.cpp
(qdcxx_tape_inspect_tool). Protocol сохраняет данные TapeRejection/TapeDiagnostic и точные checkpoints,
без имён CLI-профилей и советов по выбору. Перенос представления сохраняет байты stdout/stderr,
версии форматов и коды завершения. Авторские проверки исправления ревью
отделены от исторической валидации; повторное независимое ревью ожидается.

QDCXX-022 добавляет --profile default-quote-v1 со всеми восемью неизменными полями default composite
Quote. Транспорт остаётся BINARY/uncompressed/NONE/EMPTY_SET/STREAM_DATA. TSV по умолчанию и
--output-format human имеют отдельную version 2 для этого профиля: точные type:raw поля, mapped
binary 64 биты и время в миллисекундах; human цены/размеры выводятся decimal text, не raw integers.
[Полная грамматика строк, безопасные объяснения и потери отображения](../spec/protocol/DEFAULT-QUOTE.ru.md).

--diagnostics-version 1|2 выбирает прежнюю диагностику из девяти ячеек или новую из десяти.
По умолчанию 1 для oracle-sre-v1 и 2 для default-quote-v1. Version 2 добавляет статическое имя
причины; human — фиксированное объяснение с сохранением точных offsets. Явная version 2 объясняет
также неподдержанный локальный профиль до открытия файла. Без opt-in весь прежний S/R/E вывод и
ошибки побайтно сохраняются; QTP inspector неизменен. Help перечисляет оба профиля, эквивалентность
вызова без аргументов/--help сохраняется. Прежние числовые бюджеты применяются с однократным
списанием typed поля. Автоопределения профиля нет.
API потоковой инспекции проверяет совместимость схемы/вывода до чтения или записи stdout;
несовпадение возвращает 4 со stage profile и причиной LOCAL_PROFILE в версии 2. Вывод Quote требует
одну запись Quote с восемью точными типами по порядку; явные lookup-связи остаются контрактом вызывающей стороны.

[Выполненные проверки](../tests/conformance/protocol/quote/VALIDATION.ru.md); независимое ревью ожидается.

[English version](TAPE-INSPECT.md). Английская версия является основной.

Необязательная qdcxx-tape-inspect читает [ограниченную tape](../spec/protocol/TAPE-READER.ru.md).
Обязательны --input PATH --profile oracle-sre-v1. Нет stdin, сети и автоопределения.
По умолчанию TSV; --output-format human использует прежнее безопасное представление записей
и version в кавычках UTF-8. Без аргументов и с отдельным --help вывод идентичен: stdout, пустой stderr,
код 0 при успешном выводе. Непустые неверные/неполные аргументы дают 2 до открытия файлов.

Лимиты — беззнаковые десятичные size_t, без повторов опций и без значения «неограниченно»;
ноль допустим, кроме chunk-size. --max-input, --max-frame, --max-frames, --max-descriptions,
--max-actions, --max-name-units, --max-total-name-units, --max-records, --max-fields, --max-values,
--max-symbol-units, --symbol-units, --max-output, --max-construction, --max-properties,
--max-messages, --max-descriptor-units и --max-text-units задают отдельные конечные лимиты.
Help перечисляет значения по умолчанию. Frame+9 и streamsize должны быть представимы.
Лимиты локальной схемы: 1024 записи, 65536 полей/lookup, 1024 единицы/имя, 1048576 единиц суммарно.
Встроенный профиль — диагностический S/R/E, не default Quote и не схема, выведенная из входа.
Оба инспектора можно собирать независимо с BUILD_TESTING=OFF без загрузки тестов и поиска Python.

Вывод LF/без BOM, канонические числа, точные UTF-16 единицы строчным hex в TSV, '-' для пустых
последовательностей. Грамматика frame/record и human-экранирование повторно используются без изменения
старого инспектора. Новый заголовок: `format<TAB>qdcxx-tape-inspect<TAB>1`; human-заголовок:
`qdcxx-tape-inspect human 1 profile=oracle-sre-v1 identities=local`.
После принятого дескриптора выводится `descriptor, version-present(0|1), version-hex-or--,
time(NONE|absent), send(15|-), receive(-)` с TAB-разделителями. Принятие гарантирует type=tape и пустое
opt. Human-дескриптор выводит version в кавычках либо absent, type=tape opt=EMPTY_SET,
time=NONE|absent и send=15|-. Version никогда не определяет поддержку.

Перед завершением выводится `markers<TAB>count` (human `Markers: count=N authenticated-footer=no`).
Это наличие пустых конвертов, не подлинность, физический EOF или полнота записи. Итоговая строка
complete использует прежнюю грамматику шести ячеек счётчиков под новым идентификатором формата.
Успех требует кода 0 после последнего flush; физическая ошибка вывода может усечь любую строку.
Каждая строка сначала проверяется по бюджету закодированных байтов до расширения/выделения/записи.
Завершённый префикс данных сохраняется после ошибки; частичная текущая запись не выдаётся.
После обнаруженной ошибки нет markers/complete. Ошибки чтения/flush дают ненулевой код.

Коды: 0 успех/help, 2 аргументы, 3 IO, 4 неподдерживаемое/порядок, 5 повреждение, 6 ресурсы/память.
Диагностика: `incomplete, code, stage, detail, frame-start, accepted-file-bytes, payload-start,
payload-consumed, payload-error` (9 ячеек с TAB); недоступные позиции '-'. Detail вложенного этапа —
порядковое значение существующего enum, иначе ноль. Принятая файловая позиция не подменяет потребление
payload. Абсолютная позиция его проверки равна payload-start плюс относительная. IO-диагностика
использует метку операции без выдуманных позиций парсера. Читаются ограниченные порции; на точном
лимите входа один peek отличает чистый EOF от превышения. Нет продолжения после ошибки,
удаления/перестановки входа и разбора протокола в представлении.

Настройка: -DORG_TTLDTOR_QDCXX_BUILD_TAPE_INSPECT=ON; target qdcxx_tape_inspect,
файл qdcxx-tape-inspect. [Авторская валидация](../tests/conformance/protocol/tape/VALIDATION.ru.md)
содержит завершённые проверки; независимое ревью ожидается.

Строки дескриптора в CLI также имеют фиксированный лимит тела 4096 байт; библиотека предоставляет
отдельный параметр этого лимита. Независимые вызовы tool API по умолчанию используют local-schema
и подписи field[index]; CLI явно выбирает oracle-sre-v1. При ошибке декодированного события строки
frame и завершённого префикса выводятся до сообщения ошибки парсера; ошибка записи этого префикса
имеет приоритет IO/бюджета вывода. Это не разрешает обработку последующего входа.

## Метаданные записей, которые не представляют прежние форматы

Прежние форматы записей, включая общие версии4/6/7 и вывод Profile, не имеют колонок исходных
флагов символа или removalTime. Formatter::record и Formatter::profileRecord отклоняют ненулевые
SymbolValue.eventFlags либо любой заданный removalTime, включая ноль, через invalid_argument
до построения строки. Явный нулевой префикс представим: сам eventFlagsBytes не вызывает отказ.
Байты прежнего вывода с нулевыми флагами и отсутствующим временем удаления сохраняются.
Бизнес-поле Flags у Profile независимо от исходных флагов символа QTP.

Автоматическое преобразование в tape-write отклоняет заданный removalTime до создания writer view:
удаление не превращается молча в свежие нулевые значения. Входные форматы writer не меняются.
[Контракт метаданных](../spec/protocol/STREAM-DATA.ru.md#catalog-event-metadata) задаёт явную политику
только для чтения. Здесь не вводятся новые параметры CLI или грамматика вывода.



## Явное обнаружение binary и вывод версии 8

```sh
qdcxx-tape-inspect --input tests/fixtures/encoding/field-types/expected/dispatch/normal/writer-MESSAGE-20.qtp --wire-schema binary-catalog-v1 --tape-mode binary-catalog-v1
```

Оба расширенных режима нужно выбирать вместе. Это обычное обнаружение 19 точных идентификаторов
бинарных полей, четырёх семейств данных и выбранной политики NONE/MESSAGE/входа без заголовка из
[BINARY-MESSAGES](../spec/protocol/BINARY-MESSAGES.ru.md). Оно не выводит индексную раскладку из имён,
не загружает расширенную схему через native-v1 JSON, не запускает collectors и не интерпретирует
сериализованные объекты Java. Прежние ordinary-v1 и старые режимы сохраняют точное поведение,
отказы и вывод версий 4–7.

TSV начинается с `format<TAB>qdcxx-tape-inspect<TAB>8<TAB>binary-catalog-v1<TAB>binary-catalog-v1`.
Грамматика строк схемы и источника совпадает с описанной выше версией 7; в версии 8 поколение
продвигается только при успешной публикации непустого неизменяемого снимка. Пустой пакет описаний
выдаёт только свой frame и не подтверждает завершение входа без заголовка. Равные непустые пакеты
создают новое поколение. Строки frame сохраняют исходные семейство и тип; RAW представлен один раз,
без размножения по Java collectors.

`wire-data-v8` содержит ровно 14 ячеек вместе с меткой: frameIndex, recordIndex, generation,
senderId, localId, recordNameHex, symbolHex, typedValues, timestampMs, eventTimeSequence,
eventTimeMs, flags, removalTime. Имена и символы записываются прежним строчным UTF16 hex.
Каждое значение в списке через запятую имеет вид `fullType:raw:units:bytes`: скаляры используют
`raw:-:-`, типы 10/137 — `0:null|empty|utf16hex:-`, типы 9/233/249 — `0:-:null|empty|bytehex`.
Непрозрачные байты записываются строчным hex и никогда не исполняются. Пустому списку значений
соответствует пустая ячейка. Отсутствие timestamp/removal обозначается `-`; заданный 0 отличается
от отсутствия. Три колонки времени сохраняют различие исходного, упакованного и доставленного времени.

`descriptor-v8` содержит ровно 9 ячеек: label, frameIndex, versionPresent, versionHex, optPresent,
optHex, timePresent, timeHex, effectiveSendMask. Наличие обозначается 0/1; hex присутствующего
пустого текста — `-`. Биты send равны `(1u<<5)|(1u<<10)|(1u<<15)|(1u<<20)` для фактически
объявленных известных отправляемых типов; это не разрешение на данные. HUMAN представляет ту же
информацию безопасным текстом в кавычках и hex, называя все принятые семейства и управляющие сообщения.
Канонические значения и метаданные сохраняются; избыточные байты кодирования префикса/cipher не обещаются.

Отдельный метод formatter — `catalogRecord(record, schema, ..., timing, generation)`: ожидаемая
бинарная схема, локальный ID, происхождение, точное число полей, полные ID и каноническая форма
проверяются до построения строки и работы с бюджетом вывода. Имя берётся из этой схемы. Вызов
прежнего formatter записи, принимающего только имя, с расширенным профилем даёт отказ; прежние
сигнатуры и отказы для метаданных и payload сохраняются.

| Параметр только расширенного режима | По умолчанию | Значение |
| --- | --- | --- |
| --field-payload-encoded-bytes |65536| Проверенные байты префикса/тела одного нового payload |
| --field-payload-bytes |65536| Допущенные объявленные байты тела одного значения |
| --max-payload-encoded-bytes |16777216| Суммарные проверенные байты новых payload |
| --max-payload-work-bytes |16777216| Суммарная допущенная работа по телам без возврата бюджета |
| --max-owned-payload-bytes |8388608| Логические байты payload завершённых/текущих/временных значений |
| --max-snapshot-units |16777216| Одновременно живые метаданные схемы/описаний/контекста/дескриптора и временных объектов |

Значения по умолчанию действуют только при отсутствии соответствующего параметра; явный 0 остаётся 0.
Прежние режимы отклоняют эти параметры до I/O tape. Прежние независимые ограничения единиц строк,
конструирования, входа/frames/записей/значений, времени и вывода продолжают действовать; STRING137
подчиняется и ограничениям единиц строк, и новым ограничениям payload. Библиотечный reader не
применяет скрытый набор настроек CLI. Запуск без аргументов и отдельный --help идентичны и не требуют
рабочих файлов. Несовместимые режимы/источники и неверные параметры дают отказ до открытия входа.

Байты вывода, включая заголовок, схему, время и завершение, учитываются до расширения и записи.
Коды сохраняются: 0 — успех/справка, 2 — аргументы, 3 — I/O, 4 — неподдерживаемое, 5 — повреждение,
6 — ресурсы. Успех требует физического EOF, успешного reader.finish, всех записей и последнего flush,
а также кода 0. Уже записанные байты нельзя отозвать после ошибки flush. Инспекция заимствованных
потоков не доказывает закрытие владельцем; приёмка Java отдельно инструментально проверяет закрытие.
Эти функции вывода 8 для заимствованных потоков по-прежнему исключают FIELD (включая сырой ноль),
спутники, сжатие и цепочки источников; для них используйте явный владеющий профиль выше. [Валидация](../tests/conformance/protocol/field-types/DISPATCH-VALIDATION.ru.md)
задаёт точные границы производственных, нативных и полных файловых проверок.
