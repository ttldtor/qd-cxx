# База знаний QD и qd-cxx

[English version](README.md). Английская версия является нормативной.

Этот указатель помогает разработчикам библиотеки и приложений найти требование, доказательство
и решение, стоящие за поведением. Он разделяет совместимость с Java QD, решения нативной реализации
и открытые вопросы. Действующие спецификации остаются нормативными; указатель не вводит API или
формат передачи.

## Как читать

- Для поиска необходимой возможности или нерешённого вопроса начните с
  [реестра требований](REQUIREMENTS.ru.md).
- Для перехода от утверждения к исходникам, наблюдаемому поведению и проверкам используйте
  [связи решений](DECISION-TRACE.ru.md).
- Для использования реализованного компонента откройте его контракт из указателя ниже и проверьте
  соответствующий профиль валидации.

## Базовые доказательства

Нативная база этой редакции — коммит `7580559f97419f6c43dd520ec4a622a5d5969ea2`.
Java QD закреплена на версии 3.355, коммите `0ddc0a09779fb61d74cc0b37c6449ff47dcb715f`, в
[upstream.lock](../../upstream.lock). Опубликованный [профиль подписок](../../tests/fixtures/subscriptions/CAPTURES.ru.md)
и его manifest определяют используемые Java-наблюдения. Анализ исходников, наблюдение production-кода
и проверка нативной реализации — разные уровни доказательств; каждое утверждение сохраняет свой профиль.

Для STREAM и TICKER существуют ограниченные нативные контракты коллекторов. Нативная выдача HISTORY,
объединение запросов вышестоящему источнику и полное поведение подписок от источника до потребителя
в этой базе ещё не реализованы. Общее декодирование или наблюдение Java не доказывает эти возможности.
[Текущие возможности](../CURRENT-STATE.ru.md) фиксируют границы реализации.

## Границы вопросов о маршрутах и каналах

Подтверждённая цель — описать требования, доказательства и открытые вопросы проектирования QD и qd-cxx.
Несколько каналов и происхождение событий через посредников — темы обсуждения, а не утверждённые
новые возможности или гарантии маршрута. Идентичность логического канала, её связь с соединениями
и метаданные маршрута пока не определены.
Реестр различает поток событий и поток запросов подписок, а также известную локальную точку входа
и полную цепочку от производителя до потребителя. Поле маршрута, упаковка source ID, топология
или развёртывание gateway/MUX здесь не выбираются. Конкретная инфраструктура — отдельная работа.
