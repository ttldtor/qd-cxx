# Потоки и время жизни объектов Feed API

[English](API-THREADS.md) · [Feed API](FEED-API.ru.md) · [Встраивание среды выполнения](../spec/transport/RUNTIME-EMBEDDING.ru.md)

Здесь описаны действующие `Endpoint`, `ApiRuntime`, `Feed`, `Subscription`,
дескрипторы запросов и механизм исполнения обработчиков событий. Правило строки
таблицы распространяется на все перечисленные перегрузки. Условия проверки аргументов,
ресурсных ограничений и ошибок отдельных методов заданы в
[feed.hpp](../include/qd/api/feed.hpp) и
[callback_execution.hpp](../include/qd/api/callback_execution.hpp).

## Какие потоки участвуют

**Создающий поток** — главный поток приложения, создавший среду выполнения.
**Рабочий поток SDK** обслуживает соединения и состояние коллекторов.
**Вызывающий поток приложения** может передавать команды из другого потока,
пока объект существует. **Исполнитель событий** — необязательная политика приложения,
определяющая, где вызываются обработчики событий.

Методы изменения SDK согласуют доступ к своему состоянию. Приложение обеспечивает
время жизни объектов, входных буферов и зависимостей обработчика на нужный интервал.
Отдельные копии `shared_ptr` позволяют иметь независимых владельцев. Сброс или
уничтожение одного и того же дескриптора нельзя выполнять одновременно с обращением
через него. Перемещение запроса или задания также требует согласования с вызовами
методов этого объекта.

Синхронный метод может захватывать мьютекс, выделять память, копировать входные данные
или освобождать захваченные приложением объекты. «Без ожидания завершения» ниже означает,
что метод не присоединяет рабочий поток и не ожидает результата доставки. Это
не гарантия отсутствия блокировок или верхней границы времени самого вызова.

## Среда выполнения и Endpoint

| Операция | Вызывающий поток и работа | Владение и завершение |
| --- | --- | --- |
| `Endpoint::create` | Только создающий поток; первый вызов выполняется до запуска потоков приложения. Проверяет параметры и получает среду выполнения библиотеки. | Каждый вызов создаёт независимый Endpoint; общий рабочий поток запускается по необходимости. Позднейший вызов из другого потока получает `WRONG_THREAD`. |
| Конструкторы `ApiRuntime` | Только создающий поток. Владеющий режим подготавливает SDK до потоков приложения. Заимствующий режим требует уже подготовленного bootstrap. | Право использования bootstrap сохраняется после закрытия среды до её уничтожения. В заимствующем режиме приложение сохраняет владельца bootstrap до этого момента. |
| Обе перегрузки `ApiRuntime::createEndpoint` | Вызывающий поток приложения; проверка и копирование конфигурации, резервирование Endpoint под мьютексом среды. Соединение и обработчики не запускаются. | Параллельные вызовы допустимы при живом объекте среды. Допуск и завершение согласуются этим мьютексом; закрытый допуск возвращает `CLOSED`. Уничтожение самой среды согласует приложение. |
| `ApiRuntime::closeAndAwaitTermination` | Только создающий поток; закрывает Endpoint и присоединяет рабочий поток. | Ожидает сетевую работу, выбранные обработчики и освобождение их захватов. Повторный вход при завершении или из уничтожаемого захвата получает `INVALID_STATE`. |
| Деструктор `ApiRuntime` | Только создающий поток; завершает работу с ожиданием. | Уничтожение из другого потока завершает процесс. Освобождению собственного bootstrap предшествует завершение потоков приложения. |
| `Endpoint::getFeed` | Вызывающий поток приложения; возвращает общий дескриптор фасада. | Фасад сохраняет отделённое управляющее состояние, не продлевая работу среды выполнения. |
| `connect`, `connectTape`, `connectOnDemand` | Вызывающий поток приложения; проверка и копирование аргументов, допуск асинхронной работы с источником. | Ввод-вывод выполняет рабочий поток SDK. Аргументы заимствуются на время допуска; принятые данные источника сохраняются во владении SDK. Действуют прежние правила выбора источника и повторов. |
| `disconnect`, `disconnectAndClear`, `reconnect` | Вызывающий поток приложения; фиксация намерения и границ допустимой доставки. Без ожидания завершения. | Выбранный обработчик может закончить вызов. Наблюдение отключённого состояния само по себе не подтверждает завершение обработчиков или очистки кэша. |
| `setTapePaused`, `restartTape`, `stopTape` | Вызывающий поток приложения; команды воспроизведения файла. Без ожидания завершения. | Перезапуск прекращает допуск старого источника; повторные запросы присоединяются к текущему перезапуску. Stop/close имеют преимущество. Фактический исход возвращает ожидание Endpoint. |
| `setOnDemandSpeed`, `pauseOnDemand`, `stopOnDemandAndClear`, `stopOnDemandAndResume` | Вызывающий поток приложения; команды исторического воспроизведения. Без ожидания завершения. | Переход выполняет рабочий поток. Владеющие снимки воспроизведения и диагностика показывают его состояние. |
| `setRequestedAggregationPeriod` | Вызывающий поток приложения; фиксация локальной ревизии. Без ожидания завершения. | Принятое намерение сохраняется и на отключённом/закрытом дескрипторе; сообщённый сервером диапазон учитывается отдельно. |
| `createFilter` | Вызывающий поток приложения; синхронная подготовка классификатора без мьютекса управления Endpoint. | Обычные категории не запускают ввод-вывод. Явно переданный resolver контекста может ожидать свою ограниченную начальную загрузку. Результат владеет состоянием классификатора. |
| `close`, деструктор Endpoint | Вызывающий поток приложения; запрос закрытия без присоединения рабочего потока. | Исчерпание обычных мест допуска не препятствует закрытию. Возврат деструктора не подтверждает завершение обработчиков. |
| `closeAndAwaitTermination` | Только создающий поток; запрос закрытия и ожидание фактического завершения. | Включает сетевую работу, выбранные обработчики и их захваты. Повторный вызов возвращает сохранённый локальный результат. Чужой/рабочий поток получает ошибку до ожидания; повторный вход при освобождении также запрещён. |
| `awaitState` | Только создающий поток, в том числе после завершения среды. | Ожидает текущее состояние, другое терминальное состояние, отмену или монотонный предельный срок. Не закрывает Endpoint и не ожидает завершения наблюдателей. |

Наблюдения Endpoint `getState`, `getDiagnostic`, `getStatistics`,
`getEffectiveConfiguration`, `getRequestedAggregationPeriod`, `getAggregationPeriodInfo`,
`getOnDemandPlayback`, `getOnDemandPlaybackDiagnostic`, `getStateChangeDiagnostic`,
`getEventExecutor` доступны вызывающим потокам приложения. Они копируют принятое
состояние или возвращают владеющий дескриптор политики без сетевой работы и ожидания
обработчиков. Владеющий снимок остаётся действительным после изменения Endpoint.
Ошибки выделения памяти и несовместимого режима определяются конкретным методом.

Регистрация/удаление обработчиков Endpoint и `setEventExecutor` подчиняются правилам
каналов вызова ниже. Приём конфигурации не вызывает обработчик синхронно.

## Feed и подписка

| Операция | Поток, ожидание и повторный вход | Владение и завершение |
| --- | --- | --- |
| `Feed::createSubscription`, `createTimeSeriesSubscription` | Вызывающий поток приложения, включая обработчик; синхронная проверка и атомарная регистрация. | Подписка владеет отделённым управляющим состоянием. Закрытый Endpoint отказывает в допуске. |
| `Feed::getLastEvent`, `getLastEventIfSubscribed` | Внешний поток может ожидать до локального срока в одну секунду. Собственный рабочий поток SDK читает своё последовательно обслуживаемое состояние напрямую. | Возвращает владеющее событие, значение по умолчанию или отсутствие согласно методу. Вызывающий поток не обслуживает сеть; занятой запрос или истечение срока могут дать ошибку. |
| `Feed::getIndexedEventsIfSubscribed`, `getTimeSeriesIfSubscribed` | Внешний поток может ожидать снимок рабочего потока до локального срока в одну секунду. Собственный рабочий поток SDK возвращает неполное наблюдение без ожидания. | Нужны существующий интерес и актуальный источник. Результат владеет данными и явно сообщает полноту. Временная подписка не создаётся. |
| `Feed::requestLastEvent`, `requestLastEvents`, `requestIndexedEvents`, `requestTimeSeries` | Вызывающий поток приложения; синхронный допуск, асинхронное завершение. | Параметры копируются; дескриптор владеет ответственностью за отмену. Принятый предельный срок ограничивает операцию. Автоматического подключения Endpoint нет. |
| `addSymbols`, `removeSymbols`, `setSymbols`, `addSelectors`, `removeSelector`, `setSelectors`, `clearSymbols`, `setFromTime` подписки | Вызывающий поток приложения; проверка и фиксация желаемого изменения. Наблюдатели символов могут вызываться синхронно после фиксации. Повторный вход использует ограниченную очередь отложенных фаз. | Входные представления нужны до возврата. Отказ до фиксации сохраняет прежнюю ревизию. Выбранные обработчики данных могут закончить вызов. |
| `setAggregationPeriod`, `setEventExecutor` подписки | Вызывающий поток приложения; политика для следующего выбора работы. Без ожидания доставки. | Начатый интервал или выбранный обработчик сохраняет прежнюю политику. Замена политики не делает исполняемую порцию недействительной. |
| Наблюдения подписки | `getSnapshot`, `getFromTime`, `getStatistics`, `getAggregationPeriod`, `getAggregationPeriodInfo`, `getHistorySnapshot`, `getEventTypes`, `containsEventType`, `getState`, `getDiagnostic`, `getChangeDiagnostic`, `getStateChangeDiagnostic`, `getCallbackDispatchDiagnostic`, `getEventExecutor`: вызывающий поток приложения, без сетевой работы и ожидания обработчиков. | Результаты владеют значениями или дескрипторами политики. Наблюдение HISTORY у подписки отличается от запросов Feed выше: копирует опубликованные данные и проверяет их относительно текущих границ допустимости. |
| `close`, деструктор подписки | Вызывающий поток приложения, включая обработчик; запрос закрытия без ожидания. | Исполняемая порция событий может завершиться позже. Освобождение выполняет среда; обычное исчерпание мест допуска не препятствует закрытию. |
| `awaitState` подписки | Только создающий поток; правила ожидания состояния как у Endpoint. | Требование потока сохраняется и на отделённом терминальном дескрипторе. `CLOSED` само по себе не подтверждает завершение наблюдателей. |

Одна секунда для локальных чтений — действующая политика реализации. Это не обещание
свежести сетевых данных или жёсткого времени планирования ОС. Для собственного срока
операции приложение использует асинхронный запрос.

## Каналы вызова обработчиков

| Регистрация/удаление | Исполнение и повторный вход | Владение и ошибки |
| --- | --- | --- |
| `addEventListener` / `removeEventListener` подписки | Рабочий поток SDK по умолчанию, выбранный `CallbackExecutor` при явной настройке. Вызовы одной подписки последовательны и не перекрываются, включая вложенное исполнение заданий. Из обработчика разрешены методы передачи команд. | `span` заимствуется до возврата обработчика; для сохранения нужно скопировать событие. Выбранный обработчик может закончиться после удаления. Его исключение завершает подписку с `CALLBACK_FAILURE`. |
| `addStateChangeListener` / `removeStateChangeListener` Endpoint или подписки | Рабочий поток SDK; при завершении без запущенного рабочего потока — создающий поток. Начального уведомления нет. | Выбранные наблюдатели могут закончиться после удаления. Исключения сохраняются отдельно в `getStateChangeDiagnostic`; ожидание Endpoint включает их освобождение. |
| `addChangeListener` / `removeChangeListener` подписки | При отсутствии конкуренции вызывающий поток доставляет изменение после фиксации до возврата, в том числе без подключения. Параллельные и повторные изменения резервируют отложенные фазы; их выполняет текущий владелец вызова. | Изменение заимствуется до возврата обработчика. Удаление резервирует финальную фазу CLOSED и может отказать до изменения состояния. Исключения сохраняются отдельно в `getChangeDiagnostic`. |
| `addOnDemandPlaybackListener` / `removeOnDemandPlaybackListener` Endpoint | Последовательные уведомления рабочего потока SDK вне управляющих мьютексов. | Выбранный вызов может завершиться после удаления; ошибки сохраняются в `getOnDemandPlaybackDiagnostic`. |

Вызовы приложения и уничтожение выбранных захватов/политик происходят вне управляющих
мьютексов SDK. Захват может уничтожаться в потоке, освободившем последнего владельца;
приложение должно допускать это. Удаление регистрации не ожидает завершения вызова.
Объекты, заимствованные обработчиками Endpoint/нативной подписки, сохраняют до завершения ожидания Endpoint. Для независимых подписок действуют дополнительные правила ниже.

Разные подписки уже могут исполняться на отдельных потоках приложения. Медленный
обработчик по умолчанию задерживает общий рабочий поток SDK. Пользовательская политика
позволяет другим подпискам продолжать работу в пределах возможностей очереди приложения
и правил завершения старого источника. SDK не останавливает потоки приложения и не
прерывает его обработчики принудительно.

`CallbackExecutor::post` должен быстро возвращаться и подтверждать только успешную
передачу задания. Разрешён вызов задания прямо внутри `post`. Отказ или исключение
после начала исполнения нарушает контракт исполнителя. Параллельные или повторные
`CallbackTask::run` получают право исполнения не более одного раза; старые и отменённые
задания бездействуют. Вложенный вызов может вернуть `DEFERRED`: существующий механизм
завершит его после освобождения внешнего вызова. Перемещение, присваивание и уничтожение
задания нельзя совмещать с обращениями к нему. Потеря принятого неисполненного задания
отражается в диагностике. Все исходы и правила резервирования описаны в
[контракте исполнения обработчиков](../spec/subscriptions/CALLBACK-EXECUTION.md) (EN).

## Независимая подписка на несколько Feed

[IndependentSubscription](../include/qd/api/independent_subscription.hpp) владеет
желаемыми селекторами и обработчиками независимо от Endpoint. Конструктор и
`withAttachmentListener` выполняются в вызывающем потоке приложения без подключения.
`attach`, `detach`, `detachAndClear`, `setSelectors`, `getSelectors`,
`getAttachmentDiagnostic` и `close` согласуют своё состояние внутри объекта.
Приложение сохраняет объект и переданный Feed на время вызова и согласует уничтожение
объекта с параллельными обращениями.

Каждое присоединение имеет собственную нативную подписку. Разные Feed могут вызывать
один обработчик одновременно, в том числе из разных сред выполнения. Общее состояние
обработчика защищает приложение. Это действующее отличие от последовательности одной
нативной Subscription. `setSelectors` принимает желаемый набор локально, затем сообщает
отказы отдельных присоединений; общей атомарной транзакции нескольких Feed здесь нет.

`detach` и `close` прекращают новый выбор вызовов без ожидания уже выбранных.
Деструктор вызывает `close`. `detachAndClear` вызывает невыбрасывающий обработчик очистки
сразу, если выбранных вызовов нет; иначе ровно один раз при выходе из последнего
выбранного обработчика, вне мьютекса независимого объекта. Повторный вход для отсоединения
разрешён. Принятая очистка сохраняется при последующем close или новом присоединении и
несёт ID прежнего присоединения. Прежде чем освобождать заимствованные зависимости
обработчиков, прекращают и дожидаются вызовов приложения к независимому объекту,
включая синхронную очистку. Затем закрывают независимую подписку, освобождая её
собственные ссылки на обработчики, и ожидают соответствующие Endpoint в их создающих
потоках: это завершает выбранные вызовы данных и отложенную очистку. После этого можно
освобождать зависимости. Одно ожидание Endpoint не присоединяет вызов синхронной
очистки другого потока и не освобождает обработчики ещё открытого независимого объекта.

## Запросы и данные после завершения среды

`LatestEventRequest` и `HistorySnapshotRequest` — перемещаемые владельцы отмены запроса.
`isDone` и `cancel` доступны потокам приложения при стабильном живом дескрипторе;
наблюдение истёкшего срока может завершить запрос. Уничтожение или замена отменяет
незавершённый запрос и освобождает его состояние. Перемещение и уничтожение согласует
приложение с остальными обращениями к тому же объекту.

`LatestEventRequest::await` и `HistorySnapshotRequest::get` ожидают завершения или
принятого срока. Ожидание незавершённого запроса из собственного рабочего потока SDK
получает `WRONG_THREAD`; готовый результат можно прочитать там без ожидания. Эти методы
не ограничены создающим потоком. Обработчикам на исполнителе приложения следует избегать
ожидания работы, которая зависит от завершения их собственного вызова. Повторное
успешное чтение возвращает владеющие значения. Перемещённый дескриптор не содержит
запроса; ожидание/чтение получает `INVALID_STATE`. `LatestEventRequest::getSymbol`
возвращает заимствованное представление, действительное пока дескриптор удерживает состояние.

Владеющие события, неизменяемые снимки и статистика сохраняются после завершения среды.
Заимствованные представления обработчика заканчиваются с его вызовом. Отделённые
Endpoint/подписки сохраняют терминальное состояние и исходную диагностику, но не могут
снова запустить сетевую работу. Старые отменённые задания исполнителя удерживают только
метаданные отделённого пула. Память каждого сохранённого объекта освобождается после
ухода его последнего владельца.

## Завершение и принятое направление развития

Перед освобождением зависимостей обработчиков Endpoint/нативной подписки вызывают
`closeAndAwaitTermination` в создающем потоке. Для независимой подписки дополнительно
соблюдают порядок завершения выше. `CloseResult::drained` сообщает об успешной локальной
доставке принятого префикса. Ошибки подписок и вывода приложения проверяются отдельно.
Срок завершения доставки не прерывает пользовательский код и не задаёт жёсткий предел
освобождения ресурсов операционной системой.

Принятая следующая архитектура сохраняет последовательность одной логической подписки
для событий и будущей доставки записей, допускает параллельность независимых подписок
и передаёт между потоками владеющие неизменяемые данные. Публичные `RecordFeed`, общий
настраиваемый исполнитель SDK и единый API результатов/корутин пока не доступны.
Будущие дополнения сохраняют порядок, границы источника, точное завершение и владение
результатами. Таблицы выше описывают действующие методы.
