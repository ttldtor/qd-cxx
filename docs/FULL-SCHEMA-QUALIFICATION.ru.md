# Проверка поставки полной схемы

[English version](FULL-SCHEMA-QUALIFICATION.md).

Поставка полного бинарного каталога поддерживает два профиля схем QD, default и dxlink. В комплекте binary-v2 идут логические объявления записей и точные имена исходящих полей. Приложение может загрузить оба файла через `qdcxx_schema_json`, создать издателя с проверенным каталогом и подключить установленную цель `qdcxx::feed`. Совместимость загрузчика с binary-v1 покрыта регрессионным набором схем.

## Матрица проверок

Исходники продукта соответствуют ревизии `dee3a879128ad50882faa5fd97b55ff8c84c1800`. Проверки выполнены на Windows с MSVC 19.42.34444 Release и на Linux с GCC 13.3.0 Debug и ASan/UBSan. На каждой платформе SDK установили в новый каталог, собрали с ним внешний проект и поставляемый пример раздачи, затем запустили отдельные процессы раздачи по TCP.

| Сценарий | QD default | QD dxlink |
| --- | --- | --- |
| Потребитель установленного SDK | 331 запись, 3 186 полей | 297 записей, 2 750 полей |
| Сравнение полей с Java QD 3.355 в обоих направлениях | Все 331 запись | Все 297 записей |
| TICKER по TCP | 331/331 | 297/297 |
| STREAM по TCP | 331/331 | 297/297 |
| HISTORY по TCP, нулевые значение границы и индекс удаления | 160/160 индексных записей | 126/126 индексных записей |

Установленная утилита NetTest прошла проверку англоязычной и русскоязычной справки и запуска с конечным временем ожидания. На каждой сборке прошли девять выбранных регрессионных проверок издателя, фильтров Feed, очереди MUX, коллектора HISTORY, записи подписок, загрузчика схем, NetTest и справки примера раздачи.

Сравнение с Java охватывает четыре сценария значений с граничными скалярами, null и пустыми объектами, порядком описаний, независимо назначенными ID отправителя и полными знаковыми ключами удаления. В TCP-сценариях для каталога проверяются ADD и REMOVE к источнику и данные записи к потребителю. В каждом DATA-кадре передаётся одно вхождение записи. Границы снимка HISTORY и знаковое удаление проверяются отдельным TCP-тестом с двумя клиентами на подмножестве записей.

## Применение

Полный ретранслятор принимает до 32 сопоставленных вхождений в одном входящем DATA-кадре. Его источник согласует TICKER, STREAM, HISTORY и `hs`. Профиль dxlink задаёт записи и поля для QTP. Для подключения через dxLink WebSocket нужен отдельный адаптер.
