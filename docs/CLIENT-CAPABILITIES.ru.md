# Возможности клиента и профили протокола {#client-capabilities-ru}

[English version](CLIENT-CAPABILITIES.md). Английская версия нормативная.

Используйте эту справку, чтобы выбрать контракт приёма, физическую запись и источник до создания типизированной подписки. В каждой строке указаны область действия контракта и точные имена CTest для детерминированных проверок или проверок на закреплённых фикстурах Java. Соберите и запустите тесты в проверяемой конфигурации. Имя теста указывает способ проверки. Результат зависит от ревизии исходников и конфигурации сборки.

## Маршруты типизированного приёма

`TICKER` хранит текущие значения, `STREAM` сохраняет порядок принятых записей, `HISTORY` сохраняет ограниченные индексированные транзакции и покрытие диапазона. Имя физической записи в таблице определяет семейство согласованных записей. Числовые ID принадлежат выбранной схеме. Значения по умолчанию, типы полей и ошибки задаёт контракт сопоставления события.

| Событие | Контракт и ограничения | Детерминированные проверки |
| --- | --- | --- |
| `Quote` | TICKER и STREAM. Составной `Quote`, региональный `Quote&Q` с логическим `AAPL&Q` и физическим `AAPL`, если такой маршрут есть в реестре. Владеющие значения bid/ask и поля бирж. Этот маршрут не допускает HISTORY. | `feed_api`, `event_time_feed`, `event_time_routing`, `quote_java_values`, `quote_java_tape` |
| `Profile` | TICKER и STREAM `Profile`. Явный реестр поддерживает обратный порядок полей и псевдонимы пользователя. Логический региональный Profile может сохранить суффикс при использовании составной записи. | `feed_api`, `event_registry_feed`, `profile_mapping_contract` |
| `Trade` | TICKER и STREAM `Trade`. Для `Trade&Q` нужен явный совместимый реестр. Сохраняет знаковое упакованное время, флаги и преобразование LONG в бизнес-значение. | `trade_feed`, `trade_java`, `event_field_conversions_feed` |
| `TradeETH` | TICKER и STREAM `TradeETH`. Для `TradeETH&Q` нужен явный реестр. Наносекундная часть берётся из `Last.TimeNanoPart`. При переходе к основной сессии флаг ETH может сбрасываться. | `trade_eth_feed`, `trade_eth_java` |
| `Summary` | TICKER и STREAM `Summary`. В явно заданном `Summary&Q` открытый интерес может отсутствовать. Составной адаптер сохраняет знаковые идентификаторы дней и полную разрядность открытого интереса. | `summary_feed`, `summary_java` |
| `TextMessage` | STREAM `TextMessage` с владеющим UTF-16 и различием отсутствующей и пустой строки. Регистрация в TICKER отклоняется. | `text_events_feed`, `text_events_java_oracle` |
| `TextConfiguration` | TICKER и STREAM `TextConfiguration`. Сопоставленное поле версии управляет приёмом и выдачей из кэша TICKER. STREAM сохраняет порядок принятых записей. | `text_events_feed`, `text_events_java_oracle` |
| `Message` | STREAM `Message`, полный идентификатор поля 249 (`SERIAL_OBJECT`). Отсутствующее и присутствующее пустое тело различаются. Для декодирования в значение C++ нужен явный кодек. | `misc_feed`, `attachment_serialized_contract`, `attachment_codec_contract` |
| `Configuration` | TICKER и STREAM `Configuration` с сериализованными байтами и необязательным Version. Первая отрицательная версия даёт нулевое представление TICKER по правилам Java. Меньшая версия сохраняет предыдущее значение. | `misc_feed`, `misc_event_projections`, `attachment_serialized_contract` |
| `Candle` | TICKER и HISTORY через `Candle` и `TradeHistory`, включая явно заданный минутный маршрут bid. STREAM отклоняется. Feed принимает свечи из совместимых записей, пропущенные периоды остаются пропусками. | `candle_feed`, `candle_routes`, `candle_payload` |
| `Greeks` | TICKER и HISTORY с диапазоном для `Greeks`, источник DEFAULT. Маршрут события покрывает явную схему tiny-decimal и независимую временную метку FIELD. | `greeks_feed` |
| `Underlying` | TICKER и HISTORY с диапазоном для `Underlying`, источник DEFAULT. Доступные значения call/put определяют объём опционов и обработку NaN. | `underlying_feed` |
| `TheoPrice` | TICKER и HISTORY с диапазоном для `TheoPrice`, источник DEFAULT. HISTORY требует физических полей Time и Sequence и восстанавливает диапазон при переподключении. | `theo_price_feed` |
| `TimeAndSale` | STREAM и HISTORY для `TimeAndSale` и встроенных региональных маршрутов. HISTORY сохраняет исправление, отмену, удаление, последовательность и покрытие снимка при переподключении. | `time_and_sale_feed`, `sale_lifecycle_feed` |
| `OptionSale` | HISTORY `OptionSale`. Знаковый индекс, бизнес-время и время FIELD независимы. Удаления и транзакции сохраняют свою семантику. | `option_sale_feed`, `sale_lifecycle_feed` |
| `Series` | HISTORY `Series`, включая буквальный символ `AAPL&Q` и источник DEFAULT. Сохраняет знаковый индекс и флаги снимка и транзакции. | `series_feed`, `indexed_schema_java_current` |
| `NuamTrade` | Составной `NuamTrade` в TICKER и STREAM. Статистика биржи обновляется независимо от общих полей Trade. | `nuam_trade_feed`, `nuam_trade` |
| `NuamTimeAndSale` | Составной `NuamTimeAndSale` в STREAM и HISTORY, с `matchId` и флагами транзакций и удаления HISTORY. Для региональной доставки нужна явная регистрация. | `nuam_time_and_sale_feed` |
| `Order` | Нативный `Order` в HISTORY (DEFAULT и явно заданный `Order#...`, включая точный случай `#NTV`). Суффикс записи определяет источник. Производные Order из Quote в TICKER и из MarketMaker в HISTORY — отдельные проекции. | `order_feed`, `order_route`, `derived_order_feed`, `derived_order_oracle` |
| `MarketMaker` | HISTORY `MarketMaker` с нативными полями и отдельно выбираемой проекцией агрегированных Order. Координаты и флаги агрегированных заявок принадлежат этой проекции. | `derived_order_feed`, `derived_order_oracle` |
| `SpreadOrder` | HISTORY `SpreadOrder`. Сохраняет базовый символ и отдельный nullable `spreadSymbol`. Обычная регистрация в TICKER и STREAM отклоняется. | `order_variants_feed` |
| `AnalyticOrder` | HISTORY `AnalyticOrder`. Полные сырые флаги айсберга независимы от индексированных флагов. Явный `AnalyticOrder#NTV` допускает сопоставление в настроенной схеме даже при отсутствии возможности публикации для этого источника. | `order_variants_feed` |
| `OtcMarketsOrder` | HISTORY `OtcMarketsOrder` и `OtcMarketsOrder#pink`. Сохраняет знаковую плату за доступ к котировке, упакованные источник и индекс, отдельные флаги OTC. | `auction_order_feed` |
| `OrderImbalance` | TICKER `OrderImbalance`, `#NTV`, `#ARCA`, `#NUAM`. Один символ может иметь значение на каждый источник. Регистрация в HISTORY и STREAM отклоняется. | `auction_order_feed` |
| `NuamOrder` | HISTORY `NuamOrder`, `NuamOrder#NUAM`, `NuamOrder#nuam`. Два источника, отличные от DEFAULT, сохраняют регистр и точные индексированные значения. | `nuam_order_feed` |

## Символы, источники и значения

| Возможность | Контракт и ограничения | Детерминированные проверки |
| --- | --- | --- |
| Рыночный символ и биржа | Значение рыночного символа сохраняет логический биржевой суффикс `&Q`. `MarketEventSymbols` читает и меняет биржу или атрибут, сохраняя остальной текст. Суффикс у физического символа зависит от региональной записи. | `market_event_symbols`, `event_time_routing` |
| CandleSymbol и период | Разбор и вывод периода, типа цены, выравнивания, сессии, биржи и уровня цены. Канонические значения по умолчанию, неверные атрибуты и выбор `TradeHistory` для тиков проверяются отдельно. | `candle_symbol_values`, `candle_attribute_values`, `candle_period_values`, `candle_routes` |
| Индексированные источники | `OrderSource` и `IndexedEventSource` сохраняют идентичность и регистр. DEFAULT, явный `#NTV`, синтетические источники и флаги публикации имеют разный смысл. Неизвестный или несовместимый физический маршрут может отклонить подписку. | `event_sources`, `order_source_capabilities`, `order_route` |
| Селекторы и фильтры | Точные символы, символы с атрибутами и wildcard подчиняются правилам профиля и типа. Маршрут определяется контекстом реестра. Отклонение по профилю или конфликту сохраняет ранее принятое намерение. | `subscription_selectors`, `selector_profile`, `selector_feed`, `feed_filter`, `feed_filter_config` |
| Время события и сырые значения | Независимое время FIELD, неопределённое время события, упакованное бизнес-время, знаковые дни, SHORT_STRING, полные сырые флаги и nullable-поля имеют отдельную семантику. Перед проекцией проверяются точный тип на проводе и пределы копирования. | `event_values_java`, `event_time_java`, `event_time_feed`, `event_field_conversions_java`, `configured_java_events`, `configured_event_fixture_negatives` |
| Текст событий | Java-совместимый текст событий использует явный временной контекст. Округление, отказ при выделении памяти и отличие разрядности Summary проверяются отдельно. Формат вывода событий отделён от канонического представления CandleSymbol. | `event_text`, `event_text_summary`, `event_text_rounding`, `event_text_allocations` |
| Неизменяемый реестр событий | Пользовательская неизменяемая схема, точный ID записи, псевдонимы полей и идентичность типа. Несовместимые повторные маршруты, другой контекст, неверная форма и превышение пределов профиля отклоняются до сетевой активации. | `event_registry`, `event_registry_feed`, `selector_profile` |

## Запросы, подписки и модели

| Возможность | Контракт и ограничения | Детерминированные проверки |
| --- | --- | --- |
| Чтение сохранённого TICKER | `getLastEvent` и `getLastEventIfSubscribed` возвращают владеющие текущие значения и различают отсутствие точной подписки, значения по умолчанию и данные в кэше. Пассивное чтение работает с подходящим локальным тейпом TICKER, в том числе без слушателя. | `feed_api`, `tape_feed` |
| Одиночный запрос TICKER | `requestLastEvent` может создать временную точную подписку по TCP. Отмена, срок ожидания, clear, переподключение и закрытие завершают future и снимают временную подписку. Запрос к тейпу возвращает `UNSUPPORTED_PROFILE`. | `feed_api`, `tape_feed` |
| Групповой запрос TICKER | `requestLastEvents` сохраняет позиции повторяющихся символов и успешные ответы из кэша при отказе принять общую подписку для промаха. Clear и переподключение затрагивают только незавершённые запросы. Запросы при выборе тейпа завершаются до активации файла. | `feed_api`, `tape_feed` |
| Подписка и наблюдение HISTORY | `getHistorySnapshot()` возвращает владеющие метаданные состояния и покрытия зафиксированного диапазона. События поступают отдельно через обычную подписку HISTORY, в том числе из совместимых тейпов. Неполное и усечённое покрытие различаются. | `history_feed`, `tape_feed` |
| Индексированный снимок HISTORY | `requestIndexedEvents` и `getIndexedEventsIfSubscribed` требуют одного точного нативного маршрута по типу, символу и источнику. Синтетические и неоднозначные маршруты за пределами профиля. Результаты TCP различают `NOT_SUBSCRIBED`, `INCOMPLETE`, подтверждённый пустой и усечённый снимки. Оба метода отклоняют тейп с `UNSUPPORTED_PROFILE`. | `feed_api`, `tape_feed` |
| Снимок временного ряда HISTORY | `requestTimeSeries` и `getTimeSeriesIfSubscribed` используют включительные границы в бизнес-миллисекундах, включая ненулевые sequence на верхней границе. Владеющие события упорядочены по бизнес-времени и индексу. Обратный интервал, исчерпание лимитов и недостаточное покрытие имеют явные исходы. | `time_and_sale_feed`, `time_series_query_policy`, `feed_api` |
| Одновременные запросы HISTORY | Независимые запросы могут совместно использовать точную сетевую подписку в пределах числа слотов endpoint. Отмена завершает только свой future. Снимаемая подписка сохраняет занятый слот до завершения. Автовосстановление отсекает незавершённые снимки старой эпохи. | `feed_api`, `time_and_sale_feed` |
| Независимые подписки | Типизированную подписку можно подключить к нескольким Feed. Отсоединение относится к одному поколению подключения. Detach-and-clear выдаёт одно уведомление очистки после принятой доставки и сохраняет второй Feed. | `feed_api`, `callback_execution` |
| Жизненный цикл и диагностика | Ожидание состояния, снятие слушателя, изоляция исключений, закрытие с учётом callback, ограниченный drain и статистика используют существующее владение рантаймом. Снимок endpoint или подписки не удерживает нативный транспорт. | `feed_api`, `callback_execution`, `endpoint_configuration` |
| Модель индексированных событий | Владеющие индексированные снимки учитывают источник и индекс, удаления, завершение транзакций и снимков в пределах конечного объёма памяти. | `indexed_event_model` |
| Модель временных рядов | Владеющие снимки временных рядов сохраняют точные координаты при изменении диапазона и применяют квалифицированное воспроизведение HISTORY после переподключения. | `time_series_event_model`, `sale_lifecycle_feed` |
| Модель книги заявок | Применяет квалифицированные индексированные обновления к владеющим снимкам bid/ask в пределах явных лимитов модели. Область применения — локальная сборка книги в приложении. | `order_book_model`, `client_models_values` |
| Инструменты и значения IPF | Переносимые профили инструментов, локальное чтение и запись и снимки коллектора сохраняют поля, типизированные значения и владеющие ревизии. Разбор и обработка неверного ввода проверяются отдельно. | `ipf_values`, `ipf_reader`, `ipf_writer`, `ipf_collector` |
| Вспомогательные API инструментов | Глоссарий, шаги цены и цепочки опционов используют ограниченные API значений. Соответствующие тесты используют фикстуры Java там, где они подключены. | `glossary`, `price_increments`, `option_chains` |
| Торговые расписания | Правила календаря и запросы сессий используют необязательные закреплённые данные часовых поясов проекта. Для неизвестных зон и неподдерживаемых запросов действуют документированные ошибки. | `schedule_rules`, `schedule_queries` |

## Профили источников и пакетов

| Источник или профиль сборки | Контракт и ограничения | Детерминированные проверки |
| --- | --- | --- |
| Обычный QTP по TCP | Endpoint принимает согласованные со схемой кадры TICKER, STREAM и HISTORY по явно выбранному контракту. Время FIELD берётся из кадров, где оно передано. Действуют пределы источника, callback и границы восстановления. | `protocol_live_session`, `event_time_feed`, `feed_api`, `history_feed` |
| QTP с проверкой TLS | Необязательный контролируемый статический SDK и явные параметры доверия и идентичности сервера. Котировка после проверки принимается. Недоверенная цепочка, неверный SAN, недостаточный бюджет, локальный тейп и OnDemand без TLS отклоняются. Сборка без TLS возвращает `UNSUPPORTED_PROFILE` для настроек TLS. | `feed_tls`, `transport_tls_recovery`, `transport_tls_resources` |
| Basic в QTP с проверкой TLS | Ответ провайдера принимается только для текущего запроса проверенной TLS-сессии и её ревизии. Прикладные DATA допускаются после подтверждения. Переподключение может использовать обновлённые данные. Повторный запрос после отправки авторизации завершает работу с `tls-authentication-denied`. | `feed_tls`, `protocol_live_session` |
| Локальный бинарный тейп Feed | Один обычный бинарный файл с совместимым заголовком или самоописанием без заголовка и встроенным временем NONE, MESSAGE или FIELD. DATA выбранного контракта и RAW_DATA маршрутизируются отдельно. Пауза, темп, перезапуск и остановка учитывают границы эпох. В этом профиле Feed отклоняет text/blob, сжатие и отдельный файл времени. | `tape_feed`, `protocol_binary_tape`, `raw_tape_java_conformance` |
| Воспроизведение OnDemand через loopback | Явный IPv4 loopback, один конечный несжатый ответ с составными Quote, конверт запроса Java QD v2. Покрывает начальную догонку, паузу и темп, EOF, явную очистку и переход к обычному QTP. Неверный формат или отсутствие покрытия начала не открывают историческую эпоху. | `on_demand_feed` |
| Внешний живой сервис OnDemand | Внешний живой сервис исключён из этой квалификации. Проверки HTTP по loopback и конверта Java относятся к детерминированной фикстуре. | Согласованное исключение |
| Передача и соединение IPF | Локальный обычный файл и ограниченный HTTP, с необязательным контролируемым HTTPS. Транспорт, gzip и завершение IPF различаются. Соединение публикует владеющие ревизии и сохраняет готовый префикс при последующем сбое завершения транспорта. | `ipf_transfer_control`, `ipf_transfer`, `ipf_compression`, `ipf_connection`, `ipf_connection_control` |
| Независимая установка | Установленный `qdcxx_feed` и отдельно собранные примеры используют экспортированные цели на Windows MSVC и Linux GCC. Внешний потребитель после переноса установки и граф зависимостей со включённым или выключенным TLS проверяются отдельно. | [Сборка пакета](CPP-BUILD.ru.md) |
| Клиентские примеры | Офлайн-фикстуры покрывают рыночный Feed, запросы и локальные модели. Справка примеров запускается без подключения. | `feed_demo_help`, `feed_market_help`, `feed_market`, `client_queries_help`, `client_queries_loopback`, `client_models_help`, `client_models_values` |

## Пределы квалификации

Строка события описывает маршруты, проверяемые указанными тестами. Результаты не распространяются на все комбинации пользовательских схем, источников, транспортов и типов событий. При отсутствии фикстуры или запуска для конфигурации соответствующая проверка остаётся открытой. Полная совместимость с произвольными QD-узлами, историческими сервисами и контейнерами тейпов выходит за пределы описанных профилей.

Вызовы API приведены в [справке Feed](FEED-API.ru.md). [Реестр приёма](../spec/events/EVENT-REGISTRY.ru.md) определяет идентичность схемы и допуск маршрута. [Справка о бинарных тейпах](../spec/protocol/BINARY-TAPE-COVERAGE.ru.md) описывает отдельные средства офлайн-декодирования и инспекции.
