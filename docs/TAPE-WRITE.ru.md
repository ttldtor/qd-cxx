# Строгая офлайн-перезапись tape

[English](TAPE-WRITE.md). Английский текст является нормативным.

qdcxx-tape-write — нативная офлайн-утилита нормализации по этому контракту; реализация и фактически
выполненные проверки поставляются отдельно. Допускается только явный
[RAW_MESSAGE_V1](../spec/protocol/TAPE-WRITER.ru.md), сохраняются допущенные действия, метаданные и значения,
публикуется новый файл. Частные входы, настройки окружения, свойства Java, транспортные адреса,
сопутствующие файлы и внешние включения не читаются. Утилита не записывает работающий сетевой connector и не обещает побайтно
одинаковый результат с Java FileWriter.

## Командная строка и владение конфигурацией

```text
qdcxx-tape-write --input INPUT --output OUTPUT --tape-mode raw-message-v1 --profile BUILTIN [LIMITS]
qdcxx-tape-write --input INPUT --output OUTPUT --tape-mode raw-message-v1 --schema SCHEMA [LIMITS]
```

Требуется ровно один источник: --profile oracle-sre-v1|default-quote-v1|default-profile-v1|oracle-field-types-v1
или --schema PATH. Встроенные профили — прежние явно проверенные схемы инспектора; адаптеров/проекций
событий не добавляется. Профиль ограничивает локальные типы, не выбирает режим tape. Обязателен
--tape-mode raw-message-v1, без неявного legacy. --schema использует прежнюю
[грамматику версии1](../spec/schema/NATIVE-JSON.ru.md). Необязательный загрузчик остаётся отдельным;
при его отключении LOADER_DISABLED возникает до tape I/O.

Отсутствие аргументов и отдельный --help дают одинаковый stdout, пустой stderr, exit0 при успешном
выводе, не открывают schema/input/output. Ошибка записи/выгрузки help — exit3. Другие сочетания --help,
неизвестные/повторные/неполные/позиционные аргументы и конфликт источников — ошибки использования.
Значения передаются отдельными argv; --key=value, коротких опций, автоматического поиска и общего
загрузчика свойств нет. Пути — буквальные нативные пути, пустой путь ошибочен. Бюджеты — десятичные
ASCII числа без знака/пробелов; zero допустим, переполнение — ошибка использования. Конфигурация
разрешается один раз в явный владеющий объект до любого I/O.

Необязательная цель qdcxx_tape_write создаёт qdcxx-tape-write; ORG_TTLDTOR_QDCXX_BUILD_TAPE_WRITE
по умолчанию OFF. Новых зависимостей нет. Сборка только библиотеки/без утилиты остаётся рабочей;
JSON-OFF не получает simdjson, BUILD_TESTING=OFF — doctest. Новый запускатель Python или зависимость не добавляется.

## Строгий допуск: полный preflight и детерминированный второй проход

Успешного reader недостаточно: прежняя привязка допускает неизвестные записи/поля, повторные
назначения и значения raw-zero по умолчанию. Прежние политики reader сохраняются. Сначала полный
ограниченный вход читается во владеющие байты и успешно закрывается. Новый RAW_MESSAGE_V1 TapeReader
с выбранной схемой проверяет **каждый** кадр/описание, включая неиспользованные описания. finish
вызывается только после настоящего EOF операционной системы. Временного выходного файла ещё нет.

API admitTape(const LocalSchema&,span<const byte>,AdmissionLimits) в qd/protocol/tape_admission.hpp,
пространство имён org::ttldtor::qdcxx::protocol, возвращает expected<AdmittedTape,AdmissionDiagnostic>.
AdmittedTape неизменяем, перемещаем, с закрытым конструктором; владеет ограниченной копией байтов,
схемы, явных layouts и точного дескриптора. Вызывающая сторона не устанавливает открытый логический
флаг EOF и не подделывает подтверждение завершения. EOF библиотеки означает исчерпание переданной
полной последовательности; файловая граница отдельно подтверждает физический EOF и закрытие.
Перемещение token делает исходный объект неактивным. `valid()` сообщает это состояние времени
жизни, а не устанавливаемый вызывающей стороной флаг EOF. Потребители отказывают неактивным
объектам до заимствования их содержимого; accessors требуют активный объект, а представления
теряют действительность при перемещении или уничтожении.
Сохраняются исходные байты, не история декодированных записей/действий. Результат кадра освобождается
после обработки; контекст и представления не переживают своего владельца.

| Точка допуска | Требование |
| --- | --- |
| Режим/кадры/начальный заголовок | Прежние синтаксис и политика RAW-TAPE успешны, ровно один начальный дескриптор. Неизвестные/повторные свойства, записи списка приёма, расширения и другое время/опции/сообщения отвергаются reader. |
| Проекция дескриптора | Каждый принятый член точно представим: version отсутствует/пустой, opt отсутствует/пустой/hs, time MESSAGE/message, список отправки пустой/один RAW. Прежние флаги, противоречия и будущие непредставимые члены отвергаются до вывода. Порядок пар и ширины примитивов нормализуются. |
| Полезная нагрузка описания | Полный владеющий frame.payload повторно разбирается parseDescribeRecords; дополнительная работа учитывается. Имена/порядок не выводятся из финальных значений. |
| Каждая привязка | bindRecord даёт известный localRecordId; полные типы точны; все действия имеют цели, каждая локальная цель ровно одна и покрытие полное. Пропуск, повтор, отсутствие и преобразование отвергаются, включая пустые/неиспользованные неизвестные записи. |
| Неизменяемый набор | Повтор sender ID/local ID/имени запрещён, даже одинаковый. Добавление описаний допустимо на исходном месте без изменения определения. Данные только для объявленного ID. Точные wire-имена, порядок и IDs сохраняются, не первые псевдонимы поиска. |
| Диапазон исходящего ID | Writer допускает0..INT32_MAX-1. INT32_MAX отклоняется до переписывания, без перенумерации. [Контракт writer](../spec/protocol/TAPE-WRITER.ru.md#неизменяемые-layouts-и-имена) описывает переполнение в закреплённом Java и отдельные ресурсные ограничения плотной таблицы. |
| Данные/heartbeats | Все результаты успешны, ошибочный префикс не маскируется. Flags0, канонические типизированные значения; все формы empty/bits0/bits1, timestamps и markers представимы. |
| Завершение входа | Физический EOF и закрытие успешны; reader finish FINISHED. Marker не EOF. Обрыв после корректного префикса/marker отвергает всю перезапись. |

Полный синтаксический разбор предшествует строгой привязке; прежняя проверка полного типа предшествует
известности, пропускам и покрытию. Проверки идут по порядку на проводе: неизвестная запись,
пропускающее действие, повтор цели, отсутствие цели в конце записи. Повторы проверяются до публикации набора.
Неиспользованные имена/типы сохраняются. Корректная перестановка целей разрешена; изменение множества
целей отвергается. Финальный набор публикуется только после полного допуска. Нет вставки значений по умолчанию,
незаметного удаления или упрощения схемы.

Новый reader второго прохода читает те же неизменяемые байты с отдельными расходами. Дескриптор,
группы описаний, heartbeats, группы данных и markers выводятся в исходном порядке конвертов.
Группы описаний выбирают IDs финального набора в исходных местах. Data сохраняет порядок, точные
локальные значения, units symbol и исходное время/cursor. Sender ID однозначен благодаря уникальным
local IDs. Пустые кадры данных/описаний сохраняются; объединения кадров, синтетического footer
и подмены MESSAGE бизнес-временем нет. Каноническое кодирование примитивов, свойств и symbols может
менять длины и offsets; обещается семантическое равенство.

Семь опций и значений по умолчанию нативной схемы точно совпадают с NATIVE-JSON. Копирование встроенной
схемы применяет те же SchemaLimits; байты/глубина только для JSON. Для COMPACT_INT нормализатор создаёт
точные представления FieldValue типа8 в бюджете значений/работы, не угадывает двойной legacy/typed
массив. Профили типа8/Quote сохраняют проверку своего точного профиля, не расширяются автоматически.

AdmissionLimits содержит владеющие байты входа, TapeLimits, LayoutLimits, дополнительный workUnits
и пиковые scratchBytes/scratchUnits. Они покрывают одновременно кадр результата, дополнительное
описание, привязку и кандидат layout; превышение проверяется до выделения памяти. Опции --max-admission-scratch-*
управляют только AdmissionLimits, --max-scratch-* — только WriterLimits. Байтовый scratch admission
считает целую временную копию источника до передачи в AdmittedTape и дополнительные байтовые буферы;
кадр и ожидающий буфер reader ограничены отдельно TapeLimits. Временные элементы UTF-16 учитывают
дополнительные имена/текст исходных описаний и исходящих кандидатов, включая старую/новую копии
до фиксации. Финальные схема/layout/дескриптор имеют отдельные пределы; контейнеры действий/записей —
LayoutLimits. Каждый скопированный элемент расходует работу. Лишние полные промежуточные копии входа
не создаются: готовая ограниченная копия передаётся при фиксации. Каждый проход имеет отдельные счётчики; работа двух
проходов не считается одним. Расход reader на построение и поля не возвращается. Копии и временные
буферы используют проверенную арифметику; непроверенного reserve нет. Логические элементы не учитывают
служебные данные выделения памяти.

Утилита задаёт общий writer ledger посещений descriptor/name проверенной суммой
`--max-descriptor-units` и `--max-description-name-units`. Сохранённые descriptor и layout
по-прежнему ограничены отдельно; повторные сравнения, вычисление размера и кодирование могут
исчерпать общий ledger раньше этих пределов сохранённого размера. Пределы UTFString одного
текста writer — descriptor string limits; проверка layout дополнительно применяет `--max-name-units`.
Работа физических файловых операций ограничена отдельно проверенными выражениями
`4 * inputBytes + 68` для чтения (включая копирование при геометрическом росте буфера) и
`2 * outputBytes + 68` для записи/публикации. Она не расходует traversal ledgers admission/writer.
Каждый владеющий native path ограничен 4096 code units, включая создаваемый временный путь;
встроенный NUL отвергается. Переполнение арифметики даёт exit 6.

## Публикация и отказ от same path

После проверки схемы пути приводятся к абсолютным, альтернативные пути существующих родителей
разрешаются, конечные записи каталогов проверяются с учётом символических ссылок, идентичность
существующих файлов сравнивается где возможно. Отвергаются одинаковые пути через лексические и
родительские альтернативы, символические/жёсткие ссылки и равенство регистра Windows. Любая запись
цели, включая символическую ссылку без цели/каталог, считается существующей. Родитель уже существует;
создания каталогов, переключателя перезаписи и tape в stdout нет. Обычные альтернативные пути проверяются;
враждебная одновременная замена родителя вне гарантии, это не изолирующая среда безопасности.

Лишь после полного допуска исключительно создаётся частный временный файл в разрешённой директории
цели реальным платформенным exclusive create, не exists+обычный ofstream. Сохраняются только
принадлежащие операции файловый дескриптор и путь. Записи целых фрагментов проверяются; частичная/
нулевая запись с ошибкой терминальна. Обязательны writer finish, финальная выгрузка, проверенное
закрытие и отсутствие отложенных ошибок. Деструктор и непроверенное закрытие Java не подтверждают завершение.

Публикация — создание новой жёсткой ссылки от закрытого временного файла к свежей цели реальным
create_hard_link с обработкой ошибок. На поддерживаемой локальной файловой системе появившаяся
после проверки цель не заменяется: создание ссылки ошибочно. Замены на rename нет. Неподдерживаемая,
запрещённая, межтомовая или ошибочная ссылка даёт отказ публикации и удаление только своего временного
файла. Та же директория исключает намеренную межтомовую публикацию. Каждая среда отдельно проверяет
гарантии; обычный POSIX rename способен заменить возникшую цель и не используется.

После создания ссылки удаляется своё временное имя. Ошибка очистки сохраняет корректный опубликованный
файл, сообщает ненулевой результат/published=true и ограниченный точный путь своего временного файла
для оператора; цель ради видимости отката не удаляется. До создания ссылки ошибки не создают цель
и пытаются очистить свой временный файл. Очистка вторична, не заменяет первую ошибку. Отказ exclusive
create не позволяет удалить чужую запись. Защита от враждебных гонок имён, fsync директории,
сохранность при потере питания и универсальная атомарность при аварии не обещаются. Успешно видимая
цель содержит полностью записанные/закрытые/проверенные байты по проверенным свойствам файловой системы.

## Результаты и приоритет ошибок

Успех молчалив: пустые stdout/stderr, exit0 только после публикации и cleanup. При ошибке — не более
одной ограниченной UTF-8/LF строки stderr:
`tape-write-error<TAB>1<TAB>STAGE<TAB>CODE<TAB>published=0|1<LF>`.
Входные значения, имена схемы и учётные данные не выводятся. Только ошибка очистки добавляет
ограниченные подробности и принадлежащий операции путь. Отказ записи/выгрузки диагностики остаётся
ненулевым результатом, не заменяет прежнюю первую ошибку и не отменяет публикацию.

| Exit | Категория |
| --- | --- |
| 2 | Использование, запись бюджета или конфликт опций. |
| 3 | Пути, файловое I/O, создание, запись, выгрузка, закрытие, создание ссылки, очистка или вывод диагностики. |
| 4 | Неподдерживаемые режим, профиль, загрузчик, тип, flags или дескриптор либо строгий отказ из-за потери информации. |
| 5 | Некорректная схема, tape, описание или значение, повторы либо оборванный EOF. |
| 6 | Бюджет, проверенная арифметика или выделение памяти. |

Порядок: аргументы/help → доступность загрузчика → чтение/закрытие/проверка схемы → пути → открытие/
чтение/EOF/закрытие входа → полный допуск → исключительное создание временного файла → второй разбор/
компоновка/запись → reader finish → writer finish → выгрузка → закрытие → ссылка → очистка.
Первая обнаруженная ошибка останавливает. Отказ чтения предотвращает разбор/допуск; отказ записи —
дальнейший разбор вместо поиска «более подходящей» ошибки входа. FAILED результат второго прохода
с завершённым префиксом даёт ошибку входа без записи его данных. Ошибка приёмника вывода не превращается
в успешный EOF. Независимые дефекты схемы
сохраняют ограниченный порядок NATIVE-JSON, а не придуманный общий приоритет.

Стабильные строгие коды: UNKNOWN_RECORD, SKIPPED_FIELD, REPEATED_TARGET, MISSING_TARGET,
DUPLICATE_LAYOUT_IDENTITY, UNREPRESENTED_DESCRIPTOR. Reader/writer сохраняют типизированные причины/позиции.
Повторно используемая владеющая диагностика может содержать ограниченные пути/смещения; обычная строка
не содержит входных данных. Выходной префикс не завершённый результат, даже если отдельно разбирается.
