# Архитектура

[English version](ARCHITECTURE.md). Английский документ является основным.


## Уточнение цели: библиотека и рабочие программы

Проект должен включать аналоги необходимых утилит qds-tools, а не только библиотеку/инспектор.
Инвентаризация QDCXX-020 определит фактический список и порядок. Feed, мультиплексирование,
запись/replay и диагностика — направления применения, не заранее утверждённые имена команд.
Общая обработка данных и подписок относится к библиотекам; transport отвечает за соединения;
программы собирают компоненты, конфигурацию, управление и наблюдаемость. Не превращать инспектор
в универсальный сервер и не дублировать общую логику. Выбор transport/threading и совместимость
CLI/properties остаются отдельными решениями. [План и правила перехода](NEXT-STEPS.ru.md).

## Цель

QDCXX-025 реализует ограниченную [границу подготовленных отображений событий](../spec/events/EVENT-MAPPING.ru.md):
неизменяемые локальные схемы передают непрозрачный контекст записи через общее декодирование, а отдельные
адаптеры Quote/Profile владеют проверенными выборами полей и значениями событий. Копии схемы сохраняют контекст;
новое создание схемы даёт новую идентичность. Wire binding и конфигурация источников остаются отдельными.
[Подмножество Java-конфигурации](../spec/schema/CONFIGURED-EVENTS.ru.md) даёт доказательства источников;
оно не добавляет C++ loader, неявные настройки процесса или transport в библиотеки core/events.

`qd-cxx` будет воспроизводить внешне наблюдаемые контракты Java QD без механического повторения иерархии классов или исторических решений реализации. Цель — модульная, проверяемая система на C++23.

## Предлагаемые границы

Это направления проектирования, а не обязательства по реализации:

- **qd-core**: records, field values, scheme semantics, symbols, subscriptions и core state transitions. Не должен зависеть от transport.
- **schema/model**: предлагаемые immutable resolved records, fields, полные type identities, names/lookups и Java slot projection; source operations и mapping/provider information сохраняются как provenance, а не executable Java mappings.
- **encoding**: байтовые примитивы и stateful codecs с явными правилами ошибок и владения.
- **protocol**: QTP messages, framing, negotiation и protocol state machines независимо от socket library.
- **transport adapters**: connections, I/O scheduling, backpressure, lifecycle и интеграция с будущим networking runtime.
- **tools**: importers, inspectors, fixture capture и compatibility diagnostics.

Зависимости направлены внутрь: transport может зависеть от protocol; protocol — от encoding и core contracts; core не должен зависеть от transport.

## Настраиваемые схемы и отображение событий

[ADR-0003](decisions/ADR-0003-configurable-schemas-and-event-mappings.ru.md) закрепляет разрешаемые во время выполнения схемы как общее требование проекта.
Встроенные варианты по умолчанию и будущие XML/JSON либо программные источники используют одну проверяемую границу локальной схемы.
Общие записи доступны без адаптеров стандартных событий; mappings Quote/Profile привязываются к конкретной схеме, не предполагая default-порядок полей.
Конфигурация источников, wire-адаптация и проекция событий остаются отдельными обязанностями.
QDCXX-025 реализует первое ограниченное применение решения; решение не означает уже имеющейся поддержки загрузчиков или произвольных схем.
[Требования к конфигурации](CONFIGURATION.ru.md) распространяются не только на схему: источники properties, приоритеты, область действия, момент чтения и диагностика — явные вопросы совместимости.

## Принципы проектирования

- Описывать наблюдаемое поведение до реализации.
- Явно определять ownership, lifetime, cancellation, threading и error semantics.
- Отделять детерминированные преобразования от I/O.
- Предпочитать заменяемые adapters на границах upstream, filesystem, timing и transport.
- Сохранять прослеживаемость поведения Java QD до исходников.
- Использовать ADR для существенных или труднообратимых решений.

## Пока не решено

Не выбраны networking library, package manager, стабильный public API, threading model или binary compatibility policy. Дополнение владельца к QDCXX-010 выбирает doctest как тестовую зависимость FetchContent. Эти решения требуют ограниченных задач и доказательств.

QDCXX-010 реализует только примитивы compact int/long границы encoding с предварительным API на span, минимальными CMake/CTest и без сторонних runtime-зависимостей. См. [сборку/API](CPP-BUILD.ru.md) и [валидацию](../tests/conformance/encoding/VALIDATION.ru.md). Это не реализует и не меняет остальные предложенные границы.

## Принятые границы ADR-0001

Утверждено владельцем проекта 2026-09-21. Три границы определяют логическое владение и не требуют трёх форматов файлов или трёх подсистем сериализации. Core может использовать разрешённую локальную схему без загрузки XML и его истории. Потеря copied main alias сохраняется только для XML-импорта в закреплённом профиле QD 3.355; это не требование к будущему программному созданию схем в C++. Java slot projection сохраняется без предписания физического хранения C++. Утверждена структурированная диагностика unsupported-local-type для BYTE/SHORT с сохранением отклонения локального построения; это не запрещает их wire-коды. Исходные requests и selected layouts остаются раздельными. JSON принят для обмена описаниями схем; библиотеки, канонические хеши и сериализация всей сессии остаются открытыми. Существующие oracle-доказательства неизменны.
