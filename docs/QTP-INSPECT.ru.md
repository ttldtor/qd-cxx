# Офлайн-инспекция QTP

[English version](QTP-INSPECT.md). Английская версия является нормативной.

`qdcxx-qtp-inspect` — необязательный ограниченный диагностический executable, не tape reader и не
клиент. [Контракт версии 1](../spec/protocol/OFFLINE-INSPECTION.ru.md) определяет порядок, точный
TSV, смещения, коды выхода и учёт ресурсов. Нет importer, transport, dynamic session, ненулевых
flags, conversions или общего загрузчика схем. Сырой QTP не является tape-контейнером.

## Сборка и запуск

```powershell
cmake -S . -B .work/inspect -DORG_TTLDTOR_QDCXX_BUILD_QTP_INSPECT=ON -DBUILD_TESTING=OFF
cmake --build .work/inspect --config Release
.work/inspect/Release/qdcxx-qtp-inspect.exe --profile oracle-sre-v1 --input tests/fixtures/protocol/offline-inspection/expected/composed.qtp
.work/inspect/Release/qdcxx-qtp-inspect.exe --help
```

Для Ninja/Makefiles используйте `.work/inspect/qdcxx-qtp-inspect` (или `.exe` в Windows).
`ORG_TTLDTOR_QDCXX_BUILD_QTP_INSPECT` по умолчанию OFF; доступна сборка только библиотек. BUILD_TESTING=OFF
не скачивает doctest и не требует Python. При включённых тестах и инструменте CTest включает
интеграцию executable и переносимые инъекции ошибок I/O; Python 3 нужен только тестам.
Production линкует только существующие qdcxx_protocol/qdcxx_core/qdcxx_encoding и стандартную библиотеку.

## Аргументы и конечные значения по умолчанию

`--profile oracle-sre-v1 --input PATH` обязательны, в любом порядке. Нет позиционных аргументов,
`--key=value`, сокращений, повторных опций или stdin `-`. `--help` должен быть единственным
аргументом. Числовой операнд состоит только из ASCII десятичных цифр; ноль разрешён, кроме chunk-size.
Неизвестные опции/профиль, отсутствующие операнды и выход за size_t/uint64_t/streamsize, где применимо,
дают usage. Frame+9 должен помещаться, frame — в signed 64 bits. Лимиты сообщения больше общих
допустимы: декодер получает минимум. Значения по умолчанию — десятичные количества:

| Опция | По умолчанию | Единица/область |
| --- | --- | --- |
| --chunk-size | 4096 | Байты входа/чтение, положительно |
| --max-input | 67108864 | Принятые байты файла |
| --max-frame | 1048576 | Type+payload байты/кадр; также предел payload и входного span символа |
| --max-frames | 4096 | Все кадры, включая heartbeat |
| --max-descriptions | 1024 | Начальные описания между кадрами |
| --max-actions | 65536 | Начальные действия wire-полей всех описаний |
| --max-name-units | 1024 | UTF-16 units/имя описания |
| --max-total-name-units | 1048576 | Все units имён записей/полей описаний |
| --max-records | 1048576 | Списанные записи всех data сообщений, включая пропуски |
| --max-fields | 4194304 | Списанные wire-поля всех data сообщений |
| --max-values | 4194304 | Завершённые локальные значения всех data сообщений |
| --max-symbol-units | 4194304 | Units принадлежащих завершённому результату символов с повторами |
| --max-output | 67108864 | Все байты stdout, включая format/complete |
| --message-records | 65536 | Списанные записи/data сообщение |
| --message-fields | 262144 | Списанные поля/data сообщение |
| --message-values | 262144 | Завершённые значения/data сообщение |
| --message-symbol-units | 262144 | Units принадлежащих результату символов/data сообщение |
| --symbol-units | 4096 | Units/текущий символ и сохранённый символ сообщения |

Точный лимит успешен, превышение отклоняется; пустой вход может быть успешен с нулевыми бюджетами
данных. Нулевой бюджет вывода не вмещает даже format. Это логические пределы, не обещания RSS.

## Явная диагностическая локальная схема

`oracle-sre-v1` использует существующую [схему oracle STREAM_DATA](../tests/fixtures/protocol/stream-data/COVERAGE.ru.md).
Все поля — обычный полный type 8, hasTime=false. ID равны позициям; упорядоченные поля и явные
ключи поиска ниже (алиасы не выводятся автоматически):

| ID/имя | Поля в локальном порядке | Ключи → field ID |
| --- | --- | --- |
| 0 / S | 0:v | v, S.v → 0 |
| 1 / R | 0:y, 1:x, 2:z | y, R.y → 0; x, R.x, xdot → 1; z, R.z → 2 |
| 2 / E | нет | нет |

Это временный fixture-адаптер, не production-модель схем. Локальная функция инструмента `inspect`
принимает независимо переданную валидированную LocalSchema с фиксированными пределами проверки,
описанными в контракте. Будущим загрузчикам не требуется менять binding или decoding. Описания
отправителя никогда не определяют локальную схему. Вывод — точный unit hex: R — `0052`,
ABC — `004100420043`.

## Завершение и ошибки

Успех — exit 0 и ровно одна финальная complete. Пустые файлы/файлы только с описаниями могут
успешно завершиться без записей. Exit 2 usage, 3 I/O, 4 неподдерживаемый профиль/порядок,
5 некорректные данные, 6 ресурсы. Stderr помечает вывод incomplete и сообщает доступные позиции
кадра/payload. После ошибки могут остаться предыдущие завершённые записи. Физическая ошибка
write/flush может оставить частичные байты, даже complete; всегда проверяйте exit status.
Это отличается от Java callback batching ошибочного сообщения. Число и смысл ячеек — в контракте.

## Читаемый вывод

Добавьте `--output-format human`; отсутствие опции или `--output-format tsv` сохраняет прежний TSV
версии 1. Неизвестные, повторные или отсутствующие операнды формата — ошибки использования.
Автоматического выбора по TTY нет.

```powershell
.work/inspect/Release/qdcxx-qtp-inspect.exe --profile oracle-sre-v1 --input tests/fixtures/protocol/offline-inspection/expected/composed.qtp --output-format human
```

Human версии 1 показывает заголовок формата/профиля, имена/числовые ID кадров и фактические границы
байтов, локальные имена/ID записей, символы в кавычках, подписанные значения в локальном порядке
и итог. Явные метки — `S.v`, `R.y`, `R.x`, `R.z`; независимый вызов утилиты без метаданных отображения
использует `field[index]`. Lookup-псевдонимы не являются каноническими именами для вывода. Показанные
идентификаторы локальные, личности отправителя не восстанавливаются. Пустые символы (`""`)
отличаются от отсутствия полей (`fields={}`).

Оба режима детерминированы, без BOM, со строками LF. Human использует UTF-8, объединяет корректные
суррогатные пары, без потерь экранирует одиночные суррогаты, кавычки/обратные косые черты,
управляющие символы, разделители строк и bidi controls. Точные таблица и грамматика — в
[контракте](../spec/protocol/OFFLINE-INSPECTION.ru.md). Нет нормализации Unicode или незаметной замены.
`--max-output` считает фактические байты, включая заголовок/экранирование/итог; стоимость зависит
от формата. Строки подсчитываются до выделения развёрнутого представления, поэтому недостаточный
бюджет не приводит к намеренному выводу частичной строки. Stderr и коды выхода прежние; при ошибке
может остаться завершённый префикс, а доставленный итог не отменяет ошибку записи/финального flush.

Читается raw QTP, не QD tape: нет tape-контейнеров, сжатия, time-файлов, protocol descriptors,
расширенных полей, importer, transport или динамических сессий.
[Покрытие human и авторская валидация](../tests/conformance/protocol/human-inspection/VALIDATION.ru.md)
используют прежние доказательства Java; само представление — спроектированная политика C++.
