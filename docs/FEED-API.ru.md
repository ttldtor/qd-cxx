# Публичный feed API {#feed-api-ru}

[English version](FEED-API.md) · [Практические руководства](guides.ru.md) · [Справочник API](api.ru.md)

Подключите `qd/api/feed.hpp` и линкуйте `qdcxx_feed`, чтобы получать типизированные
`events::Quote`, `events::Profile`, `events::Trade`, `events::TradeETH`, `events::Summary`, `events::TextMessage`, `events::TextConfiguration`, `events::Message`, `events::Configuration`, `events::Order`, `events::MarketMaker`, `events::SpreadOrder`, `events::AnalyticOrder`, `events::OtcMarketsOrder`, `events::OrderImbalance` и `events::Series` через рабочий поток библиотеки. Приложение создаёт
endpoint, обработчики и подписки на точные символы; библиотека продвигает соединение,
конечные переподключения, очереди и доставку. Подписки можно создавать до и после
`connect()`.

Поддержан обычный бинарный QTP поверх TCP со встроенными полными схемами Quote/Profile/Trade/TradeETH/Summary
и текстовых событий либо явными валидированными схемами вызывающего кода и зарегистрированными mappings.
Endpoint выбирает TICKER (по умолчанию: последние значения с возможным объединением
обновлений), STREAM (каждая принятая выбранная запись источника) либо явный HISTORY
(индексируемое общее хранилище и независимые представления). Обычный Order, MarketMaker,
SpreadOrder, AnalyticOrder, OtcMarketsOrder и Series используют HISTORY. Производный от Quote
Order и OrderImbalance используют TICKER.
[MarketMaker и производный Order](MARKET-MAKER-ORDER.ru.md) описывает источники A..Z,
которыми владеет SDK. Стандартная схема
Order принадлежит SDK и не требует схемы от приложения. Стандартный HISTORY-реестр также
включает оба варианта с источником DEFAULT. Для записей `SpreadOrder#ISE` или
`AnalyticOrder#NTV` передайте явный проверенный реестр и выберите точный источник через
`SubscriptionSelector::indexed`. Символ подписки SpreadOrder обозначает базовый инструмент.
Тот же селектор выбирает конкретный источник OtcMarketsOrder или OrderImbalance.
Обычный символ выбирает все доступные источники этого типа события.
См. [ордера OTC и аукционный дисбаланс](AUCTION-ORDER-EVENTS.ru.md).
Подробнее о [вариантах Order](ORDER-VARIANTS.ru.md). Остальные девять типов сохраняют
существующие профили TICKER/STREAM и отклоняют HISTORY до native-регистрации. Wildcard-селекторы
требуют существующего явного разрешения STREAM. Загрузка схем является отдельной задачей.
[Низкоуровневые API получения](SUBSCRIPTIONS.ru.md) предоставляют отдельные профили.

Для типизированного приёма `events::TimeAndSale` используйте `createSubscription<events::TimeAndSale>()`
в STREAM или `createTimeSeriesSubscription<events::TimeAndSale>()` в HISTORY. В обоих случаях
доступны составные символы, например `AAPL`, и региональные, например `AAPL&Q`.
[Контракт TimeAndSale](../spec/events/TIME-AND-SALE.ru.md) описывает маршрутизацию, время и флаги исправлений.

## Получить Quote

Сначала [соберите пакет с включённым API](CPP-BUILD.ru.md#public-feed-api-build-ru).
[Полный консольный пример](../examples/feed_quote/main.cpp) проверяет аргументы,
обрабатывает прерывание и ошибки вывода, ограничивает время работы и возвращает
ошибку при отсутствии данных. [Инструкция по сборке и запуску](../examples/feed_quote/README.ru.md)
использует установленный пакет.

Основная последовательность приложения:

```cpp
#include "qd/api/feed.hpp"

#include <chrono>
#include <iostream>
#include <stop_token>

int main() {
    namespace q = org::ttldtor::qdcxx;

    try {
        std::stop_source stop;
        q::api::ApiRuntime runtime;
        auto endpoint = runtime.createEndpoint();
        auto quotes = endpoint->getFeed()->createSubscription<q::events::Quote>();

        quotes->addEventListener([](std::span<const q::events::Quote> batch) {
            for (const auto &quote : batch) {
                std::cout << quote.bidPrice.toString() << '\n';
            }
        });
        quotes->addStateChangeListener([source = stop](auto, auto current) mutable {
            if (current == q::api::SubscriptionState::FAILED) {
                source.request_stop();
            }
        });
        quotes->addSymbols({"AAPL", "IBM"});
        endpoint->connect("demo.dxfeed.com:7300");

        const auto cutoff = std::chrono::steady_clock::now() + std::chrono::seconds(10);
        static_cast<void>(endpoint->awaitState(q::api::EndpointState::CLOSED, cutoff, stop.get_token()));

        const auto closed = endpoint->closeAndAwaitTermination();
        runtime.closeAndAwaitTermination();

        if (closed.diagnostic.code != q::api::ErrorCode::NONE) {
            std::cerr << "Endpoint diagnostic=" << static_cast<int>(closed.diagnostic.code)
                      << " stage=" << closed.diagnostic.stage << " native=" << closed.diagnostic.nativeCode
                      << " detail=" << closed.diagnostic.detailCode << " drained=" << closed.drained
                      << " expired=" << closed.deadlineExpired << " gap=" << closed.hadGap << '\n';
        }

        return closed.drained && !closed.deadlineExpired && !closed.hadGap &&
                       quotes->getDiagnostic().code == q::api::ErrorCode::NONE
                   ? 0 : 1;
    } catch (const q::api::Error &error) {
        std::cerr << error.diagnostic().stage << '\n';
        return 1;
    }
}
```

Ожидание ограничивает интервал получения в приложении, а не продвигает feed.
Короткий пример не проверяет, поступил ли хотя бы один Quote; для этого используйте
полную программу. Demo-адрес служит примером входных данных; доступность, подписки
и задержка данных зависят от внешнего сервиса.

Для Profile создайте `createSubscription<q::events::Profile>()` и обработчик с
аргументом `std::span<const q::events::Profile>`. Для STREAM задайте
`EndpointOptions::contract = DeliveryContract::STREAM` перед `createEndpoint(options)`.
Выбранный контракт доставки действует для всех подписок этого endpoint.

Типизированный параметр `EndpointOptions::batchRecords` ограничивает число целых физических записей
в одной выборке для callback (по умолчанию и максимум 4). Одна запись может дать несколько
прикладных событий. `EndpointOptions::pendingRecords` ограничивает число отделённых физических
записей на подписку, включая выбранные для callback (по умолчанию и максимум 128). Оба лимита
должны быть положительными, и `batchRecords` не может превышать `pendingRecords`. Для хранения
исходных данных HISTORY действуют отдельные лимиты.

STREAM сохраняет порядок и повторы, пока хватает ёмкости. Если при подготовке следующего префикса
заканчивается резерв подписки, SDK отклоняет этот префикс для данной подписки и отражает переполнение
в её состоянии и статистике. TICKER может объединить ожидающие значения одного ключа до доставки.
`getStatistics()` позволяет различить объединение значений и переполнение.

## Получить Greeks

`events::Greeks` содержит цену опциона, волатильность, дельту, гамму, тету, ро и вегу.
Для последних значений вызовите `createSubscription<events::Greeks>()` на endpoint
TICKER. Для истории используйте endpoint HISTORY и
`createTimeSeriesSubscription<events::Greeks>()`. Перед добавлением символов задайте
через `setFromTime()` включительную нижнюю границу в миллисекундах Unix.

Источник индексированного события — DEFAULT. Упакованный индекс хранит секунды
со знаком, миллисекунды и sequence. Флаги содержат признаки снимка и транзакции
HISTORY. Отдельное время события доступно, если peer передал метаданные FIELD.
`getHistorySnapshot()` возвращает последнее наблюдение о полноте диапазона.
Встроенный реестр использует wide-decimal. Для настроенной схемы tiny-decimal
передайте явный реестр с типами полей источника.

## Получить Underlying

`events::Underlying` содержит общую, ближнюю и дальнюю волатильность базового актива,
объёмы call и put и отношение объёмов put к call. Для TICKER используйте
`createSubscription<events::Underlying>()`, для HISTORY —
`createTimeSeriesSubscription<events::Underlying>()` с включительной границей
`setFromTime()`. Источник индексированного события — DEFAULT.

Отсутствующие числовые поля дают NaN. `getOptionVolume()` суммирует доступные объёмы,
возвращает один из них при отсутствии второго и даёт NaN при отсутствии обоих.

## Получить TheoPrice

`events::TheoPrice` содержит теоретическую цену, цену базового актива, дельту,
гамму, дивиденды и процентную ставку. Для TICKER используйте
`createSubscription<events::TheoPrice>()`, для HISTORY —
`createTimeSeriesSubscription<events::TheoPrice>()` с включительной границей
`setFromTime()` в миллисекундах.

Отсутствующие дивиденды и ставка дают NaN. В настроенной неиндексированной схеме
отсутствующий Sequence даёт ноль. Для HISTORY нужна физическая пара Time и
Sequence, задающая координату диапазона. После переподключения endpoint повторно
запрашивает принятый диапазон на новом соединении.

## Получить Trade

Built-in registry добавляет composite Trade2, сохраняя Quote0/Profile1. Используйте owning
`events::Trade` с Java business getters; LONG может отличаться от wide-to-double на1ULP.
Для реального regional Trade&Q передайте явный экспортированный registry с соответствующим
`EventType::TRADE`. Selector AAPL&Q тогда отправляется как physical(Trade&Q,AAPL); простого
переименования символа после generic decoding недостаточно. Полные fields/types/defaults, flags,
packed time и явная граница однослотового TradeId описаны в [Trade](../spec/events/TRADE.ru.md).

```cpp
auto trades = endpoint->getFeed()->createSubscription<q::events::Trade>();
trades->addEventListener([](std::span<const q::events::Trade> batch) {
    for (const auto &trade : batch) {
        std::cout << trade.getTime() << ' ' << trade.getPrice() << ' '
                  << trade.getSizeAsDouble() << '\n';
    }
});
trades->addSymbols({"AAPL"});
```

Runtime/endpoint прогрессируют через SDK; клиент не опрашивает queue или work budgets. Копия Trade
владеет символом и inline snapshot, callback span действует только во время вызова. Непустые наборы зарегистрированных типов с учётом выбранного delivery contract можно
выбирать mixed-подпиской; предел полной receiving-схемы —42 records.

## Явный реестр событий

Для значений по умолчанию настраивать реестр не требуется. Для валидированной
пользовательской `schema` зарегистрируйте явные маршруты записей до создания endpoint:

```cpp
const std::array routes{q::api::EventRegistration{q::api::EventType::QUOTE, 1},
                        q::api::EventRegistration{q::api::EventType::QUOTE, 2}};
q::api::EventRegistryWork work;
auto registry = q::api::EventRegistry::create(schema, routes, {}, work);

if (!registry) {
    // Inspect the typed cause and optional registrationIndex before continuing.
    return 1;
}

q::api::EndpointOptions options;
options.eventRegistry = std::move(*registry);
auto endpoint = runtime.createEndpoint(options);
auto quotes = endpoint->getFeed()->createSubscription<q::events::Quote>();
```

Этот расширенный фрагмент предполагает существующий runtime и подключение `<array>`
и `<utility>` вместе с `qd/api/feed.hpp`. Local record IDs остаются плотными позициями
каталога; пример требует совместимых записей 1/2 после записи 0. Имя записи не
выбирает класс события. Существующие адаптеры разрешают поддержанные явные business
lookup aliases и точные типы, сохраняя иной порядок полей, дополнительные поля и
generic records. Участвуют зарегистрированные composite-записи запрошенного типа;
региональные Quote-маршруты подчиняются выбору exchange ниже.
Повторные маршруты local ID отклоняются, отсутствующий тип отклоняется синхронно.
Для нескольких типов в одной логической подписке используйте перегрузку ниже.

Endpoint копирует неизменяемый владеющий снимок реестра. Последующие присваивание
или уничтожение исходных schema/registry/options не могут заменить его. Создание
имеет явные конечные пределы схемы, маршрутов, allocation requests и работы; оно не
вызывает callbacks приложения, loader или сеть. Receiving profile поддерживает до
42 записи, 284 поля суммарно, 724 lookups, 128 UTF-16 units на имя и 16384 units
всех имён. Реестр, допустимый при больших пределах, отклоняется на `profile-schema`
до native activation; усечения нет. См. полный
[контракт владения, ошибок и пределов реестра](../spec/events/EVENT-REGISTRY.ru.md).

Подготовленные Quote/Profile/Trade/TradeETH/Summary/Message/Configuration используют исчерпывающие
[правила преобразования полей](../spec/events/FIELD-CONVERSIONS.ru.md): допустимые числа
сохраняют WideDecimal поля и предоставляют прямые Java business getters вроде
`quote.getBidPrice()`/`profile.getBeta()` без LONG-to-wide округления. Raw int свойства сохраняют Java physical-slot поведение,
UTF_CHAR_ARRAY/STRING сохраняют nullable UTF-16 текст. Неверные присутствующие типы отвергаются
при подготовке registry. Default registration допускает 128 альтернатив типов; меньшие custom
границы остаются явными resource limits.

Для региональной доставки Quote передайте настоящее проверенное объявление региональной
записи и зарегистрируйте его как `EventType::QUOTE`. Например, если выбранная схема содержит
`Quote&Q`, обычная подписка `quotes->addSymbols("AAPL&Q")` отправляет физический interest
`Quote&Q`/`AAPL`. Принятый владеющий Quote имеет символ `AAPL&Q`; отсутствующие exchange-поля
получают суффикс записи. Правило одинаково для любого зарегистрированного exchange.
Composite и regional interests различаются в смешанной подписке. Совпадающий региональный
маршрут выбирается отдельно для каждого вида событий; иначе composite-маршруты сохраняют
точный логический символ. Завершающие атрибуты сохраняются. Remove и явный reconnect
используют ту же выбранную запись и физический символ.

Выбранный региональный маршрут должен восстанавливать точное логическое написание.
Необратимые формы вроде `AAPL&N&Q` или `AAPL{x=y}&Q` вызывают `INVALID_ARGUMENT` на
`subscription-symbol-representation` из `addSymbols`/`setSymbols`; отклоняется полное
изменение, прежний desired set сохраняется. Composite fallback оставляет эти буквальные
символы без изменений. Обычная форма с атрибутами `AAPL&Q{x=y}` представима.

Встроенный registry содержит composite Quote/Profile/Trade/TradeETH/Summary и оба текстовых события. Этот путь через явный ограниченный
registry не загружает полный региональный каталог и не реализует более широкие selectors.
[Контракт времени и вариантов](../spec/events/EVENT-TIME.ru.md) задаёт необязательные
Sequence/nanoseconds, секунды/миллисекунды Quote, halt-секунды Profile, независимые метаданные
событий и границы детерминированных локальных wire-доказательств. Новых утверждений
о доступности публичного сервиса нет.

## Получение нескольких типов событий

Фрагмент предполагает существующий endpoint и подключение `<type_traits>`:

```cpp
auto mixed = endpoint->getFeed()->createSubscription(
    {q::api::EventType::QUOTE, q::api::EventType::PROFILE, q::api::EventType::QUOTE});
mixed->addEventListener([](std::span<const q::api::RegisteredEvent> batch) {
    for (const auto &event : batch) {
        std::visit([](const auto &value) {
            using Event = std::decay_t<decltype(value)>;
            if constexpr (std::is_same_v<Event, q::events::Quote>) {
                // Read the owning Quote value.
            } else {
                // Read the owning Profile value.
            }
            (void)value;
        }, event);
    }
});
mixed->addSymbols({"AAPL", "IBM"});
```

Создаётся одна `Subscription<RegisteredEvent>` с одним набором символов. Повторы
типов объединяются; зарегистрированные маршруты каждого выбранного типа используют
описанный выше exchange-выбор. Набор типов копируется и остаётся фиксированным для подписки. Массив runtime
можно передать перегрузке `std::span<const EventType>`. Пустой список или неизвестный
enum даёт `INVALID_ARGUMENT`; отсутствие поддержанного типа в реестре endpoint —
`UNSUPPORTED_PROFILE`, без публикации подписки.

`RegisteredEvent` — владеющий variant всех поддержанных зарегистрированных событий, включая TextMessage и TextConfiguration.
Скопируйте значение, чтобы сохранить его после callback span. Конкретные и смешанные
подписки могут независимо перекрываться; закрытие одной отзывает только её оставшиеся
исключительные interests. Границы callback batch следуют очереди; один batch может
содержать не все выбранные типы. См. полный
[контракт смешанного выбора и доставки](../spec/events/MIXED-SUBSCRIPTIONS.ru.md).

### Приём каталога SDK по одному соединению

```cpp
q::api::EndpointOptions options;
options.contract = q::api::DeliveryContract::MIXED;
auto endpoint = runtime.createEndpoint(options);
auto subscription = endpoint->getFeed()->createCatalogSubscription();
subscription->addEventListener([](std::span<const q::api::RegisteredEvent> events) {
    // Consume owning events from any of the three contracts.
    (void)events;
});
subscription->addSymbols("IBM");
endpoint->connect(address);
```

Endpoint согласует TICKER, STREAM и HISTORY в одной QTP-сессии. Обычный Quote
идёт через TICKER, обычный TimeAndSale через STREAM, нативный Order через HISTORY.
Для временных рядов используйте `createTimeSeriesSubscription<Event>()` и
`setFromTime()`. Такая подписка использует HISTORY. Обработчик может получать отдельные
пакеты по каждому семейству. Статистика применения подписки показывает общую
локальную ревизию. Отправка команд и обработка на стороне источника асинхронны.

Для конфигурации через свойства задайте `qdcxx.deliveryContract=mixed`.
Смешанный профиль использует встроенный каталог и точные селекторы.
Пользовательские реестры, wildcard, создание фильтров через endpoint,
проигрывание тейпов и OnDemand используют явные одноконтрактные профили.

## Запрос индексированного снимка HISTORY

На endpoint с HISTORY используйте
`requestIndexedEvents<Event>(symbol, source, deadline)` для отменяемого
запроса по точному типу события, символу и источнику. Для типа с одним
источником используется `IndexedEventSource::DEFAULT`, для обычного
нативного Order — точный ID источника. Запросу нужен один подходящий
нативный маршрут HISTORY. Синтетические ордера и неоднозначные маршруты
выходят за пределы этого профиля.

Запросы сохранённых снимков работают через TCP. После выбора локальной записи
через `connectTape` оба метода сообщают `UNSUPPORTED_PROFILE`. Ожидающий запрос,
принятый до подключения, завершается с той же ошибкой при выборе записи, даже
если воспроизведение остановлено до открытия файла. Обычные подписки HISTORY
могут получать события из записи.

`getIndexedEventsIfSubscribed<Event>(symbol, source)` читает текущий срез
по существующей подписке приложения. Метод различает отсутствие подписки
`NOT_SUBSCRIBED`, неполный срез `INCOMPLETE` и подтверждённый пустой
результат `COMPLETE`. Пассивное чтение обращается к рабочему потоку
с ограниченным ожиданием. Из обработчика этого потока метод возвращает
неполный срез при наличии подписки, поэтому обработчик не ждёт себя.

Запрос может создать одну временную подписку HISTORY. У неё нет обработчиков
событий, и пассивное чтение её не учитывает. Срок, отмена, закрытие endpoint
и смена источника завершают запрос один раз. Слот остаётся занят до завершения
временной регистрации.

Endpoint принимает до `RuntimeOptions::maximumSubscriptionsPerEndpoint`
одновременных запросов, включая запросы с завершающимися временными
регистрациями. Эти регистрации занимают обычные слоты подписок endpoint.
Запросы одного физического ключа делят подписку на проводе. Результат и
отмена у каждого запроса свои. Отмена одного запроса сохраняет интерес
остальных. После привязки к эпохе источника разрыв при автоматическом
восстановлении отменяет запрос. Новый запрос может выбрать следующую эпоху.

Результат владеет событиями и содержит эпоху источника. События упорядочены
по возрастанию знакового индекса, флаги очищены. `TRUNCATED` возвращает
доступные значения, если источник сообщил об отсечении выше запрошенной
нижней границы. `HistorySnapshotOptions::maximumResults` задаёт максимум
элементов. Превышение лимита или исчерпание работы проекции даёт явную ошибку.

## Подключение одной типизированной подписки к нескольким feed

Заголовок `qd/api/independent_subscription.hpp` предоставляет владеющую
`api::IndependentSubscription<Event>`. Обработчик и типизированные селекторы
можно задать до подключения к feed. Каждое подключение занимает один слот
нативной подписки соответствующего feed. Повторное подключение к тому же feed
возвращает прежний идентификатор. Отключение убирает только соответствующую
регистрацию и сохраняет желаемый набор. При следующем подключении выделяется
новый идентификатор.

```cpp
#include "qd/api/independent_subscription.hpp"

#include <array>
#include <span>

// firstFeed and secondFeed are feeds from existing receiving endpoints.
api::IndependentSubscription<events::Quote> quotes(
    [](std::span<const events::Quote> batch) {
        // Process this batch before the callback returns.
    });
const std::array selectors{api::SubscriptionSelector::plain(u"IBM")};
const auto initialRefusals = quotes.setSelectors(selectors);
const auto first = quotes.attach(*firstFeed);
const auto second = quotes.attach(*secondFeed);
quotes.detach(*firstFeed);
```

Разные feed могут одновременно доставлять в том числе одинаковые события
из разных источников. Общие данные обработчика требуют синхронизации.
Отключение прекращает новый отбор вызовов для этого подключения. Уже отобранный
вызов может завершиться. Обработчик может отключить свой feed изнутри вызова.
Закрытие навсегда прекращает отбор по всем подключениям и запрашивает завершение
нативных регистраций без ожидания обработчиков.

`setSelectors` сначала принимает ограниченный желаемый набор локально, затем
передаёт его каждому текущему подключению. Последнее вхождение селектора
с данным идентификатором задаёт его действующие атрибуты. Синхронный отказ
содержит идентификатор подключения и сохраняет прежний желаемый набор
соответствующего feed. Последний локальный набор доступен при новых подключениях
и повторных попытках. Каждая нативная регистрация применяет собственные
возможности и лимиты. Последующий нативный сбой можно узнать через
`getAttachmentDiagnostic(feed)`. Сервер применяет изменения по каждому
соединению независимо.

По умолчанию поддерживаются четыре активных подключения с учётом ещё
завершающихся обработчиков, 16 аргументов-селекторов и 128 кодовых единиц UTF-16
на символ. Ёмкости задаются через `IndependentSubscriptionLimits`. Отключённое
подключение может занимать независимый слот до завершения уже отобранной
доставки. Нативный слот feed может оставаться занятым до завершения регистрации,
в том числе пока runtime ждёт первого соединения.

### Очистка представления отключённого подключения

Создайте подписку через
`IndependentSubscription<Event>::withAttachmentListener(onData, onClear)`,
чтобы хранить представления по идентификатору подключения. Обработчик
`onData(id, batch)` получает события конкретного подключения. При успешном
`detachAndClear(feed)` обработчик `onClear(id)` может удалить всё
представление по этому идентификатору. Он должен быть объявлен `noexcept`.
Новое подключение к тому же feed получает новый идентификатор, поэтому
отложенная очистка может выполняться одновременно с новой доставкой.

`detachAndClear` прекращает новый отбор данных для удалённого подключения
и запрашивает завершение его нативной регистрации. Если вызовы обработчика
не были отобраны, очистка выполняется синхронно. В остальных случаях она
выполняется один раз после выхода из последнего отобранного вызова, в том
числе если он сам запросил отключение или завершился исключением. Операция
не ждёт завершения обработчиков. Последующее закрытие сохраняет уже принятую
очистку. Повторный вызов для отключённого feed возвращает false и не отправляет
новое уведомление.

Java описывает очистку как публикацию пустых событий. Обработчик C++ получает
точный идентификатор для очистки представления. Значения событий, исходные
времена, кэши endpoint и желаемый набор селекторов сохраняются. Для конструктора
с обработчиком без идентификатора вызов на подключённом feed возвращает
`UNSUPPORTED_PROFILE` через исключение до удаления подключения.
Обычные `detach` и `close` обходятся без уведомлений об очистке.

## Runtime, обработчики и завершение

Создавайте владеющий `ApiRuntime(RuntimeOptions)` на главном потоке **до потоков
приложения**; они должны завершиться до его уничтожения. Хост, заранее создавший
`RuntimeBootstrap` на главном потоке до запуска потоков, позже может вызвать явный
заимствующий конструктор на том же создавшем потоке, сохраняя владельца хоста.
Обе формы удерживают bootstrap lease до уничтожения самого объекта runtime,
включая период после закрытия. Worker лениво запускается при первом принятом
`connect()` и обслуживает endpoint одного runtime. Согласуйте всех пользователей
того же состояния c-ares. См. [контракт встраивания и владения](../spec/transport/RUNTIME-EMBEDDING.ru.md).

Уничтожайте runtime в создавшем его потоке. Он не копируется и не перемещается.
`Endpoint::closeAndAwaitTermination()` и `ApiRuntime::closeAndAwaitTermination()`
разрешены только в этом потоке. Другой поток, включая обработчик, получает
`ErrorCode::WRONG_THREAD` до ожидания. Нарушение требования к потоку деструктора
runtime завершает процесс.

Повторный await из деструктора освобождаемого захвата обработчика (включая циклы
между endpoint), а также await runtime при освобождении захватов или рекурсивном
shutdown отклоняется с `ErrorCode::INVALID_STATE`.

Producer-методы endpoint и подписки можно вызывать из обработчиков. `close()`
запрашивает завершение без ожидания; исчерпание обычной ёмкости не блокирует этот
запрос. Освобождение endpoint/подписки запрашивает закрытие; завершением продолжает
владеть runtime. Дескрипторы могут пережить runtime как закрытые отсоединённые
порты и не удерживают нативный рабочий поток.

После полного завершения запросы состояния/диагностики и освобождение последней
ссылки на терминальный дескриптор разрешены на другом потоке. `awaitState` остаётся
привязанным к создавшему потоку даже при уже достигнутом терминальном состоянии;
закрытая подписка отклоняет новый приём с `CLOSED`. Дескрипторы не удерживают lease
SDK и не могут возобновить native-работу после уничтожения runtime. Сохранённая
native-ошибка остаётся `FAILED` с исходной диагностикой, а не превращается в успешное `CLOSED`.

Event listeners вызываются последовательно для каждой подписки, по умолчанию на SDK worker.
Явная [event executor policy](CALLBACK-EXECUTION.ru.md) заимствует application workers с сохранением
serial selection, actual completion accounting и source-epoch fences. Span действителен только
до возврата из вызова; скопируйте событие, чтобы сохранить владеющие строки и значения.
Такие копии не удерживают очередь или runtime; хранение копий приложением не входит
в конечные резервы библиотеки. Не блокируйте обработчики надолго: это задерживает
другие endpoint и завершение. Deadline drain и деструктор не могут прервать код
приложения и не обещают жёсткой границы времени завершения операций ОС.

Исключение обработчика событий переводит его подписку в ошибку `CALLBACK_FAILURE`.
Вызов не повторяется, другие подписки продолжают работу. Удаление обработчика
запрещает будущий выбор, но уже выбранный вызов может завершиться. Захваты
обработчиков освобождаются вне управляющих блокировок. Ожидание закрытия endpoint
подтверждает завершение вызовов и освобождение захватов.

`CloseResult::drained` описывает реально принятый локальный префикс. Проверяйте также
`deadlineExpired`, `hadGap` и `diagnostic`. Результат не подтверждает ACK источника,
полноту ещё не прочитанных сетевых данных или непрерывность истории upstream.

## Подключение с проверкой TLS

Соберите `qdcxx_feed` с `ORG_TTLDTOR_QDCXX_BUILD_TLS=ON` и квалифицированной
статической сборкой SDK. Перед созданием endpoint задайте `EndpointOptions::tls`
владеющим значением `VerifiedTlsOptions`. Передайте полный набор доверенных
сертификатов в PEM, проверяемое имя DNS SAN или числовой адрес IP SAN, конечные
сроки рукопожатия и закрытия, лимиты ресурсов и параметры контролируемого
приложения. Маршрут в `connect` по-прежнему имеет вид `host:port` или
`[IPv6]:port`. Проверка и DNS SNI используют заданное имя, которое может
отличаться от маршрута. Разрешение маршрута использует настройки DNS runtime.

Для расчёта двух бюджетов SDK вызовите `transport::tlsRequirements` из TLS-цели.
`residentBytes` также покрывает адаптер, сохранённую конфигурацию и резервы
транспорта и сессии. До завершения работы endpoint приложение контролирует
всех пользователей того же экземпляра SDK, включая заявленные лимиты потоков,
контекстов и истории неудачной инициализации. См. [профиль ресурсов](../spec/transport/TLS-RESOURCES.ru.md).

SDK копирует настройки, проверяет сервер перед доставкой QTP, соблюдает конечное
число попыток и возвращает статические диагностики. Профиль исключает переход
на открытый TCP и обращение к системному хранилищу доверия. Сборка
Feed с выключенным TLS отклоняет параметр с `UNSUPPORTED_PROFILE`. Текстовые
свойства endpoint этот параметр не принимают. Endpoint с TLS отклоняет выбор
локальной записи и OnDemand через открытый HTTP на loopback.

### Авторизация QTP Basic

Задайте `VerifiedTlsOptions::credentials` значением `BasicTlsCredentials` с
разделяемым `client::CredentialProvider`. Провайдер записывает полный токен с
префиксом `Basic ` в заимствованный буфер UTF-16 и возвращает длину записи.
Ёмкость буфера составляет 7–1024 кодовые единицы вместе с префиксом. Отсчёт
положительного срока авторизации начинается после проверки сервера. Вызов
происходит на последовательном рабочем потоке Feed, поэтому провайдеру нужно
быстро возвращать результат. При совместном использовании провайдера несколькими
endpoint защищайте изменяемое состояние приложения.

Feed вызывает провайдер не более одного раза за проверенную попытку, в которой
сервер прислал запрос аутентификации QTP. Вызов выполняется вне управляющих
блокировок Feed. Если отключение, переподключение, очистка или закрытие успели
заменить попытку до постановки подготовленного ответа в очередь, Feed отбрасывает
этот ответ. Байты, уже принятые в очередь прежней попытки, могли дойти до сервера.
Доставка данных ждёт явного подтверждения аутентификации от сервера. Срок
авторизации продолжает отсчитываться, пока сервер не запросил или не подтвердил
аутентификацию. Данные, полученные до подтверждения, переводят endpoint с
провайдером в состояние ошибки. Конфигурация, диагностика и статистика не содержат
текст токена или исключения провайдера. Гарантии безопасного стирания токена нет.

Для смены учётных данных обновите состояние общего провайдера под блокировкой
приложения, затем вызовите `reconnect()` у активного endpoint. Действует прежний
конечный лимит попыток. В новой TLS-сессии Feed заново проверяет сервер и вызывает
провайдер только в ответ на запрос QTP этой сессии. Само изменение состояния
провайдера не меняет установленную сессию. Если сервер отклоняет ответ новым
непустым запросом аутентификации, endpoint завершает работу с
`tls-authentication-denied` без повторной попытки. Для входа с исправленными
данными после этого отказа создайте новый endpoint.

## Историческое воспроизведение OnDemand через loopback

На новом endpoint со стандартным TICKER можно воспроизвести один конечный
ответ OnDemand через IPv4 loopback. До подключения создайте обычную подписку
Quote и добавьте точный композитный символ.

```cpp
using namespace std::chrono;
auto endpoint = runtime.createEndpoint();
auto quotes = endpoint->getFeed()->createSubscription<q::events::Quote>();
quotes->addEventListener(onQuotes);
quotes->addSymbols("MOCK");
endpoint->connectOnDemand(mockPort, u"MOCK", sys_days{2024y / February / 12} + 14h + 30min + 5s);
const auto completion = endpoint->awaitState(q::api::EndpointState::CLOSED, steady_clock::now() + 70s);
const auto closed = endpoint->closeAndAwaitTermination();
```

Результат `completion` сообщает о `CLOSED`, терминальном `FAILED` или истечении
ожидания. `closed` подтверждает завершение работы и содержит диагностику сбоя. Источник
переходит в `CONNECTED` после проверки полного ответа, покрывающего
запрошенное время. Первые записи до этой точки включительно подаются
с обычным объединением TICKER. Остальные по умолчанию воспроизводятся
на скорости 1× по монотонным часам с момента готовности доставки. Каждая
котировка сохраняет время события из записи. По окончании
ответа endpoint завершает принятую работу и закрывается. Закрытие во
время запроса завершает работу сокета и прекращает приём записей.

Профиль принимает один несжатый блок композитного Quote одним
запросом HTTP/1.1 POST к `/MarketDataReplay` на явно указанном
loopback-порту. Символ содержит до 16 латинских букв ASCII, цифр и точек,
из них хотя бы одну букву. Запрос использует бинарный формат Java QD v2
с синтетическими полями доступа. На весь сетевой запрос даётся пять секунд,
при этом действуют меньшие тайм-ауты endpoint. Источник планирует проверку
сети и завершения не реже раза в 10 мс. Ответ должен содержать один
`Content-Type: application/octet-stream` и один положительный `Content-Length`.
Пределы составляют 2 КиБ заголовков, 8 КиБ тела и 64 записи. Ответ может
покрывать не более 60 секунд после запрошенного момента. Источник отклоняет
перенаправления и кодирование HTTP, сжатые блоки, неподдерживаемые символы
и схемы, повреждённые либо слишком большие кадры и ответ вне запрошенного
времени. HTTP 401 даёт статическую диагностику `ondemand-access-refused`.
Для профиля проверен синтетический локальный сервис. Доступ к внешнему
поставщику и его данным, защищённый HTTP, дополнительные окна и перемотка
квалифицируются отдельно. [Генератор фикстур и локальная проверка](../tools/upstream/ondemand-oracle/README.ru.md)
воспроизводят проверенные байты протокола и сценарии жизненного цикла.

Начальную скорость можно передать четвёртым аргументом `connectOnDemand`.
Для открытого источника скорость меняет `setOnDemandSpeed(rate)`.
Допустимы конечные значения от 0 до 100×, в том числе дробные.
`pauseOnDemand()` запрашивает нулевую скорость. При нуле записи до текущей
позиции курсора включительно по-прежнему могут поступить в подписку, и
endpoint сохраняет исторический кэш. Последующие записи ждут положительной
скорости. HTTP и закрытие работают во время паузы. Рабочий поток сначала
учитывает время на прежней скорости, затем применяет последнее значение.
Эпоха источника сохраняется.

`getOnDemandPlayback()` возвращает последнюю применённую скорость, позицию
исторического курсора и признаки активного режима и подтверждённого покрытия.
До ответа может примениться новая скорость, а курсор остаётся на запрошенной
точке. После закрытия доступна последняя позиция с нулевой скоростью.
`addOnDemandPlaybackListener` регистрирует обработчик, который получает пары
предыдущего и нового состояния последовательно на рабочем потоке SDK,
независимо от исполнителя событий. В одной паре сначала учитывайте скорость,
затем время. При одинаковых наблюдениях уведомления нет. Из обработчика можно
запрашивать паузу, вызывать неблокирующий `close()` и удалять себя. Исключение
доступно через `getOnDemandPlaybackDiagnostic()`.

Вызов `stopOnDemandAndClear()` завершает историческую доставку и очищает
сохранённые значения. Те же объекты Feed и подписок остаются открытыми
и сохраняют символы и обработчики. Очистка завершается в состоянии
`NOT_CONNECTED` без нового подключения. Вызов
`stopOnDemandAndResume(liveAddress)` запускает явно заданный обычный маршрут
QTP после закрытия исторического сокета и завершения выбранных обработчиков.
Его можно вызвать и после очистки. Последний исторический курсор доступен
с нулевой скоростью. Live-источник устанавливает собственную эпоху и
передаёт свежие события. При истечении срока перехода возвращается
`ON_DEMAND_TRANSITION_TIMEOUT`, подключение live не запускается.

## Локальный файл записи

Создайте endpoint с нужным `DeliveryContract`, настройте обычные
типизированные подписки и слушателей, затем вызовите `endpoint->connectTape(path)`.
Runtime открывает и читает обычный файл на рабочем потоке. Для успешного
завершения дождитесь `EndpointState::CLOSED`, затем вызовите
`closeAndAwaitTermination()`, чтобы дождаться освобождения ресурсов callback.
Вызов `closeAndAwaitTermination()` до EOF запрашивает досрочную остановку.

Во время воспроизведения TICKER API последних событий читает сохранённые
значения обычных подписок. После EOF или явного закрытия эти значения недоступны.

`TapeSourceOptions` задаёт пределы файла, относительную скорость и начальную
паузу. Для удвоенной скорости передайте
`{.playback = TapePlaybackPolicy::SOURCE_TIME, .speedPercent = 200}`. Вызов
`endpoint->setTapePaused(true)` приостанавливает приём, а `setTapePaused(false)`
возобновляет его. Пока источник подключён, `endpoint->restartTape()` открывает
тот же файл с нулевого байта, сохраняя подписки. `endpoint->stopTape()`
запрашивает окончательное закрытие. После завершения для нового проигрывания
создайте новый endpoint.
[Форматы, доставка и ошибки локального файла](../spec/protocol/FEED-TAPE-SOURCE.ru.md).

## Наблюдатели состояния

Зарегистрируйте наблюдателя endpoint или подписки до нужных переходов:

```cpp
const auto listener = endpoint->addStateChangeListener(
    [](q::api::EndpointState previous, q::api::EndpointState current) {
        // Observe the transition; keep this callback short.
        (void)previous;
        (void)current;
    });
endpoint->removeStateChangeListener(listener);
```

Те же методы `Subscription<Event>` используют `SubscriptionState`. Регистрация
**не вызывает начального уведомления**; `getState()` отдельно возвращает текущий
снимок. Наблюдатели получают различные фактические старое и новое состояния
в порядке публикации, включая ошибку и терминальное состояние. Полный снимок
наблюдателей выбирается атомарно с переходом; вызовы идут в порядке регистрации
вне управляющих блокировок. Удаление запрещает будущий выбор; уже выбранный вызов
может состояться. Удаление идемпотентно и доступно после close. Добавление после
отсечения приёма отклоняется с `CLOSED`; обычная ёмкость не блокирует close.

После первого `connect()` этого runtime вызовы выполняет SDK worker. Если runtime
ещё не запускал worker, завершение endpoint/runtime в создавшем потоке вызывает
наблюдателей состояния без запуска worker. Из обработчика можно читать состояние,
вызывать close, удалять наблюдателей и работать с другим endpoint. Await из worker
отклоняется с `WRONG_THREAD`; повторный await того же endpoint или runtime из
создающего потока при завершении отклоняется с `INVALID_STATE`. Разные неактивные
endpoint могут завершаться рекурсивно; завершение неактивного endpoint в создающем
потоке может идти одновременно с worker другого активного endpoint.

Наблюдатели состояния носят уведомительный характер. Если один бросает исключение,
вызывается весь выбранный снимок. `getStateChangeDiagnostic()` отдельно сохраняет
первую статическую ошибку `CALLBACK_FAILURE`; состояние владельца, `getDiagnostic()`
и `CloseResult` не меняются. `CLOSED` и `FAILED` остаются поглощающими. Как и раньше,
`CLOSED` подтверждает завершение нативной регистрации и освобождение всех захватов
**обработчиков событий**. Только новые явно добавленные наблюдатели состояния ещё
могут выполняться или освобождать захваты; await endpoint включает обе категории
до возврата и освобождения слота runtime.

Отдельные положительные лимиты `maximumStateListenersPerEndpoint` и
`maximumStateListenersPerSubscription` учитывают принятые, выбранные и завершаемые
объекты наблюдателей. Удаление освобождает ёмкость лишь после последнего выбранного
вызова и уничтожения захватов приложения. Очередь состояний не растёт с переходами:
первый опубликованный producer-потоком `CONNECTING` занимает один отложенный слот,
а остальные наблюдения сразу доставляются владеющим контекстом исполнения.
Синхронный отказ запуска worker не публикует переход и не вызывает наблюдателя
в producer-потоке. См. [полный контракт](../spec/subscriptions/FEED-STATES.ru.md).

## Принятые изменения и ошибки

`addSymbols`, `removeSymbols`, `setSymbols` и `clearSymbols` асинхронно принимают
ограниченное желаемое состояние. Дубликаты объединяются; `setSymbols({})` отзывает
все интересы. Возврат producer-вызова не означает отправку ADD/REMOVE или ACK peer.
У подписок независимые интересы и доставка, в том числе для пересекающихся символов.

Синхронный отказ бросает `api::Error`; `diagnostic()` содержит независимые статические
и числовые сведения. `getState()` и `getDiagnostic()` endpoint/подписки показывают
последнее зафиксированное состояние и первую асинхронную ошибку. Для продвижения
соединения и доставки приложению не требуется polling.

`connect()` принимает ASCII `host:port` или `[IPv6]:port`. Первый принятый адрес
фиксируется; повтор того же адреса при логически включённом подключении ничего
не меняет. После `disconnect()` тот же адрес возобновляет работу в свежей эпохе. Другой
адрес или попытка подключить закрытый/ошибочный endpoint отклоняются. Автоматические
конечные переподключения используют политику endpoint. Селекторы — непустые точные
строки printable ASCII в пределах лимита runtime, без ведущего `*` и wildcard/All.

`disconnect()` немедленно публикует `NOT_CONNECTED`, сохраняя желаемые интересы и
спроецированный кэш. После физической quiescence паузы новые/изменённые подписки
могут получить этот кэш. `reconnect()` запрашивает свежую эпоху при логически
включённом подключении; после явного disconnect ничего не делает.
`disconnectAndClear()` немедленно запрещает новый выбор старых данных и запрашивает
асинхронную настоящую очистку, в том числе при уже отключённом endpoint.
`NOT_CONNECTED` не является барьером завершения clear. Уже выбранный снимок
listeners может завершиться; собственные копии событий действительны. Управление
не пополняет конечные попытки/работу. См.
[полный контракт lifecycle и admission](../spec/subscriptions/FEED-LIFECYCLE.ru.md).
## Конечные значения по умолчанию

Настройте `RuntimeOptions` до создания runtime и `EndpointOptions` до создания
endpoint. Лимиты учитывают ожидающие, активные и завершающиеся объекты. Это логические
резервы, а не предел RSS процесса. Увеличение лимитов может потребовать значительной
памяти; неподдержанное вычисление ёмкостей завершается явным отказом.

| Runtime option | По умолчанию |
| --- | --- |
| `maximumEndpoints` | 4 |
| `maximumSubscriptionsPerEndpoint` | 8 |
| `maximumSymbolsPerSubscription` | 16 |
| `maximumListenersPerSubscription` | 4 |
| `maximumStateListenersPerEndpoint` | 4 |
| `maximumStateListenersPerSubscription` | 4 |
| `maximumEventTypeArgumentsPerSubscription` | 64 исходных аргумента типов, включая повторы; положительное |
| `maximumPendingStateChangesPerEndpoint` | 8; ожидающие/исполняемые/освобождаемые снимки |
| `maximumSymbolUnits` | 128; настраивается в 1..128 |
| `dnsServers` | Пусто: до 4 системных IPv4-адресов DNS-серверов |
| `dnsPort` | 53 |

| Endpoint option | По умолчанию |
| --- | --- |
| `contract` | `TICKER` |
| `eventRegistry` | Отсутствует: встроенные Quote0/Profile1/Trade2/TradeETH3/Summary4/TextMessage5/TextConfiguration6; явное значение копируется как неизменяемый снимок |
| `connectTimeout`, `dnsTimeout`, `writeTimeout` | По 5000 мс |
| `readTimeout` | 30000 мс |
| `pollInterval` | 1 мс |
| `maximumAttempts` | 3 всего, включая первую попытку |

| `drainTimeout` | 1000 мс |

Лимиты количества должны быть положительными. Deadline и период продвижения endpoint
задаются положительными миллисекундами до `INT_MAX`; retry delay положителен при числе
попыток больше одной. Конечное время drain может истечь с переходом к abort; это
не жёсткий timeout блокирующего await.

## Настройка DNS

Пустой `RuntimeOptions::dnsServers` считывает ограниченный системный снимок при
создании runtime: Windows `GetNetworkParams`, Linux `/etc/resolv.conf`. Сохраняются
до четырёх уникальных пригодных IPv4-адресов DNS-серверов в порядке платформы.
Ошибка обнаружения или отсутствие таких адресов даёт `DNS_CONFIGURATION`;
публичный DNS-сервер автоматически не подставляется. Снимок считывается даже для
будущего числового адреса endpoint; после создания числовой маршрут обходит lookup.

Для явной настройки добавьте в `dnsServers` от одного до четырёх ненулевых числовых
IPv4-адресов `transport::DnsServer` и при необходимости задайте `dnsPort` (1..65535).
Например, если адрес DNS-сервера получен из настроек вашей сети:

```cpp
q::api::RuntimeOptions options;
options.dnsServers.push_back(q::transport::DnsServer{{192, 0, 2, 53}});
q::api::ApiRuntime runtime(options);
```

`192.0.2.53` — адрес-заполнитель документации; замените его реальным DNS-сервером.
Эта настройка выбирает транспорт DNS-сервера, а не TLS или политику символов/доставки.

## Ожидание текущего состояния

`endpoint->awaitState(target, deadline, stopToken)` и
`subscription->awaitState(target, deadline, stopToken)` блокируют только
поток-создатель runtime без опроса и выполнения native-работы.
`StateWaitResult<State>` возвращает текущее состояние и первую диагностику
жизненного цикла. Приоритеты условий заданы явно: целевое `REACHED`, другое
поглощающее `TERMINAL` (`CLOSED`/`FAILED`), `CANCELLED`, затем `DEADLINE_EXPIRED`.
По умолчанию срок равен steady-clock `max()`, stop token пустой. Прошедший переход
не запоминается.

Чужие потоки/SDK callbacks получают `api::Error` / `WRONG_THREAD`; любой контекст
callback/освобождения захватов на потоке-создателе получает `INVALID_STATE`,
в том числе для другого объекта и уже совпавшего состояния. Неверное значение enum
даёт `INVALID_ARGUMENT`. Проверки предшествуют быстрому возврату готового результата.
Ожидание состояния не меняет жизненный цикл и не расходует ёмкость наблюдателей.
`awaitState(CLOSED)` может вернуться до освобождения подключённых наблюдателей
состояния; полный барьер quiescence — `closeAndAwaitTermination()`.
См. [результаты ожидания, отмену и время жизни обработки сигналов](../spec/subscriptions/FEED-WAITS.ru.md).

## Наблюдение принятых подписок и query classifiers

`getSnapshot()` копирует одну полную принятую desired revision, точные типизированные логические selectors и неизменяемый нормализованный набор event types. Результат переживает мутацию и завершение runtime. `getEventTypes()` и `containsEventType()` читают этот неизменяемый набор. Accepted revision отличается от worker application, физического спроса и peer acknowledgement.

`addChangeListener()` сообщает начальное непустое состояние и committed REMOVED/ADDED phases. Replace сначала удаляет, затем добавляет с одной ревизией. Callback заимствует аргументы; для независимого хранения копируйте `change.snapshot` или selectors. Вызовы происходят вне control locks. Reentry и concurrent calls используют конечное after-return continuation, включая разные runtime и выход всего выбранного data callback. Caller не опрашивает состояние, не управляет очередями и не продвигает сеть.

Observer exceptions являются advisory и доступны через `getChangeDiagnostic()`; прежняя политика ошибок event listeners сохраняется. `close()` остаётся nonblocking fence. Фактический worker retirement либо creator `closeAndAwaitTermination()` доставляет terminal CLOSED и включает выбранные callbacks и разрушение captures. Перед зависимостью от native timing differences относительно Java прочитайте точный [контракт observation/lifetime/budgets](../spec/subscriptions/OBSERVABLE-SUBSCRIPTIONS.ru.md).

`Endpoint::createFilter(orderedCategories, context)` строит независимый classifier с фактическим registry и delivery contract endpoint; advanced builder также принимает явный registry и finite limits. Он не меняет subscription demand. Optional context задаётся один раз для явных resource capabilities. [Filter queries, categories, trackers и владение IPF source](FEED-FILTERS.ru.md) описывают отдельные lifetimes и optional backend.

Installed/relocated [public consumer](../tests/conformance/subscription_observer_consumer/CMakeLists.txt) собирается только через `find_package(qdcxx CONFIG REQUIRED COMPONENTS feed)` и `qdcxx::feed`. Он независимо включает каждый публичный header и проверяет detached snapshots, callback phases, classifier queries, refusal и offline retirement без private headers и source paths.

## Статистика endpoint

`endpoint->getStatistics()` копирует последнюю согласованную публикацию в
владеющий `EndpointStatistics`. Чтение разрешено параллельно из потоков producer
и после завершения runtime. `ownerIdentity` удерживает только ограниченный
непрозрачный токен; сравнивайте его на равенство, не интерпретируя адрес. Разные
владельцы не совпадут, пока сохранено старое наблюдение. `generation` остаётся
равным единице в течение жизни владельца. `observedAt` — монотонное время
публикации, а не чтения. Чтение не выделяет память, не выполняет IO/DNS, не вызывает
callback и не сбрасывает работу. Заблокированный callback задерживает следующую
публикацию; читатели продолжают видеть предыдущий согласованный срез.

Поля `connection` разделяют физический IO ОС и завершение протокола.
`readBytes`/`writtenBytes` учитывают положительные результаты native receive/send
и completion, включая частичные передачи и впоследствии отброшенный вход. В plain
Feed TCP это октеты потока QTP. Полный структурно принятый входной кадр увеличивает
`readMessages` до обработки payload, поэтому отвергнутый payload тоже даёт один
кадр. DATA учитывается после проверки всего payload и построения события, включая
wire records, пропущенные локальной привязкой схемы, до проекции и fan-out.
Исходящие сообщения и записи ADD/REMOVE учитываются после принятия сокетом
последнего байта кадра. Очередь и desired selectors ничего не добавляют; реальный
replay считается повторно. Принятие сокетом не доказывает peer acknowledgement.
При неизвестном префиксе прерванной Windows write sticky `writeAcceptanceUnknown`
обозначает число байтов как нижнюю границу; полные кадры считаются по сообщённому
прогрессу.

`connectionAttempts` считает реальные входы в recovery factory, включая ошибки
DNS/connect. `attemptIdentity` — текущий порядковый номер factory этого владельца;
без владельца попытки значение отсутствует. `sourceEpoch` — номер установленного
источника; до установления и после retirement он отсутствует. Для ненасыщенных
итогов `establishedConnections = closedConnections + activeConnections`;
готовность протокола — отдельное состояние. Reconnect меняет источник, сохраняя
итоги и generation. Baseline — независимая копия потребителя; разрушительного
reset и метода расчёта скорости нет.

Каждый `StatisticCounter` содержит собственный `availability`. Доступные счётчики
в простое равны нулю; переполнение насыщается до `UINT64_MAX` со sticky `SATURATED`,
после чего точные дельты этого поля недоступны. Входящие подписки, исходящий DATA
и QD lag/RTT сейчас возвращают `UNSUPPORTED`. Метки событий и длительность callback
не заменяют wire timing. В TLS счётчики байтов учитывают шифротекст на уровне
сокета, включая рукопожатие. Счётчики сообщений и записей QTP возвращают
`UNSUPPORTED`. Установленные источники и их эпохи учитываются после проверки TLS.

Native итоги сохраняются после возврата всех собственных completion. `final`
становится true лишь после retirement native, listeners и callable captures,
включая наблюдателей изменений подписки и состояния; после этого итоги и время неизменны.
Само CLOSED не является этим барьером. Сохранённый снимок не удерживает сокеты,
схемы, callback или runtime. Полный [послойный контракт](../spec/subscriptions/CLIENT-STATISTICS.ru.md).

[Конфигурация endpoint](ENDPOINT-CONFIGURATION.ru.md): явные адреса/свойства, неизменяемые снимки, эффективные локальные значения и границы совместимости Java.

## Статистика подписки

`subscription->getStatistics()` возвращает detached `SubscriptionStatistics` под
одним mutex учёта подписки. Реальные переходы collector/FIFO admission, selection,
cleanup и пользовательских вызовов обновляют этого же владельца. Чтение не выделяет
память, не выполняет IO, dispatch, reset и не ждёт callback. Пользовательский код
работает вне mutex учёта и управления. Для `ownerIdentity`, `generation`, `observedAt`
и `final` действуют описанные выше правила endpoint; чтения двух владельцев дают
разные cuts. `sourceEpoch` — последний наблюдённый установленный источник endpoint,
отсутствующий при неактивном соединении. Lifetime итоги и старые pending события
переживают смену источника без изменения внутреннего provenance. Final ждёт retirement
event, state и change-observer captures вместе с деструкторами; затем значения и время
замораживаются.

`desiredSelectors` считает принятые логические селекторы один раз независимо от типов
событий и квалифицируется `desiredRevision`. `activeSelectors` публикуется только после
полного фактического source mapping commit, с `activeDesiredRevision` и наблюдённым
`sourceEpoch`. Pending/failed mapping не объявляет следующую команду active; последующий
submit не переименовывает старый mapping candidate. Unchanged команды сохраняют
физический mapping и публикуют собственную логическую квалификацию. После фактического
clear/reset mapping и retirement active selectors ноль, active revision отсутствует.
Это локальное применение, не peer acknowledgement.
`queueCapacityEvents` — реально зарезервированные FIFO slots плюс pending slots TICKER
view; до native регистрации ноль. Это slots, не свободная ёмкость или память процесса.
`pendingEvents` включает pending значения source view и detached FIFO события;
`inFlightEvents` охватывает полный выбранный вызов адаптера, включая блокировку listener.

До насыщения выполняется lifetime равенство:

```text
admittedEvents = deliveredEvents + conflatedEvents + discardedEvents +
                 callbackFailedEvents + evictedOverflowEvents + pendingEvents + inFlightEvents
droppedEvents = rejectedOverflowEvents + evictedOverflowEvents
```

Совпадение одного события с двумя подписками даёт admission каждой. Fanout listeners
не умножает admission или delivered events. `deliveredEvents` требует нормального
завершения всей выбранной группы listeners. Отсутствие listeners, отказ projection,
source/clear fence и отмена относятся к `discardedEvents`. Исключение listener относит
весь выбранный batch один раз к `callbackFailedEvents`, даже если предыдущий listener
его видел; оставшиеся queued события discarded. Close может подавить ещё не начатые
вызовы, не объявляя dispatch завершённым.

`droppedEvents` считает только известный overflow. STREAM отклоняет входящие
per-registration FIFO candidates; TICKER может потерять уже admitted source-view
candidates как overflow victims. Замещённые pending TICKER значения относятся к
`conflatedEvents`, не dropped. Equal/filtered input и неклассифицированная потеря общего
STREAM source не превращаются в выдуманные admission/drop подписки: сохраняются
существующие gap/unknown-eligibility diagnostics для нематериализованной потери.

`callbackCalls`/`callbackFailures` считают реальные вызовы/исключения event listeners.
`callbackDurationSamples`, `callbackDurationTotal` и `callbackDurationMaximum` измеряют
завершённые вызовы steady clock в наносекундах, включая исключения и блокировки;
queue wait, state/change observers исключены. До завершения первого вызова timing имеет
`NO_SAMPLE`. Переполнение count/sum насыщает отдельное поле со sticky availability;
чтение и reconnect никогда не сбрасывают итоги.

[Серверная агрегация](SERVER-AGGREGATION.ru.md): отдельные local request и peer report, bounded descriptor updates и явный UNKNOWN.

## Наблюдения диапазонов HISTORY

`Feed::createTimeSeriesSubscription<Event>()` использует тот же владеющий facade подписки с
`getFromTime()`/`setFromTime(ms)` и начальным знаковым64 MAX. Нужны проверенный native time-series
mapper и явно выбранный HISTORY endpoint. Поддерживаются Candle, TimeAndSale, NuamTimeAndSale,
Greeks, Underlying и TheoPrice; неподдерживаемые типы отклоняются до регистрации. Обычные подписки
отклоняют операции диапазона. Принятые range/set/revision и observer snapshots меняются вместе;
SDK применяет demand и снимает устаревшую HISTORY доставку, которая ещё не началась.
Границы capability, callback BEGIN, конечного work, пересечений, output refusal и recovery описаны
в [контракте живых диапазонов HISTORY](../spec/subscriptions/LIVE-HISTORY-RANGES.ru.md).

Выбирайте `DeliveryContract::HISTORY` явно. Worker владеет collector, независимыми views, replay и ACK reset. `Subscription<Event>::getHistorySnapshot()` возвращает пассивный владеющий срез AS-OF; getter не выполняет I/O и не ждёт callback. Current completion требует настоящих данных о доставленном диапазоне и соответствия принятым logical/source/clear/callback fences. Стандартный реестр HISTORY из SDK включает перечисленные выше индексируемые семейства событий. Подписки без маршрута HISTORY отклоняются до native-регистрации. См. [поля Order, source-селекторы и владение](ORDER.ru.md) и [MarketMaker и производный Order](MARKET-MAKER-ORDER.ru.md). Точные состояния, конечные storage limits и сырые индексируемые координаты описаны в [контракте HISTORY](../spec/subscriptions/HISTORY-RECEIVING.ru.md).

## Чтение последнего сохранённого события

`Feed::getLastEvent(quote)` возвращает независимую копию последнего принятого
значения TICKER для типа события и символа. Если актуального значения в кэше
нет, переданное событие возвращается без изменений. Вызов
`getLastEventIfSubscribed<events::Quote>("IBM")` отличает отсутствие точной
подписки от ожидания данных для подписанного символа. Во втором случае
результат содержит запрошенный символ и значения полей C++ по умолчанию.
Например, поля биржи покупки и продажи в региональном Quote равны нулю
до появления значения от источника. Wildcard не считается точной подпиской.
На endpoint STREAM и HISTORY эти методы не возвращают значения.

Чтение обращается к коллектору даже при отсутствии слушателей, во время
локальной агрегации и при задержке в пользовательском executor. После
обычного отключения кэш снова доступен, как только источник завершит работу.
Принятые очистка, повторное подключение, удаление символа или закрытие
сразу исключают затронутые значения. Возвращённая копия остаётся доступной
после очистки кэша и закрытия endpoint.

Чтение использует существующий поток runtime. Оно не запускает поток, не
открывает соединение, не меняет подписку и не запрашивает данные у источника.
Слушатель на потоке этого runtime читает значение напрямую. Внешний вызов
занимает один слот запроса на endpoint и ждёт завершения до одной секунды.
Занятый слот даёт `ErrorCode::RESOURCE_LIMIT`, истечение срока ожидания даёт
`ErrorCode::WORK_LIMIT`. После истечения срока слот остаётся занятым до
завершения обработки запроса владельцем.

Типизированное чтение принимает поддерживаемые LastingEvent, включая
региональные символы и канонические символы Candle. Другие типы событий
возвращают ошибку `UNSUPPORTED_PROFILE`. Для точной подписки Candle можно
передать разобранный `CandleSymbol` в `getLastEventIfSubscribed<events::Candle>`.

## Запросить одно последнее событие

Вызов `requestLastEvent<events::Quote>("IBM", deadline)` ждёт одно реальное
событие TICKER из TCP. Передайте абсолютный срок `std::chrono::steady_clock::time_point`.
Сначала запрос проверяет принятые данные в кэше. При отсутствии значения он
может создать временную точную подписку для действующего соединения или после
явного `connect()`. Запрос на отключённом endpoint может дождаться первого
последующего явного подключения. Он запускает локальную обработку в runtime
и сохраняет текущее намерение подключения. Явный запрос на endpoint с уже
выбранным тейпом получает `UNSUPPORTED_PROFILE`. Если тейп выбран первым
источником после приёма запроса, незавершённый запрос получает ту же
диагностику. Пассивное чтение кэша TICKER доступно во время воспроизведения.

```cpp
auto request = feed->requestLastEvent<events::Quote>(
    "IBM", std::chrono::steady_clock::now() + std::chrono::seconds{2});
auto quote = request.await();
```

Каждый успешный вызов `await()` возвращает владеющую копию одного и того же
результата. `isDone()` показывает, завершился ли запрос. `cancel()` пытается
завершить его отменой. Перемещаемый дескриптор также отменяет незавершённый
запрос при разрушении. Ожидание незавершённого запроса на его потоке runtime
возвращает ошибку `WRONG_THREAD`. Готовый результат доступен на этом потоке.

Runtime публикует один окончательный результат. При сбое источника, закрытии
endpoint, `REQUEST_CANCELLED` или `REQUEST_TIMED_OUT` метод `await()` выбрасывает
`Error`. Принятая очистка, а также отключение или явное переподключение после
привязки запроса к источнику отменяют запрос. Истечение срока до публикации
исключает выдачу более позднего значения.

Endpoint принимает один одиночный запрос или группу до завершения и
освобождения временной подписки. При отсутствии значения в кэше временная подписка также занимает
обычный слот подписки. При исчерпании ёмкости возвращается `RESOURCE_LIMIT`.
Временная подписка обходится без обработчика приложения и может освободиться
после публикации результата запроса.

## Запросить последние события для нескольких символов

Вызов `requestLastEvents<events::Quote>({"IBM", "MSFT"}, deadline)` возвращает
отдельный запрос на каждую входную позицию. Вектор сохраняет порядок и
повторяющиеся символы. `getSymbol()` показывает точный логический символ
дескриптора даже при ошибке. Представление заимствовано у живого дескриптора.

Весь вход проверяется и копируется до приёма группы. Число входных позиций,
включая повторы, ограничено `RuntimeOptions::maximumSymbolsPerSubscription`.
Пустой вход даёт пустой вектор. Группа и одиночный запрос используют один
общий слот endpoint. Активные запросы используют TCP. Endpoint с выбранным
тейпом отклоняет непустую группу. Если тейп выбран после приёма группы до
подключения, каждый ожидающий запрос завершается с `UNSUPPORTED_PROFILE`,
а ранее полученные результаты остаются доступны.

Значения из кэша завершаются независимо до создания временного спроса для
символов без данных. Одна временная подписка обслуживает все точные символы,
которых ещё ждут. Завершение или отмена убирает соответствующий спрос,
когда этого символа больше не ждёт ни один запрос. Отказ в приёме временной
подписки завершает оставшиеся запросы с ошибкой. Владеющие результаты уже
завершённых запросов остаются доступны после ошибок, отмены соседних
запросов, смены источника или закрытия. У группы общий абсолютный срок,
каждый дескриптор отменяется отдельно.

## Локальная агрегация

`EndpointOptions::aggregationPeriod` или свойство конфигурации `dxfeed.aggregationPeriod` задаёт минимальный локальный период endpoint. `Subscription::setAggregationPeriod` задаёт необязательный период подписки. Применяется максимум двух значений после завершения текущего интервала. `Subscription::getAggregationPeriodInfo` показывает локальный период, выбранный для последнего фактического вызова обработчика. До первого вызова значение отсутствует. `Endpoint::getAggregationPeriodInfo` отдельно возвращает данные upstream descriptor.

Ожидающие обновления TICKER остаются в collector, где повторные значения одного ключа могут объединяться. STREAM и HISTORY используют ограниченные упорядоченные очереди с существующей диагностикой переполнения. Во время интервала начальные значения TICKER в collector доступны раньше ожидающих обновлений. Уже выделенные записи очереди сохраняют свой порядок. Закрытие обрабатывает принятые события без ожидания локального интервала. Ноль сохраняет немедленную доставку.

Для индексированных заявок Nuam используйте `createSubscription<events::NuamOrder>()` на HISTORY endpoint. См. [получение NuamOrder](../spec/events/NUAM-ORDER.ru.md).
