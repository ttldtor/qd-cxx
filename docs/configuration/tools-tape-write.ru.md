# Запись tape

[English](tools-tape-write.md) · [Оглавление справочника](../CONFIGURATION-REFERENCE.ru.md)

Контракты потребителей отдельных полей и сведения деклараций/исходников с оговорённой доказательностью явно различаются ниже. НЕИЗВЕСТНО обозначает недостающее сведение. Известные объявленные сведения сохраняются; их семантическая проверка ещё не завершена. Ссылки указывают декларацию или потребителя и не означают нового запуска тестов. Значения описывают текущий API; принятые изменения перечислены в [архитектурном контракте](../CONFIGURATION.ru.md).

### `Configuration::input` — CFG-0920 {#cfg-0920-ru}

- Тип: `std::filesystem::path`. Исходное значение: Инициализатора в классе нет. Это не доказывает обязательность ввода; инициализация значением отличается.
- Источник: явный нативный вход указанного владельца; источник слоя свойств, где он поддержан, определяется resolver endpoint. Семантика отдельного поля установлена по потребителю.
- Единицы: путь в формате ОС полного входного файла
- Допустимые значения: CLI требует непустой --input и остальные обязательные параметры. resolvePaths затем требует существующий обычный файл по разрешённому каноническому пути, без NUL и в пределах FileLimits.pathUnits.
- Момент чтения: CLI проверяет наличие/непустоту --input и сохраняет путь. run вызывает resolvePaths до открытия: проверяются исходный и канонический путь, затем readInput открывает и читает полный вход.
- Изменяемость и время жизни: Постоянный владеющий Configuration одного запуска; метода изменения во время работы инструмента нет.
- Ошибка: Отсутствующий/пустой --input даёт ArgumentStatus::INVALID и код 2, arguments/USAGE. При resolvePaths вход с NUL/пустотой — path/INVALID_PATH (код 3); не помещающаяся длина — path/PATH_LIMIT (6); невозможность получить канонический путь или отсутствие обычного файла по этому пути — path/INPUT_PATH_FAILED (3); совпадение с назначением либо подтверждённый алиас — path/INPUT_OUTPUT_ALIAS (3). bad_alloc при разрешении — path/ALLOCATION_FAILED (6). После разрешения фактическое открытие может дать input-open/OPEN_FAILED, чтение — input-read/READ_FAILED, закрытие — input-close/CLOSE_FAILED, каждое с кодом 3.

### `Configuration::output` — CFG-0921 {#cfg-0921-ru}

- Тип: `std::filesystem::path`. Исходное значение: Инициализатора в классе нет. Это не доказывает обязательность ввода; инициализация значением отличается.
- Источник: явный нативный вход указанного владельца; источник слоя свойств, где он поддержан, определяется resolver endpoint. Семантика отдельного поля установлена по потребителю.
- Единицы: путь в формате ОС нового выходного файла
- Допустимые значения: CLI требует непустой --output. resolvePaths запрещает алиас входа и любую существующую запись назначения; OutputFile публикует новый файл через исключительное создание жёсткой ссылки без перезаписи.
- Момент чтения: CLI проверяет наличие/непустоту --output. resolvePaths проверяет форму пути, существующий каталог назначения, отсутствие алиаса входа и любой существующей записи назначения. Только после полной подготовки входа OutputFile создаёт своё исключительное временное имя и публикует результат созданием новой жёсткой ссылки.
- Изменяемость и время жизни: Постоянный владеющий Configuration одного запуска; метода изменения во время работы инструмента нет.
- Ошибка: Отсутствующий/пустой --output: код 2, arguments/USAGE. В resolvePaths NUL/пустота дают path/INVALID_PATH; невозможность получить абсолютный путь или пустое имя файла — path/OUTPUT_PATH_FAILED; несуществующий или родитель, который не является каталогом — path/OUTPUT_PARENT_FAILED; отказ проверки статуса — path/OUTPUT_STATUS_FAILED; алиас входа — path/INPUT_OUTPUT_ALIAS; другая существующая запись — path/OUTPUT_EXISTS. Эти файловые отказы имеют код 3. path/PATH_LIMIT и path/ALLOCATION_FAILED имеют код 6. Позднее создание может дать output-create/CREATE_FAILED или EXCLUSIVE_COLLISION (3), а публикация — output-link/LINK_FAILED (3); перезапись не разрешается.

### `Configuration::schemaPath` — CFG-0922 {#cfg-0922-ru}

- Тип: `std::filesystem::path`. Исходное значение: Инициализатора в классе нет. Это не доказывает обязательность ввода; инициализация значением отличается.

- Единицы: путь в формате ОС документа JSON схемы
- Допустимые значения: Непустой --schema допускается ровно вместо --profile. Отдельный численный предел длины schemaPath в parseArguments не установлен. При включённом загрузчике run читает этот путь напрямую через readInput с пределами документа schemaLimits, затем вызывает loadJsonSchema; предварительный resolvePaths входа/назначения относится к другим путям и выполняется позднее.
- Момент чтения: parseArguments сохраняет выбор источника без чтения. run сначала проверяет наличие загрузчика, затем при включённой поддержке читает документ и загружает схему до разрешения путей рабочего входа и назначения.
- Изменяемость и время жизни: Постоянный владеющий Configuration одного запуска; метода изменения во время работы инструмента нет.
- Ошибка: Одновременные --schema/--profile либо отсутствие обоих дают ArgumentStatus::INVALID: код 2, arguments/USAGE. Непустой schemaPath при отключённом загрузчике даёт код 4, schema/LOADER_DISABLED. Отказ чтения документа сохраняет input-open/input-read/input-close FileDiagnostic: fileExit даёт 6 для ресурсных токенов и 3 для обычных файловых ошибок. При loadJsonSchema RESOURCE_LIMIT/ALLOCATION_FAILURE дают код 6; INVALID_SCHEMA/MALFORMED_JSON — 5; UNSUPPORTED_PROFILE/VERSION/TYPE/INDEXED — 4. Стадия=schema, токен=jsonSchemaErrorName(error).
- Исходники потребителя: [src/schema/json_schema.cpp](../../src/schema/json_schema.cpp).

### `Configuration::schemaLimits` — CFG-0924 {#cfg-0924-ru}

- Тип: `schema::JsonSchemaLimits`. Исходное значение: Инициализатора в классе нет. Это не доказывает обязательность ввода; инициализация значением отличается.
- Классификация: составной вход: вложенные типизированные настройки, без новой скалярной единицы. Контракт декларации или исходника, без независимой перепроверки. Семантическая проверка поля и его времени жизни ещё не завершена; запуск runtime-тестов не заявляется.
- Источник: указанная декларация. Явный типизированный вход; псевдоним свойства и отдельный приоритет поля не установлены.
- Объявленное назначение: Неизменённые нативные пределы загрузки.
- Единицы: НЕИЗВЕСТНО: см. объявленное назначение; дополнительные единицы из типа не выводятся
- Объявленные ограничения: Скалярный диапазон неприменим. Вложенные ограничения или возвращаемые наблюдения сохраняют объявленный смысл.
- Момент чтения: Явный разбор и подготовка CLI до рабочего I/O, кроме отдельно обозначенных runtime-состояний и наблюдений.
- Изменяемость и время жизни: Общего CLI-пути обновления во время работы нет; только явные операции конкретной команды.
- Ошибка: Ошибка использования CLI или ограниченной рабочей операции; см. parser и справку соответствующей команды.
- Дополнительный перечень ошибок/статусов владельца (без соответствия полю): `ArgumentStatus`.

### `Configuration::limits` — CFG-0925 {#cfg-0925-ru}

- Тип: `std::array<std::size_t, 31>`. Исходное значение: Инициализатора в классе нет. Это не доказывает обязательность ввода; инициализация значением отличается.
- Источник: явный нативный вход указанного владельца; источник слоя свойств, где он поддержан, определяется resolver endpoint. Семантика отдельного поля установлена по потребителю.
- Единицы: Массив содержит 31 именованную координату с разными единицами. Эффективные значения CLI и единицы каждой позиции перечислены в effectiveCliDefaults; исходное выражение объявления сохранено отдельно.
- Допустимые значения: parseArguments до проверки --help заполняет все 31 позиции числами LIMIT_OPTIONS, затем рабочие аргументы переопределяют только соответствующую именованную ячейку. Синтаксис значений — полный неотрицательный десятичный ввод, представимый в uint64_t и size_t; 0 допустим синтаксически. admissionLimits отдельно проверяет FRAME_BYTES+9, FRAME_BYTES≤INT64_MAX и сумму DESCRIPTOR_UNITS+DESCRIPTION_NAME_UNITS, которая становится WriterLimits.textUnits. Остальные ограничения применяют конкретные читатель, допуск и объект записи. writerLimits сам последнее сложение не проверяет; штатный main предварительно вызывает admissionLimits.
- Момент чтения: Сначала parseArguments присваивает весь именованный набор значений по умолчанию, включая вызов справки. После переопределений admissionLimits и writerLimits читают конкретные индексы и передают их независимым библиотечным потребителям; таблица содержит точные пути полей.
- Изменяемость и время жизни: Постоянный владеющий Configuration одного запуска; метода изменения во время работы инструмента нет.
- Ошибка: Неверный синтаксис/повтор/конфликт — ArgumentStatus::INVALID; известный неподдержанный режим или профиль — UNSUPPORTED. Непредставимые зависимости предварительного допуска возвращают код 6; файловые/схемные отказы позднее имеют собственные точные стадии и коды.

### `FileLimits::inputBytes` — CFG-0926 {#cfg-0926-ru}

- Тип: `std::size_t`. Исходное значение: `{16777216}`
- Источник: явный нативный вход указанного владельца; источник слоя свойств, где он поддержан, определяется resolver endpoint. Семантика отдельного поля установлена по потребителю.
- Единицы: байты завершённого собственного входного массива
- Допустимые значения: readInput принимает очередной прочитанный блок только если read≤inputBytes-bytes.size(); 0 допускает лишь пустой физический файл при достаточном work. Полный EOF и успешное закрытие обязательны.
- Момент чтения: FileLimits передаётся явно resolvePaths/readInput/create; OutputFile сохраняет собственную копию. Проверка стоит до указанного копирования/операции.

- Тип: `std::size_t`. Исходное значение: `{67108864}`
- Источник: явный нативный вход указанного владельца; источник слоя свойств, где он поддержан, определяется resolver endpoint. Семантика отдельного поля установлена по потребителю.
