## CharArrayLimits {#cfg-0304-owner-ru}

[include/qd/encoding/char_array.hpp](../../include/qd/encoding/char_array.hpp)

### `CharArrayLimits::encodedBytes` — CFG-0304 {#cfg-0304-ru}

- Тип: `std::size_t`. Исходное значение: Инициализатора в классе нет. Это не доказывает обязательность ввода; инициализация значением отличается.
- Источник: явный нативный вход указанного владельца; источник слоя свойств, где он поддержан, определяется resolver endpoint. Семантика отдельного поля установлена по потребителю.
- Единицы: байты всего CharArray, включая префикс
- Допустимые значения: 0 не вмещает даже префикс null или пустого значения. Читатель ограничивает доступный вход этим числом; писатель учитывает префикс и каждый UTFChar.
- Момент чтения: readCharArray получает лимиты по значению на каждый вызов и применяет их в порядке: ограниченный префикс → домен count/null → исходная MESSAGE граница → codeUnits → чтение символов. writeCharArray выполняет собственный полный предварительный расчёт до записи.
- Изменяемость и время жизни: Новый вызов может получить новые лимиты; уже возвращённое значение не меняется.
- Ошибка: При чтении сначала bounded=min(input.size(),encodedBytes) ограничивает доступные байты префикса. Если полного префикса нет, искусственное отсечение даёт RESOURCE_LIMIT, естественная нехватка — INSUFFICIENT_INPUT. После полного префикса длина вне -1..INT32_MAX даёт INVALID_LENGTH, а -1 завершается как null. Для неотрицательного count в MESSAGE сначала count&gt;input.size()-consumed даёт INVALID_LENGTH по исходной физической границе; только затем count&gt;codeUnits даёт RESOURCE_LIMIT. При PRIMITIVE проверка физического размера сообщения пропускается. В цикле UTFChar искусственно отсечённый конец даёт RESOURCE_LIMIT, естественно короткий ввод — INSUFFICIENT_INPUT. Писатель отдельно возвращает INVALID_LENGTH для count&gt;INT32_MAX, RESOURCE_LIMIT для codeUnits/encodedBytes и INSUFFICIENT_OUTPUT для выходного буфера.
- Исходники потребителя: [include/qd/encoding/char_array.hpp](../../include/qd/encoding/char_array.hpp), [src/encoding/char_array.cpp](../../src/encoding/char_array.cpp).

## SymbolLimits {#cfg-0306-owner-ru}

[include/qd/encoding/symbol_reader.hpp](../../include/qd/encoding/symbol_reader.hpp)

### `SymbolLimits::inputBytes` — CFG-0306 {#cfg-0306-ru}

- Тип: `std::size_t`. Исходное значение: Инициализатора в классе нет. Это не доказывает обязательность ввода; инициализация значением отличается.
- Источник: явный нативный вход указанного владельца; источник слоя свойств, где он поддержан, определяется resolver endpoint. Семантика отдельного поля установлена по потребителю.
- Единицы: байты переданного входа и UTF-тела символа
- Допустимые значения: input.size() ≤ inputBytes; в UTF_BYTES длина тела также ≤ inputBytes. 0 не позволяет прочесть непустой код символа.
- Момент чтения: Лимиты копируются конструктором SymbolReader/PmrSymbolReader, без локального численного валидатора; проверяются при read/readBounded.
- Изменяемость и время жизни: Постоянны в экземпляре; readBounded может временно ужесточить codeUnits одного вызова. beginMessage сбрасывает состояние, не меняя лимиты.
- Ошибка: Превышение байтов или единиц даёт SymbolStatus::RESOURCE_LIMIT и переводит сообщение в FAILED; последующие read требуют beginMessage. Ошибка не публикует частичное значение.
- Исходники потребителя: [include/qd/encoding/symbol_reader.hpp](../../include/qd/encoding/symbol_reader.hpp), [src/encoding/symbol_reader.cpp](../../src/encoding/symbol_reader.cpp).

## UtfStringLimits {#cfg-0309-owner-ru}

[include/qd/encoding/utf_string.hpp](../../include/qd/encoding/utf_string.hpp)

### `UtfStringLimits::bodyBytes` — CFG-0309 {#cfg-0309-ru}

- Тип: `std::size_t`. Исходное значение: Инициализатора в классе нет. Это не доказывает обязательность ввода; инициализация значением отличается.

- Единицы: байты тела UTFString без префикса
- Допустимые значения: 0 допускает null и пустое тело. Тело ≤ bodyBytes; грамматика отдельно допускает не больше 8589934588 байтов и null длины -1.
- Момент чтения: Читается на каждом вызове read/write; структуры limits передаются по значению. Предварительной отдельной фабрики настройки нет.
- Изменяемость и время жизни: Новый вызов может получить новые лимиты; уже возвращённое значение не меняется.
- Ошибка: Превышение bodyBytes — Status::RESOURCE_LIMIT; нарушение предела грамматики — INVALID_LENGTH.
- Исходники потребителя: [include/qd/encoding/utf_string.hpp](../../include/qd/encoding/utf_string.hpp), [src/encoding/utf_string.cpp](../../src/encoding/utf_string.cpp).
