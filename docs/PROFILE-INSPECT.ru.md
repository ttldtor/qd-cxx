# Ограниченный просмотр Profile

[English version](PROFILE-INSPECT.md). Английская версия является нормативной.

Явный preset `--profile default-profile-v1` задаёт полную стандартную схему Profile из
[PROFILE](../spec/events/PROFILE.ru.md). Это удобная схема инструмента, а не общий загрузчик схем.
Настроенные схемы используют библиотечный [API подготовленного отображения](../spec/events/EVENT-MAPPING.ru.md).
Свойства источников и внешний XML разрешаются вне C++ core, протокола и отображения событий.

## Выбор и ограничения

Используются прежние параметры `--input`, `--output-format tsv|human` и `--tape-mode legacy|raw-message-v1`.
Legacy выбирает BINARY/NONE/EMPTY_SET/STREAM_DATA без сжатия; явный RAW-режим — существующий
контракт BINARY/RAW_DATA/MESSAGE. QTP event flags остаются нулевыми. Бизнес-поле Flags события Profile
является обычными данными записи и может быть ненулевым. Прежние профили и версии их вывода неизменны.

Preset Profile требует одну обычную запись Profile с локальным ID 0, полный стандартный логический
порядок полей и точные типы, а также совместимые подготовленные выборки полей. Неверная пара схемы
и отображения отвергается до чтения входа или записи вывода: exit 4 и диагностика LOCAL_PROFILE.
Для этого preset диагностика по умолчанию имеет версию 2; явная версия 1 сохраняет прежнюю грамматику.

Однократная подготовка preset использует `MappingLimits`: fields 16, lookups 64, selections 16,
keys 32, typeAlternatives 32, nameUnits 128, totalNameUnits 4096 и comparisonWork 131072.
Эти фиксированные бюджеты инструмента не заменяют бюджеты вызывающей стороны в настраиваемом библиотечном API.

`--max-event-units` ограничивает суммарные units UTF-16, копируемые в события Profile, включая символ,
Description и StatusReason; по умолчанию 4194304. Ноль является настоящей границей. Ограничения
отдельного символа и поля также действуют. Null и пустая строка списывают ноль units, но различаются.
Этот бюджет независим от работы декодирования и закодированных байтов stdout. Проекция не возвращает
предыдущие списания. Одно временное владеющее событие сосуществует с ограниченным результатом
декодирования; инспектор не сохраняет историю событий. Все прежние ограничения файла, кадра,
записей, полей, строк и вывода продолжают действовать.

## TSV версии 5

Вывод использует LF без BOM. Заголовок состоит из пяти ячеек:
`format`, `qdcxx-tape-inspect`, `5`, `default-profile-v1`, `<mode>`.
Прежние строки frame, descriptor, heartbeat, timing, markers и complete сохраняют грамматику
выбранного tape-режима. Время RAW является явными metadata и отделено от времени остановки торгов Profile.

Каждая запись выдаёт строку `profile-record`, затем строку события `profile`. Первая содержит семь
ячеек: имя строки, индекс кадра, индекс выданной записи, локальный ID, имя локальной записи в UTF-16 hex,
символ в UTF-16 hex и логические значения через запятую. Каждое значение имеет вид `type:raw:payload`;
payload скаляра — `-`, а type 10 использует `null`, `empty` либо строчные четырёхзначные UTF-16 units.
Так сохраняется точная исходная identity каждого стандартного поля независимо от проекции события.
Маркер пустого имени/символа — `-`.

Строка события содержит ровно 21 ячейку в следующем порядке:

| Ячейка | Значение |
| --- | --- |
| 0–1 | `profile`, индекс выданной записи |
| 2–5 | binary64 bits beta, earningsPerShare, dividendFrequency, exDividendAmount |
| 6 | exDividendDayId, знаковое десятичное число |
| 7–12 | binary64 bits high52WeekPrice, low52WeekPrice, shares, freeFloat, highLimitPrice, lowLimitPrice |
| 13–15 | haltStartTimeMs, haltEndTimeMs, исходные знаковые Flags |
| 16–17 | Description и StatusReason: `null`, `empty` либо точный строчный UTF-16 hex |
| 18–19 | числовые коды tradingStatus и shortSaleRestriction |
| 20 | доставленное eventTime в миллисекундах; ноль в legacy |

Ячейки binary64 содержат ровно 16 строчных шестнадцатеричных цифр; NaN использует канонические
quiet-NaN bits. Исходные decimal-представления остаются в `profile-record`. Целые числа записываются
канонически. Обе строки вместе проверяются по оставшемуся бюджету закодированных байтов до
выделения памяти и первой записи.

## Human версии 5 и ошибки

Заголовок: `qdcxx-tape-inspect human 5 profile=default-profile-v1 tape-mode=<mode> identities=local`.
Строка исходной записи начинается с `Profile <index>: frame=<frame> local=<id> name=<quoted> symbol=<quoted>`
и перечисляет type/raw каждого логического поля и nullable-текст. Следующая строка
`ProfileValues <index>:` явно именует все свойства события, decimal-текст, время в миллисекундах,
Flags, nullable-строки и коды enum. Имена, символы и строки используют прежнее безопасное цитирование
UTF-8 без потерь, включая экранирование управляющих символов и непарных суррогатов.
Строки не нормализуются и не передаются в терминал без экранирования.

Коды завершения прежние: 0 успех/help, 2 usage, 3 I/O, 4 unsupported, 5 malformed, 6 resource/allocation.
Отсутствие аргументов и отдельный `--help` дают одинаковый stdout, пустой stderr и exit 0 при успешном
выводе, без открытия входа. Неверные непустые списки аргументов остаются ошибками usage.

Обнаруженная ошибка сохраняет уже записанный завершённый префикс и не выводит последующий маркер
complete. Ошибка финального flush возможна после доставки текста complete приёмнику, поэтому
успешный вывод требует exit 0. Обрезанный вход не становится успешным EOF. Положительные компараторы
требуют ровно одну финальную строку complete; неизвестные, повторные и последующие строки — ошибки.

Эта возможность не означает поддержку индексных событий, загрузчика properties/XML/JSON,
дополнительных wire-identities, сжатия, планировщика воспроизведения, транспорта или совместимость
с частным tape. Авторские проверки и независимое ревью фиксируются отдельно.
