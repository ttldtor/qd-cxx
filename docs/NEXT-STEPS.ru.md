# План проекта


## Согласованное направление и следующие работы

Решения владельца зафиксированы 2026-09-22. Этот план имеет приоритет над историческим списком ниже;
для каждой реализации по-прежнему нужна отдельная назначенная задача.

Цель — не только библиотека C++23, но и рабочие программы, аналогичные по назначению Java qds-tools:
источники/публикация данных, мультиплексоры, запись/воспроизведение и диагностика.
Сначала изучить фактический набор upstream-утилит; необходимые аналоги реализовать поэтапно.
Не считать эти четыре категории исчерпывающим списком. Совместимость имён команд, аргументов,
адресных строк и properties обсуждается отдельно и автоматически не обещается.

| Порядок / направление | Требуемый результат | Разрешённый объём |
| --- | --- | --- |
| Следующая: QDCXX-020, инвентаризация qds-tools | Полный обнаруженный список утилит/алиасов/точек входа, соответствия Java → qdcxx, приоритеты и зависимости; обоснованные варианты совместимости CLI/конфигурации | Только исследование и планирование |
| Пример с реальным событием | Выбрать стандартное событие, например Quote или Trade, после изучения закреплённой схемы/mapping. Детерминированно создать события Java и воспроизвести штатными средствами; перечислить все требования к полям, типам, флагам, времени и пробелы C++ | Отдельная задача; не упрощать схему под текущий код и не называть это полной поддержкой |
| Ограниченный binary tape reader | Использовать constrained-файл QDCXX-019 без изменения байтов; до C++ определить правила protocol descriptor, добавочных descriptions, EOF и ресурсов с узкими Java-проверками/ADR | Отдельное одобрение; общей tape support пока нет |
| Устранение обязательного Python | Инвентаризировать активные зависимости; поэтапно заменить UTC logging, аудиты и проверки процессов на C++/CTest, Java и небольшие PowerShell/CMake-сценарии с эквивалентным положительным/отрицательным покрытием | Отдельные задачи миграции |
| Первые рабочие программы | По инвентаризации и реальным событиям определить feed/публикацию/replay, затем подписки/маршрутизацию мультиплексора, соединения, ограниченные буферы и наблюдаемость | Отдельные задачи protocol/transport/core; сетевая библиотека не выбрана |

Новые Python-скрипты/зависимости запрещены. Прежние временно можно использовать без изменений;
цель — отсутствие обязательного Python для актуальной сборки, тестов и инструментов. Сохранить
исторические доказательства, логи и снимки хешей. Убирать старый скрипт из активного процесса
только после проверки замены. Архивный provenance может содержать Python: историю не переписывать.

Сохранить оба уровня тестирования: маленькие синтетические записи для границ/ошибок И сквозные
примеры с реальными схемами. Контролируемые значения стандартного Java-события — полноценный
пример реальной структуры без live feed. Недоступность demo не блокирует приёмку: воспроизводимые
входы получать офлайн через Java-публикацию и tape. Внешние XML/JSON-схемы остаются в плане;
локальная модель core и декодирование протокола не должны зависеть от загрузчиков схем.

В русских объяснениях предпочитать точные слова «функциональность», «возможности», «API», «метод»,
«параметр» вместо «функционал», «ручки» и лишнего управленческого жаргона. Термин «бюджет» по
отдельному решению владельца оставить. Соблюдать актуальные правила имён и CLI из AGENTS.md,
не переименовывать закреплённые идентификаторы вывода.

## Исторический план после QDCXX-007

[English version](NEXT-STEPS.md). Английский документ является основным.

Утверждено владельцем проекта 2026-09-21. Три границы определяют логическое владение и не требуют трёх форматов файлов или трёх подсистем сериализации. Core может использовать разрешённую локальную схему без загрузки XML и его истории. Потеря copied main alias сохраняется только для XML-импорта в закреплённом профиле QD 3.355; это не требование к будущему программному созданию схем в C++. Java slot projection сохраняется без предписания физического хранения C++. Утверждена структурированная диагностика unsupported-local-type для BYTE/SHORT с сохранением отклонения локального построения; это не запрещает их wire-коды. Исходные requests и selected layouts остаются раздельными. JSON принят для обмена описаниями схем; библиотеки, канонические хеши и сериализация всей сессии остаются открытыми. Существующие oracle-доказательства неизменны.

B01 завершён. Контрактная часть B03 завершена в QDCXX-008, с [валидацией](../spec/schema/examples/VALIDATION.ru.md); B04 завершена в QDCXX-009, с [ограниченной валидацией примитивов](../tests/fixtures/encoding/VALIDATION.ru.md). Остальное остаётся backlog. Реализация importer/C++ требует отдельной задачи.

| Работа | Зависимости / недостающие доказательства | Проверяемый результат |
| --- | --- | --- |
| B01 — Review compatibility profile и владельцев артефактов | Решения владельца по provenance, copied main alias, structured errors и JSON | Принятый или пересмотренный ADR; явные deviations и exclusions. Реализация не нужна. |
| B02 — Целевые schema probes | Существующий schema harness; перед добавлением alias overlays измерить collision/removal, defaulted attributes и copy docs/regionals/disabled; перед исправлением main alias измерить known mapping/property/wire effects. SC-01/02/03/04/07 сохраняют отдельные границы. | Точные stimuli, две репродукции, negative/positive verify, парные coverage/validation; сохранение failures и stages. Только пробы для следующего importer subset, а не все семейства. |
| B03 — Минимальный importer contract, затем отдельно разрешённый importer | B01; B02 для добавляемых конструкций. Начать с 17 существующих schema subcases, явно отклоняя/диагностируя неподдерживаемый scope. Custom types/generators/imports требуют дополнительных доказательств до поддержки. | Versioned interchange specification, original-input/profile provenance, предлагаемые normalized projections, проверенные относительно неизменных Java expectations; отдельная structured diagnostics. Код требует новой утверждённой задачи. |
| B04 — Primitive encoding evidence и contract | Существующий encoding source inventory; P01 недостаточно. Проверить compact width/sign boundaries, truncation/overlong forms, UTF null/empty/Unicode и ограниченные malformed lengths. | Byte vectors со ссылками на исходники и acceptance/error/partial-input rules; без выбора библиотеки. Основа для будущего явно разрешённого первого encoding component. |
| B05 — Расширение static protocol adaptation | B01/B04; измерить LONG/WIDE_DECIMAL tails и исключение missing time-index из wire; requested y,x order, P06 numeric/object mismatches и supported skip paths. | Incoming/outgoing mappings и точные bytes/values, без общего обещания defaults/coercion. Существующие P03/P04/P05 остаются regression subset. |
| B06 — Session/layout lifetime contract | Перед любым обещанием dynamic layout/session reuse: requests до/после первого использования writer, re-description и reset; P09 negotiation и соответствующие P12 probes. | Измеренное cache/lifetime/error behavior и отдельное решение совместимости. Без автоматического сохранения source-observed cache retention. |

Полный dxFeed provider/property parity, generated/regional schemas, mapping getters, PART/auth/sockets/timing и широкие rebuild sequences могут остаться вне initial profile. Им нужны отдельные ограниченные задачи, а не незаметное расширение B03 или B05. qd-core остаётся независимым от transport; backlog не добавляет C++, importer, build system или dependencies.
