# План развития продукта

[English version](NEXT-STEPS.md). Английский документ является основным.

Продукт сочетает переиспользуемую C++23 библиотеку и эксплуатационные утилиты, аналогичные по
назначению необходимым Java qds-tools. [Инвентаризация закреплённых утилит](upstream/QDS-TOOLS.ru.md)
устанавливает реальные команды и зависимости. Нативные имена команд, синтаксис аргументов,
строки адресов и совместимость конфигурации требуют явных контрактов; одинаковое назначение не обещает Java CLI parity.

## Доступная основа

[Текущие возможности](CURRENT-STATE.ru.md) включают ограниченный просмотр tape, точные поддержанные
представления полей, подготовленные отображения Quote/Profile, внешний native JSON и офлайн-экспорт
Java-схем. Java сейчас разрешает контролируемые XML/imports и поддержанные settings; C++ потребляет сохранённую схему.

## Оставшиеся направления

| Направление | Требуемый результат и зависимости |
| --- | --- |
| Покрытие реальных событий | Расширять детерминированные production Java writer/reader наблюдения и C++ conformance для неизменённых стандартных схем. Сначала инвентаризировать все identities, значения, flags и время; не упрощать реальную схему под текущую поддержку. Офлайн-генерации данных достаточно; demo endpoint не требуется. |
| Запись и воспроизведение | Ограниченный in-memory writer RAW_DATA/MESSAGE v1, строгий допуск полного файла и необязательная офлайн-перезапись tape с публикацией только нового назначения реализованы ([writer](../spec/protocol/TAPE-WRITER.ru.md), [валидация допуска](../tests/conformance/protocol/tape-write/ADMISSION-VALIDATION.ru.md), [контракт перезаписи](TAPE-WRITE.ru.md)). Необязательная синхронная библиотека replay реализована ([контракт](../spec/protocol/OFFLINE-REPLAY.ru.md), [валидация](../tests/conformance/replay/VALIDATION.ru.md)). Остаются адаптер реальных часов, composition подписок/данных, завершение очередей и контракты отказов/остановки до аналогов Connect/Post. Сохранять границы файлов/профилей и различать replay timing и event/business time. |
| Feeds и multiplexing | Сторона получения предоставляет общие STREAM/TICKER/HISTORY-очереди, изоляцию клиентов, ограниченную обработку медленных потребителей, локальные изменения подписок и восстановление соединений: [руководство приложения](SUBSCRIPTION-RECEIVER.ru.md), [руководство CLI](SUBSCRIPTIONS.ru.md). Публикация, downstream-сервер, биржевые адаптеры, несколько транспортных каналов и происхождение маршрута события остаются отдельными расширениями; при их проектировании сохраняется существующий протокол. |
| Конфигурация и источники | Продолжать [инвентаризацию конфигурации](CONFIGURATION.ru.md), сверяя закреплённых потребителей, defaults, aliases, units, приоритеты и момент чтения. Нативное построение XML, общее разрешение providers/settings, индексные схемы и замена во время работы остаются отдельными расширениями. Сохранять custom records и дополнительные поля. |
| Эксплуатационная диагностика | Строить Compare/FileAnalysis, диагностику подписок и ограниченные нагрузочные проверки на установленных возможностях схем/файлов/транспорта. IPF остаётся отдельной областью; эквивалентность RMI/JVM/Launcher не определена. |
| Инструменты и платформы | Сохранять обязательные проверки при замене оставшихся ручных Python-процессов эквивалентной положительной/отрицательной верификацией. См. [реестр миграции](PYTHON-MIGRATION.ru.md). macOS остаётся непроверенной; Windows/Linux-доказательства не устанавливают поведение macOS. |

Этот план развития не выбирает следующую область реализации. Каждому расширению нужны
ограниченный контракт и conformance-доказательства. Дополнительные типы, преобразования,
политики сессий, сжатие, flags и транспорт не должны молча расширять существующие профили.

## Условия совместимости

Использовать [открытые вопросы](upstream/OPEN-QUESTIONS.ru.md) и [оставшиеся пробелы tape](REAL-TAPE-GAPS.ru.md)
для выбора целевых production-path проб. Чтение исходников, диагностические обходы и частные
агрегированные наблюдения не заменяют сквозные измерения. При изменении наблюдаемой семантики
обновлять спецификации, архитектурные решения и fixtures вместе.
