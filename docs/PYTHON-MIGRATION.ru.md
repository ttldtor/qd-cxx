# Удаление Python из актуальных процессов

[English](PYTHON-MIGRATION.md). Английская версия является основной.

Инвентаризация исходников QDCXX-020, не выполненная миграция. Python здесь не добавлялся,
не менялся и не запускался. Цель: актуальные configure/build/tests, получение форматтеров,
валидация oracle и доказательств работают без Python. Исторические скрипты, захваты и хеши
сохраняются как исторические доказательства.

## Перечень и связи зависимостей

### Текущее назначение: QDCXX-027

QDCXX-027, ready, High, реализует шаги 1–2 ниже от принятого master
`d86c8a9842041f8876109285a33782d02e04018f`: два обязательных CLI-набора с их мутациями,
UTC-логирование и получение прежних Windows-форматтеров. Связанный план задаёт проверки эквивалентности и недоступности Python.
Само назначение пока не удаляет зависимостей; реализация и независимое ревью ещё требуются.

Ручные negatives примитивов/протокола, JSON-валидация схемы, аудит доказательств, генераторы и удаление
отслеживаемого байткода остаются продолжением (шаги 3–4). Перенос обычного CTest не делает их устаревшими или необязательными.
Старые скрипты сравнения и отслеживаемый байткод в QDCXX-027 неизменны; при сравнении отключить запись байткода.
Исходная инвентаризация QDCXX-020 ниже сохранена; план QDCXX-027 уточняет актуальные границы переноса.

Пути ниже относительно репозитория. Использованы `rg --files tools tests` с фильтром `.py`,
затем ссылки CMake/PowerShell/документации и imports/запуски процессов скриптов. Обязательное
текущее выполнение отделено от необязательного/ручного исторического воспроизведения;
наличие в Git не означает запуск в CTest. Эти скрипты не являются production-зависимостями C++.

не требуют Python через CMake; документированные логирование/получение инструментов ещё могут требовать его.

## Порядок миграции и приёмка

1. Сначала заменить UTC logging и получение форматтеров, чтобы проверять дальнейшую миграцию
   без новых зависимостей Python. Проверить ошибку запуска, ненулевой код дочернего процесса,
   пробелы/Unicode в argv, смешанные потоки, сбой вывода/лога, изоляцию UTC, отсутствие executable,
   неверный хеш архива и выход пути за каталог. Не менять часовой пояс хоста и старые логи.
2. Вместе заменить offline/human process checks, imports и offline negative driver; подключить
   CTest и убрать find_package(Python3) только после эквивалентности. Проверять точные stdout,
   stderr, коды, границу процесса 30 секунд, help/no-args, неверные аргументы, отсутствие входа/
   ошибки выхода, согласованность TSV/human, UTF-16 escaping и бюджеты вывода. Сохранить injected IO doctests.
3. Переносить каждое семейство отрицательных primitive/protocol-проверок и общие аудиты.
   Запускать старую и новую валидацию на одинаковых временных мутациях, требовать одинакового
   отклонения и успеха baseline, сравнивать хеши фикстур до/после, сохранять отдельную новую
   UTC-валидацию EN/RU.
4. Перенести JSON-валидацию и воспроизведение designed-фикстур, включая duplicate-key/unknown-row
   rejection и побайтовую генерацию в новом каталоге. Архивировать только экспериментальные
   входы или входы завершённых задач; до удаления активных ссылок перенести всё нужное текущей приёмке.
5. Проверить чистые Windows и Linux/WSL без доступного Python: production tool ON/OFF,
   BUILD_TESTING ON/OFF, CTest, получение/проверку форматтеров, нужные Java Verify, отрицательные
   наборы и аудиты. Найти ссылки Python в актуальных входах/документации, отделив архивные ссылки.
   Отсутствующий runtime не должен молча пропускать тесты. Сообщать только выполненные профили.

Итог приёмки — **актуальные процессы не требуют Python**, а не удаление всех `.py` и исторических
упоминаний. Сохранить фикстуры/захваты/логи, lock-файлы, хеши и временные метки; новые отчёты
ссылаются на прежние доказательства без их изменения. Архивный авторский отчёт не превращается
в независимо выполненную проверку. Это будущие ограниченные задачи, не разрешение реализации.
