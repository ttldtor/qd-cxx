# ADR-0011 — Эталон Java-текста событий

[English version](ADR-0011-java-event-text-reference.md). Английская версия является основной.

Статус: политика совместимости принята. Квалификация реализации отдельно описывается в [результатах проверок](../../tests/conformance/EVENT-TEXT-VALIDATION.ru.md).

## Контекст и решение

Текст сохраняет порядок полей, обработку символов и бизнес-accessors закреплённого QD при явном неизменяемом контексте. Числа следуют уточнённому контракту Double.toString Java 19+, проверяемому по Java 25. [Примечания Java 19](https://www.oracle.com/java/technologies/javase/19-relnote-issues.html#JDK-4511638) описывают более строгий выбор десятичной записи и изменения результата. [Текущая спецификация](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/Double.html#toString(double)) выбирает кратчайшую запись с обратным преобразованием; если достаточно одной цифры, действует правило ближайшего представления из одной или двух цифр. Само различие версий runtime не доказывает дефект upstream.

[Числовая fixture](../../tests/fixtures/event-text/numeric-version-differences.tsv) сохраняет обе наблюдённые записи, длины значащих частей, точные десятичные расстояния и классификацию каждого случая. Обе записи должны преобразовываться обратно в исходные биты binary64. Канонические форматы Candle, символов, sources и IPF сохраняют свои установленные контракты.

## Подтверждённый дефект кеша TimeFormat

Закреплённый [TimeFormat](https://github.com/devexperts/QD/blob/0ddc0a09779fb61d74cc0b37c6449ff47dcb715f/dxlib/src/main/java/com/devexperts/util/TimeFormat.java#L515) использует UTC-секунду как ключ результата без миллисекунд, хотя допустимый фиксированный offset может содержать миллисекунды. Для offset 1234 вызовы format(1), затем format(999) дважды дают 19700101-000001; свежий форматтер для 999 даёт 19700101-000002. Обратный порядок меняет устаревший ответ. getInstance создаёт новые объекты форматов/кешей и защитную копию timezone. Production-поведение воспроизведено на Java 8 и 25.

C++ возвращает правильное локальное время, независимое от истории и сверенное со свежим production Java-форматтером. [Три точных исключения](../../tests/fixtures/event-text/upstream-cache-differences.tsv) сохраняют кешированные и свежие результаты для offsets 1234, -2147483648, 2147483647. Остальные строки требуют точного равенства; новое различие останавливает capture/verification до ревью. Допустимые фиксированные контексты с долями секунды поддерживаются.

## Альтернативы и последствия

Копирование старого числового поведения или кеша сохранило бы документированные устаревшие записи либо подтверждённый дефект. Иной C++ синтаксис помешал бы обычному сравнению логов. Выбранная политика сохраняет точные входы и узкие документированные различия. Строгий результат представлен UTF-16; [преобразование в UTF-8](../EVENT-TEXT.ru.md) требует явной политики для непарных суррогатов. Общий parser текста событий и универсальный round trip не обещаются.
