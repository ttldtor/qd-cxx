# ADR-0015 — Общее владеющее хранение записей со схемой

[English version](ADR-0015-shared-record-blocks.md). Английская версия нормативная.

Статус: внутренний кандидат хранения реализован; публичный RecordFeed и перенос производственного тракта остаются отдельной работой.

## Контекст

Текущий локальный STREAM-тракт уже разделяет неизменяемое хранилище `SharedRecordPayload::Batch`
между владельцем локального события, STREAM-коллектором, диапазонами MUX и удержанными выдачами.
Замена этого механизма другим владельцем payload усложнила бы реализацию. Алиасы строк сохраняют
символы и поля; полным объявлениям схемы и метаданным источника нужен дополнительный неизменяемый
владелец. [Контракт владения](../../spec/schema/RECORD-OWNERSHIP.ru.md) требует сохранять объявления
и данные после замены источника и допускать последнее освобождение без работающего сетевого потока.

## Решение

Расширить существующий закрытый Batch типом `BoundRecordBatch`. Shared control создаётся для
производного типа; базовые алиасы строк удерживают тот же control. Производный деструктор освобождает
backing, затем чистую привязку и резервы. Владелец не хранит virtual dispatch, протокольный объект,
callback, executor или произвольный прикладной `shared_ptr`. Размещение и API прежнего unbound Batch сохраняются.

Создавать `RecordBlockBinding` один раз при привязке схемы. Он переносит уже владеющий `LocalSchema`
без копирования объявлений, сохраняет происхождение схемы и переданные вызывающим числовые метки
источника и поколения. Factory сохраняет эти метки точно, не удостоверяет их и не устанавливает
глобальную уникальность. Блоки и независимые копии диапазонов разделяют неизменяемую привязку.
Создание или сохраняющее происхождение копирование входной схемы — отдельная операция этапа binding.

Блок делает два запроса allocation: производный shared control и один упакованный массив байтов.
Массив содержит прежние descriptors строк и полей, точные символы и engaged nullable payload,
затем выровненные локальные ID и полные метаданные источника. Null отличается от engaged empty.
Сохраняются raw scalar bits, точные UTF-16 units, непрозрачные байты, sender/cipher/flags, removal time,
raw FIELD words и ordinal, tape MESSAGE time. Изменяемое состояние коллектора и проекции выдачи
остаются у прежних владельцев. Происхождение схемы, точные число/типы/значения полей проверяются до allocation блока.

Одна compare/exchange reservation принимает полный запрос блока до обоих allocation. Постоянное
превышение ёмкости, временная занятость, неверный вход и allocation failure имеют разные результаты.
Отказ сохраняет вход и прежних владельцев, не публикует частичный блок. Binding также резервирует
полный control/schema-capacity запрос до allocation и переноса схемы; отказ сохраняет схему вызывающего.
Последнее освобождение использует только чистое атомарное состояние ёмкости. Control-запросы остаются
учтёнными до allocator deallocation, включая существующие weak controls. Backing освобождается до возврата резерва.

Явное удержание диапазона получает отдельный потребительский резерв всего физического блока и
связанной привязки. Lease кандидата — move-only; перенос и уничтожение сохраняют один quota charge.
Второй retain резервирует вторую потребительскую долю, разделяя физическое хранилище. Удержание
не выделяет память и не копирует payload. Независимая копия непрерывного диапазона создаёт меньший
backing с прежней привязкой, копирует выбранные записи без временного массива descriptors.
Потолка числа записей нет: приём ограничен байтовой ёмкостью и представимостью размеров.

## Учёт копирования и ёмкости

| Граница | Копирование payload | Учёт метаданных и allocation |
| --- | --- | --- |
| Создание binding | Записи не копируются; готовая владеющая схема переносится | Один точный shared-control запрос; модель ёмкости схемы показана отдельно |
| Вход → bound block | Каждый символ и непустой engaged text/byte payload один раз | Один массив и один производный shared control; отдельно байты descriptors строк/полей/источника и выравнивания |
| Удержание диапазона | Нет | Move-only потребительский резерв без allocation и временного массива |
| Независимая копия диапазона | Выбранный payload один раз | Два новых block-запроса; binding разделяется, схема не копируется |
| Прежняя передача локального события | Общий payload удерживается; descriptors полей пересоздаются | Прежняя arena события, record/field descriptors и shared-row references учитываются сессией |
| STREAM collector → MUX | Общий payload удерживается | Прежние StreamRun, row-source metadata, массивы payload references, один shared ledger wrapper и один lease на клиента/input batch |
| MUX delivery и callback retain | Общий payload удерживается | Прежние массивы QueueBatch view/range и detached quota controls остаются нормативными |

`payloadCopyBytes` считает байты символов и engaged payload; хранилище scalar/tag/nullable descriptors
показано как `fieldDescriptorBytes`. `rowDescriptorBytes`, `recordMetadataBytes` и `paddingBytes`
дополняют уравнение упакованного массива. `backingAllocationBytes`, `controlAllocationBytes` и
наблюдаемое число allocation описывают реальные allocator requests блока. Измерение control layout кешируется для конкретного типа и сигнатуры конструктора: значения аргументов не меняют размещение этого allocator/control. Холодные пробы не выделяют память и считаются отдельно от runtime allocation. Control-запросы binding
и байтового домена показаны отдельно, без повторения на каждый блок. Инструментированные проверки
сопоставляют два block-запроса этим счётчикам на проверенных реализациях.

`schemaStorageBytes` — существующая модель ёмкости `LocalSchema::storageBytes()`. Она включает fixed
objects, container capacities, консервативную inline string capacity и attribution общего provenance;
это не наблюдение allocator requests схемы. Fixed LocalSchema object вычитается, когда он уже входит
в binding-control запрос. Allocation создания/копирования схемы не входят в block-copy counters.
Физический домен учитывает binding один раз; потребитель консервативно учитывает всю связанную
привязку для каждого удерживаемого блока. Прежние компонентные ledger могут независимо атрибутировать
то же backing. Эти величины не доказывают единый ledger тракта, allocator overhead, process RSS или ускорение.

## Проверка и ограничения

[Тесты хранения](../../tests/conformance/shared_record_payload_tests.cpp) проверяют все поддержанные
точные типы полей, null/empty/content, происхождение схемы и отказ чужому контексту, поколения источника,
копирование выбранного диапазона, наблюдаемые allocation requests, атомарный rollback отказов,
конкурирующие байтовые резервы, lifetime weak control и последнее освобождение из другого потока.
[Тест MUX queue](../../tests/conformance/mux_queue_tests.cpp) передаёт bound owner через реальные
local event, STREAM collector и MUX route, сравнивает адреса полей двух клиентов и освобождает последнего
detached owner после уничтожения очереди. Закрытые binding/source metadata переживают этот путь;
текущее публичное MUX record view не открывает полный каталог схемы.

Кандидат не добавляет публичный RecordFeed, общий производственный admission API, перенос decoder,
всей publisher queue, wire format или утверждение об ускорении. Прежние callback lifetime,
release affinity LiveEvent и политики очереди сохраняют свои контракты. Полный перенос TICKER/HISTORY
и парные end-to-end измерения производительности требуют собственных доказательств реализации.
