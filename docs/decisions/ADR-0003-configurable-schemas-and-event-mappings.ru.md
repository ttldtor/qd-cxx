# ADR-0003 — Настраиваемые схемы и привязка событий к схеме

[English version](ADR-0003-configurable-schemas-and-event-mappings.md). Английская версия является нормативной.

Статус: утверждено владельцем 2026-09-23. Приняты архитектурные ограничения, а не ещё не реализованная совместимость.

## Контекст

[ADR-0001](ADR-0001-normalized-model-boundaries.ru.md) разделяет разрешение источников, неизменяемую локальную схему и направленные wire descriptions.
Нынешний `LocalSchema` уже принимает записи и lookup-ключи вызывающей стороны, но `mapQuote` требует восемь значений в одном фиксированном локальном порядке.
Такое ограничение стандартного варианта было намеренным; оно не должно стать архитектурой всех событий.
Построение схемы Java может зависеть от properties и providers либо внешнего XML. Настройки источника и входящие описания — разные входы.

## Решение

1. Настраиваемость схем — общее требование к библиотекам и будущим рабочим утилитам, а не исключение для Profile. Встроенные схемы — воспроизводимые варианты по умолчанию, использующие ту же проверяемую границу схемы, что и программно созданные или импортированные схемы.
2. Адаптеры источников преобразуют явную конфигурацию в неизменяемую локальную схему. Для воспроизводимости сохраняются действующие properties, идентификаторы providers и происхождение источников. Core, кодеки и отображение событий не должны сами читать глобальные properties процесса, переменные окружения или XML-файлы. Разные конфигурации могут сосуществовать, не меняя друг друга.
3. Адаптеры стандартных событий подготавливают привязку к конкретной проверенной схеме и записи. Явные lookup-ключи и полные типы разрешаются до обработки значений; обязательные, необязательные и неподдерживаемые поля различаются. Привязку нельзя повторно использовать с несовместимой схемой только потому, что совпали ID записи, количество или типы полей. Владение и условия недействительности документируются; изменение действующей схемы остаётся отдельной работой.
4. Привязка wire-полей к локальной записи отделена от отображения локальной записи в событие. Отсутствующее wire-поле при наличии поля в локальной схеме не равно отсутствию поля в самой локальной схеме. Значения по умолчанию и допустимые преобразования требуют Java-доказательств на соответствующей границе.
5. Общий API записей и значений доступен без адаптера стандартного события. Пользовательские записи и дополнительные поля не удаляются из него молча. Типизированное событие — документированная проекция, а не вся схема и не замена исходной записи без потерь.
6. Сохраняются точная проверка полных типов и конечные бюджеты. Настраиваемость не разрешает произвольные преобразования, выдуманные aliases, выполнение произвольного XML или автоматическое восстановление локальной семантики из wire descriptions. Одного узнаваемого имени события недостаточно для установления совместимости.
7. Статические C++-типы событий и встроенные декларации полей допустимы. Фиксированные позиции полей допустимы только в явно ограниченном default API или в подготовленной привязке к конкретной схеме, но не в общем контракте отображения. Общие проверки и поиск переиспользуются там, где нужны нескольким адаптерам; система плагинов, исполняемый язык mappings и рефлексия не требуются.

## Альтернативы

- Один фиксированный layout на событие прост, но не представляет настроенные или внешние схемы.
- Отдельная ветка layout для каждой комбинации дублирует отображение и растёт вместе с числом конфигураций.
- Буквальное воспроизведение Java-фабрик и рефлексии добавляет механизмы, не доказывая совместимость поведения.
- Привязки к схеме используют существующую границу неизменяемой схемы и позволяют проверять её до повторяющейся обработки событий.

## Последствия и совместимость

Прежние default-профили и их побайтовый CLI-вывод остаются контрактами совместимости.
Quote должен получить путь с учётом схемы, а не быть удалённым или молча расширенным; Profile должен использовать тот же архитектурный подход.
Адаптеры источников XML/JSON — отдельные результаты разработки, а не постоянные исключения из продукта. Их будущий вывод должен использоваться без изменения core или написания другого mapper событий.
Существующий JSON-контракт XML-captured ограничен и этим решением автоматически не расширяется.
Сам по себе ADR не разрешает новые wire-типы, семантику индексных записей, изменение действующей конфигурации, transport или зависимости.

## Проверки и реализация

QDCXX-025 предусматривает Java-доказательства, привязки Quote/Profile к схеме и сгенерированные интеграционные тесты.
Проверяются default-схема, перестановки, необязательные поля и схема из внешнего XML, одновременные конфигурации, общие пользовательские записи и отклонение неверной схемы.
Пробы настройки источников используют закреплённый upstream и сохраняют фактическое окружение properties/providers. Прежние captures остаются историческими доказательствами.
Этот ADR не утверждает, что пробы или расширения C++ уже выполнены.
