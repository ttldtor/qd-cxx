# ADR-0002 — Ограниченное состояние tape с заменой неизменяемого снимка

[English version](ADR-0002-bounded-tape-reader.md). Английская версия является основной.

Статус: решение реализации в разрешённых владельцем границах QDCXX-021; независимое ревью ожидается.

## Контекст и решение

[Контракт](../../spec/protocol/TAPE-READER.ru.md) фиксирует Java-доказательства и явные отличия.
Использовать частный список описаний только с добавлением и перестраивать StreamDataContext для каждого
полного обновления. Начислять накопленную работу кандидата до копирования; публиковать список и контекст
только при успехе. Reader владеет ограниченной копией локальной схемы. Изменяемые планы и общий session API
не предоставляются. Повторно использовать FrameReader, description, binding и STREAM_DATA без изменения
их контрактов. Ввод-вывод и представление принадлежат необязательной утилите, не core/protocol.

Принимать ровно один начальный ограниченный дескриптор; version диагностическая, неизвестные расширения
отклоняются. Разрешать поздние первые ID, запрещать все повторы. Пустые конверты — наблюдаемые маркеры без
действия, никогда не разрешение игнорировать хвост. Чистый EOF после заголовка допустим без footer.
Первая ошибка останавливает обработку с завершённым префиксом данных. Эти ограничительные, атомарные
и терминальные правила явно разрешены задачей; разрешительные свойства Java, частичные установки
и продолжение сохраняются как наблюдения, а не требования жизненного цикла реализации.

## Альтернативы и последствия

Добавляемая изменяемая таблица планов уменьшила бы копирование, но потребовала бы нового интерфейса
декодера/контекста. Неограниченный session API вводит замену/reset вне задачи. Перестроение снимка —
минимальный путь повторного использования; цена — повторные ограниченные проходы и временное хранение
старого состояния с кандидатом. Бюджет накопленной работы ограничивает повторы, а не только хранение.
Контракт описывает квадратичные границы поиска; производительность и размер памяти аллокатора не заявлены.

Отдельный версионированный вывод tape сохраняет профиль raw-QTP-инспектора и исторический вывод.
Прежние эталоны и upstream.lock остаются побайтово неизменными. Миграция добавочная: пользователь явно
выбирает новую программу и диагностический локальный профиль. Общая tape, default TapeConnector RAW_DATA,
сжатие, время, Quote, импортер и транспорт исключены. Публичный API предварительный.

## Проверки

Решению предшествовали два чистых Java-захвата и отклонение девяти мутаций. До завершения обязательны
матрица C++, владение, атомарность, границы ресурсов, EOF и процессные IO-тесты; этот ADR до реализации
не заявляет выполненных проверок C++. Ревью остаётся открытым до отдельного выполнения.

## Дополнение QDCXX-023: явная политика RAW/MESSAGE

QDCXX-023 определяет независимый параметр режима
контейнера, владеющее состояние времени фиксированного размера и возвращаемые metadata времени
heartbeat/данных. Сохраняются append-only неизменяемые снимки и терминальные ошибки; планировщик
и изменяемые сессии не вводятся. [RAW-TAPE](../../spec/protocol/RAW-TAPE.ru.md) закрепляет production
Java-доказательства, точную матрицу options/дескриптора, упаковку/насыщение, атомарную публикацию
времени и дополнительный накопленный бюджет metadata. Стандартный legacy-режим неизменен.

Java RAW доставляется через три callbacks контрактов. Просмотр выводит каждую wire-запись один
раз и использует наблюдавшуюся STREAM-проекцию для сравнения. Общий внутренний точный payload
decoder с явным методом `decodeRawData` устраняет дублирование разбора полей, не расширяя смысл
`decodeStreamData`. Replay timestamp и cursor event-time отделены от бизнес-полей Quote. Явный
вывод версии 3 показывает каждый heartbeat, даже без следующих данных. Неизвестные поля времени
и расширения отклоняются вместо незаметной потери непредставленной информации. Представление
остаётся в tools. Новые полные типы, транспорт и полная поддержка частного tape не разрешены;
[агрегированные ограничения](../REAL-TAPE-GAPS.ru.md) рассматриваются отдельно.
