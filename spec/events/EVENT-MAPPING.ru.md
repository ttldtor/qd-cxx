# Подготовленное отображение локальных записей в события

[English version](EVENT-MAPPING.md). Английская версия является нормативной.

Этот контракт определяет ограниченную границу отображения из [ADR-0003](../../docs/decisions/ADR-0003-configurable-schemas-and-event-mappings.ru.md).
Выбранные production-наблюдения Java определяют правила полей; C++ API задаёт их ограниченную проекцию.
Разрешение источников Java и наблюдения событий описаны в [CONFIGURED-EVENTS](../schema/CONFIGURED-EVENTS.ru.md)
и [PROFILE](PROFILE.ru.md). Владение, ограничения подготовки и структурированные ошибки ниже — политика C++ API.

## Идентичность и владение

Каждый успешный `LocalSchema::create` создаёт новую непрозрачную идентичность, даже если объявления
совпадают с другой схемой. Обычные и ограниченные копии сохраняют идентичность. Перемещение передаёт её.
Контекст записи владеет ссылкой на эту идентичность фиксированного размера и выбранным локальным ID записи.
Невалидные контексты, в том числе созданные по умолчанию, никогда не совместимы даже друг с другом.
Валидные контексты совместимы только при совпадении идентичности и ID записи. Количество полей,
последовательность типов и числовые ID сами по себе не доказывают совместимость.
Канонический хэш, глобальный реестр, глобальный счётчик и сравнение схем для каждого события не используются.

Идентичность не владеет именами схемы, записями, исходными файлами или планами протокола. Сохранение
декодированной записи или подготовленного отображения продлевает только жизнь идентичности;
уничтожение схемы не создаёт висячих ссылок. Это защита от случайного смешивания контекстов,
а не от намеренной подмены метки вызывающим кодом, который управляет своими данными.
Значения, переданные вручную, должны нести контекст схемы, определяющей их локальный порядок полей.

Декодер копирует контекст проверенной локальной схемы в каждый план известной записи и каждую
завершённую запись. Контекст добавляется в конец существующего публичного агрегата записи, поэтому
прежние инициализаторы остаются допустимыми, но создают запись без метки, которую новый API отвергает.
Прежний `mapQuote` остаётся явно ограниченным восьмиполевым API совместимости без метки.

`TapeReader` использует ограниченную копию схемы с сохранением идентичности. Append-only обновления
wire-описаний перестраивают wire-планы для той же локальной идентичности; они не инвалидируют
отображения событий и прежние записи. Создание новой локальной схемы создаёт новый контекст и требует
нового отображения. ID отправителя, порядок описаний и время tape не входят в идентичность локальной схемы.

## Подготовка и разрешение полей

Подготовка получает проверенную неизменяемую локальную схему, явный локальный ID записи, заимствованные
запросы полей и конечные ограничения. Каждый запрос перечисляет явные допустимые ключи поиска,
точные полные identities типов и обязательность поля. Запросы содержат только данные, без исполняемого DSL.
Адаптеры задают измеренные правила полей. Получение источников, разрешение свойств и wire-адаптация
находятся вне этого помощника. Свойства процесса, окружение, XML и JSON не читаются.

Поиск использует только явные ключи выбранной записи и точное равенство UTF-16. Нельзя удалять точки,
добавлять имя записи, нормализовать Unicode или придумывать псевдонимы. Несколько совпавших ключей
могут ссылаться на одно поле. Совпадения с разными полями неоднозначны и приводят к атомарной ошибке.
Отсутствие обязательного поля — ошибка; отсутствие необязательного сохраняется в выборе для
доказанного правила по умолчанию адаптера. Присутствующее поле должно иметь одну из точных полных
identities запроса. Общие биты сериализации не разрешают представление. Дополнительные поля остаются
в общей записи в исходном порядке.

Неизменяемый результат владеет контекстом, полной локальной формой типов и выбранными позициями.
Он не заимствует запросы, имена, контейнеры схемы или входные значения. Результат публикуется только
после проверки всех запросов. Специфичные для события значения по умолчанию, время, decimal-представления
и смысл флагов остаются в адаптерах.

Конкретный общий API — `EventMapping::prepare(schema, localId, requests, limits)` с
`FieldRequest { keys, types, required }`. `selections()` возвращает неизменяемое упорядоченное
представление optional-позиций полей; пустой optional означает локальное отсутствие.
`RecordValueView { context, values }` заимствует полный набор типизированных локальных значений.
`validate(view)` проверяет его без копирования. `LocalSchema::recordContext(localId)` возвращает
невалидный контекст для ID вне диапазона; `boundedCopy(limits)` сохраняет идентичность после проверки
всех логических количеств и имён схемы.

## Ограничения, проверка и ошибки

Все ограничения задают конечные логические количества; ноль является настоящей границей.
Подготовка ограничивает поля выбранной записи, исходные ключи поиска, запрошенные выборки,
ключи запросов, units UTF-16 ключей и работу сравнения. Количества и текст проверяются до
пропорционального выделения памяти. Работа списывается до сравнения ключей, с вычитанием для
предотвращения переполнения. Альтернативы типов также расходуют работу. Это ограничения логического
хранения и работы, а не обещание точной ёмкости аллокатора или количества байтов кучи.

`MappingLimits` содержит `fields`, `lookups`, `selections`, `keys`, `typeAlternatives`, `nameUnits`,
`totalNameUnits` и `comparisonWork`. Поля и исходные ключи относятся только к выбранной записи;
ключи запросов и альтернативы типов суммируются по всем запросам. Units имён включают каждый исходный
ключ и ключ запроса, считая повторы, но исключают имена записей: подготовка не ищет по ним.
Каждое сравнение ключа с lookup стоит `max(units ключа, units lookup)` плюс один, списываемые отдельно
для предотвращения переполнения. Каждая альтернатива, сравниваемая с присутствующим полем, стоит
одну единицу работы даже после предыдущего совпадения. Отсутствующие необязательные поля не
сравнивают типы. Пустой список запросов для пустой записи требует нулевого бюджета подготовки.
Пустые списки ключей/типов, пустые или некорректные UTF-16 ключи и identities вне реализованного
расширенного подмножества — неверный вход. Повторные ключи одного поля и повторные поддерживаемые
типы разрешены и полностью расходуют бюджеты.

Порядок ошибок: неверный ID записи; количества выбранных полей/lookup/запросов; суммарные количества
ключей/типов запросов; ограничения исходного текста и текста запросов; синтаксис запросов и
поддержка альтернатив; затем запросы по порядку с обходом их ключей и исходных lookup по порядку.
Ресурсная проверка предшествует каждому сравнению, неоднозначность разных целей немедленно
завершает вызов, отсутствие обязательного поля проверяется после поиска, полный тип — после
единственного совпадения. Ошибка выделения памяти возможна после предварительной проверки
количеств/текста. `MappingError` различает `INVALID_INPUT`, `MISSING_REQUIRED`, `AMBIGUOUS_FIELD`,
`INCOMPATIBLE_TYPE`, `WRONG_CONTEXT`, `INVALID_VALUES`, `RESOURCE_LIMIT` и `ALLOCATION_FAILURE`.
Никакая ошибка не публикует частичное отображение.

Проекция принимает представление значений с меткой. Сначала проверяются контекст, затем полное
количество полей, точные теги и каноническая форма `FieldValue`, до обращения к выбранным позициям
и копирования строк события. В частности, type 10 требует raw zero, скаляры не могут содержать строку,
а диапазоны следуют [FIELD-TYPES](../encoding/FIELD-TYPES.ru.md). Неверный контекст нельзя подтвердить
совпадением количества и типов.

Проекция ограничивает владеющие units символа, каждой строки и их сумму до копирования.
Null-строки владеют нулём units и отличаются от пустых строк. При любой ошибке частичное событие
не публикуется. Исключения выделения памяти и длины преобразуются в структурированную ошибку.
Проекция не сохраняет события и не накапливает скрытое состояние; вызывающий код, сохраняющий
несколько результатов, отвечает за их совокупный бюджет. Инспектор дополнительно ограничивает
файл, записи, работу декодирования и закодированный вывод.

Ошибки различают неверный вход подготовки, отсутствие обязательного поля, неоднозначный поиск,
несовместимый полный тип, неверный контекст/форму значений, превышение ресурса и ошибку выделения памяти.
После предварительной проверки количеств проверка следует порядку входа; ошибка контекста предшествует
проверкам значений и владения. Совпадение классов исключений Java не обещается. Неудачная подготовка
или проекция не изменяет входные данные.

## Заимствованные значения очереди

`RecordValueView` по-прежнему заимствует полные владеющие элементы `core::FieldValue`.
Отдельный `BorrowedRecordValueView` заимствует полные элементы `core::FieldValueView`,
где nullable UTF-16 и byte payload представлены spans/views. `EventMapping::validateView`
и `mapView` подготовленных Quote/Profile проверяют те же правила: сначала provenance,
затем весь канонический shape, как у API с владеющими входными элементами.
Валидация не выделяет память, не копирует payload и не сохраняет входные значения.
Успешные бизнес-проекции по-прежнему владеют символом и отображёнными строками
в тех же явных пределах результата.

Существующие имена и сигнатуры `validate`/`map` сохранены, включая вызовы с пустыми
aggregate-аргументами. [Получатель подписок](../subscriptions/RECEIVER.ru.md) использует
заимствованный путь напрямую для неизменяемых записей очереди; дополнительные generic-поля
остаются доступны независимо от проекции.

## Интеграция и совместимость

Core владеет идентичностью схемы; общий помощник событий зависит только от core. Протокол передаёт
контекст без зависимости от адаптеров событий. Quote и Profile используют общую подготовку и проверку.
Общим пользовательским записям не нужен адаптер события. Узнаваемое имя само по себе не доказывает
совместимость формы, а проекция события не удаляет дополнительные поля общей записи.

Wire-профили, точное связывание, raw-zero defaults отсутствующих wire-полей, завершённые префиксы,
счётчики списаний, терминальные ошибки и политика времени по-прежнему определяются
[STREAM-DATA](../protocol/STREAM-DATA.ru.md), [TAPE-READER](../protocol/TAPE-READER.ru.md)
и [RAW-TAPE](../protocol/RAW-TAPE.ru.md). Загрузчик, индексные записи, дополнительные identities типов,
общие wire-преобразования, транспорт и изменяемая замена схемы не добавляются.
Независимое ревью остаётся отдельным от исходной проверки.
