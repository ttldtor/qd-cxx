# Эпохи источника для независимых моделей

[English version](MODEL-SOURCE-EPOCH.md). Английская версия нормативна.

[Стакан](ORDER-BOOK-MODEL.ru.md) и [модель временного ряда](TIME-SERIES-EVENT-MODEL.ru.md)
могут связывать независимые снимки с состоянием источника. Приложение
по-прежнему вызывает методы каждой модели последовательно. Оно владеет
подпиской Feed, очередью обработчиков и сведениями о том, какая активация
источника доставила каждую пачку.

## Действия при сбросе источника

1. Вызовите `beginSourceEpoch(ordinal)` при активации источника. Передайте
   положительный номер, который растёт от активации к активации модели.
   Модель очищает прежние значения, незавершённые входные данные и отметки
   коррекции стакана. Символ, fromTime и ревизия диапазона временного ряда
   сохраняются.
2. Захватывайте возвращённый `ModelSourceEpoch` вместе с исходной пачкой при
   передаче обработчику. Передавайте этот токен в `processSourceEvents`.
   Для временного ряда захватывайте также ревизию выбранного диапазона.
   ID источника в индексах заявок остаётся отдельным аргументом стакана.
3. Вызовите `confirmSourceEpoch` после подтверждения полной повторной доставки
   для выбранных данных. Для временного ряда также передайте ревизию
   диапазона, для которой получено это подтверждение. Незавершённая локальная
   транзакция или снимок не позволяют подтвердить готовность. Запоздалое
   подтверждение предыдущего диапазона отклоняется даже в той же эпохе.
4. При обнаружении потери данных или сброса вызовите `markSourceGap` с токеном
   затронутой эпохи. `RETAIN_COMPLETED` сохраняет завершённый снимок для
   просмотра истории. `DISCARD` очищает его. В обоих случаях незавершённые
   транзакции удаляются. Начните эпоху с большим номером для новой доставки.
   Запоздалая пачка или сообщение о разрыве со старым токеном не меняет новый
   снимок.
5. Вызовите `closeSource` с подходящим токеном для завершения работы модели
   с источником. Выберите, сохранять ли последний завершённый снимок.
   Закрытая активация не принимает данные и не запускается повторно.

Токен владеет небольшой уникальной отметкой. Он не удерживает Feed, модель
или событие. Одинаковые номера эпох у разных моделей не дают взаимного
доступа. Номер служит для диагностики, а приём данных проверяет сам токен.
При обработке запоздалых данных нельзя подставлять более новый токен.
Перемещение модели передаёт право принимать данные по токену. Исходная
модель после перемещения отклоняет старый токен. При присваивании перемещённого
стакана прежний токен модели-получателя тоже теряет силу.

## Чтение снимка

| Состояние | Значение |
| --- | --- |
| `UNTRACKED` | Исходные методы чтения и приёма работают без проверки непрерывности источника. |
| `RECOVERING` | Модель принимает данные новой эпохи. Завершённые значения ещё не подтверждены повторной доставкой. |
| `CURRENT` | Последний завершённый снимок подтверждён для эпохи и выбранных данных. Новая незавершённая пачка в него не попадает. |
| `GAP` | Вход закрыт. Сохранённый снимок относится к данным до разрыва. |
| `CLOSED` | Вход закрыт окончательно. Сохранённый снимок относится к прошлому состоянию. |

Метод `getSourceSnapshot` возвращает значения и их статус за одно
последовательное чтение. Копия сохраняет исходные значения и статус после
обновлений, разрыва или уничтожения модели. При отслеживании источника
обычные методы чтения отклоняют нетекущий снимок. Исходный `processEvents`
без токена больше не принимает данные. `clear()` стакана очищает данные
и закрывает вход до начала новой эпохи. Изменение выбранного диапазона
временного ряда удаляет незавершённые фрагменты и требует нового
подтверждения повторной доставки, пока источник принимает данные. Ревизия
диапазона независимо ограждает прежние пачки.

## Подтверждение со стороны Feed

Модель не подключается к Feed и не определяет эпоху транспорта.
`CONNECTED` описывает состояние принимающего сеанса. Подтверждённое
[наблюдение HISTORY](../subscriptions/HISTORY-RECEIVING.ru.md) может служить
подтверждением повторной доставки, если эпоха, выбранные данные и
завершённые диапазоны соответствуют данным, переданным приложением.
Наблюдение относится к конкретному моменту публикации. Чтение после
произвольного callback не устанавливает источник этого callback.
Приложение должно сохранить идентичность на своей границе доставки
или оставить модель в восстановлении, пока не подтвердит источник
и покрытие диапазона. Если новый владелец подписки начинает отсчёт
эпох заново, используйте больший номер эпохи модели.
