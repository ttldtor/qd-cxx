# Снимки стакана заявок

[English version](ORDER-BOOK-MODEL.md). Английская версия нормативна.

Используйте `OrderBookModel` с обычными событиями `Order`. Передавайте
в одном вызове точный символ, ID источника и события в порядке поступления.
Модель применяет [контракт индексных транзакций](INDEXED-EVENT-MODEL.ru.md) и
накапливает незавершённые транзакции и снимки отдельно по источникам. Обновление
из второго источника не публикует незавершённые изменения первого.

Метод `getSnapshot(symbol)` возвращает независимые списки заявок на покупку
и продажу. Снимок содержит опубликованные значения выбранного символа из всех
источников. Каждая заявка сохраняет полный упакованный индекс и точный ID
источника. Для отсутствующего символа оба списка пусты. Вызывайте методы одной
модели последовательно. Модель не хранит подписки, обработчики или ссылки на
входные события. Сохранённый снимок действителен после обновления, вызова
`clear()` или уничтожения модели.

## Состав и порядок

Снимок показывает отсортированные заявки до фильтрации по областям агрегации.

Индексный REMOVE удаляет только запись с той же тройкой «символ, источник,
индекс». Некомпозитная заявка с нулевым размером или NaN в стакан не попадает.
Композитная заявка остаётся видимой и с таким размером. Заявки BUY попадают
в список покупок, SELL и заявки без стороны — в список продаж, как в Java QD.

Покупки сортируются по убыванию цены, продажи — по возрастанию. При равной
цене неиндивидуальные заявки предшествуют индивидуальным. Ключи сортировки
внутри групп:

- Для неиндивидуальных заявок размер сравнивается по убыванию. Затем по
  возрастанию сравниваются упакованные время и последовательность, область
  агрегации, код биржи, текст маркетмейкера и знаковый упакованный индекс.
  Отсутствующий текст предшествует любой строке. Размер сравнивается по
  правилам Java `Double.compare`, включая знаковый ноль и NaN.
- Для индивидуальных заявок по возрастанию сравниваются упакованные время и
  последовательность, затем знаковый упакованный индекс. Индекс уже содержит
  биты источника.

Цена сравнивается как binary64, полученное из типизированной заявки.
Положительный и отрицательный ноль равны при сравнении цены. Цена NaN
помещается после числовых цен на обеих сторонах. Так сохраняется строгое
слабое упорядочение, поскольку сравнение Java QD считало бы NaN равным
любой числовой цене.

## Настройки отображения

Вызов `getFilteredSnapshot(symbol, options)` создаёт независимый снимок того
же опубликованного состояния. Необязательный ID источника выбирает один точный
знаковый ID. Затем модель применяет фильтр областей агрегации отдельно к каждой
стороне. Семь фильтров Java выбирают композитные, региональные, агрегированные
или индивидуальные заявки, композитные вместе с региональными, все кроме
индивидуальных либо все области. `UNFILTERED` оставляет подходящие заявки
всех областей. Исходный метод `getSnapshot(symbol)` использует этот режим.

Среди подходящих заявок на одной стороне индивидуальная заявка скрывает
агрегированные с тем же кодом биржи и тем же маркетмейкером, включая
отсутствующее имя. Индивидуальная или агрегированная заявка скрывает
региональную котировку своей биржи. Любая видимая некомпозитная заявка
скрывает композитную котировку на этой стороне. После удаления более
детальной заявки может снова появиться менее детальная. Нулевая глубина
даёт две пустые стороны. Остальные конечные значения глубины ограничивают
каждую отсортированную сторону отдельно.

Положительный размер лота умножает отображаемый размер композитных,
региональных и агрегированных заявок. Индивидуальные размеры и исходные
биты десятичного формата сохраняются. Каждый снимок вычисляет отображаемый
размер из сохранённого исходного значения, поэтому округление не накапливается
при смене множителя. Неизвестный фильтр и неположительный размер лота
возвращают `INVALID_OPTIONS`.

## Коррекция агрегированных заявок

Коррекция включается при создании модели с политикой
`OrderBookCorrectionPolicy::SAME_SYMBOL`. Она сравнивает подходящие
агрегированные заявки всех источников точного символа, даже если последующий
снимок выбирает только один источник. Сравниваются заявки с положительным
размером, конечной ценой и стороной BUY или SELL. Остальные заявки сохраняют
обычные правила видимости. Запись символа и свойства окружения не включают
коррекцию.

Завершённая агрегированная заявка может скрыть заявку с той же стороной и ценой,
если её время совпадает с новым или старше него. Более новая заявка также
может скрыть более старую при разнице времени от `keepAge` или пересекающуюся
заявку на противоположной стороне при разнице от `flipAge`. Опоздавшее значение,
которое строго выходит за предел, скрывается. В сравнении возраста и
пересечения участвуют только разные видимые записи. Так сама проверяемая
заявка и ранее скрытые значения не влияют на сравнение из-за группировки
условий в исходной Java-реализации.

Отметка о скрытии не даёт повторно показать заявку с той же стороной, ценой и
индексом, если её время совпадает с сохранённым или старше него. Более свежее
изменение может её восстановить. Явное удаление, нулевой размер или полная
замена снимка источника убирают соответствующие отметки. Удаление более новой
заявки само по себе не восстанавливает скрытые значения.

Коррекция обрабатывает только завершённые индексные изменения. Если за вызов
один индекс меняется несколько раз, учитывается его итоговое изменение.
Индексные данные и отметки публикуются вместе, одним обновлением обеих сторон.
Лимит отметок учитывает видимые и скрытые записи всех символов. Его превышение
отклоняет весь вызов, включая попытку завершить ожидающую транзакцию.
Неотрицательные интервалы вычисляются по времени событий. Модель не обращается
к системным часам. Неизвестная политика и отрицательный интервал отклоняются
при создании модели.

## Завершение снимка и пределы

Современные данные используют SNAPSHOT_END или SNAPSHOT_SNIP. В старых данных
нулевой индекс записи может завершить открытый снимок. Для специального
источника должно быть нулевым и упакованное поле биржи. Флаг TX_PENDING
откладывает публикацию до завершения транзакции. Входное событие не меняется.

Пределы индексной модели задают число пар «символ, источник», длину символа,
а также число входных, сохранённых и ожидающих заявок. Объединение снимков и
нормализация создают дополнительные независимые копии в пределах этих
количеств. Пределы измеряют число объектов и единиц UTF-16 в символе.
Неверный ключ, исчерпание предела или ошибка выделения памяти сохраняют
предыдущее состояние. Если `getSnapshot` не может создать полную копию,
он возвращает типизированную ошибку.

Порядок конечных цен, правила размера и завершение старых снимков сверяются
с `OrderBookModel` и его `IndexedOrderModel` в закреплённом исходнике Java QD.
