# Снимки стакана заявок

[English version](ORDER-BOOK-MODEL.md). Английская версия нормативна.

Используйте `OrderBookModel` с обычными событиями `Order`. Передавайте
в одном вызове точный символ, ID источника и события в порядке поступления.
Модель применяет [контракт индексных транзакций](INDEXED-EVENT-MODEL.ru.md) и
накапливает незавершённые транзакции и снимки отдельно по источникам. Обновление
из второго источника не публикует незавершённые изменения первого.

Метод `getSnapshot(symbol)` возвращает независимые списки заявок на покупку
и продажу. Снимок содержит опубликованные значения выбранного символа из всех
источников. Каждая заявка сохраняет полный упакованный индекс и точный ID
источника. Для отсутствующего символа оба списка пусты. Вызывайте методы одной
модели последовательно. Модель не хранит подписки, обработчики или ссылки на
входные события. Сохранённый снимок действителен после обновления, вызова
`clear()` или уничтожения модели.

## Состав и порядок

Снимок показывает отсортированные заявки до фильтрации по областям агрегации.

Индексный REMOVE удаляет только запись с той же тройкой «символ, источник,
индекс». Некомпозитная заявка с нулевым размером или NaN в стакан не попадает.
Композитная заявка остаётся видимой и с таким размером. Заявки BUY попадают
в список покупок, SELL и заявки без стороны — в список продаж, как в Java QD.

Покупки сортируются по убыванию цены, продажи — по возрастанию. При равной
цене неиндивидуальные заявки предшествуют индивидуальным. Ключи сортировки
внутри групп:

- Для неиндивидуальных заявок размер сравнивается по убыванию. Затем по
  возрастанию сравниваются упакованные время и последовательность, область
  агрегации, код биржи, текст маркетмейкера и знаковый упакованный индекс.
  Отсутствующий текст предшествует любой строке. Размер сравнивается по
  правилам Java `Double.compare`, включая знаковый ноль и NaN.
- Для индивидуальных заявок по возрастанию сравниваются упакованные время и
  последовательность, затем знаковый упакованный индекс. Индекс уже содержит
  биты источника.

Цена сравнивается как binary64, полученное из типизированной заявки.
Положительный и отрицательный ноль равны при сравнении цены. Цена NaN
помещается после числовых цен на обеих сторонах. Так сохраняется строгое
слабое упорядочение, поскольку сравнение Java QD считало бы NaN равным
любой числовой цене.

## Завершение снимка и пределы

Современные данные используют SNAPSHOT_END или SNAPSHOT_SNIP. В старых данных
нулевой индекс записи может завершить открытый снимок. Для специального
источника должно быть нулевым и упакованное поле биржи. Флаг TX_PENDING
откладывает публикацию до завершения транзакции. Входное событие не меняется.

Пределы индексной модели задают число пар «символ, источник», длину символа,
а также число входных, сохранённых и ожидающих заявок. Объединение снимков и
нормализация создают дополнительные независимые копии в пределах этих
количеств. Пределы измеряют число объектов и единиц UTF-16 в символе.
Неверный ключ, исчерпание предела или ошибка выделения памяти сохраняют
предыдущее состояние. Если `getSnapshot` не может создать полную копию,
он возвращает типизированную ошибку.

Порядок конечных цен, правила размера и завершение старых снимков сверяются
с `OrderBookModel` и его `IndexedOrderModel` в закреплённом исходнике Java QD.
