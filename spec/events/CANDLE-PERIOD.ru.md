# Типы и периоды агрегации Candle

[English version](CANDLE-PERIOD.md). Английская версия нормативная.

Независимая цель C++23 `qdcxx_candle_values` предоставляет
[`candle_period.hpp`](../../include/qd/events/candle_period.hpp) в пространстве
`org::ttldtor::qdcxx::events`. `qdcxx_feed` подключает её публично, в том числе
через `qdcxx::feed` установленного пакета. Чистой цели не нужны SDK, runtime,
сеть, неявная конфигурация или инициализация. Приватный архив реализации binary64
устанавливается для замыкания статических зависимостей; числовые заголовки не устанавливаются.

Контракт охватывает только значения. Атрибуты Candle, CandleSymbol, отображение
полей, агрегация и приём событий Candle — отдельные возможности.

Источник: [upstream.lock](../../upstream.lock), ревизия
`0ddc0a09779fb61d74cc0b37c6449ff47dcb715f`, production-классы
`dxfeed-api/src/main/java/com/dxfeed/event/candle/CandleType.java` и `CandlePeriod.java`.

## Единицы и разбор

| CandleType | Сокращение | Оценка миллисекунд на единицу |
| --- | --- | ---: |
| TICK | t | 0 |
| SECOND | s | 1000 |
| MINUTE | m | 60000 |
| HOUR | h | 3600000 |
| DAY | d | 86400000 |
| WEEK | w | 604800000 |
| MONTH | mo | 2592000000 |
| OPTEXP | o | 2592000000 |
| YEAR | y | 31536000000 |
| VOLUME | v | 0 |
| PRICE | p | 0 |
| PRICE_MOMENTUM | pm | 0 |
| PRICE_RENKO | pr | 0 |

`candleTypeShortName` возвращает заимствованный неизменяемый статический текст UTF-16.
`parseCandleType` сначала ищет точное сокращение с учётом регистра, затем префикс
имени enum без учёта регистра в порядке таблицы. Поэтому `m`/`M` означает MINUTE,
`mo`/`Mo` — MONTH, а `P` — PRICE. Строчные `pm` и `pr` являются точными сокращениями;
Прописное `PM` недопустимо, а `PR`/`Pr` означает PRICE как префикс имени enum.
К полному имени можно добавить одну строчную `s`: `Minutes` и `MINUTEs` допустимы,
а `MINUTES` — нет. Сравнение регистра Java включает I с точкой и без точки,
длинную S и знак Кельвина там, где они соответствуют ASCII-буквам имени enum.
Пробелы не обрезаются, нормализации Unicode нет. Пустое, постороннее или некорректное
имя вызывает `std::invalid_argument`.

Интервал является оценкой: MONTH и OPTEXP используют тридцать дней, YEAR — 365.
Он не определяет календарные границы, биржевые сессии или даты экспирации опционов.
У нетемпоральных единиц длительность не определена и представлена нулём.

## Значения периода, представление и равенство

`CandlePeriod(value, type)` сохраняет любой множитель binary64 без изменений,
включая отрицательные значения, оба нуля, payload NaN и бесконечности. Недопустимое
значение enum вызывает `std::invalid_argument` в конструкторе и отдельных запросах
единицы. Конструктор по умолчанию, `TICK` и `DEFAULT` задают один тик; `DAY` — один день.
`getValue()` и `getType()` возвращают сохранённую пару.

`toString()` дописывает сокращение единицы к множителю. Ровно единица опускается.
Если значение равно результату сужения Java до signed64, преобразованному обратно
в double, используется целое число. Поэтому оба нуля выводятся как `0`, а
положительное binary64-значение 2^63 — как `9223372036854775807`. Остальные множители
используют цифры Java 8 `Double.toString`, прописную E без плюса у положительной
экспоненты и фиксированную запись для модулей от 10^-3 включительно до 10^7
исключительно. Правило целого числа имеет приоритет над этими порогами.
Форматирование не зависит от локали.

Равенство проверяет единицу и эквивалентность Java `Double.compare`: все NaN равны,
положительный и отрицательный ноль различаются. Строковое представление поэтому
не является взаимно однозначной кодировкой идентичности. Совпадение идентичности
Java-объектов и хешей enum не обещается.

`getPeriodIntervalMillis()` умножает множитель double на оценку единицы и сужает
результат по правилам Java: NaN становится нулём, переполнение насыщается до границ
signed64, остальные значения усекаются к нулю. Само умножение выполняется в binary64;
нулевая длительность, умноженная на бесконечность, даёт NaN и возвращает ноль.

## Текст периода

`CandlePeriod::parse` выделяет числовой префикс только из ASCII-цифр и символов
`.`, `+`, `-`, `e`, `E`. Отсутствующий префикс означает единицу; имеющийся должен
быть полным десятичным double Java. Суффикс разбирается по правилам `parseCandleType`.
Сканер периода не обрезает пробелы. Переполнение и исчезновение порядка дают
бесконечность и ноль с сохранением знака, как в Java. Например:

```cpp
#include <qd/events/candle_period.hpp>
using namespace org::ttldtor::qdcxx::events;
auto period = CandlePeriod::parse(u"2.5Minutes");
// period.toString() == u"2.5m", interval == 150000 milliseconds.
```

Фактический сканер имеет приоритет над общим утверждением Javadoc об обратимости.
NaN и бесконечности можно создать и вывести, но полученные строки этот сканер не
разбирает. Шестнадцатеричные литералы и суффиксы чисел Java тоже недопустимы.
`-0t` разбирается как отрицательный ноль и выводится как `0t`; `1e309d` разбирается
как бесконечность и выводится как `Infinityd`, которую разобрать нельзя.

## Владение, ошибки и проверка

Значения не владеют общим состоянием runtime и не сохраняют заимствованные входы.
Константные операции не изменяют кеши и могут выполняться параллельно; изменение
того же значения требует обычной внешней синхронизации. Callback, отложенной работы
и настроек процесса нет. Вход разбора заимствуется только на время вызова, выходная
строка принадлежит вызывающему коду. Разбор и вывод могут передать `std::bad_alloc`
или `std::length_error`; ошибка выделения памяти не превращается в ошибку синтаксиса.
Работа и память линейны по длине входа; генерация цифр binary64 использует внутреннюю
арифметику фиксированной ёмкости и ограниченное количество цифр. Неявного глобального
ограничения длины входа нет.

[Production-оракул](../../tools/upstream/candle-period-oracle/README.ru.md) фиксирует
все тринадцать единиц, допустимые и ошибочные имена, каждый одиночный кодовый элемент
UTF-16, числовые границы и детерминированные значения raw binary64 в
[исходном TSV](../../tests/fixtures/events/candle/period-oracle.tsv) с
[происхождением](../../tests/fixtures/events/candle/period-provenance.json).
Нативный conformance-тест проверяет каждую строку и отдельно — смысловые границы,
равенство NaN/нулей и недопустимые enum. Общее числовое поведение IPF сохраняет
независимые группы проверок значений, reader и writer.
