# Модель индексированных событий

[English version](INDEXED-EVENT-MODEL.md). Английская версия является основной.

`IndexedEventModel<Event>` хранит типизированные индексированные события после
доставки. У каждой группы есть точный логический символ UTF-16 и знаковый ID
источника. Вызов `processEvents` принимает одну такую группу и проверяет ключ
каждого события. Символ включает региональный суффикс или канонические
атрибуты Candle, если они присутствуют в типизированном событии. Отсутствующий
символ Candle отклоняется. Индексы сравниваются как полные знаковые 64-битные
значения публичного API.

- Обычные события остаются незавершёнными, пока не придёт событие без
  `TX_PENDING`. Завершённые обычные транзакции в одном вызове возвращаются
  одной группой в порядке поступления. Группа сохраняет исходные флаги и
  записи удаления.
- `SNAPSHOT_BEGIN` отбрасывает незавершённые события для этого ключа. Прежнее
  видимое состояние остаётся доступно. Новое становится видимым после
  `SNAPSHOT_END` или `SNAPSHOT_SNIP` и завершения соответствующей транзакции.
  Граница, полученная до начала снимка, обрабатывается как обычное событие.
- Завершённый снимок заменяет прежние значения для своего ключа. Пустой снимок
  очищает их. Усечённый снимок обозначается отдельно и сам по себе не
  подтверждает полное покрытие источника. В снимке сохраняется порядок первой
  вставки. При повторном индексе остаётся последнее значение, а удаление с
  повторной вставкой создаёт новую позицию.
- Видимое состояние хранит последнее оставшееся значение каждого индекса
  по возрастанию знакового индекса. Индексные флаги сбрасываются в хранимых
  значениях и в возвращаемых снимках. Прикладные флаги и прочие поля сохраняют
  исходные значения. Входные события не меняются.

Модель возвращает завершённые изменения после успешной обработки всего вызова.
Несовпадение ключа, превышение лимита или сбой выделения памяти сохраняет прежнее
видимое состояние и незавершённые данные. `IndexedEventModelLimits` ограничивает
число пар символа и источника, длину каждого символа в единицах UTF-16, число
событий в одном вызове и суммарное число незавершённых и видимых событий.
Лимиты действуют на видимое состояние после каждой завершённой транзакции и
на незавершённые события по мере их поступления. Временное хранилище содержит
копии выбранной группы, обрабатываемых входных данных и возвращаемых изменений.
Лимиты событий считают владеющие объекты. Если требуется ограничение в байтах,
владелец входа задаёт границы самих прикладных данных. Ключ освобождает место,
когда для него не остаётся видимых или незавершённых событий.

Вызывающая сторона выполняет обращения последовательно и управляет подпиской и
сбросом. Модель не удерживает callback или runtime. Результаты владеют данными
и сохраняются после `clear`, последующих изменений или уничтожения модели.
Хранимое состояние само по себе не подтверждает покрытие истории источника,
текущее соединение или готовность запросов по диапазону.

Переходы состояний сверены с закреплённой Java QD, классы
`com.dxfeed.model.TxEventProcessor` и
`com.dxfeed.model.AbstractIndexedEventModel.Source`. API C++ возвращает
независимые изменения после вызова. В Java эти данные доступны через
слушателей или живой список.
