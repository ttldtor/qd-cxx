# Сериализованные вложения событий

[English](ATTACHMENTS.md). Нормативна английская версия.

Это выбранный переносимый контракт для API получения Message/Configuration
по [ADR-0014](../../docs/decisions/ADR-0014-portable-attachment-semantics.ru.md).
[API получения](../../docs/MISC-EVENTS.ru.md) реализует владеющие проекции и явный локальный реестр кодеков.
ADR-0014 сохраняет предшествующее решение; конкретные публичные имена определяются API.
Текущий [обобщённый API полей](../encoding/FIELD-TYPES.ru.md) уже сохраняет байты.

## Представление и владение

Вложение состоит из точного полного идентификатора QD-поля и владеющей optional-последовательности
байтов. Для стандартных Message/Configuration полный идентификатор равен 249 `SERIAL_OBJECT`.
У null-поля последовательность отсутствует; у engaged-empty она присутствует и имеет длину ноль.
Эти состояния нельзя заменять друг другом. Байты, включая заголовки Java-потока, неизвестные
описания классов и повреждённое сериализованное содержимое, сохраняются точно. Проверки внешних
QD-длин и framing продолжают действовать.

Полные идентификаторы 9, 233 и 249 остаются различными при одинаковых телах. Типизированное
стандартное отображение требует точной объявленной идентичности поля; оно не принимает тип 9
только из-за хранения байтов. Java byte[] приходит как сериализованный Java-массив внутри 249.
String-вложение аналогично приходит сериализованными байтами, без неявного преобразования
в нативный String. Обобщённое получение и хранение не создают Java-объект, загрузчик классов или JVM.

Полученное вложение владеет памятью независимо от исходных буферов, схем, readers, callbacks
и endpoint. Копирование даёт независимую семантику значения; изменение исходного буфера
или копии не меняет сохранённый оригинал. Перемещение передаёт владение по документированным
правилам значения события. Заимствованные byte views, если они предоставляются, действительны
только пока владелец жив и неизменён. Receiving callback может заимствовать содержащий событие
batch; для хранения после возврата callback нужна владеющая копия. Фоновое декодирование не запускается.

Создание/замена из байтов приложения проверяет вид поля и настроенный предел длины до публикации,
затем копирует или явно передаёт владение. Ошибка проверки/выделения памяти сохраняет прежнее
значение. Замена байтов явная; декодированное значение не подменяет оригинальную сериализацию.
Неявный cache декодирования не меняет равенство значений. Равенство вложений сравнивает полную
идентичность поля, наличие последовательности и каждый байт тела.

## Явные кодеки и время жизни

Приложение выбирает ключ кодека, ожидаемый нативный тип результата и версию формата в явном
локальном запросе декодирования. Это конфигурация приложения; выбор не выводится из wire-байтов,
имени записи, Java-класса, magic bytes или версии Configuration. В wire ничего не добавляется.
Кодека по умолчанию, автоматического fallback и повторной попытки другим кодеком нет.

Реестр принадлежит отдельному экземпляру и создаёт неизменяемые snapshots. Регистрация завершается
до использования snapshot; повтор ключа/версии — ошибка, сохраняющая состояние реестра. Операция
декодирования удерживает один snapshot и сильную ссылку на выбранный кодек до завершения.
Уничтожение или замена реестра приложения не инвалидирует допущенную операцию. Регистрация
владеет состоянием callback, а не заимствует его из стека приложения. Декодер не сохраняет
заимствованный payload после синхронного вызова. Владеющий нативный результат остаётся пригодным
после уничтожения вложения, реестра, кодека и контекста запроса. Результаты-указатели/views,
заимствующие вход, не входят в этот владеющий контракт.

Вызовы одной регистрации сериализуются; повторный вход в ту же регистрацию отклоняется до вызова
callback. Разные независимые регистрации могут исполняться параллельно. Занятость регистрации сразу возвращает типизированный busy-отказ без ожидания, очереди или повтора; вложенный decode разных регистраций не создаёт цикл блокировок SDK. Callback вызывается
без блокировки изменения реестра. Изменение регистрации через неизменяемый snapshot недоступно,
поэтому исполнение кодека не инвалидирует выбранную регистрацию. Асинхронные callbacks, отмена
и фоновые задачи не подразумеваются. Будущему асинхронному API нужен отдельный контракт времени
жизни и завершения.

Выбор проверяет регистрацию, тип результата и версию формата до исполнения кода, в том числе
для null. Неизвестная регистрация возвращает ошибку неизвестного кодека, сохраняя исходное
вложение. При подходящей регистрации null даёт успешный отсутствующий нативный результат
без вызова кодека. Engaged-empty вызывает его с непустым по наличию, но нулевым по длине byte span.
Callback обязан потребить тело целиком; оставшийся хвост — повреждённый вход, если выбранный
формат явно не включает и не потребляет его. Частичный успешный результат не публикуется.

## Ошибки и гарантии ресурсов

Явное декодирование возвращает владеющий результат или типизированную ошибку. Обязательно
различимы: неизвестный кодек, неподдерживаемая версия формата, несовпадение типа результата,
повреждённое тело, предел ресурсов, ошибка выделения памяти, исключение кодека и запрещённый
повторный вход в ту же регистрацию. Конкретные типы и единицы ресурсов определены в
[API](../../docs/MISC-EVENTS.ru.md). Диагностика ограничена и не выводит содержимое payload или исключений приложения.
Перехваченное исключение кодека превращается в ошибку исключения кодека; `std::bad_alloc`
классифицируется как ошибка выделения памяти. Обычные C++ исключения не выходят за границу вызова
кодека. Системные аварии процесса не входят в гарантию восстановления после исключения.

Любая ошибка сохраняет точное оригинальное тело и не публикует декодированное значение. Она
не инвалидирует другие вложения, не закрывает feed, не меняет состояние версий Configuration
и не запускает повторную попытку. Приложение может хранить, исследовать и передавать opaque-данные
после ошибки в пределах существующих возможностей исходящего API.

При получении продолжают действовать прежние конечные пределы encoded-body, payload-work
и retained-body, включая ноль, до выделения памяти. У явного декодирования отдельные переданные
приложением конечные пределы input, output, scratch, work и диагностики; число регистраций
и удерживаемое ими состояние также ограничены на экземпляр. Декодирование не повышает пределы
получения. Превышение входного decode-предела отклоняется до callback. Null не требует памяти
тела; engaged-empty остаётся присутствующим и при нулевом byte-пределе. До публикации API
реализация обязана описать единицы учёта, момент резервирования, проверки переполнения
и атомарность при ошибке.

Зарегистрированные нативные кодеки — доверенный код приложения. Принудительные output/scratch
пределы требуют контекста выделения памяти/работы кодека; произвольные внешние выделения памяти
и невозвращающийся код нельзя ограничить синхронным C++ callback. Это нарушение контракта кодека,
а не sandbox-исполнение или жёсткий wall-clock timeout. Механизм не включает произвольную
десериализацию Java.

## Границы Configuration и текста

Знаковая 32-битная версия Configuration — обычные metadata события. Закреплённый Java отклоняет
меньшие версии только для TICKER при включённом поле; [production observations](../../tests/fixtures/configuration-version/README.ru.md)
подтверждают равные версии, STREAM, batch и первую default-zero запись. Выбор версии формата кодека не читает, не продвигает
и не сбрасывает это состояние. Успех/ошибка декодирования независимы от допуска события
Configuration. Реализация фильтра версий — отдельная ответственность получения.

TextMessage и TextConfiguration сохраняют отдельный nullable String API с точной UTF-16 семантикой
и собственной квалификацией полей/отображения. Это не вспомогательные декодеры сериализованных
Object-вложений. [Oracle fixtures](../../tests/fixtures/attachments/README.ru.md) подтверждают
только идентичность стандартного поля Text; полного Text API и фильтрации версий они не доказывают.
