# Рыночные символы и общие атрибуты

[English](MARKET-SYMBOLS.md). Английская версия является нормативной.

Чистая библиотека `qdcxx_market_event_symbols` предоставляет девять свободных функций
в `org::ttldtor::qdcxx::events::market_symbols`, объявленных в
[`market_event_symbols.hpp`](../../include/qd/events/market_event_symbols.hpp).
Эталон — QD 3.355 с ревизией из [upstream.lock](../../upstream.lock),
`dxfeed-api/src/main/java/com/dxfeed/event/market/MarketEventSymbols.java`.
`Quote.java` описывает отдельные записи `Quote` и `Quote&X`. Результат помощника
не включает региональную маршрутизацию Feed или новое отображение записей.

## Точный синтаксис и операции

Все позиции и коды бирж — элементы UTF-16, включая NUL и одиночные суррогаты.
Проверки Unicode, декодирования, нормализации и поиска площадок нет.
`SUPPORTED_EXCHANGES` — исходный список `0-9A-Za-z` в порядке ASCII;
`DEFAULT_EXCHANGES` — `A-Z`. Константы описательные: разбор и композиция принимают
любой элемент. `Q` остаётся кодом и сам по себе не устанавливает площадку.

Конечный блок атрибутов существует, только если вход содержит хотя бы три элемента,
оканчивается `}`, а последняя `{` перед конечным элементом имеет хотя бы один
промежуточный элемент. Поэтому `{x}` — блок, `{}` — обычный текст, а в `{a{b}` блок
начинается со второй `{`. Наличие `=` внутри не требуется. Операции базы/кода сохраняют блок буквально; операции атрибутов ниже разбирают его.

Без учёта блока региональный суффикс — ровно `&` и один последний элемент.
`SPY&Q` региональный; `SPY` и `SPY&QQ` синтаксически составные. Суррогатная пара
после `&` имеет два элемента и региональным суффиксом не является.

| Операция | Результат |
| --- | --- |
| `hasExchangeCode` | Наличие суффикса, включая явный NUL; false для null |
| `getExchangeCode` | Код суффикса либо ноль при отсутствии/null |
| `getBaseSymbol` | Владеющая база без суффикса и блока; null сохраняется |
| `changeExchangeCode` | Замена/добавление кода или удаление при нуле; блок сохраняется |
| `changeBaseSymbol` | Замена базы без её интерпретации; старый суффикс и блок сохраняются |

Null отличается от пустого входа. `changeExchangeCode(null, 'Q')` создаёт `&Q`,
а нулевая замена сохраняет null. `changeBaseSymbol(null, base)` возвращает копию
`base`. Null вместо базы остаётся null, когда добавлять суффикс/блок не требуется;
иначе конкатенация Java создаёт буквальный текст `null` с этим суффиксом/блоком.
Измеренное поведение имеет приоритет над противоречивыми утверждениями Javadoc
о результатах null.

## Владение, ошибки и границы

Входы `std::optional<std::u16string_view>` заимствуются только на время вызова;
`std::nullopt` представляет Java null. Результаты `std::optional<std::u16string>`
владеют независимым хранилищем. Запросы наличия/кода имеют `noexcept`; операции с выделением памяти
передают стандартные `std::bad_alloc` и `std::length_error`, не изменяя входы и не
возвращая частичный результат. Рост размера выполняют проверяемые операции строк,
без непроверенного суммирования длин. Сохранённого состояния и ввода-вывода нет.

Перегрузки UTF-8 нет. Преобразование выполняется явно на границе кодировки приложения;
точное представление совпадает с `Quote::symbol`. Здесь нет regex-селекторов,
синтаксиса Candle, квалификаторов источника или интеграции подписок.

## Общие атрибуты

`hasAttributes` применяет то же правило конечного блока и возвращает false для null.
`getAttributeStringByKey` возвращает значение первого точно совпавшего ключа либо null
при отсутствии ключа/null символа. Пустые ключи и значения допустимы и отличаются от null.
Ключ обязателен: null вызывает `std::invalid_argument`, соответствующий Java
`NullPointerException`, до проверки символа и выделения памяти для результата.

`changeAttributeStringByKey(symbol, key, value)` вставляет/заменяет значение; null
вместо значения удаляет все совпадающие ключи, как `removeAttributeStringByKey`.
Null символ со значением, отличным от null, создаёт `{key=value}`; с null значением
остаётся null. При отсутствии удаляемого ключа возвращается независимая неизменённая
копия. Удаление единственного атрибута удаляет скобки. Префиксы базы и биржи сохраняются.

Разбор начинается после распознанной открывающей скобки. Ключ продолжается до
следующего `=`, даже через запятые. Значение продолжается до следующей запятой
или конечной `}`. Разбор останавливается при отсутствии следующего `=`. Ключи и
значения не проверяются, не экранируются, не декодируются и не нормализуются;
встроенные разделители влияют на последующий разбор. API равенства/хеша не добавлен:
возвращённые строки сохраняют точное равенство UTF-16.

Замена сохраняет позицию первого встреченного совпадения и удаляет последующие
дубликаты. Вставка происходит перед первым встреченным ключом, лексикографически
большим нового, по беззнаковым элементам UTF-16; иначе — в конце разбора.
Порядок остальных ключей сохраняется. Поэтому замена `a` на `x` в
`S&Q{z=2,a=1}` даёт `S&Q{a=x,z=2}`, а замена `z` — `S&Q{z=x,a=1}`.
Это локальное упорядочивание production-алгоритма, а не полная сортировка некорректного
или неупорядоченного входа. Блок без `=` сохраняет необычное исходное поведение:
добавление `a=x` к `S&Q{junk}` даёт `S&Q,a=x{junk}`.

Ошибки памяти/размера остаются `std::bad_alloc`/`std::length_error`.
Если некорректный вход вызывает в Java ошибочную границу подстроки, контракт C++ —
`std::out_of_range`; непроверенной индексации и усечения ошибочного диапазона нет.
Ограниченный [корпус атрибутов](../../tests/fixtures/market-attributes/README.ru.md)
содержит 276 958 production-наблюдений, включая 9 672 исключения null-ключа;
ошибок Java substring в нём не наблюдалось, все возможные строки он не покрывает.
[Воспроизведение](../../tools/upstream/market-attribute-oracle/README.ru.md) отделено
от неизменяемого fixture региональных кодов/базы.
