# Источники записей Order и упаковка индекса

[English version](ORDER-INDEX.md). Английский текст имеет приоритет.

Независимый компонент C++23 `qdcxx_order_index` экспортирует
[order_index.hpp](../../include/qd/events/order_index.hpp) и зависит от чистых
компонентов отображений полей и идентификаторов источников. `qdcxx_feed`
подключает его публично. Сеть, SDK, настройки процесса и изменяемый кеш не нужны.

Основание — [upstream.lock](../../upstream.lock), ревизия QD
`0ddc0a09779fb61d74cc0b37c6449ff47dcb715f`: production-классы
`MarketEventMapping`, `OrderMapping`, `OrderDelegate`, `OrderBase`, `OrderSource`,
`MarketFactoryImpl`. [Наблюдения](../../tests/fixtures/order-index/oracle.tsv)
содержат фактические вызовы, объявления полей и отказы.
[Инструмент](../../tools/upstream/order-index-oracle/README.ru.md) сохраняет
хеши исходников и неизменившийся инвентарь production-классов.

## Явное подготовленное отображение

`PreparedOrderSource::prepare(schema, localId, limits)` выбирает ровно одну
явно указанную локальную запись валидированной схемы. Последний `#` отделяет
имя источника. Без `#` выбирается `OrderSource::DEFAULT`. Суффикс содержит от
одного до четырёх ASCII букв/цифр в единицах UTF-16, с сохранением регистра, и
разрешается через `OrderSource`. Пустой суффикс, `#DEFAULT`, `#COMPOSITE_BID`,
пунктуация и не-ASCII недопустимы. `Order#NTV#BZX`, например, выбирает BZX.
Семейство записи задаёт вызывающая сторона; префикс не определяет класс события.

Подготовка выбирает обязательный точный ключ `Index` с полным типом
`COMPACT_INT` (8) через `EventMapping`. Сохраняются существующие правила схемы
для псевдонимов одного поля и дополнительных полей. Отсутствие Index даёт
`MISSING_REQUIRED`, другой полный тип — `INCOMPATIBLE_TYPE`.

Это явный профиль стандартного поля. Java `MappingUtil.findIntField` принимает
физический `DataIntField`, а `OrderMapping.getIndex` читает сырой слот int, в том
числе у полных типов INT, DECIMAL и SEQUENCE. C++ профиль не приписывает Java
отказ от этих типов. Более широкие преобразования остаются отдельной работой;
подготовку можно расширить без изменения публичного API источников и индексов.

План владеет источником, полной формой локальных полей, позициями и неизменяемым
контекстом записи. Он не сохраняет исходную схему, имена, поля или заимствованные
значения. Копии сохраняют точное происхождение схемы; независимо созданная равная
схема остаётся чужой. Проекция сначала проверяет контекст, затем все поля,
включая дополнительные. Проекция не выделяет память и не сохраняет значения.

`mapIndex` / `mapIndexView` повторяют production Order delegate:
`(uint64(sourceId) << 32) | uint32(wireIndex)` с возвратом сырых signed64 битов.
Отрицательный signed32 индекс сохраняет все младшие биты при приёме. Это отдельно
от ограничений публикации Java `putEvent`. Источник записи, региональная биржа,
бизнес-символ и физическое происхождение соединения различны; биржа и endpoint
не участвуют в упаковке.

Сохраняются конечные `MappingLimits`. Длина имени записи ограничена `nameUnits`;
его единицы дополнительно расходуют `totalNameUnits` и `comparisonWork` перед
подготовкой полей. Имя источника содержит не более четырёх логических единиц,
либо семи для DEFAULT. Вместимость строки и метаданные аллокатора зависят от
реализации; логические пределы не обозначают RSS процесса. При отказе нет
частичного плана. Перемещённый план можно уничтожить или присвоить; его источник
просматривать нельзя.

## Помощники сырых индексов

`isSpecialOrderSourceId` истинен ровно для ID от 1 до 9.
`orderIndexSourceId` читает старшие signed16; если это специальный источник,
возвращает его, иначе возвращает старшие signed32. `orderIndexSource` разрешает
ID, может выбросить `std::invalid_argument` при неверно закодированном имени или
`std::bad_alloc` при создании владеющего имени.

`changeOrderIndexSource` точно повторяет `OrderBase.setSource`: новый специальный
источник использует сдвиг48, остальные — сдвиг32. Старое значение определяет
маску: при специальном high16 сохраняются low48 (биржа и локальный индекс),
иначе low32. Новые биты источника объединяются OR с этим остатком. При смене
старого специального источника на обычный могут сохраниться перекрывающиеся
биты биржи; помощник их намеренно не нормализует. Беззнаковая арифметика и
побитовое преобразование исключают переполнение знакового сдвига C++.

Помощники принимают все signed64 битовые комбинации. Это не делает отрицательные
индексы события допустимыми: публичный Java `setIndex` их отвергает. Явно
отмеченная reflection-проба наблюдает production `getSource` / `setSource` на
иначе недостижимых отрицательных состояниях. Полное C++ событие Order и его
setter здесь не вводятся.

## Граница интеграции

Компонент подготовлен для использования полным typed Order адаптером. Здесь не
добавляются `EventType::ORDER`, доставка Order через Feed, маршрутизация подписок
по источнику, флаги возможностей, публикация и snapshot-семантика коллектора.
Они остаются в плане полного принимающего клиента. Quote/Profile и общий путь
записей сохраняют прежнее поведение. См. [пример](../../docs/ORDER-INDEX.ru.md)
и [контракт источников](EVENT-SOURCES.ru.md).
