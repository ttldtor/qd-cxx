# Идентичность источников индексированных событий и заявок

[English](EVENT-SOURCES.md). Английская версия является нормативной.

Независимая цель C++23 qdcxx_event_sources предоставляет
[IndexedEventSource](../../include/qd/events/indexed_event_source.hpp) и
[OrderSource](../../include/qd/events/order_source.hpp) в пространстве
org::ttldtor::qdcxx::events. Зависимость qdcxx_feed публичная. Чистая цель не
требует SDK, сети, настроек окружения или запуска.

Эталон: [upstream.lock](../../upstream.lock), ревизия
0ddc0a09779fb61d74cc0b37c6449ff47dcb715f, классы
dxfeed-api/src/main/java/com/dxfeed/event/IndexedEventSource.java и
dxfeed-api/src/main/java/com/dxfeed/event/market/OrderSource.java.
Наблюдения production-кода имеют приоритет над утверждением Javadoc о неотрицательном ID.

## Идентичность и разрешение

IndexedEventSource(id, name) принимает любой знаковый 32-битный ID и владеющую
nullable-строку точных единиц UTF-16: допускаются пустая строка, NUL и непарные
суррогаты. nullopt обозначает Java null. Нормализации Unicode нет.

Равенство учитывает только id(), игнорируя имя и семейство источника.
hashCode() возвращает точный знаковый ID. std::hash преобразует его в size_t;
это хеш контейнера C++, без обещания знакового представления Java.

OrderSource::valueOf(optional UTF-16 view) сначала ищет точное встроенное имя
с учётом регистра. Остальные имена должны содержать от одной до четырёх ASCII-букв
или цифр (0-9A-Za-z); последовательные единицы упаковываются в байты от старшего
к младшему. valueOf(int32_t) сначала ищет встроенный ID; иначе удаляет ведущие
нулевые байты и требует ASCII-букву или цифру в каждом оставшемся байте.
Внутренние нулевые байты, отрицательные ID и неизвестные малые специальные ID
недопустимы. Ноль разрешается в DEFAULT.

| ID | Встроенное имя |
| --- | --- |
| 0 | DEFAULT |
| 1, 2 | COMPOSITE_BID, COMPOSITE_ASK |
| 3, 4 | REGIONAL_BID, REGIONAL_ASK |
| 5, 6 | AGGREGATE_BID, AGGREGATE_ASK |
| 7, 8, 9 | COMPOSITE, REGIONAL, AGGREGATE |

Остальные встроенные источники используют ID из имени, включая NTV.
Для всех закреплённых встроенных источников есть константы. Строчные имена Java
получают прописные константы C++ с _LOWER (например, ntv → NTV_LOWER);
name() и valueOf сохраняют точное имя Java.
См. [захваченный перечень](../../tests/fixtures/event-sources/oracle.tsv).

## Владение и ошибки

Оба типа — владеющие значения с независимыми копиями, без обещания интернирования
или идентичности адресов. OrderSource использует композицию; indexedSource()
заимствует базовое значение. Имена возвращаются как заимствованные представления.
Ссылки и представления теряют силу при уничтожении, присваивании или перемещении
из владельца. Вход valueOf заимствуется только на время вызова.
Чтение неизменяемых значений не использует общий кеш.

Некорректные имена/ID заявок вызывают std::invalid_argument. Java
NullPointerException для null явно отображается в std::invalid_argument.
Операции с выделением памяти передают обычные std::bad_alloc/std::length_error,
не выдавая частичный результат. Текст ошибок не является контрактом совместимости.
Базовый конструктор не запрещает nullable-имена и знаковые ID.

Идентичность источника отличается от регионального кода биржи и физического маршрута.
Возможности источников, отображение Order/упаковка индекса, подписки и новые
сетевые события находятся за границами API.

## Соответствие

[Oracle](../../tools/upstream/event-source-oracle/README.ru.md) вызывает фактические
закреплённые production-классы с provenance и перечнями классов. Его 311 наблюдений
покрывают встроенные источники, обратимые преобразования, некорректные имена/ID,
nullable/пустые/некорректные UTF-16 имена базы, одинаковые ID с разными именами,
равенство и хеш между семействами. Тест C++ читает наблюдения напрямую.
[Руководство](../../docs/EVENT-SOURCES.ru.md) описывает независимый установленный API.
