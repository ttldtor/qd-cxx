# JSON разрешённой нативной схемы, версия 1

[English version](NATIVE-JSON.md). Английская версия нормативна.

Это спроектированный профиль `qdcxx-native` для владеющей обычной локальной схемы. Он следует
[ADR-0003](../../docs/decisions/ADR-0003-configurable-schemas-and-event-mappings.ru.md) и
[границе конфигурации](../../docs/CONFIGURATION.ru.md). Синтаксис JSON — политика проекта, а не
наблюдаемый формат Java. Существующие [контракт XML-captured](JSON-CONTRACT.ru.md), примеры и
provenance не меняются; этот загрузчик явно не поддерживает `qd-3.355-xml-captured`.

Отдельно выбранный профиль `loadBinaryJsonSchema` / `qdcxx-native-binary` описан в
[Native binary JSON](NATIVE-BINARY-JSON.ru.md). Обычный профиль и требования ниже сохранены.

## Документ и грамматика объектов

Вход — ровно один JSON-документ в UTF-8 с допустимыми пробелами JSON до и после него, без BOM.
Пустой вход или только пробелы, комментарии, завершающие запятые, последующие документы,
некорректный UTF-8, ошибочные escape-последовательности и непарные суррогатные escape-последовательности
означают ошибочный JSON. Корень должен быть объектом. Все перечисленные члены обязательны;
необязательных членов, расширений, выводимых значений по умолчанию и допустимых `null` нет.
Порядок членов несущественен; порядок массивов сохраняется. Неизвестные члены и повторные
**декодированные** имена членов отклоняются на каждом уровне нативных объектов:
`name` и `na\u006de` — один ключ.

| Объект | Точные члены и виды значений |
| --- | --- |
| Корень | `formatVersion`: целое; `profile`: объект; `records`: массив объектов record |
| Profile | `id`: строка; `version`: целое |
| Record | `id`: целое; `name`: строка; `hasTime`: boolean; `fields`: массив объектов field; `lookups`: массив объектов lookup |
| Field | `serialTypeId`: целое |
| Lookup | `name`: строка; `fieldId`: целое |

`formatVersion` равен `1`; `profile` — ровно `{"id":"qdcxx-native","version":1}`.
Версия формата определяет представление, версия профиля — семантику. Другие версии или ID профиля
корректного вида не поддерживаются; неявной миграции нет. Корневые версия и профиль читаются до
интерпретации записей. Распознанный старый XML-captured профиль отклоняется как неподдерживаемый до
проверки его неизвестных нативному формату корневых членов; это не проверяет и не исполняет его
отдельную грамматику.

Каждый числовой член имеет целочисленную запись JSON и значение в `0..2147483647`. Boolean, строки,
дробная или экспоненциальная запись (включая `1.0` и `1e0`), отрицательные значения и переполнение
некорректны как члены схемы. Целое `-0` имеет значение ноль и допустимо везде, где допустим ноль.
Синтаксически ошибочное число JSON означает ошибочный JSON. Числа вне представимого числового
диапазона DOM-парсера также дают `MALFORMED_JSON`; после успешного разбора неверные виды/диапазоны
дают `INVALID_SCHEMA`. Обе ошибки имеют exit 5. Ни один числовой член не принимается
путём округления через floating-point.

## Локальные записи, точные имена и lookup

`id` записи равен её позиции с нуля в `records`; это не wire sender ID. Имена записей непустые и
уникальны в документе. Каждое имя — точный текст из Unicode scalar values, преобразуемый во владеющий
UTF-16 без нормализации, удаления пробелов, изменения регистра или удаления точек. Эквивалентные
escape-последовательности и буквальные строки равны. Дополнительные символы занимают две UTF-16
units; экранированный NUL допустим и занимает одну unit. Имена записей и lookup следуют действующей
политике имён core.

Поддерживается только `hasTime:false`. Значение `true` запрашивает неподдерживаемую индексную
семантику; отсутствие члена, числовые и строковые подстановки некорректны. Поля — упорядоченные
логические значения, чьи неявные ID внутри записи равны позициям с нуля. Java slots, синтетические
VOID tails, aliases, property names и порядок полей не выводятся автоматически.

`serialTypeId` — полная identity, включая representation bits. Поддерживаются только
**2/8/10/40/56/72/88/120**, определённые в [FIELD-TYPES](../encoding/FIELD-TYPES.ru.md). Другие целые
ID в допустимом диапазоне — неподдерживаемые типы, даже при совпадении serialization bits. Это не
меняет wire-кодировки и семантику значений или значений по умолчанию.

Lookup names непустые и уникальны внутри содержащей записи с точным равенством UTF-16. Каждый
`fieldId` должен указывать на существующее поле этой записи. Разные lookup names могут указывать
на одно поле. Каждому полю нужен хотя бы один lookup. Порядок lookup сохраняется, но не разрешает
повторные ключи и не меняет target. Ключи могут повторяться в разных записях. Префиксы и aliases
не создаются автоматически; wire binding и подготовка событий используют только явные ключи.

`records:[]` — корректная пустая схема. Запись без полей корректна с `fields:[]` и `lookups:[]`;
её непустое имя всё равно расходует бюджет. Lookup в записи без полей имеет отсутствующий target
и некорректен. Каждая успешная загрузка использует `LocalProfile::EXTENDED_FIELDS_V1`, включая
пустые схемы и схемы только с int. Лишь полная проверка публикует владеющий неизменяемый
`LocalSchema`; время жизни входа и parser не распространяется на результат. Каждая независимая
загрузка создаёт независимую identity схемы. Копии, wire plans и
[подготовленные mappings](../events/EVENT-MAPPING.ru.md) сохраняют действующие правила контекста.

## Конечные ограничения загрузки

Значения по умолчанию библиотеки и внешнего CLI совпадают. Все ограничения логические и конечные,
включая ноль; равенство допустимо, превышение приводит к ошибке. Они не обещают точного предела
heap или линейного времени полной проверки. Проверка core остаётся нормативной для локальных
инвариантов.

| Параметр CLI | По умолчанию | Единица и учёт |
| --- | --- | --- |
| `--max-schema-bytes` | 1048576 | Все байты входа, включая пробелы |
| `--max-schema-depth` | 16 | Одновременно вложенные объекты/массивы; глубина корневого объекта равна 1 |
| `--max-schema-records` | 1024 | Число записей |
| `--max-schema-fields` | 16384 | Общее число полей всех записей |
| `--max-schema-lookups` | 32768 | Общее число lookup entries всех записей |
| `--max-schema-name-units` | 1024 | UTF-16 units одного имени записи/lookup |
| `--max-schema-total-name-units` | 1048576 | Сумма units всех имён записей/lookup, включая повторы в разных областях |

Скалярные значения не увеличивают глубину контейнеров. Заполненный объект field/lookup имеет
глубину 5. Проверки байтов документа и глубины ограничивают parsing, включая отклонённую структуру;
бюджеты имён охватывают семантические имена, а не фиксированные ключи грамматики или ID профиля.
Ограничение байтов по-прежнему ограничивает эти строки. Числа элементов и units имён проверяются
до пропорциональных владеющих выделений памяти. Временные коллекции членов/дубликатов также
ограничены. Арифметика padding parser и размеров выделения не должна переполняться. При ошибке
выделения памяти частичная схема не выдаётся. Пропуск входа и ошибка не разрешают безграничного
временного буфера.

Необязательная цель `qdcxx_schema_json` использует приватно закреплённый simdjson DOM. Публичный
API содержит только типы проекта/STL. Библиотека принимает переданные байты и ограничения, не
открывает файлы, не ищет environment/properties, не получает URLs/includes и не разыменовывает
provenance. Core, codecs, protocol и event mappings остаются независимыми от JSON и simdjson.

## Ошибки загрузки и порядок CLI

Ошибки библиотеки типизированы и не содержат копии входа, текста с временем жизни parser или
выдуманных позиций. При нескольких независимых дефектах общий порядок первой ошибки не обещается.
Ошибки байтов/глубины и JSON parsing могут остановить структурные проверки; распознавание
версии/профиля предшествует интерпретации записей. Ни один документ с повторными ключами или
неизвестными членами не может успешно пройти нативную грамматику.

| Стабильный код | Значение | Exit CLI |
| --- | --- | --- |
| `MALFORMED_JSON` | Ошибочные синтаксис, кодировка, escapes, BOM, пустой вход или последующий документ | 5 |
| `INVALID_SCHEMA` | Неверные набор/вид/диапазон членов, повторные декодированные ключи или локальные инварианты | 5 |
| `UNSUPPORTED_PROFILE` | Другой ID профиля, включая XML-captured | 4 |
| `UNSUPPORTED_VERSION` | Другая версия формата или нативного профиля | 4 |
| `UNSUPPORTED_TYPE` | Полный ID типа в диапазоне, но вне точного реализованного набора | 4 |
| `UNSUPPORTED_INDEXED` | Boolean `hasTime:true` | 4 |
| `RESOURCE_LIMIT` | Превышен конечный бюджет загрузки либо предел размера/глубины parser | 6 |
| `ALLOCATION_FAILURE` | Нельзя выделить необходимую владеющую память/parser storage | 6 |
| `IO_ERROR` | Ошибка открытия/чтения файла схемы; только CLI | 3 |
| `LOADER_DISABLED` | Внешняя схема запрошена в сборке с отключённым загрузчиком; только CLI | 4 |

`qdcxx-tape-inspect` требует `--input PATH` и ровно один источник: `--schema PATH` или
`--profile BUILTIN`. Повторные, конфликтующие или отсутствующие аргументы — usage errors (2).
Ограничения схемы используют действующую CLI-грамматику unsigned decimal; они не меняют бюджеты
декодированных записей/полей. Порядок: проверка аргументов, доступности загрузчика,
открытие/чтение/загрузка/проверка схемы, затем открытие tape. Поэтому ошибочная схема имеет приоритет
над отсутствующим tape. Схема читается один раз с ограничением самого чтения, даже если файл растёт
после начальной проверки размера. Отката к встроенному профилю нет.

Каждая ошибка загрузки схемы выводит одну ограниченную строку stderr в обоих форматах вывода и
обеих версиях diagnostics: `schema-error<TAB>1<TAB>CODE<LF>`, где `CODE` берётся из таблицы.
Путь/содержимое входа, выдуманная позиция, stdout header или record не выводятся. Ошибки схемы
отделены от protocol diagnostic enums. Последующие ошибки tape сохраняют действующие diagnostics
protocol/IO. Внешний режим по умолчанию использует diagnostics version 2 и принимает явно 1 или 2.
Defaults, diagnostics и приоритет ошибок встроенных профилей не меняются.

`ORG_TTLDTOR_QDCXX_BUILD_SCHEMA_JSON` по умолчанию ON. При OFF configure/build не получает simdjson;
встроенный просмотр остаётся доступным. Корректный запрос `--schema` возвращает `LOADER_DISABLED`
до открытия любого из файлов. Вызов без аргументов и отдельный `--help` по-прежнему эквивалентны:
stdout, пустой stderr и exit 0 при успешном выводе справки, без файлового IO. Ошибки вывода справки
сохраняют ненулевой exit.

## Identity внешнего вывода и строки

Отдельно выбранный tape mode — `legacy` по умолчанию либо `raw-message-v1`; JSON не выбирает и не
расширяет его. Оба режима используют output version **6**, profile identity **external-schema-v1**,
LF и отсутствие BOM. TSV header:
`format<TAB>qdcxx-tape-inspect<TAB>6<TAB>external-schema-v1<TAB>MODE<LF>`.
Human header:
`qdcxx-tape-inspect human 6 profile=external-schema-v1 tape-mode=MODE identities=local<LF>`.

Общие строки данных повторно используют типизированную
[грамматику FIELD-TYPES](../encoding/FIELD-TYPES.ru.md): семь TSV cells — `field-record`, frame index,
emitted index, local ID, record-name UTF-16 hex, symbol UTF-16 hex, values. Значения идут в локальном
порядке полей как разделённые запятой `type:raw:payload`. Скалярный payload — `-`; тип 10 имеет
raw zero и payload `null`, `empty` либо точные lowercase четырёхзначные UTF-16 units. При пустом
списке полей седьмая cell пустая. Пустые последовательности name/symbol используют действующую
кодировку `-` (имена схемы сами по себе не могут быть пустыми).

Human data rows: `Fields INDEX: frame=FRAME local=ID name=QUOTED symbol=QUOTED fields={ENTRIES}`.
Entries имеют вид `field[i]=(type:T raw:R)` для scalars и
`field[i]=(type:10 raw:0 units:null|QUOTED)` для строк; пустые поля дают `{}`. Безопасные кавычки
сохраняют точные units, включая controls и lone surrogates wire-значений. Business, calendar, price,
ShortString и Quote/Profile projection не выводятся автоматически из имени записи.

Строки descriptor, frame, timing, marker и completion сохраняют действующую грамматику выбранного
режима из [TAPE-READER](../protocol/TAPE-READER.ru.md) и [RAW-TAPE](../protocol/RAW-TAPE.ru.md).
RAW timing остаётся отдельным от field SEQUENCE. Общий вывод сохраняет каждое декодированное
локальное поле, включая дополнительные поля и custom records; неизвестные wire records следуют
действующей политике пропуска. Строки ограничиваются до выделения памяти/первой записи. Только
exit 0 после final flush означает успешный вывод. Встроенные профили сохраняют байты и версии
вывода, кроме расширения справки.

## Повторно используемые примеры и граница проверки

- [empty.json](examples/native/empty.json) задаёт корректную пустую схему.
- [field-types.json](examples/native/field-types.json) объявляет диагностический layout `FieldTypes`
  для неизменённых tapes [mixed STREAM](../../tests/fixtures/encoding/field-types/expected/mixed-stream.qtp)
  и [mixed RAW](../../tests/fixtures/encoding/field-types/expected/mixed-raw.qtp).
- [mixed.json](examples/native/mixed.json) сохраняет custom record со всеми восемью типами,
  переставленные поля Quote с обязательными prices/sizes, необязательным Sequence и дополнительным
  текстом, а также переставленные поля Profile с обязательным Description, выбранными необязательными
  полями и дополнительным ShortString. Явные ID 1 и 2 выбирают подготовку Quote/Profile; отсутствующие
  необязательные поля используют действующие правила mappings.

Примеры задают нативный синтаксис, а не новые наблюдения Java. Семантика полей/событий по-прежнему
основана на связанных контрактах и существующих oracle fixtures. Загрузка узнаваемого имени события
сама по себе не доказывает успешную подготовку события; подготовка использует явный ID, lookups,
типы и контекст. XML, разрешение Java properties, auto-detection, новые wire types/conversions,
живая замена схемы, transport и поддержка частного tape остаются вне этой границы. Выполненные
проверки и статус независимого ревью относятся к отчёту проверки реализации, а не к этим
спроектированным примерам.
