# Явные индексные схемы и неизменяемые поколения описаний

[English version](INDEXED-SCHEMAS.md). Английский текст является нормативным.

Это расширение чтения требует явного `LocalProfile::BINARY_FIELDS_V1`. Вызывающий код
передаёт проверенную локальную схему; имена wire не создают индексную разметку.
Частичный `TapeMode::BINARY_CATALOG_V1` добавляет замену активных описаний отправителя,
сохраняя ограниченную грамматику BINARY/NONE/EMPTY_SET/STREAM_DATA с нулевыми флагами.
Вход без заголовка, остальные семейства данных, опции и флаги, время FIELD и цепочки
источников остаются отдельными работами.
[Отчёт о проверке](../../tests/conformance/protocol/field-types/INDEXED-VALIDATION.ru.md)
различает выполненные проверки и оставшиеся ограничения.

## Хранилище источника и локальные значения

Java QD3.355 в `0ddc0a09779fb61d74cc0b37c6449ff47dcb715f` и QD3.356 в
`f71e4cb390d1586f2d4e3a83d9b9067e3326ef19` определяют индексное время курсора через
первые два физических целочисленных слота: сначала знаковое старшее слово32, затем биты
младшего слова32. `getTime`/`setTime` независимы от EventTimeSequence курсора и времени
tape MESSAGE/FIELD. См.
[время курсора](https://github.com/devexperts/QD/blob/0ddc0a09779fb61d74cc0b37c6449ff47dcb715f/qd-core/src/main/java/com/devexperts/qd/ng/RecordCursor.java#L511-L534),
[порядок слов](https://github.com/devexperts/QD/blob/0ddc0a09779fb61d74cc0b37c6449ff47dcb715f/qd-core/src/main/java/com/devexperts/qd/ng/RecordCursor.java#L1331-L1342)
и [вторую ревизию](https://github.com/devexperts/QD/blob/f71e4cb390d1586f2d4e3a83d9b9067e3326ef19/qd-core/src/main/java/com/devexperts/qd/ng/RecordCursor.java#L1331-L1342).

`LocalRecord.hasTime` остаётся явным признаком. Добавленное в конец необязательное
поле `indexedTimeLayout` владеет одним из следующих отображений:

| Вариант | Логические ID полей | Допустимые точные идентичности |
| --- | --- | --- |
| `IndexedTimePairInt32` | `firstField`, отличный от него `secondField` | Каждое full4/8/24/40/56/72/88 |
| `IndexedTimeSingleInt64` | `field` | Full104/120/152 |

Индексная запись требует разметку; обычная запись требует её отсутствия. Несогласованное
присутствие, одинаковые ID пары и ID вне диапазона дают INVALID_SCHEMA. Узкие BYTE/SHORT/
UTF_CHAR, VOID и объектные поля не сохраняют произвольные слова времени; их выбор в качестве
составляющих даёт UNSUPPORTED_PROFILE. Прежние локальные профили по-прежнему отклоняют
индексные записи и метаданные. Политика точных типов обычных полей сохраняется.

Физические слоты источника, логические ID локальных полей, порядок wire-полей, ID отправителя,
локальные ID записей и позиции декодированных значений — разные области. При создании контекста
локальная разметка разрешается в добавленное в конец владеющее поле
`StreamRecordPlan.indexedTimeLayout`: `ResolvedIndexedTimePairInt32` либо
`ResolvedIndexedTimeSingleInt64`. Оно переживает уничтожение схемы. Сейчас локальные ID полей
равны проверенным позициям; это не разрешает использовать слот Java или разреженный ID
отправителя как индекс значения.

Беззнаковое объединение слов с последующим битовым приведением к signed64 сохраняет все биты
без переполнения знакового сдвига. Поле single64 уже хранит их. Преобразований Decimal,
единиц времени и бизнес-значений нет. Отсутствующие wire-поля сохраняют свежие плотные значения
по умолчанию; повторные присваивания выполняются по порядку, последнее побеждает. Перестановка
wire-полей и явные aliases меняют действия связывания, а не разрешённые позиции.
Дублирующего поля indexedTime в доставленной записи нет.

Производственные LONG104/WIDE_DECIMAL120/TIME_MILLIS152 занимают по два целочисленных слота Java.
Их проверенный физический хвост VOID исключён из логических значений и wire-описаний.
Самостоятельный явно описанный VOID сохраняет отдельный
[контракт поля](../encoding/FIELD-TYPES.ru.md).
[BinaryRecordDesc](https://github.com/devexperts/QD/blob/0ddc0a09779fb61d74cc0b37c6449ff47dcb715f/qd-core/src/main/java/com/devexperts/qd/qtp/BinaryRecordDesc.java#L162-L216)
использует фактические property names и опускает хвосты. В DESCRIBE_RECORDS нет бита hasTime.
Существующие [экспортёр Java](JAVA-EXPORT.ru.md) и загрузчик native-v1 по-прежнему отклоняют
индексный вход. Проверенные вручную метаданные и наблюдения источника не расширяют этот формат.

## Явный выбор политики протокола

Используйте конструктор TapeReader с переданной схемой BINARY_FIELDS_V1 и режимом
BINARY_CATALOG_V1. Конструктор обычного обнаружения схемы отклоняет новый режим. Прежние режимы
tape сохраняют допуск обычных схем, отказ при повторном sender ID, поведение пустого пакета и
вывод; индексные схемы они отклоняют. Значения по умолчанию и выбор inspector не меняются.

Новый режим хранит одну разреженную таблицу активных отправителей в порядке первого появления.
Замена сохраняет позицию, новый ID добавляется в конец. INT_MAX — ключ, а не индекс выделения
памяти. Локальные ID остаются ID переданной схемы. Смена имени может связать другую локальную
запись либо дать поддерживаемый план пропуска. Descriptions() показывает активные записи,
а не историю объявлений.

Для каждого полного непустого пакета проверяются все элементы по порядку wire, включая
промежуточные заменяемые элементы. Последнее допустимое описание отправителя определяет
кандидат. Создаются новая identity схемы и новый контекст, затем схема, описания и контекст
публикуются через проверенные статически небросающие перемещения и обмены. Равные числовые
формы получают новую identity. Пустой пакет ничего не меняет. Пользовательские callbacks
между публикациями не вызываются; это однопоточная гарантия.

Ошибки разбора, типов, ресурсов и выделения памяти не публикуют ни одного элемента пакета.
Прежние заимствованные адреса, значения и provenance сохраняются; счётчики работы и терминальная
диагностика могут измениться. Владеющие записи, копии контекстов и снимки схем независимы.
Заимствованные представления истекают при успешной публикации, перемещении, присваивании либо
уничтожении владельца. Reader хранит только текущее поколение.

[Цикл парсера Java](https://github.com/devexperts/QD/blob/0ddc0a09779fb61d74cc0b37c6449ff47dcb715f/qd-core/src/main/java/com/devexperts/qd/qtp/BinaryQTPParser.java#L354-L410)
устанавливает полные описания сразу; поздняя ошибка может сохранить предыдущие изменения.
C++ намеренно выбирает откат всего пакета и точное совпадение типов, отклоняя измеренное
Java-преобразование wire4 в local8, даже если более поздний элемент заменил бы такой элемент.

Для независимого закрытого источника явно создавайте новый reader. Старые описания отправителя
ему недоступны; прежний владеющий результат сохраняется. Reset Java остаётся применимым
наблюдаемым поведением. Сброс существующего C++ reader, неявный сброс по заголовку и политика
цепочек источников не добавлены.

## Точные конечные логические бюджеты

Новому режиму нужен добавленный в конец `TapeLimits.snapshotUnits`; ноль конечен. Прежние режимы
игнорируют его. Существующие лимиты схемы, входных полей/имён и конечного контекста независимы.
`context.descriptions` ограничивает входные попытки вместе с повторами и отдельно — число
уникальных активных отправителей. Работа накапливается без возврата.

| Категория | Логические единицы |
| --- | --- |
| S, схема | Одна identity, записи, поля, lookup-элементы, владеющие UTF-16 units имён/ключей, одна присутствующая локальная разметка |
| D, исходные описания | Описания, объявленные элементы полей, владеющие units имён записей/полей |
| C, контекст | Планы, действия, заголовки векторов defaults и значения defaults, одна присутствующая разрешённая разметка на индексный план |
| Временная проверка | Один план и его действия полей |

Пик включает одновременно существующие прежние S+D+C, исходный staging, копии кандидата,
новую схему/контекст и временную проверку. Слоты полей staging допускаются по проверенному
счётчику до конструирования. Имена измеряются без выделения через существующие compact/UTFChar
примитивы, затем точное число units допускается до владеющего декодирования UTFString.
Ёмкость векторов, метаданные allocator и внешние копии вызывающего кода не являются этими
единицами или измерением RSS. Память кадров, заголовка, данных и результатов имеет отдельные лимиты.

Работа учитывает S+C конструктора, допущенные байты payload описаний, создание исходных
метаданных, каждую копию кандидата/схемы/контекста и каждый временный план связывания.
Уничтожение staging освобождает хранение, но не возвращает работу. Поток равных замен
достигает точных лимитов без истории. Счётчики завершённых payload/строк сохраняют
накопительную семантику между поколениями.

В ограниченном примере переставленной Pair: S28, пустой C4, D23, активный C9. Конструктор
стоит32, первый пик92, пик замены129. Full72 требует два compact-байта, поэтому первая
накопленная работа148, каждая равная замена добавляет139. Это проверки конкретного примера,
а не универсальные константы или размеры heap. Проверки используют вычитание перед сложением.
Исключения выделения сохраняют прежнюю типизированную терминальную ошибку; частичный кандидат
не публикуется.
