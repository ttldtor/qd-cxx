# Требования к normalized model

[English version](NORMALIZED-MODEL.md). Английский документ является основным.

Статус: **предложение**, QDCXX-007; решение: [ADR-0001](../../docs/decisions/ADR-0001-normalized-model-boundaries.ru.md), **proposed**. «Требуется» ниже означает предлагаемое требование, а не принятую политику совместимости. Здесь не реализованы формат, importer, публичный C++ API или изменение oracle expectations.

## Доказательства и начальный профиль

База: Java QD 3.355, `0ddc0a09779fb61d74cc0b37c6449ff47dcb715f`. **C** — зафиксированное наблюдение; **S** — исходный код закреплённой версии из [schema SOURCES](SOURCES.md) или [protocol SOURCES](../protocol/SOURCES.md); **P** — проектное предложение; **U** — непроверенное поведение или нерешённый вопрос. Исходный код не доказывает runtime-покрытие. Границы сравнений задают schema [coverage](../../tests/fixtures/schema/COVERAGE.md) и [validation](../../tests/fixtures/schema/VALIDATION.md), protocol [coverage](../../tests/fixtures/protocol/COVERAGE.md), [validation](../../tests/fixtures/protocol/VALIDATION.md) и [CAPTURES](../protocol/CAPTURES.md).

**P:** Начать с 17 schema-подслучаев и девяти protocol cases как отдельных целей совместимости. Schema-профиль использует прямые XML loaders, отключённые sysprops/dxprops и зафиксированное окружение JDK/JAXP/providers. Protocol cases используют программные схемы; P05 — свежие настоящие connection parser/composer с инструментированием heartbeat/protocol metadata. Это не доказывает эквивалентность протокольного поведения произвольного XML. Искусственные schema records не имеют mappings при зафиксированных пяти factory providers; это не доказывает отсутствие mappings для известных dxFeed events. Ни одно семейство S01/S04/S05/S07/S08/S15 или P01/P03/P04/P05 не покрыто целиком.

**P:** Локальный артефакт может происходить из XML или программного построения. Неизвестные source metadata явно недоступны, а не выдумываются из runtime names. ## Локальные инварианты и сохранение данных

1. **P, C:** Сохранять порядок выпущенных records и local IDs внутри именованного schema snapshot; IDs не являются глобальными идентификаторами. S04-order-disabled выпускает Alpha=0, Beta=1 и исключает HiddenRecord. В provenance сохранять порядок semantic declarations/generation отдельно от int/object order. Никогда не выводить порядок records из зафиксированного обхода HashMap. S: SchemeModel.generationOrder, DXScheme.loadRecords, DefaultScheme constructor в [model/runtime sources](SOURCES.md).
2. **P, C:** Представлять логические поля отдельно от явной Java-compatible slot projection: category, ordinal, serial type, synthetic role и owning field/index position. S15-slots содержит головы LONG/WIDE_DECIMAL и VOID tails; S05 — отсутствующие/отключённые time positions. Сохранять их диагностические имена и lookup results в projection. VOID не является самостоятельным прикладным значением. Физическое хранение C++ может использовать одно 64-битное значение или другую структуру; требование Java arrays/classes отсюда не следует. Index roles и hasTime относятся к локальной семантике, а не к предполагаемому wire flag. Неподдерживаемые формы индексов остаются U.
3. **P, C/S:** Разделять semantic source name (если известно), effective main name, full/local/final property names и lookup scopes. Explicit-main declaration metadata хранить в provenance независимо от effective selection. Разделять record-level lookup keys и scheme-level full-name lookup; не создавать prefixed aliases. C: S07-explicit/fallback, S08-main-alias; S: DefaultRecord name installation/addFieldAlias, AbstractDataField.setRecord. Правила collision/removal/overlay ordering сверх captures — U, а не разрешение сортировать или дедуплицировать aliases.
4. **P, C/S:** Сохранять полный числовой SerialFieldType ID, включая representation bits; отображаемого имени или категории хранения «integer» недостаточно. Разделять declared custom type chain в provenance, resolved embedded type и construction support. C: S15-slots (8, 10, 9, 104, 120), S15-byte/short (1, 3); S: SerialFieldType, DefaultEmbeddedTypes, SchemeType. Не считать каждый распознанный тип конструируемым, конвертируемым или поддерживаемым на wire во всех контекстах.
5. **P:** Публикуемый resolved artifact представляет только успешное построение. Отдельный resolution result может сохранять успешную source model и неуспешную local-construction stage, input location, type и reason. Java exception/cause остаются диагностическими доказательствами; не превращать ошибку построения в успешную пустую схему. C: S01-no-urls против S01-empty; S05-disabled-both; S15-byte/short.
6. **P, S:** Сохранять templates, generator/visibility rules, disabled records/fields, docs, enums, tags, bitfields и custom type declarations в provenance, даже если их нет среди активных local fields. В core artifact экспортировать только resolved fields/roles/names/types и необязательные ссылки на неисполняемые metadata. Tags могут влиять на visibility, custom types — на resolution до этой границы; enums/bitfields не должны превращаться в generated event mappings. S: [inventory](README.md), SchemeModel/Generator/VisibilityRule, DXScheme.buildOneRecord. Полная семантика их исполнения отложена; сохранение не означает поддержку. Будущий importer должен сообщать о неподдерживаемых конструкциях, а не молча терять их эффект.
7. **P, S/U:** Записывать provider identities/order, classpath fingerprints, loader options и effective property profile в resolution provenance. Java mapping class names — наблюдения, а не переносимые реализации. XML loadMappings пуст; Java RecordMappingFactory services могут влиять на names, defaults и behavior. Known-event mappings, VersionedRecord update behavior, dxFeed property/regional/Nuam profiles и withProperties isolation требуют отдельных проб (SC-06/07). Начальный артефакт не обещает это поведение. Java digest можно сохранить как доказательство, но нельзя использовать как полную semantic identity: DefaultScheme.calculateDigest исключает alias tables и source metadata.

## Инварианты направленного протокола

**P, C/S:** Хранить sender ID и record name полученного descriptor независимо от resolved local record ID; упорядоченные field descriptions — независимо от local slot ordinals. Сопоставлять по наблюдаемому name lookup. Будущий adaptation plan должен различать assign, convert и consume-without-delivery, но их полная матрица — U (P06/P07/P08). Не приравнивать unknown record к undescribed ID и не утверждать безопасный skip при всех unknown-record options (QT-03). Источники: BinaryQTPParser.remapRecord, BinaryRecordDesc, [schema exchange](../protocol/SCHEMA-EXCHANGE.md).

**P, C:** Представлять requests как absent, originally zero fields или nonempty ordered list. Сохранять исходный request, даже если selection даёт zero fields. Хранить selected output names/types/order и outgoing sender ID отдельно от request. P05-none/zero выбирают x,y; P05-x выбирает x; P05-z не выбирает полей, но доставляет R/ABC. Каждый случай — первое использование writer на свежем connection. Здесь не выбраны правила dynamic update, reset/cache invalidation, negotiation или lifetime (QT-04/07). Session/direction identifier предотвращает случайное повторное использование между peers; API и concurrency implementation остаются открытыми.

**S, P:** Default wire construction использует property names, сначала integer, затем object fields, исключает VOID и сохраняет полные serial type IDs; optional built-in metadata имеют отдельные protocol roles. Numeric field IDs, alias table и отдельный hasTime flag не передаются. Сохранять это различие в модели; requested order не обязан совпадать с default order. Источники: BinaryQTPComposer.describeRecord, BinaryRecordDesc, BuiltinFields. Исключение VOID установлено по исходникам, но не измерено LONG/time-index wire capture в QDCXX-006.

**S/U:** Полный selected wire type ID может отличаться от local type: default writer path BinaryRecordDesc заменяет WIDE_DECIMAL на DECIMAL при отключённой wide-decimal support. Хранить local, requested и selected type identities отдельно. Version-dependent adaptation не измерена compact-int cases P05 и остаётся отложенной вместе с P06/P09.

## Предложение по представлению и версиям

**P:** Предпочтителен версионируемый data-only JSON interchange для resolved artifacts и необязательных protocol diagnostic snapshots: ordered arrays для семантического порядка, явные ссылки на local IDs/fields/provenance. Использовать строки имён без case/dot normalization, integer serial IDs, различные absent/null/empty semantics и отдельную версию compatibility profile. До сериализации определить точные numeric domains (включая точное представление будущих 64-битных значений); задача не выбирает JSON library или formal schema dependency. Не сериализовать runtime pointers, Java classes как исполняемые типы, caches или sockets.

**P:** Format versions описывают представление; profile versions — поведение. Неизвестная обязательная семантика/версия должна приводить к явной ошибке; optional extension metadata можно сохранить без исполнения. При deterministic serialization сохранять ordered arrays; canonical bytes/hashes определить позже. Разделять source/provenance identity, local semantic identity и session identity. Эквивалентность Java digest и точный XML round trip не обещаются. Будущий golden для interchange должен быть отдельно проверенной projection, а не перезаписью Java TSV.

Альтернативы: runtime-only JSON меньше, но теряет объяснение overlays; единый XML AST/runtime/wire graph сохраняет всё, но связывает lifetimes и провоцирует путаницу IDs; прямое принятие TSV удобно для diff, но привязывает модель к observation rows и exception formatting; XML interchange использует исходный синтаксис, но плохо выражает resolved/session distinctions; binary format компактен, но преждевременен без проверенной модели. Выбор представления обратим до принятия последующего serialization contract.

## Условия решений и ограниченное продолжение

См. [backlog](../../docs/NEXT-STEPS.ru.md). Утверждение владельцев уровней, сохранения metadata, pinned copy behavior, structured error deviation и направления JSON требуется для importer contract, а не для этой документационной задачи. Точные JSON schema/public API остаются открытыми.

Необходимые пробы перед расширением scope: alias-copy вместе с known mapping/property/wire observation перед выбором исправленной семантики; alias collision/removal/defaulted-overlay order перед поддержкой таких overlays; LONG/time-index wire descriptions перед заявлением slot-to-wire conformance; requested y,x order/type mismatches и изменения до/после использования writer/reset перед dynamic layouts; ограниченные primitive boundaries/malformed input и P06 перед поддержкой conversions. Ни одна из них не выполнена QDCXX-007.

Можно отложить при явном исключении: полный dxFeed property/provider parity, generators/regional profiles, parser lexical edges, mapping getters, PART/auth/timing и широкое rebuild behavior. Они блокируют заявления об этих возможностях, но не представление из трёх уровней. Существующие [open questions](../../docs/upstream/OPEN-QUESTIONS.md) остаются открытыми, пока доказательства и решения действительно их не разрешат.
