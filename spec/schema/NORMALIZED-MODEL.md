# Normalized-model requirements

[Русская версия](NORMALIZED-MODEL.ru.md). This English document is authoritative.

Status: **proposal**, QDCXX-007; decision: [ADR-0001](../../docs/decisions/ADR-0001-normalized-model-boundaries.md), **proposed**. “Require” below means a proposed requirement, not accepted compatibility policy. No format, importer, public C++ API or changed oracle expectation is implemented here.

## Evidence and initial profile

Baseline: Java QD 3.355, `0ddc0a09779fb61d74cc0b37c6449ff47dcb715f`. **C** means a captured observation; **S** means the locked source indexed in [schema SOURCES](SOURCES.md) or [protocol SOURCES](../protocol/SOURCES.md); **P** means a design proposal; **U** means unmeasured or undecided. Source facts do not establish runtime coverage. The schema [coverage](../../tests/fixtures/schema/COVERAGE.md) and [validation](../../tests/fixtures/schema/VALIDATION.md), protocol [coverage](../../tests/fixtures/protocol/COVERAGE.md), [validation](../../tests/fixtures/protocol/VALIDATION.md) and [CAPTURES](../protocol/CAPTURES.md) bound every comparison.

**P:** Start with the 17 schema subcases and nine protocol cases as separate compatibility targets. The schema profile uses direct XML loaders, sysprops/dxprops disabled and the recorded JDK/JAXP/provider environment. Protocol cases use programmatic schemes; P05 uses fresh real connection parser/composer paths with heartbeat/protocol metadata instrumentation. These are not proof that arbitrary XML produces equivalent protocol behavior. Artificial schema records have no mappings under the recorded five factory providers; this does not establish mapping absence for known dxFeed events. No entire S01/S04/S05/S07/S08/S15 or P01/P03/P04/P05 family is covered.

## Local invariants and retention

1. **P, C:** Preserve emitted record order and local IDs within a named schema snapshot; IDs are not global identities. S04-order-disabled emits Alpha=0, Beta=1 and omits HiddenRecord. Preserve semantic declaration/generation order in provenance and distinguish it from int/object order. Never derive record order from captured HashMap iteration. S: SchemeModel.generationOrder, DXScheme.loadRecords, DefaultScheme constructor in [model/runtime sources](SOURCES.md).
2. **P, C:** Represent logical fields separately from an explicit Java-compatible slot projection: category, ordinal, serial type, synthetic role and owning field/index position. S15-slots has LONG/WIDE_DECIMAL heads and VOID tails; S05 has missing/disabled time positions. Preserve their diagnostic names and lookup results in the projection. VOID is not an independent application value. Physical C++ storage may use a single 64-bit value or other layout; no Java array/class requirement follows. Index roles and hasTime belong to local semantics, not an inferred wire flag. Unsupported index shapes remain U.
3. **P, C/S:** Keep semantic source name (when known), effective main name, full/local/final property names and lookup scopes distinct. Retain explicit-main declaration metadata in provenance independently of effective selection. Preserve record-level lookup keys and scheme-level full-name lookup separately; do not manufacture prefixed aliases. C: S07-explicit/fallback, S08-main-alias; S: DefaultRecord name installation/addFieldAlias, AbstractDataField.setRecord. Collision/removal/overlay ordering rules beyond captures are U, not a license to sort or deduplicate aliases.
4. **P, C/S:** Retain full numeric SerialFieldType ID including representation bits; a display name or “integer” storage category is insufficient. Distinguish declared custom type chain in provenance from resolved embedded type and construction support. C: S15-slots (8, 10, 9, 104, 120), S15-byte/short (1, 3); S: SerialFieldType, DefaultEmbeddedTypes, SchemeType. Do not infer that all recognized types are constructible, convertible or wire-supported in every context.
5. **P:** A published resolved artifact represents successful construction only. A separate resolution result can retain a successful source model plus a failed local-construction stage, input location, type and reason. Keep Java exception/cause evidence in diagnostics; do not turn a failed construction into an empty successful schema. C: S01-no-urls versus S01-empty; S05-disabled-both; S15-byte/short.
6. **P, S:** Retain templates, generator/visibility rules, disabled records/fields, docs, enums, tags, bitfields and custom type declarations in provenance, even when omitted from active local fields. Export only resolved fields/roles/names/types to the core artifact, plus optional non-executable metadata references. Tags can affect visibility and custom types affect resolution before this boundary; enums/bitfields must not become generated event mappings. S: [inventory](README.md), SchemeModel/Generator/VisibilityRule, DXScheme.buildOneRecord. Their full execution semantics are deferred; retention is not support. A later importer must report unsupported constructs rather than silently drop their effect.
7. **P, S/U:** Record provider identities/order, classpath fingerprints, loader options and effective property profile as resolution provenance. Java mapping class names are observations, not portable implementations. XML loadMappings is empty; Java RecordMappingFactory services can affect names, defaults and behavior. Known-event mappings, VersionedRecord update behavior, dxFeed property/regional/Nuam profiles and withProperties isolation require separate probes (SC-06/07). The initial artifact does not promise those behaviors. Java digest may be retained as evidence, never used as a complete semantic identity: DefaultScheme.calculateDigest omits alias tables and source metadata.

## Directional protocol invariants

**P, C/S:** Store a received descriptor's sender ID and record name independently of its resolved local record ID; its ordered field descriptions independently of local slot ordinals. Bind by the observed name lookup surface. A future adaptation plan must distinguish assign, convert and consume-without-delivery, but their full matrix is U (P06/P07/P08). Do not treat an unknown record as an undescribed ID, or assert all unknown-record options safely skip (QT-03). Sources: BinaryQTPParser.remapRecord, BinaryRecordDesc, [schema exchange](../protocol/SCHEMA-EXCHANGE.md).

**P, C:** Represent requests as absent, originally zero fields, or a nonempty ordered list. Preserve the original request even if selection yields zero fields. Keep selected output names/types/order and outgoing sender ID separate from that request. P05-none/zero select x,y; P05-x selects x; P05-z selects no fields and still delivers R/ABC. Each is first writer use on a fresh connection. No dynamic update, reset/cache invalidation, negotiation or lifetime rule is selected here (QT-04/07). A session/direction identifier prevents accidental cross-peer reuse; its API and concurrency implementation remain open.

**S, P:** Default wire construction uses property names, integer then object fields, omits VOID and retains complete serial type IDs; optional built-in metadata has separate protocol roles. No numeric field IDs, alias table or standalone hasTime flag are exchanged. Preserve that distinction in the model; requested order need not equal default order. Sources: BinaryQTPComposer.describeRecord, BinaryRecordDesc, BuiltinFields. VOID omission is source-established, not measured by a LONG/time-index wire capture in QDCXX-006.

**S/U:** The complete selected wire type ID can differ from the local type: BinaryRecordDesc's default writer path falls back from WIDE_DECIMAL to DECIMAL when wide-decimal support is disabled. Retain local, requested and selected type identities separately. Version-dependent adaptation is not measured by the compact-int P05 cases and remains deferred with P06/P09.

## Representation and versioning proposal

**P:** Prefer a versioned, data-only JSON interchange for resolved artifacts and optional protocol diagnostic snapshots, with ordered arrays for semantic order and explicit references for local IDs/fields/provenance. Use strings for names without case/dot normalization, integer serial IDs, distinct absent/null/empty semantics, and a separate compatibility profile version. Specify exact numeric domains before serialization (including an exact representation for any future 64-bit values); this task does not choose a JSON library or formal schema dependency. Do not serialize runtime pointers, Java classes as executable types, caches or sockets.

**P:** Format version changes describe representation; profile versions describe behavior. Unknown required semantics/version must fail explicitly; optional extension metadata may be retained without execution. Preserve ordered arrays under deterministic serialization; define canonical bytes/hashes later. Keep source/provenance identity, local semantic identity and session identity separate. No Java digest equivalence or round-trip XML fidelity is promised. A future golden for this interchange must be a separately reviewed projection, never an overwrite of Java TSV.

Alternatives: runtime-only JSON is smaller but loses overlay explanations; a unified XML AST/runtime/wire graph retains everything but couples lifetimes and encourages ID confusion; direct TSV adoption is easy to diff but binds the model to observation rows and exception formatting; XML interchange reuses source syntax but cannot naturally represent resolved/session distinctions; a binary format is compact but premature without a reviewed model. Representation choice is reversible until the later serialization contract is accepted.

## Decision gates and scoped follow-up

See [backlog](../../docs/NEXT-STEPS.md). Approval of layer ownership, metadata retention, pinned copy behavior, structured error deviation and JSON direction gates an importer contract, not this documentation task. The precise JSON schema/public API remains open.

Essential probes before widening scope: alias-copy plus known mapping/property/wire observation before choosing repaired semantics; alias collision/removal/defaulted-overlay order before supporting those overlays; LONG/time-index wire descriptions before claiming slot-to-wire conformance; requested y,x order/type mismatches and before/after-writer/reset changes before dynamic layouts; bounded primitive boundaries/malformed input and P06 before conversion support. None has been executed by QDCXX-007.

Safely deferred by explicit exclusion: full dxFeed property/provider parity, generators/regional profiles, parser lexical edges, mapping getters, PART/auth/timing and broad rebuild behavior. They block claims about those features, not the three-layer representation. Existing [open questions](../../docs/upstream/OPEN-QUESTIONS.md) stay open until evidence and decisions actually resolve them.
