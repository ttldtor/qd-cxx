# Офлайн-экспорт разрешённой Java-схемы

[English version](JAVA-EXPORT.md). Английский документ является нормативным.

Этот контракт определяет явно запускаемый инструмент разработчика: переход от закреплённой Java
`DataScheme` к существующему [native JSON version 1](NATIVE-JSON.ru.md) согласно
[ADR-0003](../../docs/decisions/ADR-0003-configurable-schemas-and-event-mappings.ru.md).
Java строит и экспортирует схему; обычные C++ API загрузки, просмотра и подготовки событий используют
результат без Java. Нативный конструктор XML и общий механизм настроек не добавляются.
[Руководство](../../tools/schema-export/README.ru.md) описывает запуск;
[авторская проверка](../../tests/conformance/schema-export/VALIDATION.ru.md) отдельно фиксирует
выполненные проверки и статус независимой приёмки.

## Граница источников

Повторно используемый экспортёр принимает уже разрешённую `DataScheme`, необязательный точный выбор
записей и явные конечные лимиты. Он не читает properties, файлы или окружение, не изменяет переданные
объекты и глобальное состояние. Вызывающая сторона обеспечивает неизменность схемы и aliases во
время экспорта. Произвольные реализации и конкурентные изменения находятся вне контракта.

Офлайн-команда запускается в новой JVM JDK 8 с проверенным закреплённым classpath. Отдельный адаптер
источников вызывает производственные пути построения Java. `--source` принимает ровно один режим:

- `default`: закреплённый singleton `DXFeedScheme`, инициализируемый после явных startup settings.
- `endpoint`: разрешённая схема FEED endpoint без подключения, построенная с явными настройками;
  построение endpoint не разрешает подключение, поиск properties-файла или получение данных.
- `xml`: `DXScheme.Loader` с явно заданными property options и предварительно проверенными источниками.

Команде требуется `--output NEW_DIR`. Без аргументов и с отдельным `--help` выводится одинаковая
справка в stdout, stderr пуст, после успешного вывода код 0; работа и файловый IO не начинаются.
Непустые некорректные, повторные и неполные аргументы — ошибки использования. Ошибка вывода справки
сохраняет ненулевой код. Повторяемый `--record NAME` выбирает точные имена записей; повтор одного
имени — ошибка. Без выбора экспортируются **все** исходные записи, а не неявное подмножество Quote/Profile.

`--startup KEY=VALUE` задаёт startup settings. `--properties FILE` явно выбирает один properties-файл
endpoint или XML; `--set KEY=VALUE` задаёт переопределения builder endpoint или XML loader. Повтор ключа в
одном источнике запрещён, а один ключ в разных источниках сохраняет сведения об источнике и
разрешается закреплённым производственным путём. Отсутствие свойства не равнозначно явному false.
Разрешено только исследованное подмножество из [CONFIGURED-EVENTS](CONFIGURED-EVENTS.ru.md):

| Настройка | Допустимое явное значение |
| --- | --- |
| `dxscheme.nanoTime`, `dxscheme.wide` | `true` или `false` |
| `dxscheme.enabled.Sequence`, `dxscheme.enabled.TimeNanoPart` | 1–128 символов по `[A-Za-z*][A-Za-z0-9*]*`; только `*` означает wildcard |
| `dxscheme.price`, `dxscheme.size`, `dxscheme.shares` | `int`, `wide`, `tiny`, `decimal`, без учёта регистра |

Неподдерживаемые итоговые полные типы всё равно отклоняются при проекции: допустимое значение
настройки не разрешает преобразование типа. Неизвестные ключи, настройки подключений и неявный поиск
properties-файла запрещены. Синтаксис properties-файла — `Properties.load(InputStream)`; повторные
декодированные ключи запрещены. Настройки проверяются до инициализации Java-схемы. Для измеренного
подмножества endpoint приоритет таков: builder override, затем явный файл, затем startup. Режим
default принимает только startup settings. XML options `--xml-sysprops true|false` и
`--xml-dxprops true|false` по умолчанию false и управляют стадиями system/explicit properties
закреплённого loader. Настройки, которые выбранный источник/options не может применить, отклоняются,
а не объявляются действующими. В частности, `dxscheme.shares` отклоняется в режиме XML, поскольку
этот источник его не применяет. Явные XML settings перекрывают startup settings, когда обе стадии
включены. Явный выбор полей независимо перекрывает сокращение nanoTime. Общий порядок приоритетов
за пределами этих потребителей не подразумевается.

Launcher отклоняет `JAVA_TOOL_OPTIONS`, `_JAVA_OPTIONS` и `JDK_JAVA_OPTIONS`. Команда использует
контролируемый snapshot properties и не принимает произвольные service providers или расширения
classpath. Проверка runtime, classpath и upstream относится к границе инструмента, а не к C++ loader,
и не доказывает доверенность произвольного Java-кода, вызывающего экспортёр.

## Граница XML-ресурсов

Локальный XML требует одного явного `--input-root DIR`. Повторяемые `--xml RELATIVE` задают
упорядоченные корни/overlays внутри него. `--resource dxlink` явно выбирает закреплённый встроенный
`dxlink.xml` и требуемую им зависимость `dxfeed.xml`. Произвольные ресурсы этим не разрешаются.

До запуска `DXScheme.Loader` XML reader с защитными настройками проверяет ограниченное замыкание
локальных импортов и копирует принятые байты в собственное временное дерево, сохраняя относительные
пути. Относительные imports разрешаются от импортирующего файла, после разрешения реального пути
должны оставаться внутри объявленного корня и не могут содержать URL schemes, абсолютные пути или
выход за корень. Циклы imports, DOCTYPE, внешние entities, XInclude, `xml:base` и удалённые
корни/imports запрещены. Относительный путь содержит 1–240 ASCII-букв/цифр, `_`, `.`, пробел,
`/` или `-`, без начальных/конечных пробельных символов. Компоненты `..` допустимы только при
разрешении пути внутри корня. Закреплённые ресурсы и байты их зависимостей учитываются явно; импорт произвольного
встроенного ресурса не является запасным вариантом.

Разрешено точное закреплённое объявление namespace/schema
`https://www.dxfeed.com/datascheme dxfeed-schema.xsd`, обеспеченное XSD закреплённого classpath.
Другие пользовательские или удалённые schema locations отклоняются. Предварительный parser запрещает
внешний доступ к DTD/schema и проверяет эти настройки. До инициализации QD parser доступ JAXP к DTD
и stylesheets запрещается, а schema ограничивается `file`: закреплённый JDK 8 требует этого для
точного разрешённого локального объявления. Одна закреплённая XSD копируется рядом с каждым XML
snapshot; пользовательская замена XSD и её зависимости import/include отклоняются. Невозможность
обеспечить совместную границу preflight/snapshot завершает операцию ошибкой; полный запрет внешнего
schema-access не заявляется. Upstream loader получает только snapshot. Предварительная проверка управляет доступом к
ресурсам, оставляя семантику записей, aliases, типов и overlays Java. Это инструмент разработчика для
доверенных локальных входов, а не универсальный сервис для враждебного XML; точный предел heap при
построении upstream не гарантируется.

## Записи, логические поля и полное отношение lookup

Записи сохраняют исходный порядок независимо от порядка запроса. Каждое запрошенное имя должно
встречаться в источнике ровно один раз; неизвестные/повторные имена прерывают всю операцию.
Экспортированные ID — последовательные позиции массива от нуля. Provenance фиксирует исходные и
экспортированные ID, включая совпадающие отображения. Поддерживаемая пустая схема остаётся допустимым
пустым экспортом.

Выбранные записи должны иметь точную закреплённую реализацию `DefaultRecord` и `hasTime:false`.
Подклассы, включая специальный XML `VersionedRecord`, не поддерживаются. ID, имена, принадлежность
полей записи и индексы слотов должны быть согласованы. Выбор поддерживаемых записей из более широкой
схемы — явное ограничение области; он не доказывает поддержку всей схемы.

Порядок логических полей: сначала integer indices Java, затем object indices. Полный type ID
сохраняется; допустимы только **2/8/10/40/56/72/88/120**. Не восстанавливается предполагаемый
чередующийся порядок XML declarations и не выводится wire ID из Java storage index. После
поддерживаемого многослотового integer field следует ровно один физический `VoidIntField` с полным
типом zero, следующим integer index, той же идентичностью записи и точным именем
`ownerName + "$VoidTail"`. Удаляется только такой проверенный tail. Отдельный VOID, отсутствующие
или неверные tails, неподдерживаемые полные identities и несогласованная принадлежность отклоняются.
Sidecar фиксирует каждый сохранённый исходный слот и логическое поле-владельца каждого удалённого tail.

Фактический private final map `DefaultRecord.fieldsByName` перечисляется небольшим reflection
adapter только для чтения. Проверяются объявляющий класс, структура member, доступность состояния,
типы entries и идентичность закреплённой реализации. Каждый перечисленный ключ должен удовлетворять
`record.findFieldByName(key) == enumeratedField` по **идентичности объекта**. Target обязан быть
сохранённым логическим полем или проверенным удалённым tail. Каждому сохранённому полю требуется хотя
бы один ключ. При ошибке introspection нельзя переходить к предполагаемым full/local/property names.

Все ключи сохранённых полей попадают в native `lookups`; сортировка — Java `String.compareTo`
(порядок UTF-16 code units). Ключи удалённых tails перечисляются в provenance отдельно и никогда не
перенаправляются на поля-владельцы. Область lookup остаётся отдельной для каждой записи. Добавление
alias изменяет последнее property name Java-поля, сохраняя прежние ключи map; экспорт только текущих
property names потерял бы наблюдаемое поведение lookup. Дополнительного правила создания aliases
в JSON нет.

Исходные доказательства: закреплённые constructor `DefaultRecord`, `putDefaultFieldNames`,
`putNonDefaultFieldNames`, `addFieldAlias`, `findFieldByName`, создание слотов `SchemeBuilder` и
`DXScheme.buildOneRecord`; см. [инвентаризацию источников](SOURCES.md) и [upstream lock](../../upstream.lock).
Независимая [характеризация проекции](../../tools/schema-export/tests/ProjectionCharacterization.java)
создаёт производственные объекты и проверяет накопленные aliases, полные targets map,
wide/tail/int/object slots, отказ для class/access/type и выбор в исходном порядке. Также проверяются
объекты Quote/Profile по умолчанию и из закреплённого dxlink. Эти наблюдения устанавливают механику
проекции, а не совместимость tape или событий; отдельную границу устанавливают производственные
writer/reader observations и использование в C++.

## Детерминизм, бюджеты и публикация

Выход — UTF-8 без BOM, с завершающим LF и фиксированным порядком JSON members. Порядок root:
`formatVersion`, `profile`, `records`; profile: `id`, `version`; record: `id`, `name`, `hasTime`,
`fields`, `lookups`; lookup: `name`, `fieldId`. Точные scalar names не нормализуются и не обрезаются.
Управляющие знаки и пунктуация экранируются детерминированно. Supplementary scalars сохраняются;
непарные surrogate в именах отклоняются без замены. Существующие native invariants имён, количеств
и lookup остаются нормативными.

| Лимит | По умолчанию | Значение |
| --- | --- | --- |
| `--max-schema-bytes` | 1048576 | Все байты сгенерированного native JSON |
| `--max-schema-records` | 1024 | Выбранные записи |
| `--max-schema-fields` | 16384 | Всего сохранённых логических полей |
| `--max-schema-lookups` | 32768 | Все исходные lookup entries, включая ключи удалённых tails |
| `--max-schema-name-units` | 1024 | UTF-16 units в одном имени записи/исходном lookup name |
| `--max-schema-total-name-units` | 1048576 | Сумма units имён записей/исходных lookup names, включая удалённые tails |
| `--max-input-files` | 64 | Замыкание XML/imports, явный properties-файл и закреплённая XSD |
| `--max-input-bytes` | 1048576 | Всего принятых байт XML/properties/закреплённой XSD |
| `--max-import-depth` | 16 | Активная цепочка XML imports |
| `--max-sidecar-bytes` | 4194304 | Все байты сгенерированного provenance |

Лимиты — беззнаковые десятичные значения в `0..2147483647` с конечной проверяемой арифметикой;
равенство допустимо, превышение на один — ошибка, включая нулевые лимиты. Стандартные лимиты
входных файлов/байтов/глубины — жёсткие максимумы: их можно только снижать. Учёт lookup keys
удалённых tails намеренно строже native-потребителя, учитывающего сохранённые ключи. Глубина native output не превышает пяти
контейнеров; расширять стандартную глубину потребителя 16 не требуется. У provenance отдельный бюджет
байтов. Переносимый CMake launcher по умолчанию задаёт timeout процесса 30 секунд и Java heap 256 MiB;
конечный бюджет процесса не обещает точной границы resident memory. Ошибка бюджета не публикует
успешную схему или частичный bundle.

После полной проверки источника и проекции `schema.json` и `provenance.json` записываются в
собственный соседний staging directory, затем публикуется новый каталог экспорта без замены
существующего назначения. При ошибке публикации удаляется только собственное staging content
инструмента. Существующее назначение, включая пустой каталог, остаётся неизменным; успех нельзя
объявлять до полной записи обоих файлов и успешной публикации. Два свежих запуска с одинаковыми
проверенными входами дают идентичные байты схемы и sidecar; время запуска относится только к
временным журналам.

Provenance содержит только ограниченные относящиеся к делу данные: закреплённую ревизию, hashes
экспортёра/входов/classpath, режим источника, допустимые настройки источников, отображение выбранных
ID, отображение сохранённых слотов и учёт lookup удалённых tails. В нём нет дампа ambient properties,
credentials, окружения, абсолютных путей конкретной машины или частного содержимого входов.
Native C++ loader не интерпретирует sidecar и не переходит по его ссылкам.

Ошибки выводят одну строку stderr `schema-export-error<TAB>1<TAB>CODE<LF>`, stdout пуст. Диагностика
не повторяет пути входов, XML, значения properties или stack traces.

| Код | Exit | Значение |
| --- | --- | --- |
| `USAGE` | 2 | Пропущенный, повторный, конфликтующий или неизвестный аргумент команды |
| `IO_ERROR`, `PUBLICATION_FAILED` | 3 | Ошибка ввода/вывода или невозможность опубликовать новый bundle |
| `UNSUPPORTED_RECORD`, `UNSUPPORTED_TYPE`, `UNSUPPORTED_INDEXED`, `UNSUPPORTED_LOOKUPS`, `UNSUPPORTED_SOURCE` | 4 | Неподдерживаемая реализация, полный identity, indexing, lookup introspection или runtime источника |
| `INVALID_SCHEMA`, `INVALID_INPUT`, `INVALID_CONFIGURATION` | 5 | Нарушение invariants проекции, недопустимый XML/input или settings |
| `RESOURCE_LIMIT` | 6 | Превышен конечный бюджет входов, выхода, количества, имён или процесса |

Эти строки описывают ошибки Java-команды; ошибки проверки, компиляции и timeout процесса CMake
используют диагностику CMake и ненулевой код launcher, без обещания строки ошибки Java.
Ошибки проверки origin/classpath в launcher также останавливают выполнение до экспорта; ошибка
проверки не разрешает непроверенный classpath. Синтаксис запуска приведён в руководстве.
Ни экспорт, ни JSON round trip сами по себе не доказывают совместимость стандартных событий.
Контракт не разрешает новые wire types, indexed schemas, conversions, замену во время работы,
сетевой транспорт, частный tape или изменение исторических fixtures.
