# Живые диапазоны HISTORY

[English version](LIVE-HISTORY-RANGES.md).

SDK владеет применением диапазона, физическим demand, сохранёнными HISTORY views и подтверждением
reset. Приложение не собирает collectors, не передаёт рабочие кредиты каждого turn и не опрашивает
доставку. Контракт дополняет [приём HISTORY](HISTORY-RECEIVING.ru.md) и сохраняет
[идентичность time-series](TIME-SERIES-IDENTITY.ru.md).

## Пригодность и принятое состояние

`Feed::createTimeSeriesSubscription<Event>()` и перегрузки с неизменным списком типов возвращают
существующий `Subscription<Event>` в режиме time-series. Endpoint должен явно использовать
`DeliveryContract::HISTORY`, а каждому выбранному бизнес-типу нужен настоящий проверенный native
time-series mapper. Наличие в registry, объявленная вызывающим capability, поле timestamp или
индексируемая запись не дают такого разрешения. Текущие девять бизнес-типов не поддерживаются;
индексируемый Order также не подразумевает TimeSeriesEvent. Последующий бизнес-mapper использует
этот же приёмник и путь диапазона, без второго storage или callback API.

Режим неизменен. Начальный `getFromTime()` равен знаковому64 MAX. `setFromTime(ms)` принимает
включительную нижнюю границу в Unix-миллисекундах; сохраняются все значения signed64. MAX отключает
обычные исторические события, сохраняя логический символ и его физический sentinel demand.
Операции диапазона обычной подписки отклоняются с `UNSUPPORTED_PROFILE`; мутация после close
сохраняет существующий fence `CLOSED`. Сохранённое свойство режима читается и после close.

Единый принятый срез содержит полный эффективный набор символов, fromTime, неизменные типы и
проверенную логическую ревизию. `SubscriptionSnapshot::fromTime` отсутствует в обычном режиме.
В режиме time-series его символы являются эффективными TIME_SERIES identities с той же границей.
Обычный входной символ получает текущую границу под mutex подписки. Вложенный/indexed decorator
не превращается в выдуманную физическую строку; неподдерживаемая live-форма отклоняется до мутации.
Сравнение и удаление исключают атрибут диапазона из идентичности.

Изменение диапазона пустого набора меняет свойство и ревизию. Равное значение ничего не меняет.
Символы candidate и полные observer snapshots выделяются до публикации. Отказ allocation, work,
observer capacity или исчерпание ревизии сохраняет весь прежний принятый срез. Снимок observer после
изменения содержит новую границу, а не старое свойство. Сохраняются фазы removal перед addition
и выполнение callbacks с освобождением последних captures вне блокировок.

## Применение и fences доставки

Worker захватывает символы и логическую ревизию вместе. Только явная временная политика проверенного
mapper переводит Unix-миллисекунды в координаты физической записи; индексируемый route сохраняет
сырую границу области индекса. Совпадающие физические ключи объединяются по минимальной границе,
поэтому удаление или сужение одного view не снимает demand другого.

Неизменный отделённый MUX batch сохраняет логическую идентичность команды успешного mapping commit,
если подключён учёт facade. Принятая ревизия, submitted command и APPLIED ticket сами по себе не
подтверждают mapping. Выбор HISTORY callback требует совпадения этой applied identity с принятым
состоянием. Семантика выбора TICKER/STREAM не меняется.

Для отложенных callbacks принятое изменение HISTORY заставляет worker отменить устаревшую работу,
которая ещё не началась, до ожидания retirement. Host может бессрочно хранить уже инертный старый
task; поздний run не возвращает старую доставку. Настоящий BEGIN callback — claim под mutex порта
с проверкой неизменной applied revision. До пользовательского кода mutex освобождается. Invocation,
уже прошедший BEGIN, может завершиться, даже если его первая инструкция следует за конкурентной
мутацией. Отмена и completion используют существующий учёт и retirement последних captures.

Если этот fence ревизии отбрасывает настоящую выбранную HISTORY доставку, SDK заново начинает initial
snapshot затронутого view поверх существующего сохранённого cache. Это касается всех текущих ключей
этого view: неизменный ключ, уже доставленный ранее, может получить ещё один локальный snapshot.
Поэтому бизнес-доставка не имеет гарантии exactly once. Удалённые ключи исключаются, соседние views
и source epoch не меняются; сам replay не посылает физический REMOVE. Новый logical mapping получает
подтверждение только после commit подготовки replay; initial, queued и callback retirement должны
завершиться, прежде чем новый диапазон сможет сообщить полноту локальной доставки.

Авторитетная desired mutation снимает старые memberships collector и queued projections. Новая
membership владеет собственным initial cursor; параллельный payload cache не появляется. Расширение
ниже сохранённого покрытия остаётся partial до свежего snapshot источника. Хвост старого snapshot
без нового BEGIN не устанавливает недостающее покрытие. Пассивные HISTORY observations сохраняют
семантику AS-OF: несовпадение accepted/mapping/source/clear/retirement снимает current completeness,
не выполняя I/O и не обещая будущую свежесть.

## Wire, бюджеты и recovery

Изменение только границы физического ключа — HISTORY ADD с новой границей, без предварительного
REMOVE. Удаление ключа передаётся как REMOVE. MAX остаётся настоящей границей ADD. Отказ output
не меняет emitted bank; новые принятые диапазоны могут объединиться до успешного admission.
Между frames нет сетевой атомарности или гарантии подтверждения peer.

Существующий конечный work object внешнего turn оплачивает копирование snapshot, routing,
сравнение дубликатов ключей, reconcile collector, публикацию и cleanup. Проверенный консервативный
precharge включает полное old/candidate backing и ограниченные сравнения худшего случая. Helpers
не пополняют потраченные кредиты. После disconnect/reset последние принятые range и set повторяются
в свежем source epoch; старые batches и observation copies остаются историей и не становятся current.
