# Послойная статистика клиента {#client-statistics-ru}

[English version](CLIENT-STATISTICS.md). Нормативна английская версия.

Подмножество IO/recovery endpoint доступно через `Endpoint::getStatistics()`;
границы публикации описаны в [руководстве feed](../../docs/FEED-API.ru.md#статистика-endpoint).
Каталог подписки доступен через `Subscription<Event>::getStatistics()`;
см. [границы учёта доставки](../../docs/FEED-API.ru.md#статистика-подписки).
Операции над значениями в [statistics.hpp](../../include/qd/api/statistics.hpp) предоставляют независимые базовые снимки читателя, интервальные скорости и среднюю длительность callback.

## Источники и решения

Java QD 3.355 закреплена в [upstream.lock](../../upstream.lock) на
0ddc0a09779fb61d74cc0b37c6449ff47dcb715f:

- [QDStats.java](https://github.com/devexperts/QD/blob/0ddc0a09779fb61d74cc0b37c6449ff47dcb715f/qd-core/src/main/java/com/devexperts/qd/stats/QDStats.java)
  определяет раздельные накопители байтов, записей подписки, записей данных,
  lag и RTT, а также added/changed/filtered/removed и производный размер записей.
- [IOCounters.java](https://github.com/devexperts/QD/blob/0ddc0a09779fb61d74cc0b37c6449ff47dcb715f/qds-monitoring/src/main/java/com/devexperts/qd/monitoring/IOCounters.java)
  выводит скорости байтов/записей в секунду по интервалу. Lag чтения/записи —
  соответствующая дельта lag, делённая на дельту записей данных. RTT — сумма дельт
  RTT обоих направлений, делённая на все дельты записей данных/подписки обоих
  направлений. Единицы lag/RTT — микросекунды; при нулевом знаменателе Java
  выводит ноль. Эти формулы не доказывают наличие измерения C++.
- [DXFeedSubscription.java](https://github.com/devexperts/QD/blob/0ddc0a09779fb61d74cc0b37c6449ff47dcb715f/dxfeed-api/src/main/java/com/dxfeed/api/DXFeedSubscription.java)
  описывает getTotalDroppedEvents() как накопленные потери от переполнения буфера
  с создания подписки, а не фильтрацию, объединение или предполагаемые потери upstream.

Следующие каталог и правила наблюдения — инженерные решения C++, отдельные от
фактов upstream. Они не копируют топологию мониторинга Java или оборачивание
арифметики и не меняют семантику протокола.

Существующий [StreamCounts](../../include/qd/collectors/stream.hpp) —
сериализованные наблюдения коллектора: staged-записи, явные подтверждения pop,
withdrawals, discards, ignored input и saturation. Сброс источника сохраняет
накопители. Pop коллектора не доказывает успешный callback приложения.
Существующий [QueueResources](../../include/qd/mux/queue.hpp) сообщает логические
резервы, включая удержанные поколения; независимые поля могут отражать соседние
моменты, в покое значения точны. Общее хранение и перекрытие eventBytes запрещают
суммировать все поля байтов или считать их RSS. Контракт не усиливает эти API
и не меняет их ресурсные ограничения.

## Общие правила каждой строки каталога

Наблюдение содержит стабильный ID владельца, монотонное время, поколение
статистики и эпоху источника. Непрозрачные ID не совпадают со старыми владельцами.
Эпоха источника определяет один установленный транспортный/сессионный источник,
а не desired-ревизию или baseline статистики. Неустановленная попытка имеет
свой ID и явно не имеет активного источника.

Если строка не уточняет иначе, накопители начинаются с нуля при успешном создании
владельца, действуют до его завершения, переживают reconnect и смену селекторов,
считают названные элементы. Текущие величины относятся к моменту наблюдения.
Отклонённое создание ничего не публикует. Отклонённые операции не учитываются как
принятая работа; переданные байты остаются учтёнными. Накопители endpoint за время
жизни суммируют все эпохи соединения; необязательный срез эпохи содержит только её
вклад. Старая работа в очереди сохраняет исходную эпоху до завершения.

Доступность каждого поля явна: available, unsupported, no sample, saturated.
Unsupported означает отсутствие проверенного производителя для backend/профиля;
no sample — поддерживаемый производитель ещё не завершил измерение. Это не
числовой ноль. Доступные счётчики без работы нулевые. Диагностика/состояние
отдельны; отсутствие статистики не создаёт и не скрывает ошибки. Имена таблиц —
семантические обозначения, а не обещанные объявления полей C++.

Все новые накопители количества и длительности насыщаются на UINT64_MAX с
липким признаком каждого поля. Максимум длительности имеет тот же предел.
Производные значения насыщенного операнда недоступны. Текущие величины остаются
в проверенных пределах экземпляра. Оборачивание и дополнительная аллокация
запрещены. Исчерпание ID запрещает новый ID с явной диагностикой жизненного цикла
вместо совпадения со старым. Нижнеуровневые size_t-счётчики сохраняют свой контракт.

Снимок — отделённое ограниченное владеющее значение, не удерживающее сокет,
callback, схему или runtime. Читается после shutdown. Публикация даёт согласованный
срез владельца и время/поколение; отдельные чтения endpoint/подписки не являются
глобальным атомарным срезом. Чтение не продвигает сеть, не выполняет DNS,
callbacks, ожидание callback или сброс. Итоги фиксируются после фактического
покоя callbacks/captures, а не при запросе close.

## Каталог endpoint

Каждое вхождение транспорта/протокола считается один раз до раздачи подпискам.
Все строки наследуют общие правила начала/времени жизни/переполнения/доступности.

| Измерение | Уровень; единица | Момент учёта/источник и доступность |
| --- | --- | --- |
| readBytes, writtenBytes | Транспорт; октеты | Положительные байты, фактически возвращённые успешным продвижением read/write, включая частичный I/O, не длина запрошенного буфера. Обычный TCP считает октеты потока QTP. TLS различает открытый QTP и зашифрованный транспорт; неинструментированные уровни unsupported. |
| readMessages, writtenMessages | QTP; полные кадры | Чтение: структурно принятые полные кадры, включая управляющие/неизвестные типы с поддерживаемым framing, до payload. Запись: полные кадры, чей последний байт пересёк объявленную границу QTP. Частичные/некорректные/брошенные кадры не считаются полными. |
| readDataRecords, writtenDataRecords | QTP; вхождения записей | Полные проверенные записи, зафиксированные декодированием, либо записи полностью переданных исходящих сообщений. До проекции/фильтрации/раздачи; атомарно отклонённый payload даёт ноль записей. Неподдерживаемая отправка данных явна. |
| readSubscriptionRecords, writtenSubscriptionRecords | QTP; вхождения ADD/REMOVE | Полные проверенные входящие записи или записи полностью переданных исходящих сообщений; replay после reconnect считается снова. Ещё не отправленные desired-селекторы не считаются. Неподдерживаемый приём явен. |
| connectionAttempts | Жизненный цикл соединения; попытки | Один раз при начале попытки по конечной политике, включая ошибки DNS/connect. Connect без эффекта не считается. |
| establishedConnections, closedConnections | Жизненный цикл соединения; соединения | Фактическое установление и завершение соответственно; неустановленная неудачная попытка не является закрытым соединением. Источник завершается один раз, включая close/ошибку/recovery. |
| activeConnections | Жизненный цикл соединения; соединения, текущая величина | Установленные, ещё не завершённые соединения; ноль в начале и после завершения. Не означает готовность приложения peer. |
| dataLagRead, dataLagWrite | Время протокола QD; микросекунды, взвешенное среднее | Только проверенные накопители протокольного времени и соответствующие веса записей одной эпохи/интервала. Сейчас unsupported в фасаде; метки событий, вычитание wall clock и длительность callback не заменяют измерение. |
| roundTripTime | Время протокола QD; микросекунды, среднее с весами записей | Только проверенные накопители QD RTT и описанные веса; не TCP ping или время connect. Сейчас unsupported в фасаде. |

Общее количество полученных событий не является синонимом байтов, записей и
событий подписок. Необязательная детализация по записям требует проверенной
идентичности схемы; числовые ID несовместимых эпох схем не объединяются.
Неограниченная таблица символов не требуется.

## Каталог подписки

Владелец — одна подписка. Если не указано иначе, единица — вхождение события.
Две перекрывающиеся подписки считают два независимых вхождения. Раздача слушателям
не умножает количество событий подписки. Все строки наследуют общие правила.

| Измерение | Уровень; единица | Момент учёта/источник и доступность |
| --- | --- | --- |
| desiredSelectors | Desired state; разные селекторы, текущая величина | Успешно принятый текущий набор, включая ожидание согласования. Дубликаты/no-op/отклонённые мутации не увеличивают его. Clear/close отзывают по существующим правилам. |
| activeSelectors | Локальное отображение источника; разные селекторы, текущая величина | Применённое worker отображение с эпохой и desired-ревизией; не подтверждение peer. Ноль до отображения/после завершения; reconnect может временно отличаться от desired. |
| admittedEvents | Приём доставки; вхождения | Принятые в ограниченное состояние доставки подписки, включая позднее объединённые/отброшенные/завершённые ошибкой. Отклонённые входящие события не приняты. |
| deliveredEvents | Диспетчеризация подписки; вхождения | Принятые события с нормально завершённой доставкой выбранному набору слушателей. Нет слушателей — нет завершённой доставки; политика ожидания сохраняется. Не доказывает сохранение или внешнее подтверждение. |
| droppedEvents | Переполнение доставки; вхождения | Только известные потери переполнения: отклонённые входящие и вытесненные принятые события. Смысл за время жизни соответствует Java getTotalDroppedEvents(); исключает объединение, clear/close и неизвестные upstream-пропуски. |
| rejectedOverflowEvents, evictedOverflowEvents | Разбивка overflow; вхождения | Соответственно никогда не принятые входящие события и ранее принятые жертвы очереди. Один владелец/время жизни и согласованный срез с droppedEvents. Без двойного учёта. |
| conflatedEvents | Доставка TICKER; замещённые вхождения | Принятые значения очереди, заменённые новым принятым значением. Исключает потери STREAM и объединение байтов/записей. Доступный ноль для профилей без объединения. |
| discardedEvents | Локальная отмена; вхождения | Принятые события, завершённые remove/clear/close/abort/политикой эпохи без полной доставки, кроме overflow, conflation и ошибки callback. Cleanup не объявляется доставкой. |
| callbackFailedEvents | Ошибка диспетчеризации; вхождения | События принятого пакета, чья доставка выбранным слушателям не завершилась из-за исключения. Один учёт, даже если предыдущие слушатели видели их. Остальная очередь, завершённая ошибкой, — discarded. |
| pendingEvents, inFlightEvents | Состояние доставки; вхождения, текущие величины | Удерживаемые в очереди и выбранные, ещё не завершённые события соответственно. Последнее объединённое значение считается один раз; ноль в начале/после завершения. Выбранные callbacks остаются in flight до конца. |
| queueCapacityEvents | Конфигурация доставки; слоты, текущая величина | Действующая конечная ёмкость/резерв очереди экземпляра; не свободное место/RSS. Чтение не выделяет память и не увеличивает ёмкость. |
| callbackCalls, callbackFailures | Вызов приложения; вызовы | Каждый фактический вызов слушателя и каждый бросивший исключение соответственно; несколько слушателей дают несколько вызовов пакета. Существующая политика ошибки останавливает доставку. |
| callbackDurationTotal, callbackDurationMaximum | Локальное время слушателя; наносекунды, сумма/максимум | Длительность завершённых вызовов по steady clock вокруг пользовательского кода, включая исключения/блокировку, исключая очередь/lag протокола. Сумма начинается с нуля, максимум — no sample до первого завершения; до завершения вызова время no sample. |
| callbackDurationSamples | Локальное время; завершённые вызовы | Знаменатель средней длительности, включая обычные вызовы/исключения; поколение/источник совпадают с длительностями, ноль до первого завершения. |

Здесь слушатель/callback означает только слушателя доставки событий. Наблюдатели
жизненного цикла/состояния исключены из счётчиков, длительностей и учёта ошибок событий;
их рекомендательные исключения и отдельная диагностика наблюдателя не завершают
доставку событий и не заменяют основную диагностику. Набор счётчиков наблюдателей
здесь не определяется.

Ошибка callback доставки событий сохраняет первую диагностику, завершение и отсутствие retry.
Статистика не разрешает прерывать callback или раньше уничтожать captures.
Неизвестные upstream-пропуски остаются качественными, если производитель протокола
не даёт точного числа. Счётчики обеспечения ресурсов/работы и бюджеты никогда не
сбрасываются и не возвращаются чтением статистики, baseline или сменой поколения
наблюдения.

## Сброс и производные значения

Контракт не предоставляет разрушительного публичного сброса накопителей времени
жизни. Сброс потребителя записывает baseline и поколение, не меняя доставку.
Нижнеуровневые сбросы не сбрасывают фасад. Новый владелец начинает новое поколение;
reconnect меняет эпоху источника, не поколение статистики. Будущий разрушительный
сброс требует явной редакции контракта с атомарной сменой поколения и учётом
пересекающей границу работы. Сброс наблюдения не возвращает реальные ресурсы/работу.

Скорости требуют двух доступных ненасыщенных наблюдений одного владельца,
поколения, определения метрики и области с положительным монотонным интервалом.
Скорости времени жизни пересекают reconnect только с явной пометкой; скорость
эпохи требует одной эпохи. Отсутствующее поле, несовместимое поколение, граница
источника для скорости эпохи, насыщение и неположительное время дают unavailable,
а не оборачивание, отрицательное число или выдуманный ноль. Проверяемые дельты/
масштабирование не переполняют промежуточные значения; единицы — элементы/секунду
или байты/секунду с описанной точностью. Средние требуют положительной дельты
соответствующих samples; объединяются числители/веса, не средние интервалов.
Читатели и их baseline независимы.

Публичный `StatisticsBaseline` владеет отделённым снимком. Reset заменяет
только копию этого читателя; общую изменяемую копию читатели синхронизируют
сами. Скорости за время жизни имеют тип `LifetimeStatisticRate` и могут включать
переподключение. Скорости эпохи требуют одинакового положительного, ненасыщенного
порядкового номера установленного источника; для endpoint также необходимы доступные
счётчики установленных соединений. Выбранное поле задаёт одну накопительную метрику
в обоих снимках; сумму и максимум длительности callback нельзя выбирать для этих скоростей счётчиков.
Неизвестное принятие записи делает скорость writtenBytes недоступной, не влияя на
другие поля. Скорости вычисляются через секунды с плавающей точкой и округляются до
`double`; неположительный или непредставимый интервал, несовместимые, убывающие,
отсутствующие или насыщенные значения не дают результата. Средняя длительность
callback равна разности сумм длительности, делённой на положительную разность числа
завершённых измерений; начальная поддерживаемая сумма без измерений при нулевом
числе samples считается нулём. Операции не ожидают callback, не продвигают сеть и
не удерживают владельцев runtime.
## Балансы и обязательные сценарии реализации

Это требования к будущим тестам, а не выполненные проверки поведения:

1. Частичный I/O: десятибайтовый кадр порциями 3 + 2 + 5 даёт десять байтов и одно
   сообщение; abort после пяти — пять байтов и ноль полных сообщений/записей.
   Правильный framing с ошибкой payload учитывает кадр и ноль атомарно отклонённых
   записей. Следующий некорректный кадр сохраняет учёт принятого префикса.
2. Reconnect: неудачный DNS, затем два установленных/завершённых источника дают
   attempts 3, established 2, closed 2, active 0. В согласованный момент:
   establishedConnections = closedConnections + activeConnections.
   Накопители не уменьшаются; replay ADD считается снова, desired-селекторы нет.
   Старая работа в очереди сохраняет эпоху.
3. Перекрытие: одна запись, давшая одно событие двум подпискам, увеличивает
   readDataRecords один раз и admittedEvents каждой подписки один раз.
   Два слушателя влияют на callbackCalls, не admittedEvents. Записи endpoint
   не обязаны равняться сумме событий подписок.
4. До насыщения за жизнь одного владельца:
   admittedEvents = deliveredEvents + conflatedEvents + discardedEvents +
   callbackFailedEvents + evictedOverflowEvents + pendingEvents + inFlightEvents.
   droppedEvents = rejectedOverflowEvents + evictedOverflowEvents.
   Отклонённый вход не входит в баланс приёма; итоговые pending/inFlight нулевые.
   Для интервала baseline учитываются дельты текущих величин.
5. Два принятых TICKER-обновления одного ключа с заменой первого: admitted 2,
   conflated 1, pending 1. Доставка последнего: delivered 1, pending 0, dropped 0.
   Отклонённый вход STREAM увеличивает только rejected overflow/drop; вытеснение
   переводит принятую жертву в evicted overflow. Conflation не является Java-потерей.
6. Если второй выбранный слушатель пакета двух событий бросает исключение,
   оба события учитываются callbackFailed по одному разу, даже если первый
   слушатель вернулся. Считаются реальные calls, failures и завершённые samples
   времени. Remove не стирает выбранные вызовы. Close при блокировке сохраняет
   inFlight; abort отбрасывает очередь. Чтение не ждёт вызова и не объявляет
   преждевременный покой.
7. Baseline не меняют накопители или baseline другого читателя. Равные времена
   дают unavailable скорости. При UINT64_MAX приращения насыщают только затронутое
   поле и отключают производную скорость; точные числовые балансы после насыщения
   недоказуемы. Старые отделённые снимки переживают shutdown и несравнимы с новым
   владельцем. Сброс не пополняет исчерпанный бюджет работы.
8. Неинструментированное время протокола unsupported даже с трафиком.
   Поддерживаемый источник без соответствующих записей имеет no sample.
   Callback 2 ms может дать 2000000 ns локально; это не доказывает 2000 us lag/RTT.

Хранение статистики остаётся в существующих конечных бюджетах экземпляра, без
ambient настроек процесса, неограниченных меток или истории. Будущие проверки
охватывают конкурентных читателей, reconnect/ошибку, сброс потребителя и итоговые
наблюдения. Спецификация не доказывает потокобезопасность или выполнение.
