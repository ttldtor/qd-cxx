# Наблюдатели состояния публичного feed API

[English version](FEED-STATES.md). Английская версия нормативна.

Контракт расширяет [публичный feed API](../../docs/FEED-API.ru.md) наблюдателями
состояния endpoint и типизированной подписки. Доставка событий, wire-семантика,
владение bootstrap и отложенный запуск worker остаются прежними.

## Регистрация и выбор

`Endpoint` и `Subscription<Event>` предоставляют `addStateChangeListener`,
`removeStateChangeListener` и `getStateChangeDiagnostic`. Наблюдатель принимает
перечисления старого и нового состояния владельца по значению. Callable должен
быть непустым. Регистрация возвращает неповторяемый ID наблюдателя в пределах
владельца, отдельно от ID обработчиков событий. Начального вызова нет. Отдельный
`getState()` читает текущее состояние; регистрация вместе с чтением не являются
атомарной операцией подписки и получения снимка. Каждый последующий различный
публикуемый переход выбирает полный неизменяемый снимок принятых наблюдателей под
той же блокировкой порта, что и изменение состояния. Вызовы идут в порядке
регистрации вне управляющих блокировок.

Удаление идемпотентно, в том числе после close, и исключает будущий выбор.
Выбранный обработчик ещё может вызваться после удаления или close. Удаление
и добавление из обработчика влияют на последующие снимки. Разрешено читать
состояние, вызывать close и работать с другим endpoint. Close отсекает обычный
приём до уведомления об ошибке или терминальном состоянии, в том числе при
естественном завершении native. `CLOSED` и `FAILED` поглощающие; повторные попытки
завершения не публикуют дубликаты или возврат к предыдущему состоянию.

## Исполнение и границы

После первого принятого соединения, запустившего SDK worker этого runtime,
уведомления доставляет worker. Для runtime без запущенного worker завершение
endpoint/runtime в создающем потоке вызывает уведомления неактивных объектов без
создания потока. Разные неактивные endpoint могут завершаться рекурсивно. Завершение
в создающем потоке может идти параллельно worker другого endpoint, если обработчик
запускает worker. Наблюдения одного endpoint доставляет лишь его заявленный владелец
исполнения. Await endpoint из worker или постороннего потока отклоняется с
`WRONG_THREAD`; self-await и повторный await runtime при завершении в создающем
потоке отклоняются с `INVALID_STATE`, не ожидая содержащий их обработчик.

Первый `connect()` сохраняет прежнее немедленное наблюдение `CONNECTING`.
Выбранный снимок занимает слот ограниченного кольца и доставляется до остальных
наблюдений worker на каждом пути завершения: раннем close, ошибке native activation
и ошибке инфраструктуры worker. Отказ запуска worker происходит до публикации
состояния, не создаёт перехода и не вызывает обработчик в producer-потоке.
Последующие disconnect/connect/reconnect используют то же упорядоченное кольцо.
`maximumPendingStateChangesPerEndpoint` по умолчанию равен 8, включая исполняемые/
освобождаемые снимки; переполнение обычной ёмкости отклоняется до изменения lifecycle.
Для close/failure сохранён отдельный путь; см. [lifecycle admission](FEED-LIFECYCLE.ru.md).
Неограниченной очереди переходов и отсоединённого потока уведомлений нет.

`RuntimeOptions::maximumStateListenersPerEndpoint` и
`maximumStateListenersPerSubscription` — отдельные положительные конечные ёмкости,
по умолчанию 4. Учитываются принятые, выбранные и удалённые, но ещё освобождаемые
объекты. Слот освобождается лишь после уничтожения последнего захвата приложения.
Новые поля следуют за прежним `dnsPort`, сохраняя позиционные префиксы агрегата.
Пустой callback отклоняется с `INVALID_ARGUMENT`, закрытый приём — с `CLOSED`,
исчерпание ёмкости или ID — с `RESOURCE_LIMIT`, ошибка выделения собственного
хранилища — с `ALLOCATION_FAILURE`. Для close зарезервирован отдельный путь.
Выделения памяти callable приложения, удерживаемые графы объектов и время блокировки
не входят в конечные резервы количества SDK-объектов.

## Ошибки и завершение

Исключение наблюдателя сохраняет первую статическую/числовую ошибку
`CALLBACK_FAILURE` в `getStateChangeDiagnostic()`. Остальные обработчики полного
выбранного снимка вызываются. Эта отдельная диагностика не меняет состояние
владельца, `getDiagnostic()`, `CloseResult` и обычную политику ошибок транспорта
или подписки. Исключение терминального наблюдателя не создаёт переход
из `CLOSED` в `FAILED` и рекурсивных уведомлений `FAILED`.

Нативные регистрации и все прежние обработчики событий с их захватами завершаются
до публикации `CLOSED`. Новый явно подключённый наблюдатель, выбранный для этого
терминального уведомления, неизбежно остаётся жив во время вызова. Только его вызов
и освобождение захватов могут оставаться после `CLOSED`. Await endpoint и shutdown
runtime возвращаются лишь после обнуления обоих счётчиков; слоты endpoint/подписок
остаются занятыми до этого. Фаза освобождения захватов событий не ожидает ещё
зарегистрированных наблюдателей состояния, которым предстоит терминальное
уведомление. Все callable приложения уничтожаются вне управляющих блокировок,
с защитой повторного входа при завершении в создающем потоке. Дескрипторы могут
пережить runtime как отсоединённые терминальные порты с обеими диагностиками.

## Совместимость и источники

Закреплённый [Java QD reference](../../upstream.lock) определяет уведомления endpoint
в `dxfeed-api/src/main/java/com/dxfeed/api/DXEndpoint.java` (документация add/remove)
и доставляет различные фактические старое/новое состояния в
`dxfeed-impl/src/main/java/com/dxfeed/api/impl/DXEndpointImpl.java`
(`StateHolder.run` и `fireStateChangeEvent`). Регистрация лишь добавляет наблюдателя,
не отправляя начальное событие. Закреплённый [контракт Java `connect`, строки 725–729](https://github.com/devexperts/QD/blob/0ddc0a09779fb61d74cc0b37c6449ff47dcb715f/dxfeed-api/src/main/java/com/dxfeed/api/DXEndpoint.java#L725-L729)
ожидает завершения первого уведомления `CONNECTING`. C++ явно сохраняет прежний
[неблокирующий контракт `connect()`](../../docs/FEED-API.ru.md#принятые-изменения-и-ошибки):
он не ожидает наблюдателей состояния. Исполнение через executor сохранено явными
контекстами владения C++ выше. Java `DXFeedSubscription` предоставляет наблюдение
изменений символов и закрытия; существующее перечисление состояний C++-подписки
и этот ограниченный API — явно обозначенное идиоматическое расширение.
