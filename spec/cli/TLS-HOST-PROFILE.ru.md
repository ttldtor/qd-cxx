# Замкнутый профиль TLS-процесса

[English version](TLS-HOST-PROFILE.md)

Предварительная проверка TLS в утилите подписок устанавливает замкнутость фиксированного каталога
имён дайджестов, необходимую для её декларации окружения OpenSSL 3.5.9. Проверка выполняется до
декодирования сертификатов и создания recovery. Она не обнаруживает произвольных пользователей SDK
и автоматически не квалифицирует другой исполняемый файл. Сохраняются
[контракт ресурсов TLS](../transport/TLS-RESOURCES.ru.md) и
[контракт recovery](../transport/RECOVERY.ru.md).

## Замкнутый процесс и образ

Профиль требует нового процесса, единственного квалифицированного статического образа SDK, одного
последовательно работающего потока-владельца SDK, одного recovery-владельца/нативной попытки
одновременно и конечного числа попыток восстановления. Ошибка после входа в предварительную
проверку или фабрику завершает запуск. Старый приватный контекст полностью освобождается до создания
следующего. В процессе нет других пользователей SDK, хуков провайдеров/конфигурации, автозагрузки
конфигурации, регистрации собственных ошибок, инициализированного secure heap или чужих allocator hooks.
Общая идентичность, провайдеры, свойства и регистрация алгоритмов неизменны до окончательного
освобождения SDK. Это обязанности приложения, а не вывод из возвращённых чисел.

Точная конфигурация, исходники и статические библиотеки закреплены
[метаданными квалификации](../../cmake/tls-profile/openssl-3.5.9.json) и манифестами исходников/платформ.
Выбранное окружение — Windows x64 MSVC 19.42 с динамическим release CRT либо Linux x64 GCC 13.3.0
с квалифицированной нативной привязкой. Заголовки и архивы должны принадлежать одной явно указанной
установке. Системный поиск OpenSSL или подмена провайдеров этому профилю не соответствуют.

В окружении запуска должна **отсутствовать переменная `OPENSSL_ia32cap`**, включая пустое значение.
Помощник проверяет наличие, не копируя и не разбирая значение и не меняя окружение. Windows сохраняет
last-error вызывающей стороны; Linux проверяет только указатель, возвращённый нативным getter.
Параллельное изменение окружения запрещено. Наличие или неопределённость приводят к окончательному
отказу `ENVIRONMENT` до управляемого приложением входа в SDK.

Допуск предшествует первому **управляемому приложением** вызову SDK после квалифицированной
инициализации CRT/статического образа. Выбранный x86-64 startup hook вызывает `OPENSSL_cpuid_setup`
до `main`; его trigger предотвращает повторное чтение окружения при поздней базовой инициализации.
Доказательство итоговой линковки должно подтверждать сохранение startup hook и выбранной assembly-пробы.
Одни генераторы исходников не доказывают запуск или dispatch другого исполняемого файла. Отсутствие
override также исключает разбор унаследованного значения при достижении CPU setup из приложения;
оно не ограничивает задним числом работу до `main`. Профиль не обещает срок запуска loader/CRT,
число инструкций, предел RSS или задержку нативного вызова.

## Вход и владение

1. Разобрать аргументы и вычислить неизменяемые пределы входов TLS без SDK. Справка и обычный
   транспорт этот помощник не вызывают.
2. Вызвать `preflightRequirements(limits)`, предоставить точную копию shape/revision, весь общий
   резерв запрошенной памяти и каждую координату работы. В процессе разрешены ровно один
   `PreflightOnce` и один вызов. Отказ также расходует этот одноразовый допуск.
3. Проверить все координаты до списания. Неверные limits, shape, память или работа оставляют оба
   бюджета неизменными. После допуска целиком списать общий резерв и вектор до проверки окружения
   и SDK. Ошибка после допуска не возвращает бюджет и не разрешает повтор с увеличенными лимитами.
4. Первый SDK-вызов приложения — `ERR_clear_error`, затем `ERR_new`, `ERR_set_debug(NULL,0,NULL)`,
   `ERR_set_error(USER,1,NULL)` и `ERR_peek_error`. Проверить фиксированный маркер и очистить его.
   Перед этим нет запросов версии, провайдера, контекста или аллокатора.
5. Для каждого из 27 фиксированных описаний вызвать `EVP_MD_fetch(NULL,name,"provider=default")`.
   Требовать ненулевой метод, отсутствие SDK-ошибки, точное имя провайдера `default` и фактическое
   hash membership `EVP_MD_is_a==1` для всех 71 псевдонима. Освободить ссылку и проверить ERR после
   каждого описания. Перебор списка имён не заменяет эти проверки.
6. Вернуть только автономные числовые пределы и объём резерва. Любая ошибка запрещает recovery;
   перехода на обычный транспорт нет. Ссылка метода владеет им во время заимствования провайдера/имени
   и освобождается ровно один раз на каждом выходе. Заимствования методов, провайдеров, контекстов,
   callbacks или строк наружу не выходят.

Полный фиксированный набор имён и псевдонимов находится в
[скомпилированном каталоге](../../tools/subscribe/tls_digest_catalog.hpp); динамически выбранного подмножества нет.

Постоянный общий резерв остаётся списанным до освобождения SDK. Память последующего recovery и его
публичные работы factory/start/entry/close оплачиваются отдельно; preflight не пополняет их и не
меняет вектор progress/drain. Общий резерв оплачивается один раз на окружение, без повторного списания
того же общего envelope за каждый следующий приватный recovery-контекст.

## Декларация из двадцати полей

| Поле | Граница | Значение |
| --- | ---: | --- |
| namemapGroups | 6297 | Сохранённые попытки имён/групп, включая orphan/failure histories. |
| queryCount | 2 | Историческое объединение пустого запроса и `provider=default`. |
| queryBytes | 16 | Максимум байтов запроса без NUL. |
| propertyNames | 6 | Фиксированные встроенные атомы имён. |
| propertyValues | 22 | Полное статическое множество значений, включая yes/no. |
| propertyStringBytes | 28000 | `1000*(6+22)`, включая NUL. |
| propertyStringMaxBytes | 1000 | Максимальный payload одной строки свойств. |
| participatingThreads | 1 | Единственный последовательный владелец SDK до teardown. |
| globalThreadHandlers | 9 | ERR prefix 5 + общий RAND 2 + приватный RAND 2. |
| ownerThreadHandlers | 9 | Те же узлы на одном потоке-владельце. |
| ambientThreadPairs | 1 | Default context и один поток. |
| ambientGenerators | 2 | Общие public/private generator slots. |
| concurrentEntries | 1 | Нет параллельного или повторно входящего SDK-вызова. |
| errorThreads | 1 | Один зависимый поток ERR-state. |
| errorCapacityBytes | 0 | Нет внешних/прежних ERR-данных; собственные буферы SDK оплачены отдельно. |
| errorSlotCapacityBytes | 0 | Только внешний вклад; собственный минимум slot остаётся в публичной формуле. |
| errorDebugBytes | 0 | Нет прежних debug-строк; marker использует NULL debug/format. |
| failedPrivatePrefixes | 3 | Резерв recovery на запуск, а не три повтора после ошибки фабрики. |
| failedAmbientPrefixes | 4 | Резерв потенциально потерянных общих префиксов на запуск. |
| errorTableEntries | 1904 | Полная верхняя граница 39 встроенных массивов, а не минимум валидатора 1773. |

Граница namemap: `J = 1404 + 27*71 + 10*6 + 12*243 = 6297`: один сохранённый legacy import,
MD aliases preflight и конечные начальные возможности общих RAND/CIPHER. Первая сохранённая
legacy-запись предотвращает новый импорт; пустые неудачные проходы ничего не сохраняют. Ошибка
preflight окончательна, поэтому неудачные префиксы не повторяются неявно. Успешная проверка всех aliases
гарантирует нахождение существующих ID до добавления имени. Последующие digest fetch разрешены:
их число не считается нулём. Неизвестный запрошенный OID не публикует произвольную строку запроса.
Этот довод о сохранённой памяти не ограничивает всю CPU-работу потока данных.

До первого доказанного ERR-state возможны пять getter-входов. Фиксированный маркер затем доказывает
повторное использование для peek/clear. Конструирование raw MD metadata не запускает RAND/ASYNC/FIPS
контекст или вычисление дайджеста и не добавляет класс handlers. Последующие общий/приватный RAND
дают по два: `H = 5+2+2 = 9`. Неудачные приватные графы освобождаются до следующих. Публичный
проверяемый `tlsRequirements(limits,closedHostLimits())` возвращает **125582389 общих байтов** на
квалифицированном x64-профиле. Это запрошенный логический payload, а не измерение резидентной памяти.

## Отдельная работа preflight

Копия TLS shape и preflight revision связывают восемь конечных транзитивных классов. Это координаты
работы приложения, а не универсальные SDK-кредиты, аналоги публичных `PREPARE`/`ENGINE_ENTRY` или время.

| Класс | Единиц на запуск | Включённое тело |
| --- | ---: | --- |
| ENVIRONMENT_GATE | 1 | Квалифицированный getter наличия без копирования/разбора значения. |
| ERROR_PRIME | 1 | Фиксированный cold ERR marker/init/string-load graph. |
| DIGEST_FETCH | 27 | Полный граф D1–D7 ниже, включая вошедшие неудачные префиксы. |
| PROVIDER_IDENTITY | 27 | Заимствование провайдера/имени, сравнение максимум восьми байтов. |
| ALIAS_MEMBERSHIP | 71 | Поиск ненулевого method-ID в фактическом namemap hash. |
| METHOD_RELEASE | 27 | Освобождение владеющей ссылки/описателя с конечной очисткой. |
| ERROR_OBSERVE | 125 | 27 наблюдений после fetch + 71 после alias + 27 после release. |
| ERROR_CLEAR | 1 | Очистка 16 фиксированных ERR-строк без возврата буферов/state. |

Один DIGEST_FETCH включает полный холодный граф; повторное использование успешной инициализации
только уменьшает фактическую работу. Требуются фиксированные каталоги исходников, нормальная
квалифицированная семантика native once/lock/refcount, один провайдер/поток и окончательная ошибка.

| Узел | Транзитивное тело и владение |
| --- | --- |
| D1 | Generic EVP fetch фиксированного имени/query, lookup/cache/construction и temporary-store cleanup на любом выходе; внутренние кандидаты отделены от внешней владеющей ссылки. |
| D2 | Cold default `context_init`: native key/lock/ex-data, четыре method stores, decoder cache, provider/RAND/property/namemap/definition/BIO/self-test/indicator holders, thread/child-provider bookkeeping и возможный пустой compression holder. Частичный `context_deinit_objs` освобождает завершённые ненулевые holders, method stores до provider retirement, затем инициализированные ex-data/key/lock и обнуляет failure-state. Worker, дочерний провайдер или второй приватный TLS-контекст не создаются. |
| D3 | Фиксированная default fallback/provider activation, dispatch walks, provider refs/list copies и выделение/ошибка operation-bit; без внешнего configuration/module/provider catalogue и без предположения успешного operation bit. |
| D4 | Создание default provider context/BIO_METHOD и установка фиксированных BIO/seeding dispatch pointers. Ошибки setters освобождают частичных владельцев. Установленные entropy/nonce/BIO callbacks не вызываются; файл/socket/BIO I/O не открывается. |
| D5 | Копирование максимум 126 ALG + 4 ALGC cipher-строк и terminator в статическое хранилище образа. Четыре capability-вызова: две фиксированные SHA1 word-проверки и до двух SHA256 NULL assembly-проб. Без EVP_CIPHER construction, alias registration, RAND или динамического exported array. |
| D6 | Максимум 27 raw MD declarations/71 alias attempts, конечные dispatch/legacy/orphan lookup, provider refs и постоянные metadata. Five-entry/four-key parameter array требует максимум 20 сравнений ключей. Нет digest newctx/init/update/final/squeeze или обработки данных. Неудачные кандидаты освобождаются внутри shared/current envelope. |
| D7 | Два исторических query, канонические definitions/atoms, конечные sparse/cache/map paths, old/current replacement и failure cleanup. Namemap/orphan backing ограничен J; внешние expressions или callback catalogue не участвуют. |

Фиксированная область fetch имеет максимум восемь уровней sparse-path, 628 сохранённых статических
групп описаний, два query на группу и 57 различных definition-строк (до 70 байтов/четырёх clauses
каждая). Query flush посещает максимум `628*2` записей. Нормализованные name/hash keys ограничены
63/64 байтами; lookup посещает до 2048 hash slots с максимум `2048*64` сравненных байтов. Orphan-list
scans/copies используют J6297. Legacy OBJ_NAME lookup использует каталог из 436 элементов и
фиксированный alias-depth guard. Неудачные кандидаты, old/new backing и текущие raw methods оплачены отдельно.

Эти тела связаны с закреплёнными `crypto/evp/{digest,evp_fetch,evp_lib}.c`, `crypto/context.c`,
`crypto/provider_{core,child}.c`, `crypto/core_{fetch,algorithm}.c`, property/cache sources и
`providers/defltprov.c`. Холодные листья дополнительно связывают `crypto/thread/internal.c`,
`crypto/{comp_methods.c,comp/c_zlib.c}`, `providers/common/{provider_util,provider_seeding,bio_prov}.c`,
`providers/implementations/ciphers/cipher_aes_cbc_hmac_sha{1,256}_hw.c`, `include/crypto/aes_platform.h`
и `crypto/aes/asm/aesni-sha256-x86_64.pl` из точного source manifest. Startup binding использует
`crypto/cpuid.c`, `crypto/x86_64cpuid.pl` и `crypto/perlasm/x86_64-xlate.pl`.

Выбранный SHA256 assembly generator проверяет NULL в первом input и переходит прямо к `.Lprobe: ret`
в обеих generated AVX/non-AVX версиях до разыменования payload/key/hash-state, циклов обработки или
переменного scratch. Эти capability-пробы не разрешают вызовы с непустыми данными. Квалифицированная
конфигурация отключает ZLIB/BROTLI/ZSTD; возможен только пустой compression holder. Thread bookkeeping
создаёт native synchronization objects, а не worker; child-provider bookkeeping создаёт пустой holder,
а не дополнительный provider/context.

Для 27 полных единиц консервативные внутренние границы — 27 cold prefixes/provider exports,
3510 cipher-row visits, 27 terminator copies, 108 capability calls, 54 guarded NULL probes, 729 raw
MD constructions и 1917 alias attempts. Они объясняют тела классов, а не добавляют верхнеуровневые
координаты. Запрошенные владельцы оплачены существующими shared/current/failure terms. Эти числа
и обычные успешные проверки не квалифицируют произвольное повреждение allocator/native state или все
варианты ошибок выделения.

Связывание исходников относится только к точным закреплённым реализации/конфигурации и выбранному
linked startup/probe image. Перед использованием проверяются статические SDK metadata, абсолютные
пути заголовков/библиотек и итоговая линковка. Другой исходник, область мутаций, provider, ABI или
native binding требуют новой квалификации; увеличение численных бюджетов её не устанавливает.
