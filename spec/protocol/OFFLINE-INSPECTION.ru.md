# Ограниченная офлайн-инспекция, версия 1

[English version](OFFLINE-INSPECTION.md). Английская версия является нормативной.

Это политика CLI QDCXX-017, определённая до реализации CLI, а не новая wire-семантика Java.
Повторно используются [framing](FRAMING.ru.md), [описания](DESCRIBE-RECORDS.ru.md),
[binding](STATIC-BINDING.ru.md), [данные](STREAM-DATA.ru.md) и [символы](../encoding/SYMBOLS.ru.md).
Контракт JSON interchange не меняется.

## Вход и последовательность

Один именованный бинарный файл содержит сырые QTP-конверты, не tape-контейнер. Нет stdin,
автоопределения, сети, importer, восстановления, resetSession или dynamic session. Пустой вход
успешен с нулём кадров и записей; файлы только с описаниями или heartbeat также успешны, без
заявления о содержательном покрытии. Допустимо любое число начальных полных type-2 кадров,
включая пустые. Описания накапливаются по порядку; повтор sender ID внутри/между кадрами запрещён.
Каждое описание немедленно проверяется существующим binder, включая неизвестные локальные имена
и неподдерживаемые типы в файле только с описаниями. Первый type-15 требует успешно разобранного
кадра описаний, затем создаётся один неизменяемый контекст. Любой последующий type-2 запрещён,
даже идентичный или пустой. EMPTY_HEARTBEAT допустим везде как событие framing. Все остальные
типы сообщений, включая явный ноль, неподдерживаемы. Только точный обычный type 8, EMPTY_SET
и raw flags zero. Неизвестные локальные имена потребляются/пропускаются; неописанные ID дают
ошибку. Каждый вызов data начинает новое состояние символов.

Интеграция принимает независимо валидированную LocalSchema; именованная встроенная схема —
только заменяемый CLI-адаптер. Схема не выводится из описаний отправителя. Файловый I/O
и представление находятся в tools/qtp-inspect, вне production-библиотек.

## Границы и арифметика

[Аргументы/значения по умолчанию](../../docs/QTP-INSPECT.ru.md) задают конечные десятичные лимиты.
Ноль — настоящий предел, не отсутствие ограничений. Размер блока положителен и помещается
в streamsize; размер кадра допускает безопасное +9 для хранения и помещается в signed 64 bits.
Все лимиты помещаются в size_t и uint64_t. Общий лимит меньше лимита сообщения допустим:
передаётся минимум. Неверные, отрицательные, переполненные, повторные или неизвестные аргументы
и отсутствующие операнды отклоняются до входа/выхода. --help используется отдельно.

Чтение — не более chunk-size байтов за раз и остатка входного бюджета. На точном пределе входа
peek используется только для отличия настоящего EOF от превышения; лишний байт не передаётся
framer. Ошибка чтения — ошибка I/O, не finish. Обрабатываются gcount байтов короткого чтения
с EOF, извлекаются кадры, каждый непринятый суффикс передаётся повторно, finish вызывается только
при настоящем EOF. После первой ошибки следующие кадры не обрабатываются. Опережающее чтение
в пределах одного ограниченного блока не разрешает разбор последующих кадров.

Счётчик кадров включает heartbeat. Бюджеты описаний, действий и UTF-16 имён учитывают повторы
имён/полей. Кодированные байты одного имени ограничены размером кадра, units — max-name-units.
Число полей описания ограничено остатком действий. Неизменяемый контекст получает те же общие
пределы. Проверка локальной схемы имеет фиксированные пределы {records=1024, fields=65536,
lookups=65536, nameUnits=1024, totalNameUnits=1048576}, также для независимо переданных схем.

Data использует min(лимит сообщения, остаток файла) для обработанных записей, wire-полей,
выданных значений и единиц принадлежащих результату символов. Выданные записи ограничены
разрешённым числом обработанных записей. Вычитаются фактические списания processedRecords/wireFields,
включая пропущенные/ошибочные попытки, и фактические завершённые значения/символы результата.
Сброс между сообщениями не восстанавливает бюджет файла. codeUnits/stateUnits одного символа
равны symbol-units; symbol inputBytes оставшегося span и payloadBytes равны max-frame.
Общее число выданных записей не превышает обработанных. Точный предел успешен, превышение
отклоняется в существующей точке парсера. Проверенное вычитание предшествует накоплению.
Вход, кадры, описания, действия, имена, работа над данными и stdout ограничены. Это пределы
логической работы/хранения, не точного RSS или накладных расходов allocator. Результаты хранятся
не более чем для одного ограниченного payload; stdout потоковый, не накапливается для всего файла.

## Детерминированный stdout

ASCII TSV, только LF на всех хостах, без BOM и зависимости от locale. Одна строка на ряд,
разделитель — один TAB; экранирование не нужно: текст представлен lowercase UTF-16 unit hex
(четыре цифры/unit, без нормализации или замены суррогатов). `-` означает пустую последовательность
hex/значений или недоступное поле кадра; пустые TSV-ячейки запрещены. Десятичные числа без плюса,
ведущих нулей (кроме нуля) и отрицательного нуля. Значения signed int32; ID неотрицательны.

| Строка | Ячейки по порядку, включая тип строки | Число |
| --- | --- | --- |
| format | format, qd-qtp-inspect, 1 | 3 |
| frame | frame, индекс с нуля, start, exclusive end, числовой type или -, payload start или -, число байтов payload | 7 |
| record | record, индекс кадра, индекс выдачи с нуля, local ID, hex имени локальной записи, hex символа, signed значения в локальном порядке через запятую или - | 7 |
| complete | complete, принятые байты входа, кадры, выданные записи, списанные записи, списанные wire-поля | 6 |

Ровно одна format предшествует frame/record. Frame предшествует своим завершённым record;
индексы кадров и выдачи непрерывны. Неизвестные локальные записи не имеют record-строки.
Имена берутся из явной локальной схемы, ID локальные, не sender ID. ID полей — позиции в ячейке
упорядоченных значений; отсутствующие значения — raw zero декодера. Не заявляется восстановление
wire-offset или sender ID каждой записи. Начало payload кадра — проверенное
`endOffset - payload.size()` из реальных границ, даже при неканонической ширине length/type.
У heartbeat payload start/type равны `-`, размер ноль. Пустые символы и записи без полей различаются.

Успех выдаёт ровно одну финальную complete после flush предыдущего вывода. Каждая логическая
запись собирается и проверяется по бюджету до записи. Ошибка payload может оставить завершённые
предыдущие записи, включая префикс этого payload; частичная декодированная запись намеренно
не публикуется. При обнаруженной ошибке дальнейшая complete не выдаётся, stderr помечается
incomplete. Физическая ошибка вывода может оборвать любую строку или произойти при финальной
записи/flush complete; уже доставленные байты нельзя отозвать. Успех определяется exit status,
а не одним маркером. Паритет Java callback-batch не заявляется. Это неизбежное свойство I/O,
не отклонение wire-совместимости.

## Диагностика и коды выхода

Exit 0: успех/help; 2: usage; 3: входной/выходной I/O; 4: неподдерживаемый профиль или порядок;
5: некорректные данные (включая повторные/неописанные ID и усечённый конец); 6: ресурсы или
выделение памяти. Исчерпание ресурсов не является некорректностью Java-данных. Неизвестный
профиль — usage. Первая ошибка терминальна. Usage/help предшествуют выводу данных; help —
человекочитаемый ASCII, не TSV.

Stderr — одна TSV-строка с LF:
`incomplete, exit, stage, frame-index, type, frame-start, payload-start, consumed, error,
absolute-consumed, absolute-error` (11 ячеек). Недоступные позиции — `-`. Стадии парсеров —
`description.N` / `data.N`, где N — порядковый номер документированного enum в заголовках;
framing — `framing.N` с номером FrameError. Дополнительные точки: `usage`, `open`, `read`, `write`,
`flush`, `input-limit`, `frame-limit`, `sequence`, `type`, `duplicate-id`, `binding.N`, `allocation`.
Для description/data consumed/error — разные позиции относительно payload; абсолютные —
проверенное сложение payload-start и соответствующего значения. Binding и проверки повторов
выполняются после полного payload описаний и сообщают его конец, не выдуманное смещение примитива.
Ошибка framing сообщает начало кадра и абсолютную принятую позицию; type/payload/точка ошибки
недоступны. Для ошибок I/O/ресурсов вывода сохраняется известный контекст кадра без угадывания
позиций payload. Если ожидает завершения новый неполный конверт, read/input-limit диагностика
указывает его индекс/начало, оставляя type/payload недоступными, а не повторяет предыдущий кадр.
Диагностика сама может не записаться в неисправный stderr; возврат ненулевой.

## Граница доказательств

Существующие captures STREAM_DATA/binding/symbol подтверждают повторно используемые сценарии.
До кода CLI добавить workflow production Java composer/parser из locked версии с сырыми .qtp
байтами и наблюдаемыми записями. Требуются два clean captures и negative/baseline Verify.
Спроектированные CLI fixtures определяют порядок, бюджеты, диагностику и TSV; Java не задаёт
эти политики. Финальная авторская проверка и независимое ревью различаются. Нет заявлений
о timing или полной совместимости протокола.

## Опциональное читаемое представление, версия 1

`--output-format tsv|human` выбирает только представление; по умолчанию `tsv`. Повтор опции,
неизвестное значение и отсутствие операнда — ошибки использования. Определения TTY нет. Прежние
байты TSV, контракт stderr, декодирование, порядок, счётчики работы и остальные бюджеты неизменны.
Human — спроектированная политика C++-утилиты, а не наблюдение Java.

UTF-8 без BOM, только LF, десятичные числа независимо от локали. Точная грамматика строк (один
пробел между элементами) показана ниже; в фигурных скобках поля в локальном порядке через запятую-пробел:

```text
qd-qtp-inspect human 1 profile=oracle-sre-v1 identities=local
Frame 0: DESCRIBE_RECORDS (2) bytes=[0,9) payload=2 size=7
Frame 1: STREAM_DATA (15) bytes=[9,14) payload=11 size=3
Record 0: frame=1 local=0 name="S" symbol="" fields={S.v=1}
Complete: bytes=14 frames=2 records=1 charged-records=1 wire-fields=1
```

Имя heartbeat — `EMPTY_HEARTBEAT`, ID/payload — `-`, размер 0. Другие типы обозначены `UNSUPPORTED`
с числовым ID, затем прежняя ошибка. После обнаруженной ошибки итог успеха не выводится.
Имена и символы заключены в кавычки, пустой символ — `""`, отсутствие полей — `fields={}`. ID записей
и поля локальные, личности отправителя не восстанавливаются. Явные встроенные метки:
`S.v`, `R.y`, `R.x`, `R.z` в локальном порядке. Lookup-псевдонимы и входящие описания не выбирают
метки. Для независимо переданной схемы по умолчанию профиль `local-schema`, метки `field[index]`.
Метаданные остаются в утилите, без изменений core/JSON.

Точная таблица экранирования текста в кавычках (верхний регистр hex, четыре цифры в `\uXXXX`):

| Вход UTF-16 | Выход |
| --- | --- |
| U+0022 кавычка | `\"` |
| U+005C обратная косая черта | `\\` |
| U+0009 TAB, U+000A LF, U+000D CR | `\t`, `\n`, `\r` |
| Остальные U+0000–001F, U+007F–009F | `\uXXXX` (включая NUL и ESC) |
| U+2028–2029, U+061C, U+200E–200F, U+202A–202E, U+2066–206F | `\uXXXX` |
| Одиночный суррогат U+D800–DFFF | `\uXXXX` |
| Корректная пара high/low surrogate | Соответствующий Unicode scalar в UTF-8 |
| Остальные единицы | Их scalar в UTF-8 |

Без нормализации/замены. Экранирование обратной косой черты отличает буквальные подобия escape.
Текст в кавычках не может добавить терминальные escape, физические строки или строки диагностики/итога.

`max-output` учитывает фактические байты каждой строки, включая заголовок и итог. Стоимость human
зависит от UTF-8 и экранирования (до шести байт на единицу UTF-16 плюс кавычки); TSV по-прежнему
требует четыре байта на единицу либо один для пустого значения. Сначала строка подсчитывается
проверяемым вычитанием из остатка бюджета, затем выделяется и строится в точном размере. Временных
буферов размера развёрнутого текста до проверки нет; хранится не более одной ограниченной строки.
Нехватка бюджета строки даёт `write` до вывода её байтов. Ограничены логические размеры, не ёмкость
аллокатора/RSS. Политика завершённого префикса, приоритет первой ошибки и flush до/после итога прежние.
Физически доставленный итог не отменяет неуспешный код завершения.

Raw QTP — не QD tape. Не добавлены tape reader, сжатие, обработка time-файлов,
protocol-descriptor, расширенные поля, importer, transport или динамические сессии.
