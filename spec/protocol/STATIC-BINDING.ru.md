# Ограниченный статический входящий binding

## Явная обычная wire-схема

[WIRE-INVENTORY](../schema/WIRE-INVENTORY.ru.md) описывает явно включаемое
обнаружение схемы в `TapeReader` с прежней проверкой `LocalSchema` и точными
упорядоченными действиями `bindRecord`. Сгенерированная схема объединяет точные
имена полей разных отправителей; неоднозначные повторы имён исходных полей и
конфликты типов отклоняются. Переданные вызывающей стороной схемы, псевдонимы,
пропуски и повторные назначения этого API не меняются. ID и порядок источника
остаются отдельными от устойчивых локальных ID и отображений событий.

## Явное расширение полями Quote

QDCXX-022 добавляет opt-in LocalProfile::QUOTE_FIELDS_V1 рядом с неизменным default
COMPACT_INT_V1. [Точные типизированные значения](../encoding/QUOTE-VALUES.ru.md) и
[отображение default Quote](DEFAULT-QUOTE.ru.md) задают полные типы 2/8/56/120, raw-zero defaults,
порядок повторных целей и binding только точных совпадений. Каждое действие владеет полным типом,
включая skips; известная цель с другим полным типом даёт UNSUPPORTED_PROFILE. Прежние ограничения
схемы/имён/работы и атомарное владение планом сохраняются. Ниже остаётся контракт прежнего профиля
type 8; opt-in расширение отменяет исключение только этих трёх дополнительных идентификаторов.

[English version](STATIC-BINDING.md). Английская версия является основной.

QDCXX-014. Предварительный API планирует одно сырое описание QDCXX-013 относительно явно переданной
проверенной неизменяемой локальной схемы. Он не декодирует данные и не устанавливает таблицу входящих ID.

## Профиль и доказательства

Поддерживаются только обычные поля с точным полным типом 8 (COMPACT_INT). Индексы времени, объектные поля,
VOID, LONG, преобразования представлений, метаданные и field replacers исключены. Неизвестные локальные
записи и отсутствующие поля можно пропускать только после проверки типа 8 у всех сырых полей.
Другие типы в допустимом диапазоне дают UNSUPPORTED_PROFILE, не меняя более широкое принятие raw parser.
Некорректные сырые входы, созданные вручную, дают INVALID_DESCRIPTION.

[Java inputs](../../tests/fixtures/protocol/binding/inputs.tsv) используют закреплённый QD 3.355,
штатный BinaryQTPParser и настоящий DefaultScheme. Дополнительный capture содержит описания и данные,
доставленные локальные ID, значения по порядку и ошибки. Исторические P03/P04 остаются исходными
доказательствами направленного remapping ID, порядка полей и alias/property lookup; см. [CAPTURES](CAPTURES.md).
BinaryQTPParser.parseDescribeRecords и BinaryRecordDesc.field2Desc/readFields из [SOURCES](SOURCES.md)
объясняют поиск записи по имени и порядок присваиваний. Промежуточные повторные записи подтверждаются
исходниками; снаружи наблюдается только итоговое значение. Разработанные C++ plans являются проекциями,
а не callbacks parser. Нули отсутствующих локальных значений — наблюдение Java storage, не defaults приложения.

## Локальное подмножество и валидация

Локальный вход — узкая проекция [JSON-CONTRACT](../schema/JSON-CONTRACT.md) в памяти, а не новый формат
обмена или importer. Локальные ID записей равны позициям записей; ID полей равны позициям полей.
Для обычного int-only подмножества позиция логического поля также соответствует Java int ordinal.
Полные числовые ID типов сохраняются и проверяются без маскирования. Имена записей уникальны, непусты
и являются корректным UTF-16. Record-scoped lookup entries явно связывают непустые корректные UTF-16
ключи с позициями полей. Каждый ключ уникален, даже если повтор указывал бы на то же поле; все цели
должны существовать. У каждого поля должен быть хотя бы один ключ. Дополнительные full/local/property/alias
ключи передаются явно: удаления точек, добавления префиксов, изменения регистра и Unicode-нормализации нет.
Загрузчик обязан проверить полный исходный контракт до проекции; runtime не требует XML/JSON/provenance,
семантических имён или Java storage. hasTime=true и любой локальный тип кроме 8 отклоняются как unsupported.
Синтетическая/index/object форма не представима как поддерживаемое поле. Пустые схемы и записи допустимы.

LocalSchema::create заимствует вход только на время вызова, полностью проверяет его и затем владеет копией.
Доступны только const views; изменение требует новой валидации. При ошибке схема не публикуется.
Схема находится в qdcxx_core без зависимостей от protocol, файлов и транспорта.

## Планирование и владение

bindRecord сопоставляет точные UTF-16 имена записей, затем явные ключи record lookup. Возвращаемый план
владеет senderId, optional localRecordId и одним действием на каждое wire field в исходном порядке.
Наличие targetFieldId означает присваивание полю; отсутствие — чтение/пропуск одного поддерживаемого
compact int. Повторные цели сохраняются. Неизвестная запись даёт успешный план без localRecordId,
полностью состоящий из пропусков, включая допустимый план без полей. Нет описания — нет плана;
API не ищет undescribed ID. Неизвестная запись не является некорректным входом, описания не синтезируются.
Для локальных полей, отсутствующих на wire, нет действий или defaults. Имена и ссылки на схему в плане
не сохраняются. Время жизни плана независимо от обоих входов. Вызовы независимы: повторные sender ID
не задают replacement/reset/session policy. INT_MAX sender ID не требует выделения памяти по индексу ID.
Успешный план не является доставленным событием или исполняемым декодером payload.

## Конечные бюджеты и ошибки

Все бюджеты обязательны и являются конечными size_t; ноль допустим, unlimited sentinel отсутствует.
SchemaLimits ограничивает записи, общее число полей, lookup entries, UTF-16 units одного имени и сумму
units имён записей/ключей. BindingLimits ограничивает поля, units одного имени и сумму units имён записи/полей.
Это границы логических элементов, не allocator metadata или точной heap capacity. Вход уже принадлежит
вызывающему. Валидация и поиск используют ограниченные линейные проходы; заявлений о производительности нет.

Валидация схемы сначала проверяет число записей, затем ID/уникальность имени каждой записи, поддерживаемую
форму hasTime, бюджеты полей/lookup, полные типы полей, корректность ключей, диапазон целей/уникальность и покрытие полей.
Бюджеты имён учитываются вычитанием до сложения. bindRecord проверяет число полей, raw header/бюджет имени
записи, затем структурную корректность/бюджеты имён/типы всех полей до поиска и выделения памяти.
Возвращается первая обнаруженная ошибка. Частичные plan/schema не публикуются.
Ошибки: INVALID_SCHEMA, INVALID_DESCRIPTION, UNSUPPORTED_PROFILE, RESOURCE_LIMIT и ALLOCATION_FAILURE;
они отличаются от обычного отсутствия совпадения. std::bad_alloc и std::length_error преобразуются в
ALLOCATION_FAILURE. Точного соответствия Java exceptions не обещается. Параллельные read-only вызовы
требуют неизменности входов во время вызова; общего изменяемого состояния нет.

## Границы conformance

[Покрытие](../../tests/conformance/protocol/binding/COVERAGE.md) и
[валидация](../../tests/conformance/protocol/binding/VALIDATION.md) перечисляют выполненные проверки.
Бюджеты, диагностика некорректной схемы, неизменяемое владение и предельные C++ ID — разработанная
политика API, не заявления о Java parity. Огромные allocations и инъекция отказов allocator исключены.
Importers, event decoding, outgoing layouts, conversion matrices, динамическое session state, PART,
транспорт и полный DataScheme остаются за пределами задачи.

## Общий идентификатор типа

[SerialFieldType](../../include/qd/core/serial_field_type.hpp) единожды задаёт полный идентификатор
реализованного типа COMPACT_INT=8 в qdcxx_core. Локальная валидация и planner сравнивают числовые входы с
std::to_underlying(SerialFieldType::COMPACT_INT). Enum намеренно неполон: он не ограничивает структурное
принятие raw и не отбрасывает биты представления. Входной serialTypeId остаётся int32_t.
Литеральные oracle ID в тестах остаются независимыми ожидаемыми значениями.

Структурная верхняя граница отдельно задана общей константой MAX_WIRE_SERIAL_TYPE_ID=0xff в
[describe_records.hpp](../../include/qd/protocol/describe_records.hpp). Её используют raw parser и binding.
Это граница протокольной валидации, не элемент enum и не обещание поддержки каждого типа.

## Явный профиль дополнительных полей

[FIELD-TYPES](../encoding/FIELD-TYPES.ru.md) определяет EXTENDED_FIELDS_V1 с точными 2/8/10/40/56/72/88/120,
владеющим nullable UTF-16, логическими позициями полей независимо от Java slots и накопленными бюджетами строковой работы/хранения.
Оба прежних tape modes сохраняют политики descriptor, flags, времени, терминальных ошибок и append-only updates.
Прежние исключения типов ниже описывают старые профили; только этот явный профиль расширяет их.
Profile event adapter, indexed schema, импортер и неявное обнаружение схемы не добавляются.
