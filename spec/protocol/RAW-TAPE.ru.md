# Ограниченная политика tape RAW_DATA / MESSAGE

[English version](RAW-TAPE.md). Английская версия является нормативной.

Контракт QDCXX-023 расширяет [TAPE-READER](TAPE-READER.ru.md) только явным режимом
`raw-message-v1`. Выбор локальной схемы независим: синтетические S/R/E с точным типом 8 либо
неизменённый default composite Quote с точными полными типами 2/8/56/120. Другие типы, адаптеры,
ненулевые event flags, сжатие, sidecar, FIELD timing, транспорт и планировщик воспроизведения не добавлены.

## Производственные доказательства и проекция

Оракул — закреплённый upstream.lock QD. [Harness](../../tools/upstream/raw-tape-oracle/RawTapeOracle.java)
использует неизменённые `FileWriter` и `FileReader`, а отдельно реальный путь
`DXEndpoint(PUBLISHER) → TapeConnector → FileWriterHandler → FileWriterImpl` с заданными
временами событий Quote. `DXFeedScheme` и `QuoteDelegate.putEvent/createEvent` неизменны,
включая все поля default Quote и дробные размеры. Явные пустые options и стандартные `hs`
коннектора дают файлы с реальным RAW_DATA типа 5. Контрольный STREAM FileWriter даёт тип 15.
Сохранены исходные дескрипторы, описания, heartbeat и маркеры файлов.

`FileReader` доставляет каждую RAW-запись в TICKER_DATA (10), STREAM_DATA (15) и HISTORY_DATA
(20), в этом порядке внутри сброшенного блока. Это измеренное поведение производственного
парсера, а не выдуманный RAW callback. C++ выводит одну wire-запись и сравнивает её с Java
проекцией STREAM_DATA; доставка ticker/history и утроение вывода не реализованы. Группировка
callback не является контрактом границ wire-записей. Дополнительные `*-frames.tsv` сканируют
только конверты. Изменённые/сконструированные диагностические входы помечены `diagnostic-wire`.

## Матрица дескриптора и диспетчеризации

`legacy` сохраняет прежний контракт и вывод. В новом режиме остаются все остальные проверки
синтаксиса дескриптора, повторных/null/неизвестных свойств, счётчиков, receive-list и расширений.
Version — только диагностический текст; по нему не определяются options или производитель.

| Режим C++ | Время дескриптора | Send list | Реальные данные | opt | Политика |
| --- | --- | --- | --- | --- | --- |
| legacy | отсутствует/NONE | пустой либо один STREAM_DATA | STREAM_DATA | присутствует пустой | Прежний допуск |
| raw-message-v1 | MESSAGE или message | пустой либо один RAW_DATA (5), точное имя, без свойств | RAW_DATA (5) | отсутствует, пустой либо точно hs | Допуск нулевых flags и разрешённых точных типов |
| raw-message-v1 | отсутствует/NONE/FIELD/другое | любой | любые | любой | Отказ дескриптора |
| raw-message-v1 | MESSAGE/message | STREAM_DATA, смешанный или другой | любые | любой | Отказ дескриптора |
| raw-message-v1 | MESSAGE/message | допустимый | STREAM_DATA/смешанные/другие | допустимый | Отказ реального сообщения при диспетчеризации |
| raw-message-v1 | MESSAGE/message | допустимый | RAW_DATA | явный null/unknown/hs,unknown/другой | Отказ дескриптора |

Производственные дескрипторы записывают `message`; диагностические пробы измеряют и `MESSAGE`.
Полная Java-матрица независимо пересекает absent/NONE/MESSAGE/FIELD, пустой/RAW/STREAM send set
и реальные RAW/STREAM: Java допускает эти случаи, включая несоответствие. Ограниченная политика
намеренно строже; она не выводит режим из фактического сообщения или заголовка.

Отсутствующий opt не имеет пары свойств; явный null имеет пару с null UTFString; пустой — пару
с пустой UTFString. Они структурно различны. Наблюдения FileReader и
`ProtocolOption.parseProtocolOptions` показывают EMPTY_SET для absent/null/empty и unknown-only,
а hs для hs и hs,unknown. Политика допускает только absent/empty/точный hs. Java доставляет
ненулевые RAW flags даже при пустом opt диагностической пробы. C++ отказывает при любых ненулевых
flags до декодирования полей записи; допуск hs не разрешает flags.

## Грамматика heartbeat и время

Пустой конверт не содержит ID. Явный frame типа 0 содержит payload: допускается нулевая длина
либо compact-int content bits и поля по порядку битов. Java `HeartbeatPayload` определяет бит 1:
compact-long signed timestamp в миллисекундах; биты 2/4/8: compact-int timeMark/deltaMark/lagMark.
В измеренных случаях Java принимает/игнорирует неизвестные биты и лишние байты; эта политика
отказывает вместо потери непредставленной информации.

Допустимое подмножество: пустой payload типа 0, content bits 0 без следующих байтов либо bits 1
с одним полным compact-long timestamp без следующих байтов. Биты 2/4/8, неизвестные/отрицательные
bits и хвостовые расширения не поддерживаются. Отсутствующий обязательный примитив — malformed.
Правила compact-примитивов, неканонические кодировки и signed projections следуют существующим
контрактам кодирования. Пустой payload отличается от явных bits 0. Java не вызывает callback для
пустого конверта или пустого payload типа 0, но вызывает пустой callback для bits 0. Просмотр
сохраняет эти wire-различия и каждый допустимый heartbeat, включая последний перед EOF без записей.

Начальное время: timestamp отсутствует, event-time sequence равен 0. Полный bits-1 heartbeat
атомарно заменяет timestamp и sequence. Явный ноль присутствует и отличается от отсутствия,
несмотря на sequence 0. Повторные/убывающие timestamp точно заменяют состояние. Последовательные
heartbeat сохраняются; состояние действует через описания и несколько data frames, а пустые формы
его не меняют. Между reader состояние не переносится. Записи результата разделяют принадлежащее
этому data frame значение времени.

Timestamp — точные исходные signed int64 миллисекунды. Java cursor event-time sequence упакован:
`seconds = clamp(floor(timestamp / 1000), INT32_MIN, INT32_MAX)`;
`millis = floorMod(timestamp, 1000)`; signed seconds занимают биты 63..32, millis — 31..22,
младшие 22 бита нулевые. За диапазоном секунд действует насыщение, не циклическое переполнение.
Оба предела int64 измерены. Исходный timestamp и packed sequence сохраняются раздельно:
насыщение может потерять исходное время. Отрицательные деление/остаток и сборка битов должны
избегать signed overflow и левого сдвига отрицательного числа C++. Закреплённые `TimeSequenceUtil`
и `TimeUtil` определяют поведение; `packing.tsv` содержит граничные значения.

Replay timestamp, cursor sequence и бизнес-время bid/ask Quote различаются. `QuoteDelegate`
получает mapped eventTime из cursor sequence; в обычном диапазоне оно равно replay-миллисекундам,
но при насыщении может отличаться. Третий параметр неизменённого `mapQuote` остаётся бюджетом
копирования символов. Просмотр показывает измеренное время отдельно от старого untimed Quote mapping.

## Атомарность, лимиты, позиции и приоритет отказов

Сохраняются владение TAPE-READER, неизменяемые append-only описания, накопленные затраты
перестроения, завершённые префиксы данных, offsets и терминальные ошибки. Учитываются frames,
включая маркеры и потоки только heartbeat; выводимые heartbeat metadata ограничены накопленным
бюджетом. Состояние времени имеет фиксированный размер и владеет данными без скрытого накопления
истории. Возвращённые и сохранённые вызывающим события — ответственность вызывающего.

Ошибки framing/input/frame-budget предшествуют диспетчеризации. Последовательность заголовка
и политика дескриптора предшествуют обработке сообщений. Для heartbeat сначала читается примитив
content, затем проверяются bits; для разрешённых bits обязательный timestamp читается перед
проверкой лишних байтов. Время публикуется только после полного допустимого payload и проверок
ресурсов. Ошибка примитива указывает его начало; неподдерживаемые bits — checkpoint bits;
расширение — первый лишний байт. Неуспешный heartbeat не меняет состояние частично. Ошибки
дескриптора/описаний/данных сохраняют прежние checkpoints и завершённый префикс. Java может
сообщить malformed heartbeat и продолжить; C++ остаётся терминальным. Чистый EOF требует
принятого заголовка и полного framing, а не footer; он не подтверждает полноту записи tape.
EOF после допустимого heartbeat успешен и сохраняет событие.

## Владеющий API и учёт metadata

`TapeReader(schema, limits, TapeMode::RAW_MESSAGE_V1)` явно включает режим; стандартный
`TapeMode::LEGACY` сохраняет прежнее поведение. `TapeDescriptor::options` и `time` сохраняют
точные допустимые optional-строки; `explicitRawSend` отмечает явный send set с одним RAW.
Прежние поля дескриптора остаются доступными. Локальная схема не выводится автоматически.

`TapeTiming` владеет optional `timestampMs` и signed `eventTimeSequence`; `eventTimeMs()`
распаковывает доставленное время cursor из sequence. `TapeHeartbeat` владеет optional `content`
и `timestampMs`. Отсутствующий content означает явный frame типа 0 без payload; присутствующий
ноль — пустой content-примитив. `TapeFeedResult::heartbeat` сохраняет каждый допустимый явный
heartbeat. `TapeFeedResult::timing` присутствует для каждого RAW data frame, в том числе для
завершённого префикса перед ошибкой данных. Все записи этого результата имеют одно время.
Пустые конверты остаются представленными прежним frame и счётчиком маркеров.
`TapeReader::timing()` предоставляет текущее состояние фиксированного размера; скопируйте его,
чтобы сохранить после уничтожения reader.

`TapeLimits::timingEvents` по умолчанию равен нулю и является реальным конечным накопленным
бюджетом metadata. Перед разбором явного heartbeat или RAW payload проверяется и списывается
одно событие времени. Отказ бюджета предшествует синтаксису payload и ничего не публикует.
Списанная попытка с последующей ошибкой учитывается аналогично попыткам записей/полей;
`timingEvents()` предоставляет счётчик. Допустимый data frame без записей тоже учитывается.
Текущее состояние фиксированного размера не копит историю. Legacy не использует новый бюджет.
Конструктор отклоняет недопустимый TapeMode до потребления входа.

## Грамматика просмотра с временем, версия 3

Явный `--tape-mode raw-message-v1` выбирает версию 3 для обоих существующих локальных профилей.
Отсутствующий режим и `--tape-mode legacy` сохраняют прежние вывод и отказы. Версии диагностики
1/2 и прежние значения по умолчанию для профилей независимы. `--max-timing-events` задаёт новый
накопленный бюджет; стандартное значение CLI — 4096. Все прежние бюджеты IO/вывода действуют.

TSV использует LF без BOM, канонические десятичные числа, строчный UTF-16 hex и `-` для
отсутствующих/пустых ячеек по правилам ниже. Строки следуют wire-порядку:

- Заголовок: `format`, `qdcxx-tape-inspect`, `3`, локальный профиль, `raw-message-v1`.
- Прежние строки `frame` сохраняют точную грамматику и реальный ID типа, включая 5 и 0.
- `descriptor-v3`, наличие version (0/1), version hex либо `-`, точный текст времени (`MESSAGE`
  или `message`), send (`5` либо `-`), receive (`-`), options (`absent`, `empty` либо `hs`).
- `heartbeat`, индекс frame, content (`-`, `0` либо `1`), timestamp в миллисекундах либо `-`.
- `timing`, индекс frame, последний timestamp в миллисекундах либо `-`, signed packed
  event-time sequence, доставленное event-time в миллисекундах. Строка предшествует записям
  каждого RAW data frame, включая пустые frames и сохранённые префиксы перед ошибкой.
- Прежние `record` либо `typed-record` сохраняют грамматику локальных идентификаторов/значений.
  Для Quote следующая строка `quote` сохраняет порядок ячеек версии 2, но последний `eventTime`
  содержит доставленное время этого frame, совпадающее с Java QuoteDelegate. Сам `mapQuote`
  остаётся отображением полей без времени metadata. Bid/ask time, sequence и nano сохраняют смысл.
- Прежние `markers` и `complete` сохраняют грамматику. Успех требует exit 0 после последнего
  flush; после обнаруженной ошибки строка completion не выводится.

Human-заголовок: `qdcxx-tape-inspect human 3 profile=<profile> tape-mode=raw-message-v1 identities=local`.
Дескриптор: `Descriptor: type=tape opt=<absent|empty|hs> version=<quoted text|absent>
time=<MESSAGE|message> send=<5|-> receive=-` одной строкой. Строка heartbeat:
`Heartbeat: frame=N content=<-|0|1> timestampMs=<signed milliseconds|->`.
Строка времени данных: `Timing: frame=N timestampMs=<signed milliseconds|-> eventTimeSequence=S eventTimeMs=M`.
Далее идут прежние строки записей с безопасным экранированием; `eventTime` Quote — доставленное
значение. RAW frames называются `RAW_DATA (5)`, явные frames типа 0 — `HEARTBEAT (0)`;
пустые маркеры остаются отдельными. Все строки проверяются по бюджету кодированных байтов
до динамического расширения, включая version и строки только времени. Представление остаётся
вне protocol/core и не ожидает времени воспроизведения.

Этот контракт не заявляет полной поддержки частного tape; оставшиеся структурные ограничения
требуют отдельной ограниченной инвентаризации и не выводятся из успеха generated fixtures.

## Явный профиль дополнительных полей

[FIELD-TYPES](../encoding/FIELD-TYPES.ru.md) определяет EXTENDED_FIELDS_V1 с точными 2/8/10/40/56/72/88/120,
владеющим nullable UTF-16, логическими позициями полей независимо от Java slots и накопленными бюджетами строковой работы/хранения.
Оба прежних tape modes сохраняют политики descriptor, flags, времени, терминальных ошибок и append-only updates.
Прежние исключения типов ниже описывают старые профили; только этот явный профиль расширяет их.
Profile event adapter, indexed schema, импортер и неявное обнаружение схемы не добавляются.

## Доказательства флагов каталога и прежний допуск RAW

[Производственный набор флагов](../../tests/conformance/protocol/field-types/FLAGS-VALIDATION.ru.md)
характеризует все 64 известных подмножества и различия опций composer/parser в RAW5, TICKER 10,
STREAM 15 и HISTORY20. Три RAW callback помечены и сравниваются до выбора одной STREAM-проекции
wire-записей. Эти наблюдения не расширяют RAW_MESSAGE_V1 и `decodeRawData`: оба по-прежнему
отклоняют ненулевые флаги данных. Новая функция `decodeStreamDataWithEventPolicy` и режим
BINARY_CATALOG_V1 допускают только известные флаги STREAM/NONE и владеющее время удаления
по своему явному контракту. Расширенная диспетчеризация семейств и версионированный вывод
остаются отдельной работой; прежние сериализованные данные не меняются.
