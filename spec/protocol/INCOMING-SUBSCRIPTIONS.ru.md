# Входящие подписки двоичного QTP

[English version](INCOMING-SUBSCRIPTIONS.md). Нормативен английский текст.

`FrameReader` принимает частичный ввод и возвращает не больше одного владеющего кадра за вызов.
Для готового кадра подписки вызывается `decodeIncomingSubscription`. При сбое декодер возвращает
одну ошибку, без записей. Приложение может применить весь успешный пакет после завершения
декодирования. Согласование сессии, политика закрытия и применение подписок принадлежат
вызывающей стороне. Ориентированный на FEED `LiveSession` сохраняет собственные правила приёма
по направлениям и учёта памяти.

| Тип кадра | Сообщение | Поля записи |
| --- | --- | --- |
| 11 | TICKER_ADD | Символ, ID отправителя в compact int |
| 12 | TICKER_REMOVE | Символ, ID отправителя в compact int |
| 16 | STREAM_ADD | Символ, ID отправителя в compact int |
| 17 | STREAM_REMOVE | Символ, ID отправителя в compact int |
| 21 | HISTORY_ADD | Символ, ID отправителя в compact int, исходная граница в compact long |
| 22 | HISTORY_REMOVE | Символ, ID отправителя в compact int |

Записи повторяются точно до конца нагрузки. Нагрузка может не содержать записей. Для каждого
кадра заново инициализируются состояния символов Penta и флагов. Префиксы флагов входят в
грамматику символов. Действие задаёт внешний тип, как в Java-парсере подписок. Точный символ
владеет декодированными единицами UTF-16, включая пустой текст. Начальный `*` зарезервирован и
отклоняется в этом профиле точных селекторов. HISTORY_ADD сохраняет исходное знаковое 64-битное
значение без преобразования единиц. Для обеих разновидностей HISTORY известная целевая запись
должна объявлять структуру индексированного времени.

Вызывающая сторона передаёт полное отображение для входящего направления в порядке строгого
возрастания неотрицательных ID записей другой стороны. Его можно получить из предшествующих
описаний записей другой стороны или задать явно для общей схемы. Необъявленный ID приводит к
отклонению кадра. Запись с явно описанной неизвестной локальной целью декодируется целиком и
учитывается по тем же лимитам, что и известная. Её символ участвует в повторах внутри кадра.
Пакет сохраняет известные записи в порядке передачи вместе с повторами. Локальные контексты
владеют идентичностью записи. Пакет может пережить кадр, отображение и исходные объявления схемы.

Декодер ограничивает байты нагрузки, записи локальной схемы, строки отображения отправителя,
количество записей, единицы UTF-16 одного символа и сумму декодированных единиц UTF-16. Из
бюджета хода вызывающей стороны списываются попытки декодирования, допущенные байты нагрузки,
обращения к записям и отображениям, а также работа с символами. Перед чтением символа декодер
ограничивает допустимую длину по остатку общего лимита единиц и бюджета работы. Ранее списанные
затраты сохраняются при сбое. Бюджеты относятся к одному кадру и ограниченным временным данным
декодирования. Вызывающая сторона может сохранять успешные пакеты и сама учитывает срок их
жизни в своём бюджете памяти.

[Тесты соответствия](../../tests/conformance/incoming_subscription_tests.cpp) воспроизводят шесть
последовательностей байтов, записанных Java QD `BinaryQTPComposer`, в том числе HISTORY_ADD с
`INT64_MIN`, `-65`, `0`, `64`, `INT64_MAX` для `IBM` и ID отправителя `Order` `6`. Тест задаёт
явное отображение на искусственную локальную схему, проверяет все разбиения перед последним
байтом и добавляет искусственные случаи отказов и исчерпания ресурсов. Данные Java-компоновщика
получены в памяти из существующих Java-классов закреплённой версии. Некорректные случаи
проверяют контракт целого кадра в C++. См. закреплённые [исходники Java-парсера и компоновщика](SOURCES.md#framing-and-records).
