# Локальный файл записи как источник Feed

[English version](FEED-TAPE-SOURCE.md). Английская версия является основной.

`Endpoint::connectTape` выбирает один обычный бинарный файл для endpoint.
Endpoint владеет переданным путём после вызова и открывает файл асинхронно
на существующем рабочем потоке runtime. Передавайте стабильный путь к
обычному файлу на всё время проигрывания. Разбор URI и поиск файлов не
выполняются. Чтение синхронно на границе ОС, время его завершения зависит
от файловой системы.

Адаптер использует [бинарное чтение с каталогом](TAPE-READER.ru.md), точную
схему приёма endpoint и существующий путь типизированной подписки.

| Вход | Выбранный режим доставки endpoint |
|---|---|
| TICKER_DATA, STREAM_DATA, HISTORY_DATA | Записи получает соответствующий режим endpoint. Другие семейства разбираются и пропускаются. |
| RAW_DATA | Записи получает явно выбранный режим endpoint. |
| Описания, изменения дескриптора, маркеры, heartbeat | Проверяются как входные данные файла. Типизированные события для приложения не создаются. |

Поддержанные бинарные профили допускают заголовок или самодостаточное
описание без заголовка и встроенное время NONE, MESSAGE или FIELD.
Отдельные файлы времени, сжатые контейнеры, текстовый и blob-режимы находятся
за пределами этого профиля. При наличии FIELD его фактическое время задаёт
`eventTime` типизированного события. В остальных случаях используется время
Java cursor из предыдущего heartbeat с меткой MESSAGE. У события без метки
остаётся неопределённое значение времени его типа. Эти метаданные независимы
от полей времени котировки, сделки, свечи и индекса. Правило маршрутов с
`EventTimePolicy::NONE` сохраняется.

Настройте подписки до подключения. Рабочий поток применяет их начальные
запросы и синхронизирует регистрации в коллекторе перед чтением. Он использует
обычную фильтрацию, формирование пакетов, выполнение callback и хранение
истории. Каждый успешный конверт принимается целиком. Из отклонённого конверта
записи не доставляются, даже если декодер разобрал его начало. Ранее принятые
события могут завершить доставку.

Значения `TapeSourceOptions` по умолчанию — 64 МиБ файла и 65 536 конвертов.
Один буферизованный запрос читает не больше 4096 байт. Пределы на конверт
берутся из существующего профиля приёма endpoint. Создание reader,
суммарная работа декодера и владение событиями имеют отдельные конечные
пределы. Рабочий поток хранит не более одного ещё не принятого результата
разбора или подготовленного события, помимо существующих резервов
коллекторов и подписок.

## Темп проигрывания и пауза

По умолчанию действует `TapePlaybackPolicy::IMMEDIATE`. Для проигрывания
с темпом выберите `TapePlaybackPolicy::SOURCE_TIME` и задайте `speedPercent`
от 1 до 10 000 (100 — обычная скорость). Первый подходящий конверт с меткой
задаёт начало отсчёта на монотонных часах runtime. Если в конверте несколько
меток, его готовность определяет самая поздняя. Адаптер использует физическую
метку FIELD при её наличии, иначе точные миллисекунды из предыдущего MESSAGE.
Конверт без метки не добавляет задержку. Метка, которая идёт назад, сохраняет
максимальное достигнутое время и порядок записей. Задержка округляется вверх
до целой миллисекунды.

`maximumSourceSpan` ограничивает продвижение времени от первого конверта с
меткой. По умолчанию это 24 часа. В относительном режиме допустимы значения
больше нуля и не более 365 дней. Выход за предел или непредставимый срок дают
`TAPE_TIMING_RANGE`. Рабочий поток удерживает один будущий конверт и может
проснуться по его сроку, по команде источнику или для другого endpoint.

С `initiallyPaused` файл открывается сразу, а чтение конвертов ждёт
возобновления. `Endpoint::setTapePaused(true)` приостанавливает приём, а
`Endpoint::setTapePaused(false)` возобновляет его на том же endpoint.
Рабочий поток применяет последнее намерение, сдвигает относительные часы
на наблюдавшуюся длительность паузы и завершает доставку принятого. Досрочное
закрытие освобождает ожидающий конверт без ожидания его срока.

## Перезапуск и остановка

Вызывайте `Endpoint::restartTape()`, пока файловый источник подключён,
в том числе на паузе. Принятый запрос переводит endpoint в CONNECTING,
прекращает выбор новых callback из прежнего источника и объединяется с уже
начатым перезапуском. Рабочий поток отменяет ещё не начатые callback, ждёт
завершения выполняющихся, затем очищает коллектор и покрытие HISTORY. Он
открывает тот же путь с нулевого байта и создаёт новые часы и эпоху источника.
Подписки, слушатели и намерение о паузе сохраняются. CONNECTED подтверждает
открытие нового прохода.

`drainTimeout` ограничивает попытку перезапуска. По истечении срока endpoint
переходит в FAILED с `TAPE_RESTART_TIMEOUT`. Ошибка повторного открытия
сохраняет собственную диагностику. Фактическое завершение callback и ввода
ОС может занять больше времени. Старый отложенный callback не запустится
в новой эпохе. Итоговая статистика может сохранить разрыв от сброса даже
после успешного завершения нового прохода.

`Endpoint::stopTape()` запускает обычное окончательное закрытие. Его правила
отменяют отобранные callback внешнего executor, которые ещё не начались.
`stopTape(TapeStopMode::ABORT)` отбрасывает очередь доставки и может прервать
незавершённое закрытие. Остановка или закрытие имеют приоритет над
ожидающим перезапуском. `closeAndAwaitTermination()` возвращает `CloseResult`
после освобождения нативных ресурсов и завершения callback.

Состояния проходят через CONNECTING, CONNECTED после открытия файла,
CLOSING при завершении доставки и CLOSED после чистого EOF и освобождения
ресурсов. Недоступный путь, путь к объекту другого типа или ошибка ввода
дают `TAPE_IO_FAILURE`. Повреждённый вход, неподдержанный профиль и превышение
лимита дают соответственно `PROTOCOL_FAILURE`, `UNSUPPORTED_PROFILE` или
`RESOURCE_LIMIT`. После повреждённого хвоста endpoint завершает доставку
принятых данных по своему правилу закрытия и переходит в FAILED. Чистый EOF
после доставки принятого переводит endpoint в CLOSED. После CLOSED или FAILED
для нового проигрывания создайте новый endpoint. Перезапуск в этом профиле
всегда начинает с нулевого байта. Произвольное позиционирование недоступно.

У локального коллектора есть фактическая эпоха файлового источника. Для него
нет попыток TCP/DNS, удалённого дескриптора, сетевой подписки или подтверждения
другой стороны. Метрики сетевого соединения недоступны. Состояние подключения
для файла означает локальную готовность.
