# Ограниченный parser payload DESCRIBE_RECORDS

[English version](DESCRIBE-RECORDS.md). Английский документ является основным.

QDCXX-013 определяет предварительный слой сырых descriptions в qd_protocol. Вход — ровно один
полный payload типа 2 без длины и типа. Привязка к схеме, декодирование событий, таблица входящих ID,
преобразования, transport и восстановление сессии не реализуются.

## Измеренные факты Java и проекция слоя

Oracle — QD 3.355, `0ddc0a09779fb61d74cc0b37c6449ff47dcb715f`.
[Индекс исходников](SOURCES.md) указывает BinaryQTPParser.parseDescribeRecords, читающий конструктор
BinaryRecordDesc/field2Desc и SerialFieldType.Bits. [Доказательства P08](../../tests/fixtures/protocol/p08/COVERAGE.md)
отделяют диагностический обход закреплённых Java primitives от реальных установок и ошибок parser.
Диагностический обход — сверенная с исходником инструментализация, а не callback всех сырых descriptions.
Он выдаёт description только после структурной проверки всех полей. Реальный hook remapRecord вызывает
super и наблюдает лишь построенные mappings; reflection читает итоговую таблицу без изменений.
Для каждого входа полный parser получает заново завершённый frame, включая строгие префиксы payload.
Его позиция в конце frame не является диагностической позицией primitive.

Payload повторяет `compactInt senderId, UTFString recordName, compactInt fieldCount`, затем
`fieldCount` пар `UTFString fieldName, compactInt fullSerialTypeId`. Начального числа записей нет.
Все числовые проверки используют знаковые младшие 32 бита readCompactInt, принимая overlong/cross-width
формы. Весь заголовок записи читается до отклонения отрицательных ID/count или null/пустого имени.
Обе части поля читаются до отклонения null/пустого имени поля или типа вне 0..255. Поэтому ошибки
primitives могут предшествовать этим проверкам. UTFString сохраняет точные UTF-16 units, включая
одиночные суррогаты и NUL; действуют существующие правила корректности primitive.
Дубликаты структурно допустимы. Порядок и полный ID типа значимы.

Нельзя смешивать три разных вопроса:

1. Структурная корректность допускает полные ID типов 0..255 и указанные имена/числа.
2. Java BinaryRecordDesc.field2Desc обрабатывает serialization codes 0,1,2,3,4,8,9,10 после исключения
   representation bits 0xf0. Остальные вызывают InvalidDescException, перехватываемое без ошибки
   сообщения и установки. P08 измеряет 5 и 255, сохранение предыдущего mapping и продолжение чтения.
   Этот parser сохраняет такие сырые поля, не заявляя поддержки операций декодирования. VOID здесь
   сохраняется, хотя построенный Java descriptor его исключает. Serialization operations здесь нет.
3. Построение локального поля зависит от фабрик схемы. Wire BYTE/SHORT позволяют построить skip mappings
   в пустой локальной схеме P08, тогда как историческое S15 фиксирует ошибку построения локальных полей.
   Принятый [ADR-0001](../../docs/decisions/ADR-0001-normalized-model-boundaries.md) разделяет эти границы.

P08 также измеряет дубликаты, пустой payload, ноль полей, успешные descriptions перед последующим
повреждённым/усечённым description, суррогатные имена, проекцию ширины чисел и старые payload
P01/P03/P04/P05. C++ возвращает все структурно завершённые descriptions, включая неподдержанные типы;
это проекция сырого слоя, а не равенство итоговой таблице или callbacks Java. Сортировки и дедупликации нет.

## Владение, результаты и позиции

`parseDescribeRecords(payload, limits)` заимствует span лишь на время вызова. Результат владеет
упорядоченными vectors записей/полей и UTF-16 strings; senderId не является local ID, индекс поля
не является wire ID. Выделения памяти по senderId нет. При любой ошибке частичный текущий description
не выходит наружу. Предыдущие завершённые descriptions остаются в результате после уничтожения входа/frame.

Status: OK, TRUNCATED_PAYLOAD, INVALID_RECORD, INVALID_FIELD, INVALID_STRING, RESOURCE_LIMIT или
ALLOCATION_FAILURE. `consumed` — точная зафиксированная позиция исследования относительно payload.
`stage` указывает primitive либо точку проверки корректности/бюджета. `errorOffset` — начало primitive
при его ошибке, либо текущая позиция при проверках корректности/ресурсов; на OK это payload.size(),
stage — END. `primitiveStatus` сохраняет причину codec (OK для ошибок вне primitive).
Совпадение текста Java exceptions и возобновляемый descriptor не обещаются.

Незавершённые primitives внутри полного payload означают TRUNCATED_PAYLOAD. String codec получает
лишь остаток payload, поэтому даже логическое превышение длины тела не пересекает frame.
Разбор некорректного payload не меняет FrameReader. Тесты явно продолжают следующий frame;
политика восстановления/закрытия соединения относится к другому слою.

## Политика бюджетов и выделения памяти C++

Все бюджеты вызывающей стороны обязательны и конечны, имеют тип size_t, без unlimited default/sentinel:
байты payload, число descriptions, поля на description, общее число полей, байты кодированного тела
каждого имени, UTF-16 units каждого имени и суммарные декодированные UTF-16 units (имена записей и полей,
включая дубликаты). Ноль допустим. Ограничиваются логические элементы, а не метаданные allocator или
точная ёмкость heap.

Приоритеты и позиции:

1. Превышение размера payload отклоняется на PAYLOAD, позиция ноль, до чтения/выделения памяти.
2. Перед ID каждого непустого description проверяется число descriptions на DESCRIPTION.
3. Заголовок записи читается/проверяется в порядке Java. Затем проверяются бюджет полей записи и
   остаток общего бюджета на RECORD_HEADER после fieldCount. Reserve по недоверенному count нет.
4. Для имени используются лимиты UTFString, причём codeUnits дополнительно ограничивается остатком
   суммарного бюджета. Сохраняется приоритет byte-limit/encoding/unit-limit primitive. Превышение
   даёт RESOURCE_LIMIT, primitiveStatus RESOURCE_LIMIT и начало primitive; consumed включает
   измеренное исследование. Units успешных имён учитываются через проверенный остаток, даже внутри
   description, который позже завершится ошибкой. Parser останавливается на первой ошибке.
5. Каждая полная пара поля проверяется, затем добавляется. После всех полей добавляется завершённая
   запись. Счётчики растут только после проверки; переполнений и спекулятивного reserve по count нет.
   Предыдущие результаты не отбрасываются при последующей ресурсной ошибке.

bad_alloc и length_error перехватываются с ALLOCATION_FAILURE и завершённым префиксом. UTFString может
бросить исключение без позиции: его вызов считается транзакцией исследования, поэтому consumed/errorOffset
остаются в начале primitive. Ошибка добавления поля/записи в vector указывает позицию после полностью
исследованных байтов на FIELD_HEADER/DESCRIPTION соответственно. Перемещения контейнеров не бросают;
частично опубликованного description нет. Инъекции allocation failure и огромные выделения памяти
не заявляются как выполненные тесты.

[Покрытие](../../tests/conformance/protocol/descriptions/COVERAGE.md) и
[валидация](../../tests/conformance/protocol/descriptions/VALIDATION.md) фиксируют прямые проекции,

нет. Имена публичного API предварительные.
