# Ограниченная композиция исходящего live DATA

[English version](LIVE-DATA-WRITE.md).

`SubscriptionWriter::composeData` составляет один непустой двоичный кадр без сжатия
`TICKER_DATA` (10), `STREAM_DATA` (15) или `HISTORY_DATA` (20).
`LiveSession::publishData` проверяет соответствующую возможность приёма у пира
и текущее состояние аутентификации сеанса. Вызывающий код ставит
соответствующие описания типа 2 перед DATA в очереди соединения. Идентификаторы
отправителя и порядок полей берутся из неизменяемых исходящих описаний этого
сеанса. Исходящие описания пира используются при приёме.

Каждая запись содержит точный nonnull-символ и все типизированные значения
в локальном логическом порядке. Для удаления передаются пустой список значений
и точное знаковое 64-битное время удаления. Поля записываются в порядке
исходящего описания, с сохранением полных типов, скалярных значений и различия
между null и пустым содержимым. Писатель отклоняет удаление, если имя первого
исходящего поля с типом, отличным от VOID, начинается с `Event`. Java читает
такой префикс перед временем удаления даже при отключённой опции времени
события. Для записей без индексированного времени время удаления равно нулю.

Состояние Penta-символов, запасного представления CESU-8 и повторов создаётся
заново для каждого кадра. Шесть известных битов флагов (маска `0x5f`)
требуют опции history snapshot (`hs`) для всех трёх семейств.
Java отбрасывает неподдерживаемые биты при композиции. Нативный писатель
отклоняет такой ввод, чтобы вызывающий код не мог случайно заменить удаление
записью значения. Начальное значение MRU флагов равно 1. Ноль его не меняет.
Ненулевое значение кодируется как F8 при совпадении с MRU или как F9 и
compact int при смене MRU. Префикс идёт перед символом или маркером повтора.

Входные данные заимствуются на время вызова. Готовый кадр использует
существующий учёт владения памятью и частичной записи. При ошибке буфер
кандидата освобождается, затраченный бюджет вызова учитывается, а сеанс
остаётся пригодным к работе. Композиция не выполняет сетевой ввод-вывод.

Побайтовая проверка использует
[Java-кадры с флагами](../../tests/conformance/protocol/field-types/FLAGS-VALIDATION.md),
полученные через штатные `BinaryQTPComposer` и `BinaryQTPParser` в `FlagsOracle`.
Нативный тест сравнивает кадры типа 2 и DATA для трёх семейств со всеми
64 сочетаниями известных флагов при `hs`, а также результат обработки тех
же входов в Java без этой опции.
