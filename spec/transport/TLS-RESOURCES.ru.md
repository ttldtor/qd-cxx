# Ресурсный контракт контролируемого TLS

[English version](TLS-RESOURCES.md). Английская версия является нормативной.

Чистая реализация ресурсного расчёта вычисляет конечные требования к запрошенной памяти и работе,
не входя в OpenSSL. Native-проверки с привязкой к исходникам записаны в
[валидации TLS](../../tests/conformance/transport/TLS-VALIDATION.ru.md). Сам TLS runtime, учёт всего
запуска, исполнение проверок безопасности/учётных данных и установленные потребители требуют
отдельной квалификации. Ресурсные тесты не подтверждают доступность рабочего TLS или выпуск версии.

## Выбор поддерживаемого профиля приложения

Первый профиль требует, чтобы вызывающая сторона выбрала контролируемую среду с одним
квалифицированным экземпляром OpenSSL. В его идентичность входят статические исходники и
конфигурация OpenSSL 3.5.9, `no-autoload-config`, `no-ec2m`, `no-ml-kem`, встроенный провайдер default,
область запросов, выбранный RNG и профиль платформы/компилятора. Иной совместимый по API SDK
не становится квалифицированным автоматически. Первичный источник —
[закреплённые исходники](https://github.com/openssl/openssl/tree/45e844fa2a14ec92d146bd8f5778ac130b6625fb);
SHA-256 архива выпуска —
`603f5602e2eef00d77fbd429d34dcd5822bb301757a1bc9cdb24c670f1eb859a`.

Встраивающее приложение обязано ограничить всех относящихся к этой области пользователей того же
экземпляра: другие контексты/потоки, текущие входы, незавершённые префиксы ошибочной инициализации
и сохранённую историю. Профиль требует фиксированного поведения встроенных методов/провайдера/
запросов/RNG, стандартного аллокатора, неинициализированной secure heap, контролируемых глобальных
реестров и одинаковой эффективной идентичности окружающего контекста в зависимых операциях.
Адаптер не должен менять исходники SDK, подменять провайдер/RNG или изменять настройки аллокатора,
провайдера и RNG всего процесса. Создание отдельного контекста остаётся внутри выбранного профиля.

Для Linux дополнительно требуются ядро версии 4.8 или новее и закреплённый неизменённый путь вызова
системного источника энтропии при его нормальной доступности. Конечная граница
`GETRANDOM_ATTEMPT_BOUND` опирается на эти условия; для старого ядра или другого источника она
не переносится автоматически. Ограничение числа запросов не ограничивает длительность системного
вызова или ожидания энтропии.
Другие явно заданные контексты разрешены; общие эффекты и зависимые операции создания/использования/
освобождения обязаны сохранять заявленные условия квалификации и эффективную идентичность контекста.

Отдельный `OSSL_LIB_CTX` не изолирует от всех глобальных реестров процесса, ресурсов потоков,
окружающих значений по умолчанию и других контекстов. Заявленные пределы профиля, участвующих потоков/
контекстов, истории/общего состояния и ERR должны включать наши зарезервированные приращения
и остальных относящихся к области пользователей. Нельзя предполагать, что они обнаруживаются
автоматически или выводятся из одного runtime. Их достоверность до окончательного освобождения —
явная обязанность встраивающего приложения. Очистка контекстов/потоков имеет собственные правила
времени жизни OpenSSL: [официальная справка](https://docs.openssl.org/3.5/man3/OSSL_LIB_CTX/).

## Получение и сравнение требований

[`tlsRequirements`](../../include/qd/transport/tls_resources.hpp) вычисляет требования для неизменяемых
входных пределов и полного описания условий приложения. До создания объектов SDK сравните
возвращённые области запрошенной памяти и каждую координату работы с бюджетами вызывающей стороны.
Совпадение внешнего счётчика не разрешает больший граф или граф с иными условиями квалификации.
Переполнение требований, неподдерживаемый профиль или недостаточная вместимость должны приводить
к отказу до соответствующего действия.

| Вход | Ограничение первого профиля и смысл |
| --- | --- |
| `T` | Предел неизменяемых байтов доверия `trustBytes` в 1..524 288; допущенные байты укладываются в него |
| `A` | Предел якорей доверия `anchors` в 1..256; все обычные блоки CERTIFICATE считаются до декодирования |
| `C` | `certificateBytes`: предел тела Certificate другой стороны ровно 65 536 до разбора |
| `Cr` | `certificateRequestBytes`: предел тела CertificateRequest ровно 65 536 |
| `I` | Предел `identityBytes` в 1..255 для непустой ASCII/A-label или числовой ожидаемой идентичности |

Это ограничения обоснования/профиля, а не рекомендуемые значения приложения по умолчанию.
Описание условий приложения из двадцати полей также ограничивает:

| Поля | Обязательная область |
| --- | --- |
| `J` / `namemapGroups` | Максимум попыток окружающей регистрации/осиротевших записей, включая неуспешные проходы |
| `Qh` / `queryCount`, `Lqh` / `queryBytes` | Число исторически различных запросов и максимальный размер запроса |
| `An` / `propertyNames`, `Av` / `propertyValues`, `Batoms` / `propertyStringBytes`, `Latom` / `propertyStringMaxBytes` | Числа атомов окружающих свойств, суммарные байты хранения и максимальный размер |
| `p` / `participatingThreads`, `hg` / `globalThreadHandlers`, `ho` / `ownerThreadHandlers` | Максимум участвующих потоков и узлы обработчиков всего процесса/текущего владельца |
| `t` / `ambientThreadPairs`, `k` / `ambientGenerators` | Зависимые пары окружающий контекст/поток и владельцы их генераторов |
| `Qe` / `concurrentEntries`, `Ethreads` / `errorThreads`, `ErrCapacitySum` / `errorCapacityBytes`, `ErrCapacityMax` / `errorSlotCapacityBytes`, `Dh` / `errorDebugBytes` | Одновременные входы, зависимые ERR-потоки, вместимости и память отладочных данных |
| `Fpriv` / `failedPrivatePrefixes`, `Famb` / `failedAmbientPrefixes`, `Herr` / `errorTableEntries` | Ещё зарезервированные неудалённые префиксы и история общей таблицы ошибок |

Ноль означает ноль, а не отсутствие ограничений. Синтетический расчётный пример с двадцатью полями —
арифметические тестовые данные, а не наблюдаемое состояние среды или предложенная конфигурация.
Чтение отдельных фактов SDK не доказывает внешние заявления об истории/конкурентности и другой
профиль платформы.

## Запрошенная динамическая память

Метрика запрошенной памяти SDK включает каждый достижимый heap-объект, вместимость его памяти,
массивы внутри heap-объектов, перекрытие старого/кандидатного состояния, временные данные, удаляемого
владельца и явно выбранную переменную область `alloca`/ASM. Исключены обычные фиксированные
native-кадры стека, физический учёт/удержание аллокатора, RSS, инструкции и жёсткий предел времени.
Неизвестный полный размер фиксированных кадров компилятора/платформы не равен нулю. Адаптер,
сессия/компоновщик, память приложения-поставщика учётных данных и общий native runtime требуют
собственного явного учёта; коэффициент SDK их не скрывает.

Локальный резерв, обоснованный исходниками, намеренно консервативен между несколькими фазами.
Для максимального входного примера он равен 601 607 223 байтам до явных общих/ERR/host-слагаемых.
Это не выделенная арена, измеренный RSS или рекомендация памяти по умолчанию. Настоящие `sizeof`
адаптера, вместимости, native-диспетчеризация и сравнения всего запуска ещё требуют квалификации
runtime. Накладные расходы санитайзера вне метрики рабочего SDK; запуск ASan не доказывает прямой
вызов glibc `qsort`.

Полное требование памяти включает локальное хранение, затронутое окружающее состояние,
конкурентные кандидаты, метаданные потоков/реестров, глобальную инициализацию/таблицы ошибок,
память ERR и постоянную историю ошибок. Нельзя дублировать общий контейнер на каждый runtime
или исключать его из-за отдельного контекста. Возможная неудалённая частичная инициализация
сохраняет 40 865 186 байт на заявленный префикс плюс отдельную общую историю до подтверждённого
освобождения. Возврат ошибки и оплаченная раскрутка не разрешают слепое возмещение, глобальную
очистку или скрытую квоту попыток.

## Именованный вектор работы

Работа — вектор следующих 25 координат с привязкой к условиям профиля. Они ограничивают
алгоритмические запросы, прямые обращения к байтам/метаданным, RNG и квалифицированной платформе,
а не инструкции CPU или миллисекунды. Полный последовательный счётчик `malloc`/free не выбран
в качестве метрики: он не доказан и не назначен равным нулю.

| Единица | Ограниченный смысл |
| --- | --- |
| `PREPARE` | Выбранная общая/отдельная инициализация, проверки профиля, настройка каталога/ERR и частичная очистка |
| `TRUST_READ` | Одна ограниченная проверка/чтение обычного CERTIFICATE; последний дополнительный слот проверяет только EOF/обрамление |
| `CERTIFICATE_TREE` | Одно ограниченное полное/частичное дерево сертификата, обработка Names и ASN.1 |
| `DECODER_CACHE` | Одна начальная подготовка кеша декодирования открытого ключа, замкнутая по исходникам |
| `FAMILY_ATTEMPT` | Одна выбранная ограниченная попытка декодирования семейства открытого SPKI с очисткой ошибочного префикса |
| `KEY_GUARD` | Проверки кешированного ключа, типа, полноты, исходного SPKI и параметров подписи |
| `ANCHOR_STORE` | Одна вставка проверенного якоря и ограниченная работа сравнения/отпечатка |
| `CHAIN_VERIFY` | Одна проверка в том же контексте после всех необходимых проверок сертификатов |
| `INITIAL_FLIGHT` | Выбранный конечный начальный граф автомата TLS 1.2/1.3 |
| `ENGINE_ENTRY` | Один ограниченный вход в memory BIO и классификация результата |
| `RECORD_CONTROL` | Одна ограниченная возможность обработки записи или завершённого управляющего сообщения |
| `CLOSE_CONTROL` | Один переход упорядоченного close_notify |
| `ABORT_CONTROL` | Один идемпотентный переход прекращения допуска/отмены |
| `RETIRE_GRAPH` | Одно квалифицированное освобождение штатного/ошибочного графа с транзитивной очисткой |
| `DIRECT_INPUT_BYTES` | Прямые обращения к байтам предварительного фильтра доверия/подачи данных |
| `DIRECT_TEXT_BYTES` | Прямые байты проверки ожидаемой идентичности |
| `DIRECT_METADATA_VISITS` | Прямые проверки числовых полей, живого владельца и попытки |
| `RNG_EVENT` | Одна ограниченная возможность RNG или начальный префикс подготовки генератора |
| `RNG_GENERATE` | Одна выбранная ограниченная генерация CTR-DRBG |
| `RNG_INSTANTIATE` | Одно выбранное ограниченное создание CTR-DRBG |
| `RNG_RESEED` | Одно выбранное ограниченное обновление начального состояния CTR-DRBG |
| `RNG_POOL` | Одно ограниченное получение пула энтропии SDK |
| `RNG_AES_BLOCKS` | Квалифицированные запросы AES-блоков фиксированной формы |
| `NATIVE_ENTROPY_POOL` | Одно выбранное ограниченное получение пула native-бэкенда |
| `GETRANDOM_ATTEMPT_BOUND` | Квалифицированный предел запросов продвижения/ошибки Linux, а не всех системных вызовов |

ASN.1, Name, сортировка, поглощённые ошибки и работа с метаданными транзитивно включены в своих
местах вызова через конечные классы обоснования. Произвольный непрозрачный кредит за вызов SSL
их не заменяет. Штатная работа native-аллокатора/синхронизации внутри класса не превращает вектор
в полный счётчик системных вызовов. Условия платформы/компилятора/API-set/слотов/отображения по
умолчанию и штатной сортировки/компаратора остаются условными. `GETRANDOM_ATTEMPT_BOUND` может
консервативно сохраняться в Windows-векторе; это не утверждение о системных вызовах Windows.
Выбранные повторяющиеся AEAD/NST/KeyUpdate не имеют нового графа декодера ключей/RNG в этом
профиле. Эта недостижимость обоснована исходниками, а не длительностью соединения.

## Допуск фаз и освобождение

Обозначим `F` работу фабрики, `H` единственный граф начального handshake, `E` каждый вход в SDK,
`R` собственное освобождение. Это математические обозначения требований, а не закреплённые
имена публичного API.

| Граница | Необходимый допуск |
| --- | --- |
| Фабрика | Атомарно оплатить `F+R` до любого выделения SDK |
| Первый неделимый вход handshake | Оплатить `H+E`; сохранить разрешение `H` единственной попытки через WANT |
| Последующий вход в SDK, включая повтор WANT | Оплатить новый `E` текущего прохода; `H` не разрешает новую попытку |
| Вход упорядоченного закрытия TLS | Оплатить `E+closeControl` для каждой попытки |
| Прекращение допуска/отложенное освобождение | Сохранить скопированный собственный `R`; без ссылки на бюджет вызывающей стороны или вложенного нового прохода |

Предварительное списание проверяет идентичность профиля, арифметику и каждую координату до любого
вычитания и изменения фазы/владения. Нулевой/недостаточный на единицу бюджет даёт типизированный отказ
до неделимого действия. Переполнение, насыщение, скрытое пополнение и возмещение при WANT/ошибке
внутри прохода запрещены. Новый явный проход может получить новую работу после возврата предыдущего
вызова; этот предел отдельного входа не является квотой данных за всё время жизни.

`R` копируется в стабильное внутреннее владение до выделения SDK. Он переживает ошибочные префиксы
фабрики, прекращение допуска публичного владельца, активные операции и отложенное освобождение
без удержания указателя на бюджет вызывающей стороны. Очистка графа расходует его один раз после
завершения последнего необходимого активного/native-владельца. Постоянная общая память ошибок
остаётся зарезервированной независимо от оплаченной работы освобождения.
## Техническое приложение: числовая привязка

Обозначения lowerCamelCase ниже соответствуют координатам в верхнем регистре из таблицы `TlsWorkUnit`.
Для выбранной формы исходников `d=912+912²=832656`, `Np=floor(C/37)+1`. Обозначим через `RV(G)` вектор
`rngEvent=G`, `rngGenerate/rngInstantiate/rngReseed=3G`, `rngPool/nativeEntropyPool=6G`,
`rngAesBlocks=33213G`, `getrandomAttemptBound=221202G`. Координаты не суммируются в скаляр.

`F` включает `prepare=1`, `trustRead=A+1`, `certificateTree/decoderCache/keyGuard/anchorStore=A`,
`familyAttempt=A*d`, `directInputBytes=T`, `directTextBytes=I`, `directMetadataVisits=25`
и `RV(120*A*d+9)`. `H` включает `certificateTree/decoderCache=Np`, `familyAttempt=Np*d`,
`keyGuard=Np+1`, `chainVerify=1`, `initialFlight=1` и `RV(120*Np*d+2405)`.
`E` включает `engineEntry=1`, `directInputBytes=17408`, `directMetadataVisits=2` и
`recordControl=2+floor(245960/4)+floor(245960/5)=110684`. `R` включает `abortControl=1`, `retireGraph=1`.
Неуказанные координаты отсутствуют в этой фазе; это не утверждение, что исключённые метрики равны нулю.

Полная формула памяти сохраняет квалифицированное разложение на локальное/окружающее/конкурентное
состояние, потоки, глобальную память, ERR и ошибочные префиксы вместе с идентичностью исходников/
платформы. Из неё не следует безусловный предел heap-памяти одного экземпляра.
[Контракт runtime](TLS-RUNTIME.ru.md) определяет требования к доверию, callbacks и незавершённому I/O.

`SortIndirect` проверяется, хотя выбранные отдельные массивы имеют ширину не более 24 и используют
`SortDirect`. Сохраняются два одновременно живых запроса native-сортировки. Два фиксированных
17 KiB буфера SDK BIO и два сетевых окна адаптера включены в `WireRecords` один раз; композиция
с ресурсами общего транспорта не должна добавлять вторую копию тех же владельцев. Поля объекта
адаптера и сохранённые endpoint/снимок/сессия/открытые данные/DNS/память приложения-поставщика
учитываются отдельно.

Проверки области среды также требуют, чтобы `J`, `An`, `Av`, `p` и `ErrCapacityMax` помещались
в квалифицированный знаковый int SDK; `Qe>=1`, `1<=Ethreads<=p`, `Herr>=1773`, `Qh>=2`, `Lqh>=16`,
`An>=6`, `Av>=22` и `k<=2*t` с проверяемой арифметикой. `ho` — независимый предел обращений
к обработчикам потока владельца; `t` ограничивает окружающие пары контекст/поток. Они входят
в скопированные условия и квалификацию работы, хотя формула памяти использует `hg` для общего числа
узлов обработчиков и `k` для владельцев генераторов. Проверяемая сумма метаданных `J+An+Av+p+hg+ho`
также должна быть представима. Свободные независимые максимумы не получают дополнительных
недокументированных взаимных ограничений. Заявленная история включает необходимые приращения
этого допуска. Арифметическая проверка не доказывает достоверность внешних заявлений о среде.

Константы консервативно объединяют обе квалифицированные платформы: размер блокировки 56,
ERR_STATE 904 и вместимость отладочной строки ошибки 278. Они не квалифицируют скрыто иной ABI,
компилятор, CRT или SDK. Для максимального примера пяти пределов `Instance=601607223`; синтетический
пример среды из ресурсных тестов добавляет `Shared=44048771`, откуда `Total=645655994`. Это проверка
уравнений, а не выделенные арены или измеренные пики. Исключение фиксированных автоматических
кадров и условные предпосылки платформы/среды выше сохраняются.

## Ресурсный API и диагностика

Ресурсный заголовок объявляет `TlsResourceLimits` с пятью явными пределами выше,
`TlsHostLimits` со всеми двадцатью сопоставленными полями среды и 25 значений `TlsWorkUnit`
из таблицы работы. `COUNT` — служебное значение, а не координата; `TLS_WORK_UNIT_COUNT` описывает
массив. Нулевые входные пределы не настроены и недопустимы; они не задают рабочие значения
по умолчанию. Поля среды должны удовлетворять заявленным областям и включать необходимые
приращения; ноль не ослабляет минимумы.

`tlsRequirements` объявлен с возвратом владеющего `TlsRequirements`: `shape`, `sdk`, `factory`,
`initialHandshake`, `initialStart`, `entry`, `close`, `retirement`, `factoryAdmission`.
`TlsSdkRequirements` разделяет `instanceBytes`, `sharedBytes`, `totalBytes`,
`failedPrivatePrefixBytes`, `failedAmbientPrefixBytes`. Общая память относится к заявленной области
среды, а не изолированной копии каждого runtime. Входные пределы могут консервативно превышать
реальные неизменяемые байты доверия/идентичности; фактический отказ по обрамлению/числу якорей
всё равно предшествует декодированию.

`TlsWorkShape` копирует `profileRevision`, `limits`, `host`; `TLS_RESOURCE_PROFILE_REVISION`
определяет редакцию модели. `TlsWork` содержит `shape` и `remaining`; `TlsWorkVector` содержит `units`.
`admitTlsWork` объявлен для атомарного допуска по идентичности/координатам; `addTlsWork` — для
проверяемого сложения координат. Само сложение не доказывает согласованную квалификацию произвольных
векторов. Runtime обязан предоставить настоящие ожидаемые условия/потребность и не принимать
утверждение вызывающей стороны за доказательство проверки.

`TlsResourceError` объявляет `NONE`, `INVALID_CONFIGURATION`, `ARITHMETIC_OVERFLOW`, `SHAPE_MISMATCH`,
`WORK_LIMIT`; `TlsResourceDiagnostic` содержит статические `error`/`stage` без текста вызывающей
и другой стороны. Для чистой реализации и проверок переполнения/нехватки единицы/соответствия
условий есть результаты скомпилированных native-тестов. Эти тесты не исполняют TLS, провайдеры
и callbacks; они не доказывают независимость пакета без TLS или завершённость интеграции runtime.
См. отдельный статус квалификации.

## Точные объявления ресурсного API

Это объявления в пространстве имён `org::ttldtor::qdcxx::transport` из настоящего заголовка,
использующего только стандартные и проектные зависимости. Это не полные программы и не
синтетическая конфигурация среды. Реализация/тесты ресурса компилируют эти функции без исполнения

## Граница проверки реализации

Арифметика и допуск проверены отдельно: 8 тестов и 835 проверок на каждой ОС, независимый oracle — 32 случая. Ограниченный runtime-набор проверяет фактические TLS 1.2/1.3 и границы владения; [матрица доказательств](../../tests/conformance/transport/TLS-VALIDATION.ru.md) отделяет эти результаты от обоснования SDK по исходникам. Нативные тесты не измеряют весь heap SDK, RSS или жёсткое время; условия приложения и исключение фиксированных кадров сохраняются.
