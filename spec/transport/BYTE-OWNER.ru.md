# Приватная ограниченная байтовая операция

[English](BYTE-OWNER.md). Английская версия является нормативной.

Приватные `RawByteOwner` и `TlsByteOwner` предоставляют управляемые вызывающим кодом окна байтов
приложения поверх существующего [нативного TCP-владельца](TCP-RUNTIME.ru.md). У них нет установленного
заголовка или публичного API загрузки. Они не разбирают HTTP/IPF, не выбирают учётные данные, не
следуют перенаправлениям, не создают потоки и не вызывают пользовательский код. Нативный EOF,
проверенное закрытие TLS, завершение сообщения HTTP и завершение IPF остаются разными событиями.

## Владение и последовательное выполнение

Один стабильный `RuntimeCore` владеет сокетом, DNS-каналом, нативным контекстом, аренами и состоянием
завершений. Приватный слот сеанса выбирает прежний QTP `LiveSession` либо заимствование raw state.
Булева проверка слота распознаёт только QTP. Raw alternative не создаёт схему, composer или сеанс
QTP. Проверки размера и выравнивания при компиляции сохраняют существующее хранилище слота на
квалифицированных платформах; новые отдельные байтовые окна имеют собственный полный резерв.

`RawByteOwner` удерживает внешний `BootstrapLease` перед байтовым состоянием и нативным ребёнком.
Ребёнок получает прежнее независимое заимствование. Оба учитываются в одном bootstrap приложения,
включая простой после конфигурации; новой глобальной инициализации c-ares/WSA нет. Приложение
сохраняет bootstrap до завершения всех операций и освобождает его на исходном потоке очистки.

Все изменяющие вызовы, наблюдение и разрушение выполняются последовательно на создающем потоке.
Проверяемые вызовы отклоняют чужой поток до доступа к нативному/SDK-состоянию. Обычные вызовы
отклоняют повторный вход, но закрытие остаётся только запросом. Разрушение владельца во время его
активного метода нарушает предусловие. Будущий фасад с callback обязан удерживать стабильный lease
операции через пользовательский код, вызывать его вне блокировок владельца, нативных обработчиков
и SDK entries, затем повторно проверять живость, идентичность попытки и cutoff. Текущий механизм
не устанавливает пользовательские callback или планировщик.

## Вход и неизменяемый выход

Raw input имеет отдельное конечное окно во владении операции. Poll копирует только допустимый
префикс нативного входа или проверенного plaintext движка, списывая одну операцию копирования и
точное число скопированных байтов. Новый блок не заменяет сохранённый, пока `consumeInput` явно
не освободит весь остаток. Частичное потребление сохраняет стабильность остальных байтов. Слишком
большой счётчик отклоняется без изменения состояния. При обратном давлении выполнение уступает,
сохраняя нативный/engine suffix. Опубликованный вход доступен после EOF, ошибки или abort до явного
потребления либо разрушения байтового владельца. Неопубликованный нативный остаток при abort
учитывается как отброшенный вход, а не доставляется после cutoff. Предшествующий проверенный
префикс движка копируется перед обработкой более позднего нативного EOF.

Допуск выхода копирует весь блок в один конечный собственный слот до публикации. Занятый или
недостаточный слот отклоняет весь блок. Работа копирования явная; память вызывающего можно менять
или освобождать сразу после возврата. Опубликованные адрес, длина и байты неизменны через короткие
нативные записи и точные повторные TLS WANT. Принятие ciphertext сокетом и байтов приложения
движком учитываются независимо. Повторное использование выхода возможно только после принятия
всех байтов приложения. Локальное принятие не подтверждает получение другой стороной.

## Отмена, завершения и терминальные свидетельства

Нативные обработчики удерживают стабильное состояние core, только записывают завершения, не
перезапускают I/O и не вызывают пользовательский код. `requestClose` устанавливает только cutoff
допуска внешней операции: не закрывает сокет, не входит в SDK, не инвалидирует буфер и не дренирует
callback синхронно, в том числе при повторном входе. Следующий безопасный poll применяет прежний
путь закрытия core. Успешная запись, совпавшая с отменой, всё равно учитывает принятый префикс по
исходному backing до его освобождения. `CLOSED` требует нулевого числа ожидающих обработчиков и
нулевой глубины callback. Владельцы engine/WANT и выхода приложения переживают дренирование.
Резервное разрушение выполняет то же дренирование собственных операций на создающем потоке;
нативное планирование и резервная очистка не имеют жёсткой гарантии задержки.

Опубликованные терминальные данные неизменны. Последующие poll/abort возвращают прежнее CLOSED
без изменения abort, диагностики или сроков фаз. Терминальные нативные данные сохраняют EOF,
abort, основную/вторичную ошибки, принятую запись,
неопределённость нативного принятия, отброшенный нативный вход и ожидающий выход. Raw EOF означает
байтовую границу, в том числе пустую, без утверждения об успехе протокола. Вход приложения,
опубликованный до терминального наблюдения, остаётся отдельным явно потребляемым префиксом.

## Профиль TLS и резервы

`TlsByteOwner` владеет ограниченными trust/reference settings и сроками handshake/close до
освобождения движка. Он повторно использует прежние `TlsEngine`, `TlsPolicy`, конечные BIO-окна и
точный WANT tuple; в raw input допускается только plaintext с проверенными цепочкой и identity.
Здесь нет Basic provider или авторизации QTP. Даже нулевой credential pointer с общим control block
отклоняется до копирования settings: внешний provider graph или deleter не удерживается.
Повторный orderly-close после начала закрытия отклоняется без сброса исходного абсолютного срока
и сохранённого WANT. Часы фаз останавливаются при публикации terminal, в том числе при чистом peer
close и локальном orderly close. Ожидающий выход приложения/WANT запрещает orderly
close. Abort остаётся запросом; entries корректного закрытия расходуют прежний close vector.

Прежний [ресурсный профиль TLS](TLS-RESOURCES.ru.md) применяется без изменения: `tlsRequirements`
пересчитывается из максимумов того же SDK image, F+R допускается до SDK allocation, копия R живёт
до полного освобождения графа, H оплачивается один раз, E/close — для допущенных SDK entries,
а каждый entry истекает на любом выходе. Указатель на кредиты вызывающего не сохраняется, возврата
кредитов нет. Обвязка не сбрасывает и не обнаруживает общую историю query/property/ERR/thread/failure.
Все пользователи этого SDK image входят в одни host declarations, включая неудачные префиксы
подготовки. Общая память оплачивается один раз в этой host scope; показанный допуск попытки не
создаёт второго изолированного домена учёта. Внешняя истинность остаётся предусловием встраивания.

Нативный backing включает фактические размеры core/bootstrap, вход и полные арены context/handler,
а для имён — прежний DNS envelope. Raw backing дополнительно включает фактический размер своего
владельца и оба полных окна приложения, сохраняемые после close. Нативная подготовка сохраняет
прежние arena visits и три байтовых прохода по полному backing; raw preparation добавляет три
прохода по собственному backing. TLS отдельно считает обвязку, engine/policy и свои settings,
включая консервативный запас inline strings с проверкой фактических квалифицированных копий до
SDK allocation, и оба прежних SDK allowance. Нативный и общий TLS resident ceilings независимы.
Проверки охватывают exact/one-below допуски и работу без ослабления существующих пределов QTP.

См. [raw byte tests](../../tests/conformance/transport/raw_byte_tests.cpp),
[TLS byte tests](../../tests/conformance/transport/tls_byte_tests.cpp) и прежние
[TCP conformance tests](../../tests/conformance/transport/tcp_tests.cpp). Эти контракты не означают
поддержку HTTP, публичный transfer API или готовность полного переноса источников.

Приватные factories также принимают уже удерживаемую stable bootstrap lease. Независимые child
borrows используют прежние provenance/capacity counter и checkpoint factory admission.
Перемещение bootstrap facade приложения не меняет identity; moved-to owner сохраняется до
освобождения всех idle leases, child и final drain. Этот путь не удерживает адрес facade.
Plain prefix после native error использует отдельный cache-only RawByteOwner drain, без ordinary
poll. Completed Windows bytes/core input поступают в прежнее raw input window с прежними
native-step и copy-operation/byte credits. Нулевые credits дают yield до мутации; context poll,
новые socket operations, codec step и output acceptance/submission отсутствуют. Pending handlers
и output удерживаются до retirement, первый cause сохраняется.
