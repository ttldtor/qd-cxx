# Возможности и доступ к OnDemand

[English version](ON-DEMAND-ACCESS.md)

В версии Java QD, указанной в `upstream.lock`, `OnDemandService`
загружает реализацию из необязательного модуля `dxfeed-ondemand`.
Для проигрывания через endpoint с ролью `FEED` или `ON_DEMAND_FEED`
нужен коннектор `ondemand:`. Метод `isReplaySupported()` проверяет
наличие коннектора. Одна эта проверка не подтверждает доступность
сервиса или право на получение запрошенных данных.

Коннектор проигрывания использует отдельный сервисный протокол.
Обычный демонстрационный QTP-поток, API выгрузки исторических тиков и
проигрывание локального файла предоставляют разные способы доступа.
Для приёмочного теста сервиса нужны авторизованный адрес OnDemand,
разрешение на проигрывание и тип события, символ и исторический
интервал, покрытые этим разрешением.

Текущий C++ Feed синхронно отклоняет Java-адрес вида
`(ondemand:<address>)` с ошибкой `UNSUPPORTED_PROFILE` до попытки
подключения. Для локального
проигрывания доступен [API тейпов](../protocol/FEED-TAPE-SOURCE.ru.md).
Проигрывание через живой сервис OnDemand пока не подтверждено.

Точки в исходниках закреплённой версии Java QD:
`OnDemandService.getInstance`, `OnDemandServiceImpl.isReplaySupported`,
`OnDemandConnectorFactory` и `MarketDataReplay`.
