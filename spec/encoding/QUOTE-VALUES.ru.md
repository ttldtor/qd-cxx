# Точные значения профиля default Quote

[English version](QUOTE-VALUES.md). Английский документ является основным.

QDCXX-022. Контракт записан после первого production Java capture и до реализации C++.
Закреплённый oracle — [QuoteOracle](../../tools/upstream/quote-oracle/QuoteOracle.java);
[доказательства](../../tests/fixtures/protocol/quote/COVERAGE.ru.md) описывают конечный набор наблюдений.
Явно выбранный локальный профиль расширяется полными идентификаторами 2, 8, 56 и 120.
Другие идентификаторы с тем же примитивом сериализации не переинтерпретируются.

## UTF_CHAR и TIME_SECONDS

UTF_CHAR (2) читает одну кодовую точку Unicode без префикса длины. Reader принимает от одного
до четырёх байтов, избыточные кодировки и изолированные суррогаты. Результат — int32 в диапазоне
0..0x10FFFF, не обязательно одна единица UTF-16. Перед проверкой continuation читается весь
объявленный хвост; неполный хвост потребляет доступный префикс и даёт insufficient input.
Неверный первый байт потребляет один байт; неверный полный хвост или точка выше 0x10FFFF — всю
последовательность. Значение при ошибке равно нулю. Последующие байты не затрагиваются. Нет
выделения памяти или состояния продолжения. Канонический writer принимает тот же диапазон,
включая суррогаты, пишет не более четырёх байтов и атомарно отклоняет неверную точку или нехватку
выходной памяти. Проверка точки предшествует проверке ёмкости. UTFString и его правила пар
суррогатов остаются отдельными.

TIME_SECONDS (56) использует существующую проекцию compact integer: младшие 32 бита compact long
со знаком — raw секунды. Умножение на int64 1000 точно даёт миллисекунды, включая INT32_MIN и
INT32_MAX. Type 8 остаётся обычным int32 без интерпретации времени. Production FileReader хранит
дополнительные UTF_CHAR точки как int; QuoteMapping приводит их к char. Raw точка сохраняется,
а код биржи получает только младшие 16 бит.

## WIDE_DECIMAL

WIDE_DECIMAL (120) — точный знаковый compact-long шаблон. Все 64 бита сохраняются до преобразования.
Пусть s — старшие 56 бит со знаком, r — младшие восемь без знака. При r != 0 математическое значение
равно s * 10^(128-r). При r == 0 значение s == 0 означает NaN, положительное s — положительную,
отрицательное s — отрицательную бесконечность; неканонические кодировки сохраняют raw биты.
Конечное s == 0 отображается в положительный ноль при любом rank. Представления negative zero нет.

Предварительный WideDecimal владеет raw битами и предоставляет kind, significand, exponent,
десятичный текст и преобразование binary64. Конечное значение округляется из точного десятичного
к ближайшему binary64, при равенстве — к чётному, стандартным преобразованием без зависимости от
локали. Диапазон 56 бит/rank помещается в конечный диапазон экспонент binary64. NaN возвращается
как канонический quiet NaN; сравнение классифицирует NaN, не предполагая его равенства самому себе.
Другие результаты, включая знак нуля и бесконечности, сравниваются по точным битам double.
Сравнений только по epsilon нет. Десятичная арифметика, матрица преобразований и C++ composition
из double в wide не предоставляются.

Десятичное представление совпадает с наблюдаемым текстом Java WideDecimal: NaN, Infinity, -Infinity
или 0; иначе удаляются завершающие нули significand. Обычная дробная запись используется, когда
точка внутри цифр или требует не более шести ведущих нулей; целая — при добавлении не более шести
завершающих нулей. Иначе используется одна ведущая цифра, необязательная дробная часть и E
с десятичной экспонентой без дополнения нулями и без знака плюс. Временный и результирующий текст
ограничен 32 ASCII-байтами. Raw integer никогда не обозначается как сама цена или размер.

## Типизированное хранение и значения по умолчанию

FieldValue владеет полным тегом SerialFieldType и int64 raw: type 8/56 — int32 с расширением знака,
type 2 — кодовая точка, type 120 — неизменные биты. Результаты decoder соблюдают эти инварианты.
Java VOID tail и физическое хранение в двух слотах в C++ не вводятся.
Отсутствующее поле получает raw zero с локальным тегом: ноль для int/time/char и NaN для
WIDE_DECIMAL. Повторные совпадающие цели перезаписываются в порядке входа. Известные поля с другим
полным типом отклоняются; Java conversions исключены. Неизвестные поддержанные поля и записи
потребляются точным примитивом с теми же списаниями полей и ошибками.

LocalProfile::COMPACT_INT_V1 остаётся значением по умолчанию, сохраняя прежние принятие/ошибки и
результат int-vector. Явный LocalProfile::QUOTE_FIELDS_V1 допускает только 2/8/56/120. Неверный enum
профиля отклоняется. Context владеет одним типизированным набором defaults на локальную запись в
границах SchemaLimits; планы хранят входные типы без заимствования схемы. Расширенные результаты
используют только typedValues, прежние — только values. Оба считают одно логическое значение на
поле, включая отсутствующие. Применяются прежние бюджеты выходных значений, схемы и construction;
неограниченной второй копии нет. Прежние правила terminal/prefix/atomic publication и точных
позиций сохраняются.
