# Коллектор живых профилей инструментов

[English](COLLECTOR.md) — нормативная версия.

`InstrumentProfileCollector` — независимый потокобезопасный репозиторий в `qdcxx_ipf`.
Транспорт, Feed, runtime, TLS и transfer ему не нужны. Входные значения — существующая
[модель профиля](PROFILE.ru.md): все стандартные текстовые/числовые/календарные и непустые
пользовательские поля копируются без преобразования или проекции.

## Публикация и поколения

Символ — точная UTF-16 идентичность, включая пустой. Каждому текущему символу соответствует
одна неизменяемая ревизия без REMOVED и явное unsigned generation; ноль означает отсутствие
поколения. Изменённое значение получает возрастающую ревизию. Равное значение меняет только
generation, без новой ревизии, времени или уведомления. Сравнение сохраняет правила NaN
и знакового нуля модели значений.

Профили применяются в порядке span одной атомарной операцией admission. Вытесненные внутри
span ревизии исключаются из ещё не начатой доставки. TYPE `REMOVED` удаляет существующий
символ и публикует полное переданное значение удаления; неизвестный символ не меняет ничего.
`removeGenerations` игнорирует ноль и создаёт новые tombstone только с TYPE `REMOVED`
и SYMBOL, без прежних custom/description/numeric полей. Ошибка admission или выделения
памяти сохраняет модель, поколения, ревизию, время и очередь публикации.
`std::bad_alloc` выбрасывается; проверяемые ошибки возвращаются через `ProfileCollectorError`.

`lastUpdateTime()` возвращает миллисекунды system clock, изначально время создания.
Только изменённый вызов устанавливает максимум текущего времени и последнего прочитанного
времени плюс 1000 миллисекунд. Равное обновление и отсутствующее удаление время не меняют.
Исчерпание арифметических идентичностей явно возвращает ошибку, без сброса счётчиков.

## Владеющие наблюдения и доставка

`snapshot()` возвращает неизменяемый владеющий batch в точном UTF-16 порядке символов.
Каждая ревизия содержит полный независимый `InstrumentProfile`. Batch и отдельные
shared references ревизий сохраняются после замены, удаления, close и уничтожения коллектора.
Входной span и каждый профиль должны жить и оставаться неизменными весь вызов; mutex
коллектора не защищает одновременную мутацию пользовательского входа.

При регистрации непустая модель доставляется как начальный snapshot. Изменённые вызовы
готовят владеющие batches текущим слушателям. Перед началом callback вытесненные ревизии
фильтруются; пустой batch не вызывает уведомления. Уже начатый batch стабилен, даже если
callback меняет тот же символ. Начального пустого уведомления нет. Порядок batches следует
зафиксированным изменениям; порядок символов snapshot определён отдельно.

Один синхронный dispatcher последовательно вызывает callbacks вне mutex, в потоке,
начавшем внешний цикл доставки. Вложенное или конкурентное обновление присоединяется
к этому циклу и может вернуться раньше своего уведомления. Нет worker, пользовательского
polling, executor или API ожидания завершения. Callback может обновлять, регистрировать
и удалять слушателей, закрывать или уничтожать фасад. Каждый публичный вызов сначала
удерживает стабильный State и не обращается к фасаду после callback.

Удаление слушателя и close запрещают ещё не начатые по dispatch cutoff вызовы. Callback,
уже выбранный под mutex, может завершиться, включая close непосредственно перед фактическим
вызовом. Close — request-only, без ожидания. Callbacks и деструкторы captures не выполняются
под mutex. Исключения callbacks удерживаются, считаются насыщаемым `callbackFailures()`,
доставка продолжается. Обычное конкурентное уничтожение фасада требует внешней синхронизации
с обращающимися к нему потоками; удаление из собственного callback поддерживается.
За время жизни захваченных ссылок отвечает приложение.

## Конечные ресурсы

Все `ProfileCollectorLimits` — действительные конечные ограничения, включая ноль:

| Предел | Значение |
| --- | --- |
| modelProfiles | Текущие символы без удалений. |
| liveRevisions / retainedUnits | Все живые ревизии и UTF-16 длины их текста/имён, включая staging и внешние ссылки. |
| customFields | Непустые custom поля одного принятого профиля. |
| stagingProfiles | Длина входного span либо размер обхода модели при удалении поколений; также длина списка тегов. |
| listeners | Текущие регистрации; отложенные удалённые callbacks дополнительно ограничены циклом доставки. |
| liveBatches / batchReferences | Все живые batches и их суммарные ссылки на ревизии, включая внешние наблюдения. |
| workUnits | Admission работа индекса/обхода/сравнения/копирования и ссылок задач за вызов. |
| deliveryCalls | Сумма callback tasks внешнего цикла, включая вложенные/конкурентные добавления. |

Ledger не владеет State. Lease освобождается только после уничтожения backing профиля
или вектора; close не возвращает allowance внешних значений. Batch reference reservation сохраняет исходное число слотов до фильтрации вплоть до уничтожения batch; фильтрация не обновляет admission. Неудачный staging освобождает
свои резервы. Мутация временно держит до двух model maps, двух task vectors и ограниченные
staging vectors. Model nodes ограничены modelProfiles, staging vectors — stagingProfiles,
pending tasks — deliveryCalls, snapshot vectors — modelProfiles; один временный generated removal ограничен длиной уже принятого символа модели. Batch резервирует счётчики до выделения vector/control block и сбора модели. Прочитанные task slots остаются пустыми до конца конечного цикла. Close/деструктор не выделяют backing: под mutex очищаются только внутренние profile/ledger payloads, пользовательские captures освобождаются снаружи. Фиксированные стандартные
поля, custom map nodes, метаданные аллокатора и control blocks структурно ограничены этими
числами и длинами. Это **не** точный бюджет heap bytes или RSS. Пользовательские allocations
callback/capture, внутренности аллокатора, планирование ОС и произвольное время callback
не входят в ledger. Жёсткой гарантии wall-clock latency нет.

Work units консервативно списывают входные/текущие тексты и поля, копирование/индексацию
модели, сравнение тегов и копирование listener/task references до публикации. Удаление,
close, фильтрация доставки и наблюдения имеют конечные циклы по явным пределам модели,
слушателей, ссылок и задач. Reentrant публикация сверх deliveryCalls атомарно отклоняется.
Принятая работа завершается текущим dispatcher без обязательного пользовательского pump.

## Java и граница владения C++

Закреплённые Java collector/connection/update listener определяют замену символа, обновление
поколения равного значения, удаления, начальное уведомление, пропуск вытесненных элементов
и время после чтения. [Oracle](../../tests/fixtures/ipf/collector/README.ru.md) содержит
фактические наблюдения production classes ревизии `upstream.lock`.

Java по умолчанию хранит ссылки вызывающего и предоставляет protected defensive-copy hook. Base, удерживающий ссылки, публикует повтор того же неизменённого экземпляра; defensive-copy collector подавляет равный повтор внешнего значения. C++ API — неизменяемый defensive-copy/value профиль: адрес объекта не запускает публикацию, включая повтор snapshot.profile. Это адаптация владения, не универсальный паритет с reference-retaining base.
C++ всегда владеет неизменяемыми ревизиями. Слабый concurrent iterator Java может показать
удаление при обходе; C++ snapshot фиксирует одно состояние и сохраняет его. Планирование
Java executor и identity iterator не являются контрактами C++ API. Connection, reload,
completion wait и scheduler в этот компонент не входят.
