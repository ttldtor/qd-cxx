# Валидация публичного feed API

[English version](FEED-VALIDATION.md) · [Руководство приложения](../../../docs/FEED-API.ru.md)

Отчёт охватывает опциональный публичный API `qdcxx_feed`, регистрацию получателя на
существующем recovery owner и стандартный optional peer EndpointId, необходимый для
demo-источника. Полная совместимость QD и поддержка TLS/HISTORY в высокоуровневом API не заявляются.

## Нативные профили

В настроенном наборе включены CLIENT, RUNTIME, RECOVERY, FEED_API, CONNECT и TLS.
JSON OFF и ON проверяются отдельно. TLS остаётся низкоуровневым API; его включение
в матрице не добавляет TLS в публичный feed API. Зависимости используют закреплённые
профили проекта. Публичный API и сопровождаемый консольный пример используют C++23 без расширений.

| Платформа | Конфигурация | Полный результат CTest |
| --- | --- | --- |
| Windows x64, MSVC 19.42.34444.0 | Release, `/MD`, JSON OFF | 112/112 PASS |
| Windows x64, MSVC 19.42.34444.0 | Release, `/MD`, JSON ON | 113/113 PASS |
| Ubuntu 24.04 / WSL2 x86-64, GCC 13.3.0 | Debug, ASan/UBSan, JSON OFF | 112/112 PASS |
| Ubuntu 24.04 / WSL2 x86-64, GCC 13.3.0 | Debug, ASan/UBSan, JSON ON | 113/113 PASS |

Linux использует `ASAN_OPTIONS=detect_leaks=0:halt_on_error=1` и
`UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1`. Эти прогоны не подтверждают
LeakSanitizer и инструментирование внутреннего кода сторонних SDK.

По две проверки CTest прошли на каждой платформе; проверены освобождение captures, лимиты, отсоединённые handles и пять вызовов справки/неверных аргументов. Предупреждений компилятора нет. До исправления воспроизведена регрессия drain с секундой по умолчанию:
`drained=false`, `deadlineExpired=true`, `hadGap=false`. Теперь ограниченный turn
worker выполняет не более 64 recovery poll с одним recovery-work и одним submit-work
на turn, общими для его poll, как при обычном продвижении, так и при drain. Бюджет внутри turn не
пополняется. Тот же контролируемый сценарий default-drain после исправления проходит;
это не гарантия пропускной способности или жёсткого времени завершения.

## Наблюдение внешнего demo

2026-11-03 UTC [публичный консольный пример](../../../examples/feed_quote/main.cpp)
подключился к `demo.dxfeed.com:7300` через системный DNS по умолчанию,
подписался на AAPL Quote и вывел точные десятичные bid/ask цены и объёмы.

| Платформа | Интервал получения | Строк Quote | Фактический локальный результат | Exit |
| --- | --- | --- | --- | --- |
| Windows | 12 секунд | 8 | drain, без истечения deadline и сообщённого gap; диагностика подписки NONE | 0 |
| Linux ASan/UBSan | 12 секунд | 7 | drain, без истечения deadline и сообщённого gap; диагностика подписки NONE | 0 |

Наблюдения подтверждают фактическую совместимость этих запусков, но не будущую
доступность сервиса, актуальность биржевых данных или полноту непрочитанного сетевого входа.
Данные demo могут быть задержанными.

Локальное завершение и отсутствие ошибок за всю историю транспорта — разные результаты.
Windows сохранила `socket-read` / native 1236; Linux — `recovery-peer-end` / native 0.
Обе диагностики остались видимыми в endpoint и stderr консоли. Поэтому endpoint
может показывать FAILED, даже если отдельно проверенный локальный префикс прошёл drain.
Ни один код не переименован в ожидаемую отмену. Exit 0 примера требует хотя бы одной
фактической Quote, реального drain без expiry/gap и отсутствия ошибки подписки;
отсутствие ошибок за всю историю транспорта он не подтверждает. Предыдущие неудачные
live drain запуски сохранены как свидетельства отказа и не засчитаны как успех.

## Воспроизведение настроенных проверок

Используйте [явные предпосылки сборки](../../../docs/CPP-BUILD.ru.md#public-feed-api-build-ru).
При включённых соответствующих опциях:

```text
cmake --build build --target qdcxx_feed_api_tests qdcxx_feed_dns_tests qdcxx_feed_demo qdcxx_recovery_receiver_tests qdcxx_live_session_tests --parallel 2
ctest --test-dir build --output-on-failure -R "^(feed_.*|transport_recovery_receiver|protocol_live_session)$"
ctest --test-dir build --output-on-failure
```

[Руководство полного примера](../../../examples/feed_quote/README.ru.md) описывает
установленный потребитель и конечный внешний запуск. Блокирующий callback/вывод
приложения может задержать другие endpoint и завершение; конечные ёмкости и политика
drain не ограничивают RSS процесса или произвольное время выполнения кода приложения.
Выпуск и пользовательская приёмка учитываются отдельно от этих инженерных проверок.
