# Проверки контролируемого STREAM-клиента

[English version](CONNECT-VALIDATION.md). Английская версия нормативная.

[Контролируемый клиент](../../../docs/SUBSCRIPTIONS.ru.md) квалифицируется на собственных
тестовых TCP peers и существующих полных стандартных схемах. Публичный feed, credentials
и внешний сервис для этих проверок не нужны.

## Выполненные профили

- Windows x64 MSVC 19.42 Release: пройдены **47/47 корневых CTests**. Прямой тест
  STREAM-приложения содержит **10 сценариев / 177 проверок**.
- Linux x86-64 GCC 13.3 Debug: пройдены **47/47 корневых CTests** с ASan/UBSan для C
  и C++, включая квалифицированный C SDK. Основной LeakSanitizer выключен; опции
  остановки ASan/UBSan при ошибке заданы явно. Прямой STREAM-тест содержит
  **10 сценариев / 171 проверку**; платформенные проверки завершения различаются.
- Целевые группы `connect_stream`, `connect_cli_contract` и `connect_process`
  проходят на обеих платформах. Процессные тесты запускают настоящие дочерние
  процессы, проверяют ошибки вывода и автоматически завершают свои peers/процессы.

## Наблюдаемое поведение

- Настоящий TCP передаёт readiness, полные описания, исходящие подписки и данные.
  Фрагментированный ввод, точный выбор UTF-16, начальный add, удаление всего набора
  и последующие отозванные данные проверяются независимо от границ пакетов.
- Полные стандартные Quote и Profile достигают существующих prepared mappings.
  Общие строки сохраняют дополнительные поля, aliases, nullable text, непрозрачные
  байты и исходные provenance-метаданные. Prepared summaries явно содержат меньше полей.
- Owner turn с одной операцией принудительно откладывает работу принятого события.
  Следующий turn ставит его в очередь/освобождает до remove или нового source poll;
  выбранные записи доставляются. Abort из callback наблюдается до нового приёма.
- Цель в одну запись при принятом трёхзаписном префиксе проверяет семантику цели
  приёма: допустимый префикс завершается, а не молча обрезается.
- Чистый ранний EOF и EOF частичного кадра отличаются от намеренной отсечки.
  Ошибка приёмника callback не повторяется; обе области владельцев завершаются.
- Пустой feed, недостигнутая цель, прерывание и native close failure сохраняют
  отдельные application/local/transport факты и заданный приоритет кодов выхода.
- Проверяются равенство no-args/standalone help, русская UTF-8 справка, неверные
  аргументы и несовместимые профили до запуска работы. Реальные broken stdout/stderr
  дают ошибку. POSIX-процессные тесты также посылают настоящий SIGINT; native Windows
  console-control квалификация этим не заявляется.
- Отслеживаемый программный пример исполняется с контролируемым peer. Занятый
  опубликованный handle-slot отклоняется; время жизни управления и независимые
  terminal-наблюдения соответствуют описанному контракту.

Windows runtime может сохранить `READ_FAILURE/socket-read/1236` при собственном
закрытии. В соответствующих тестах ожидаемой ошибкой считается только этот точный
описанный abort-вариант с exit 1 и сохранением всех проверок причин/счётчиков.
Он не объявляется успешным happy path. Отдельные Quote/Profile data-target сценарии
проверяют и exit 0. Временные допуски loopback не являются benchmark задержки.

## Пакет, зависимости и документация

Production-only сборки и потребители перенесённых установленных пакетов проходят
на обеих платформах. Во включённом пакете **40 файлов**, каждый хеш сохранён после
переноса с нестандартными `lib64` и `public include`. Независимые consumers используют
установленные headers/targets для общего runtime/dispatch и prepared Quote/Profile;
самостоятельный callable-пример тоже собирается. Consumers не загружают SDK или doctest.

CLIENT/RUNTIME/CONNECT OFF остаётся умолчанием. Чистые installed consumers на обеих
платформах получают event mapping/Quote/Profile без runtime/client/SDK/doctest/Threads.
Включение CONNECT без явных предпосылок отклоняется конфигурацией. Фактические приватные
default/negative проверки выполняются с путями внутри отведённой области.

Закреплённые Uncrustify 0.83.0 затем clang-format 20.1.8, check/idempotence и реальные
scope-тесты форматтера покрывают новые example/tool roots и отказы для соседних/защищённых
путей. Doxygen 1.18 даёт ноль предупреждений; сгенерированные driver/options/result/sink
страницы проверены на параметры, владение, время жизни, отдельные исходы и границы
блокирования. Новые реальные Java control Capture/Verify принимают оба native captures;
прежние 344 байта входа и 4778 байт callback-вывода не изменились, source-bound provenance
обновлена для новой корневой CMake-конфигурации.

Локальное graceful-завершение, намеренный TCP abort, flush приёмника и peer ACK остаются
разными фактами. TLS, аутентификация, reconnect, wildcard, общий MUX и полные подписки
вне этого профиля. Результаты не заявляют hard preemption, границу process RSS,
exactly-once или полный roundtrip схемы/tape.
