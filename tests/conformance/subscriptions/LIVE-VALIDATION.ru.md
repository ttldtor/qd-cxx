# Проверка чистой live-сессии

[English version](LIVE-VALIDATION.md). Английская версия нормативная.

[Контракт сессии](../../../spec/subscriptions/LIVE-SESSION.ru.md) относится к
чистому компоненту QTP в памяти. Нативные тесты и опциональный
[Java-наблюдатель управляющих сообщений](../../../tools/upstream/live-session-oracle/README.ru.md)
выполняют разные проверки: первые проверяют владение и допуск кадров, второй
сравнивает настоящие callbacks закреплённого production-парсера с нативными
ожиданиями. Ресурсная проверка до парсера не заменяет это сравнение.

## Нативные сценарии

- Новые непрозрачные эпохи; передача владения при успехе и сохранение входных
  объектов при ошибке фабрики; совпадение происхождения схемы и компоновщика.
- Подтверждённые исходниками full/delta состояния протокола, точный nullable-текст,
  наследование свойств сообщений, токен `hs`, отдельные readiness/auth gates.
- Все маски heartbeat, предельные знаковые миллисекунды и marks, явный пустой
  payload в отличие от нулевой маски, пустой конверт без типа сообщения.
- Фрагментация на каждой границе, точный учёт принятого суффикса, отклонение
  ошибочного текущего кадра без публикации префикса записей и явный EOF.
- Неизменяемая замена описаний, неподдерживаемые полные типы и фактические
  wrappers, неизвестные описанные записи, старые поколения и представления
  после уничтожения сессии.
- Точный тип TICKER/STREAM/HISTORY, владение payload обобщённых полей, raw removal
  и виртуальные метаданные, запрошенные выходные layouts и raw HISTORY bounds.
- Полное резервирование удержанного выхода после частичного потребления,
  максимумы владельцев/ёмкости, отказы выделения и исчерпание работы до публикации.
- Учёт конфигурации при нулевом бюджете посещений; метрики копий и перемещений
  отражают ёмкость полученного владельца без нового обхода в фабрике.
- Последовательные кадры сверх размера одного кадра без файловой квоты
  на всё время жизни live-соединения.
- Полная схема Quote по умолчанию и исходные Java fixtures описаний/данных
  через обобщённую сессию в существующее подготовленное отображение Quote.

Внутренний `qdcxx_live_session_tests` получает корень исходников репозитория
и собственный каталог захвата через определения CMake при компиляции. Запуск:
`ctest --test-dir <build> -R "^protocol_live_session$" --output-on-failure`.
Он выполняет конечные тесты и создаёт
только синтетические управляющие сообщения и ожидаемую таблицу callbacks.
Ошибка теста даёт ненулевой код; сетевые соединения и постоянные процессы
не запускаются.

## Граница доказательств

Окончательные исходники проверены с MSVC 19.42 x64 Release и GCC 13.3 Debug
с AddressSanitizer и UndefinedBehaviorSanitizer. LeakSanitizer явно выключен.
Нативный профиль из 40 тестов прошёл на Linux. На Windows 39 тестов прошли
в sandbox; `tooling_format_contract` не смог создать source alias из-за
`Access denied`, затем отдельно прошёл с необходимым доступом к файловой системе.
Таким образом, каждый тест профиля имеет успешный результат на окончательных
исходниках; первоначальный отказ окружения сохранён отдельно.

Live-набор содержит 24 сценария и 37 314 утверждений. Независимая проверка MSVC
добавила три сценария выделения/владения с 707 утверждениями; общий независимый
запуск прошёл 27 сценариев и 38 021 утверждение. Управляющие сообщения Windows
и GCC прошли сравнение с production Java: 344 входных байта, 20 callbacks
и 97 канонических строк. Для обоих нативных входов Java запускалась на Windows
JDK 8; запуск Linux JVM этим не заявлен.

Прежний компоновщик подписок сохранил точный вывод из 317 байт, наблюдения
и чтение HISTORY time; обновлены только созданные процедурой source provenance
и manifest. Пять прежних случаев tape writer прошли production Java parser;
все 17 файлов корпуса совпали между Windows и GCC. Production-only consumers
собраны и запущены на обеих платформах с выключенными testing/JSON и без
получения внешних зависимостей. Справочник API собран без предупреждений.

Java-наблюдатель использует QD 3.355 на ревизии из
[upstream.lock](../../../upstream.lock), неизменённые подготовленные production
classes и проверенный receipt providers. Версия исходников и наблюдаемая строка
runtime учитываются отдельно. Наблюдатель допускает только тестовую авторизацию;
непустое authorization скрывается в таблице callbacks.

Генерация нативных управляющих сообщений, сравнение callbacks, хеши исходников
и providers, повторная проверка должны относиться к одним окончательным
исходникам. Сравнения прежних компоновщиков подписок и тейпов повторяются при
изменении хешируемых общих кодеков; прежние записи проверок сохраняются как
исторические доказательства.

Проверка не подтверждает транспорт, проверку TLS, прикладные callbacks,
коллекторы, переподключение, произвольные расширения описаний, сборку `PART`,
иные профили тейпов или все записи providers. Счётчики запрошенной памяти
не являются измерением RSS. Независимые копии вызывающей стороны и освобождение
из другого потока не входят в контракт владения эпохи.
