# Проверка получателя подписок

[English version](RECEIVER-VALIDATION.md). Нормативный текст — EN.

[Контракт получателя](../../../spec/subscriptions/RECEIVER.ru.md) проверяют
[тесты получателя](../subscription_receiver_tests.cpp),
[тесты borrowed-отображений](../borrowed_event_view_tests.cpp) и реальные TCP/TLS
сценарии времени жизни callback в [plain recovery](../recovery_lifecycle_tests.cpp)
и [TLS recovery](../recovery_tls_tests.cpp). Итоговая квалификация всего продукта
подписок остаётся отдельной работой.

## Нативные профили

Windows MSVC 19.42 x64 Release с динамическим release CRT прошёл 72 теста без JSON
и 73 со включённым JSON. Linux GCC 13.3 Debug с ASan/UBSan прошёл те же 72/73 теста;
проверка утечек отключена. Во всех четырёх профилях включены runtime, client,
recovery и TLS. Внешняя сеть не использовалась. Профили с отключёнными зависимостями
не входят в эти четыре запуска.

Десять сценариев получателя проверяют generic/custom-поля, Quote/Profile,
происхождение схемы, атомарный отказ фабрики, изменение подписок, удержанные generic
пакеты, владеющие результаты проекции, изоляцию исключений клиентов и явные пределы
работы. Минимальный Profile принимается при 20 visits и отвергается при 19.
Семь сценариев borrowed-view проверяют совпадение с owning-входами, неверные диапазоны
и совместимость существующих вызовов. Реальные TCP/TLS-сценарии останавливают,
уничтожают или заменяют публичного владельца recovery внутри callback до удержания
и проекции уже принятого пакета.

## Установленное консольное приложение

[Отдельное приложение](../../../examples/subscriptions/receiver/CMakeLists.txt)
собрано против перемещённых установленных пакетов на обеих платформах. На каждой
проверены числовой loopback-адрес и явный loopback DNS-сервер. Контролируемый
[источник](../subscription_receiver_example_peer.cpp) и его
[отдельная сборка](../subscription_receiver_consumer/CMakeLists.txt) объявляют полную
встроенную схему Quote из восьми полей. После фактического ACTIVE контроллер разрешает
передачу записей с canonical-символами OTHER и IBM. Подписанное на IBM приложение
печатает ровно одну строку IBM и достигает DRAINED без истечения срока. DNS-запуски
наблюдают два реальных запроса и разрешают CNAME-маршрут стенда; числовые — ни одного.

Без аргументов и с `--help` получается одинаковый английский stdout с пустым stderr;
`--help-ru` также успешен. Семь ошибочных наборов аргументов возвращают 2. Standard input
открыт без данных. Собственные процессы заканчивают работу в конечные сроки контроллера.

[Записи запусков](../../fixtures/subscriptions/receiver-example/README.ru.md) сохраняют
фактический вывод приложения, диагностику и счётчики источника. Decimal raw zero означает
NaN. Windows сохраняет socket-read 1236 после cutoff; Linux — peer-end. Успешное локальное
дренирование не стирает диагностику и не доказывает wire flush, чистое TLS-завершение,
подтверждение доставки или upstream-подписки. Источник читает один клиентский байт
и не разбирает и не подтверждает ADD-сообщение клиента.

Те же десять сценариев получателя также собраны и пройдены как отдельные потребители
установленного пакета на обеих платформах: по 3193 assertions с перемещёнными production
заголовками и библиотеками. Linux-запуск послал SIGTERM самому дочернему приложению после
ACTIVE и получил exit 130, ABORTED, отсутствие истечения срока и завершение источника.
Внешняя отправка Windows console-control не проверялась; нативные callback cutoff
сценарии и обычное дренирование Windows-примера являются отдельными проверками.

## Ограничения

Консольное приложение использует plain TCP и одну STREAM-подписку Quote. TLS и три
семейства очередей имеют отдельные нативные проверки; приложение не является
руководством по TLS/HISTORY. Эти проверки не устанавливают совместимость с публичным
поставщиком, полное покрытие бизнес-событий, предел RSS или аппаратно-независимую задержку.
DNS-резервации и логическая работа соответствуют
[квалифицированному DNS-профилю](../../../spec/transport/DNS-RESOURCES.ru.md).
