# Покрытие conformance кодирования C++

[English version](COVERAGE.md). Английский документ является основным.

## Текущее покрытие QDCXX-011

Существующий [doctest executable](../compact_tests.cpp) теперь выбирает все наблюдения
integers.tsv, forms.tsv и strings.tsv: **1146 наблюдений, ноль исключений**. Сохранены исходные
832 compact-наблюдения и регрессии ёмкости/sentinel. Разделы ниже этого обновления сохраняют
исторические числа QDCXX-010; прежние исключения UTFString больше не действуют.
[Новый журнал случаев](utf-cases.log) перечисляет все file/kind/ID/method и итоги.

| Файл UTFString | Writers | Readers | Строгие префиксы | OK reads | EOF | Invalid encoding | Invalid length |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| strings.tsv | 13 | 200 | 187 | 13 | 187 | 0 | 0 |
| forms.tsv | 0 | 101 | 79 | 10 | 80 | 8 | 3 |
| Всего | 13 | 301 | 266 | 23 | 267 | 8 | 3 |

Все 13 S ID и 22 F ID, включая каждый захваченный строгий префикс, перечислены в
[Java coverage](../../fixtures/encoding/COVERAGE.ru.md); новый журнал содержит точные развёрнутые ID.
Каждое чтение сравнивает точные единицы UTF-16/null, статус, consumed и remaining с неизменным TSV.
Ожидания не получаются C++ round trip. Ошибочные префиксы используют фактические категории Java.
Каждый UTF writer проверяет ёмкости от нуля до размера эталона + 2 с защитными байтами,
неизменным избытком и неизменным буфером при ошибке. К неполному UTF-входу sentinel не добавляется.

Четвёртый doctest case покрывает нулевые бюджеты, null/empty, отдельные суррогаты, бюджет пары,
инкрементальные лимиты, приоритет неверной длины перед политикой, неполноты/ошибки перед бюджетом
единиц, выход за тело и хвостовые байты, владение результатом, бюджеты SIZE_MAX, максимальную
Java-длину, максимум + 1 и максимум signed long без огромных выделений памяти. Ошибки политики
байтов/единиц writer атомарны. Максимальное объявленное тело без тела даёт EOF при достаточной
политике без резервирования объявленной длины. Фиктивные огромные spans исключены; безопасность
арифметики также проверена по исходнику. Четыре doctest cases выполняют **43 375 assertions**.
Парсер отвергает неверные units/hex/decimals, неизвестные methods/statuses/categories, дубликаты ID,
неполные файлы и пустое выбранное покрытие.

[Контракт UTFString](../../../spec/encoding/UTFSTRING.ru.md) отделяет эксплуатационную политику от
Java observations. Это не покрытие огромных выделений, отказов аллокатора, 32-bit, универсального
Unicode, других BufferedInput, framing, importer или transport.

QDCXX-010, 2026-09-21. Oracle: Java QD 3.355, commit
`0ddc0a09779fb61d74cc0b37c6449ff47dcb715f`. Использующий doctest
[тестовый executable](../compact_tests.cpp) напрямую читает неизменные
[integers.tsv](../../fixtures/encoding/expected/integers.tsv) и
[forms.tsv](../../fixtures/encoding/expected/forms.tsv). Отбор выполняется по столбцу метода,
а не префиксу ID. [cases.tsv](cases.tsv) фиксирует каждую включённую и исключённую строку как
файл/вид/ID случая/метод с точными итогами; это журнал выполнения C++, а не замена эталона.

| Файл | writeCompactInt | writeCompactLong | readCompactInt | readCompactLong | Исключено UTFString |
| --- | ---: | ---: | ---: | ---: | ---: |
| integers.tsv | 34 | 62 | 176 | 328 | 0 |
| forms.tsv | 0 | 0 | 116 | 116 | 101 |
| Итого | 34 | 62 | 292 | 444 | 101 |

Выбрано 832 наблюдения: 96 writer и 736 reader rows. Readers включают 592 strict-prefix EOF
случая (396 префиксов integer и 196 префиксов неканонических форм); 144 полных чтения успешны.
Исключены 101 наблюдение `readUTFString` в forms.tsv, включая все префиксы F-случаев. Отдельное
семейство strings.tsv (13 writers/200 readers) не входит в два входных файла теста; C++ реализация
и conformance UTFString не заявляются. Точные ID строк остаются в
[Java coverage](../../fixtures/encoding/COVERAGE.ru.md).

## Проверенные контракты

Выполнены все выбранные ID, включая границы переходов/экстремумы I/L со знаком, X cross-width,
XI as-long, N0–N15 с избыточным кодированием 0/−1, N16/N17 с ненулевыми старшими битами и их
зафиксированные строгие префиксы. Каждый writer сравнивает точные Java bytes. Каждый reader
сравнивает значение либо категорию insufficient-input, потреблённые и оставшиеся байты.
Строки Java EOF остаются доказательствами; C++ возвращает статус, а не Java exceptions.

Для каждой из 144 успешных reader rows добавление sentinel `25` сохраняет значение и потреблённую
позицию, оставляя sentinel следующим байтом. Для каждой из 96 writer rows ёмкости 0–10
(1056 вызовов) покрывают все недостаточные ёмкости, точную ёмкость и запас. Защитные байты до/после
выхода и неиспользованная память неизменны; неуспешные записи возвращают ноль и ничего не меняют.
Это дополнительные проверки ограниченной памяти; независимо вычисленные ожидаемые codec bytes
и замена oracle-сравнения одними round trips не используются.

Parser сохраняет пустые hex-поля, использует точные десятичные целые, отклоняет повреждённые
выбранные строки, неизвестные методы/статусы/категории, дубликаты идентификаторов строк,
отсутствующие маркеры завершения и пустое выбранное покрытие reader/writer. Стандартный `assert` не используется; fatal assertions doctest активны также в Release.
Ошибки содержат идентификатор случая и ожидаемые/фактические байты, значения, позиции.
CTest передаёт ненулевой результат также в Release.

## Границы

[Контракт примитивов](../../../spec/encoding/PRIMITIVES.ru.md) неизменен. Потребление при EOF
прямого reader не является транзакционным framing или возможностью продолжения. Не заявляются
UTFString, PentaCodec, decimal codec, schema/importer, networking, полный QTP, fuzzing, benchmark
и гарантия переносимости. [Валидация](VALIDATION.ru.md) отделяет выполненные Windows-проверки
от непроверенного покрытия.

## Дополнение doctest

Два `TEST_CASE` doctest группируют integers.tsv и forms.tsv. `REQUIRE_MESSAGE` проверяет parsing
и результаты codec/работы с памятью; `INFO` строки сохраняет файл, ID случая и метод в диагностике.
Все 28 358 assertions успешны на MSVC, ClangCL и WSL GCC в Debug/Release. Журнал выбранных/исключённых
случаев после миграции идентичен; fixtures не переписывались. doctest 2.4.12 — закреплённая хешем
тестовая зависимость FetchContent, без зависимости production-цели.
