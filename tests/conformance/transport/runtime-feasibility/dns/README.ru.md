# Проверка применимости DNS-профиля

[English version](README.md).

Необязательная внутренняя проверка исследует c-ares с выполнением на потоке владельца. Это технический пример, а не готовый транспортный адаптер и не неизменённая поставка upstream. `dependencies.lock.json` фиксирует исходный архив и квалифицирующий patch, `profile.json` — ограничения профиля.

По умолчанию сборка выключена: CMake не включает языки компилятора, не ищет SDK и не получает зависимости. Для запуска проверьте SHA-256 исходного архива, распакуйте его отдельно и примените `qdcxx1.patch` командой `patch --batch --forward --fuzz=0 -p1` из каталога исходников. Сохраните upstream-уведомления MIT; точный текст лицензии включён. Системная установка не требуется.

```sh
cmake -S . -B build -G Ninja -DORG_TTLDTOR_QDCXX_BUILD_DNS_FEASIBILITY=ON -DCARES_SOURCE_DIR=/absolute/path/to/patched-c-ares -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
ctest --test-dir build -V --output-on-failure
```

Для Linux GCC Debug укажите `-DCMAKE_BUILD_TYPE=Debug -DORG_TTLDTOR_QDCXX_DNS_SANITIZERS=ON`: инструментируются C SDK и C++-проверка. При запуске CTest задайте только дочернему процессу `ASAN_OPTIONS=detect_leaks=0:halt_on_error=1` и `UBSAN_OPTIONS=halt_on_error=1`; проверка утечек в этот профиль не входит. Windows требует окружения разработчика MSVC x64 и разрешения на собственные loopback UDP/TCP-сокеты. Внешние DNS-службы не используются; настройки DNS и firewall не изменяются.

Исполняемый файл — внутренний CTest runner. Запуск без аргументов выполняет восемь проверок отказа конфигурации, 22 проверки отмены/уничтожения ожидающих DNS-запросов и два сценария квот/возобновления UDP/TCP. В stdout выводятся состояния и измерения времени. Коды завершения: 0 — успех, 1 — ошибка проверки, 2 — ошибка bootstrap. CTest ограничивает весь процесс 20 секундами и при необходимости завершает именно свой тестовый процесс. Runner закрывает только собственные сокеты.

Квалифицированный SDK отвергает отсутствующий или чрезмерный список явно заданных IPv4 nameserver, не читает системную/environment DNS-конфигурацию и домен из hostname, запрещает reinit. Заголовок и runtime-проверка версии исключают другую разновидность SDK. c-ares нужно инициализировать до остальных потоков приложения, согласовав общий lifetime процесса и сохранив стандартные allocators. Один channel принадлежит одному независимому upstream-run; допускается один wire-запрос одновременно, A и AAAA выполняются последовательно. Event thread и монитор отсутствуют. В предполагаемом адаптере IP-литералы обходят DNS.

Socket bridge делит квоты пакетов, байтов и native read между всеми сокетами одного SDK progress-вызова. При исчерпании он возвращает would-block до чтения UDP-датаграммы; TCP-фрагменты продолжаются на следующем шаге. Проверяются действительно ожидающий запрос `hold.invalid.`, UDP-ответы с чужим ID и последующий NXDOMAIN, фрагментированный TCP NXDOMAIN. Чтение TCP по семь байт — стрессовый параметр проверки, не производственное значение по умолчанию. Пределы input buffer выведены из исходников; полный SDK heap, parser/result metadata и накладные расходы allocator требуют отдельного производственного бюджета. Успешный конечный тест не доказывает универсальную временную гарантию или полную совместимость NSS/split-DNS.
