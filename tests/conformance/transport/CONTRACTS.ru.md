# Профиль live-транспорта и контракт квалификации

[English version](CONTRACTS.md). Авторитетной является английская версия.

Этот контракт квалифицирует [ADR-0006](../../../docs/decisions/ADR-0006-live-runtime.ru.md). Пробы осуществимости проверяют механизмы SDK; это не production session, клиент подписок, TLS/auth адаптер, тест пропускной способности или квалификация развёртывания у провайдера.

## Границы доказательств

Различать факты по закреплённым исходникам, отдельно выполненные проверки механизмов и последующую интеграцию адаптера. Для каждого выполненного утверждения указывать ОС/компилятор/конфигурацию, итоговые хэши исходников/зависимостей, входы, результаты и конечный deadline тестового стенда. Более ранняя версия исходника или завершившаяся в гонке операция не является доказательством для другой ожидающей операции. Журналы/квитанции должны различать сбои инфраструктуры и поведения; повторный запуск вне ограниченной сетевой среды не переписывает первый результат.

## Интерпретация ресурсов

Хранилище SDK, принадлежащее библиотеке, входит в контракт ресурсов. Количество дескрипторов или лимиты полезной нагрузки приложения не заменяют незаметно хранилище parser, query/cache, TLS record/BIO/certificate/trust/context. Учитывать сохранённые capacities, выведенных из эксплуатации владельцев и одновременные пики кандидатов/перевыделения. Логические пределы payload/item/work отличаются от накладных расходов allocator, резервирования стека native thread, буферов ядра, наблюдаемого RSS и прошедшего времени; для каждого указывать точный охват.

Конечные счётчики callbacks/read прототипа подтверждают только проверенный механизм. Полный адаптер должен определить и проверить свой SDK envelope до заявления о соответствии. Неизвестный envelope остаётся неизвестным, а не нулевым. Планирование ОС и доступность требуемых native-криптосервисов — предусловия среды; по микросекундам loopback нельзя экстраполировать гарантию реального времени.

## Цели квалификации и отложенная интеграция

Начальные цели — Windows x64/MSVC Release и Linux x86-64/GCC с ASan+UBSan для изменённого native probe/кода адаптера. LeakSanitizer в зафиксированном профиле Linux явно отключён. Указывать, инструментированы ли сами SDK; инструментирование вызывающего кода не доказывает корректность доступа к памяти внутри каждого SDK. Материал сертификатов должен быть синтетическим, peers — локальными и принадлежащими тестовому стенду.

Результат проверки осуществимости не реализует production-адаптеры. Интеграция runtime/session, полный envelope ресурсов, обработка неверного SDK, экспортируемая статическая link closure, установка потребителя, auth, reconnect и изоляция multiplexer остаются обязательными последующими проверками. Эти пробы не квалифицируют неподдерживаемые ОС/архитектуры, MinGW/io_uring, произвольные системные SDK, неявные providers доверия/system DNS, пользовательские глобальные allocators, поздний bootstrap SDK и внешние развёртывания у провайдеров.
