# Наблюдение диапазона HISTORY, принятого recovery

[English version](HISTORY-STATUS-VALIDATION.md). Английская версия нормативная.

Здесь записана ограниченная проверка наблюдения, добавленного в QDCXX-117.
[Контракт recovery](../../../spec/transport/RECOVERY.ru.md) определяет API, а
[руководство получателя](../../../docs/SUBSCRIPTION-RECEIVER.ru.md) объясняет его применение.
Эта страница не подтверждает завершение всей вехи получения данных или выпуск.

## Выполненные целевые проверки

2026-11-02 на Windows MSVC 19.42 x64 Release с динамической CRT и Linux GCC 13.3
x64 Debug с ASan/UBSan прошли следующие три проверки CTest:

| Проверка CTest | Охват |
|---|---|
| `transport_recovery_history_status` | Семь сценариев Core с настоящими принятыми очередью и коллектором HISTORY |
| `transport_recovery_families` | Прежние сценарии восстановления семейств и публичное наблюдение через TCP |
| `transport_tls_recovery` | Прежние сценарии восстановления с проверенным TLS и публичное наблюдение через TLS |

В Linux поиск утечек был отключён. Число assertions зависит от ограниченных циклов native poll;
равенство числа assertions на разных платформах не является критерием готовности.

Сценарии Core сравнивают возвращённые наблюдения и списание работы с прямым запросом настоящей
очереди. Проверены полная доставка, неполный диапазон, незавершённая транзакция, усечение,
неопределённость источника, пауза клиента, недостаточная/точная работа и типизированные отказы
для неверных клиента/ключа. При двух принятых клиентах с разными границами верхний диапазон
завершается, нижний остаётся неполным, а фактическое общее состояние источника ещё RECEIVING.

Проверки допустимости охватывают удержанные события DATA и heartbeat, вывод соединения до
сброса очереди, cutoff, неверный поток, повторный вход из callback и изменения фактических
соединения/аутентификации/поколения, когда модель показывает ACTIVE. Отдельный настоящий
сценарий Core DEFERRED изменяет аутентификацию, когда модель ещё показывает ACTIVE.
Отказ не изменяет работу вызывающего кода и эксплуатационные свидетельства остановки/ошибки.

Настоящие локальные TCP и TLS peers ожидают фактическую подписку клиента HISTORY перед отправкой
snapshot. Публичные наблюдения проверяют завершённую доставку, отказ при повторном входе из callback,
перемещение/cutoff и сохранение отделённых данных после завершения владельца. Snapshot одного клиента
достигает общего COMPLETE; это не выдаётся за отдельный сценарий RECEIVING с двумя клиентами.

## Потребители установленного пакета

На обеих платформах текущий пакет установлен и перенесён в другой каталог перед конфигурацией
отдельного проекта потребителя. Исходный каталог отсутствовал. Оба публичных заголовка recovery
совпали с проверенными исходниками; команды компиляции и линковки использовали заголовки и архивы
перенесённого пакета. Внешний TLS peer был явно заданным неустанавливаемым helper, требуемым
при выполнении теста; он не линкуется с потребителем.

На каждой платформе прошли две проверки CTest: один выбранный публичный сценарий TCP HISTORY
и один TLS HISTORY. Doctest подтвердил выполнение ровно одного сценария в каждом executable,
исключая ложный успех при отсутствии совпадений. Сценарии выдали настоящие признаки завершения,
отказа при повторном входе и сохранения отделённых данных. Остальные сценарии этих executable
намеренно отфильтрованы. Linux ASan/UBSan не сообщил ошибок; поиск утечек оставался отключённым.

## Итоговая регрессия и справка

Итоговая матрица 2026-11-02 прошла на обоих указанных toolchain: **73/73 проверки CTest с JSON OFF**
и **74/74 с JSON ON** на каждой ОС. Все команды сборки и тестов вернули ноль. Одиннадцать файлов
кода/сборки, зафиксированных перед матрицей, сохранили точные байты до её завершения. В эти итоги
входят новый набор Core и прежние наборы транспорта, семейств, очереди, получателя и совместимости.

Десять изменённых C++-файлов прошли закреплённую проверку Uncrustify 0.83.0, затем clang-format 20.1.8.
Проверки собранной справки охватывают оба публичных метода `historyRangeStatus`, три параметра,
документацию результата, поток владельца и границу AS-OF, целостность исходников/ресурсов,
локальные ссылки и навигацию. Визуальная проверка в браузере не подтверждена.
Квалификация всей вехи получения данных остаётся отдельной работой.

## Границы выводов

Успешный запрос описывает принятый локальный префикс на момент вызова. Последующий отказ означает
неизвестное состояние; прежний полный результат нельзя представлять как текущий. Локальный drain,
сырые snapshot flags, TLS handshake и закрытие peer не доказывают `completeDeliveredRange`.

Эти проверки не доказывают подтверждение peer, охват непрочитанного входа, полноту истории поставщика,
будущее здоровье соединения, предел RSS процесса, жёсткую задержку, сертификацию безопасности или выпуск.
