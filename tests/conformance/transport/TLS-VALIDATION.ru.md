# Квалификация ресурсов и runtime TLS

[English version](TLS-VALIDATION.md). Английская версия является нормативной.

Дата: 2026-11-01 UTC. [Ресурсный контракт](../../../spec/transport/TLS-RESOURCES.ru.md) и
[runtime API](../../../spec/transport/TLS-RUNTIME.ru.md) имеют разные границы доказательств.
Реализованы чистая арифметика ресурсов и TLS runtime. Целевой набор текущих исходников прошёл
39 native-тестов: Windows MSVC 19.42.34444 x64 Release `/MD` — 11 486 проверок; Ubuntu 24.04
GCC 13.3 x64 Debug ASan+UBSan — 11 625 проверок. LSan выключен, SDK не инструментирован.
Полная регрессия на каждой ОС прошла 58/58 тестов с JSON и 57/57 без JSON. Проверка сгенерированной справки учитывается отдельно.
Обновлённый установленный пакет прошёл четыре TLS 1.2/1.3 запуска на двух ОС.
Это не сертификация безопасности, не приёмка полного клиента подписок и не выпуск версии.

## Выполненные ресурсные проверки

Эти отдельные проверки компилируют настоящие заголовок, реализацию и тесты ресурса. Они не выполняют
операции OpenSSL, TLS handshake, callbacks, native-сервер или активацию runtime.

| Профиль | Результат | Область |
| --- | --- | --- |
| Windows MSVC 19.42.34444, x64 Release `/MD` | 8/8 случаев; 835 утверждений; код 0 | Ресурсные тесты с привязкой к исходникам |
| Ubuntu 24.04 GCC 13.3, x64 Debug ASan+UBSan | 8/8 случаев; 835 утверждений; код 0 | Ресурсные тесты с привязкой к исходникам |
| Независимый native-оракул ресурсов MSVC | 32 случая прошли | Ожидаемые значения отдельно выведены из уравнений |
| Независимый повтор ресурсного набора MSVC | 8/8 случаев; 835 утверждений прошли | Настоящий скомпилированный исполняемый файл ресурса |
| Публичный заголовок runtime | Самодостаточная компиляция MSVC прошла | Без связывания/исполнения методов runtime или квалификации TLS |

Linux использовал `ASAN_OPTIONS=detect_leaks=0:halt_on_error=1` и
`UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1`; LSan исключён. Дополнительные ресурсные прогоны
MSVC — отдельные исполнения. Запись ресурсной проверки Linux просмотрена без второго Linux-прогона.
На том этапе исходная проверка охватывала арифметику ресурсов и объявления runtime; полное исполнение
runtime приведено в отдельной матрице ниже.

Ресурсные проверки охватывают пять входных пределов, двадцать скопированных максимумов среды
и 25 координат работы; 63 ненулевых случая нехватки единицы по фазам; нулевой/точный/избыточный
бюджет, несоответствие условий, независимость скопированных входов, совпадение `need` с входным
объектом, отделённые значения освобождения, переполнение сложения по всем координатам и переполнение
требований. Сто эталонных величин, выведенных из исходников, совпадают с результатами C++.
Независимые случаи пересекают малые/максимальные пределы доверия/якорей/идентичности и границы имён,
запросов, ERR и истории ошибок. Это доказательства значений/допуска, а не настоящих выделений SSL,
времени жизни callbacks или продвижения SDK.

Синтетический максимальный арифметический пример даёт 601 607 223 байта отдельного экземпляра,
44 048 771 общий байт и 645 655 994 байта суммарно. Его двадцать чисел среды не являются наблюдаемым
состоянием или настройками по умолчанию. Это консервативные резервы из исходников, а не выделенные
арены, измеренный RSS или рекомендуемые настройки памяти. Для других допустимых пределов среды
требования вычисляются отдельно. Фиксированные native-кадры, накладные расходы аллокатора/санитайзера
и жёсткий предел времени остаются вне заявленной метрики SDK.

## Выполненные native-проверки и оставшиеся границы

Целевой набор выполняет TLS 1.2/1.3, явное доверие, проверку SAN и SNI отдельно от маршрута,
обычные отрицательные случаи срока/идентичности/политики ключей и малый повреждённый DER `30 00`.
Проверены тело Certificate на границе 65 536/65 537 байт, цепочки depth 4/5, барьер учётных данных,
повторный вход, перемещение/замена/уничтожение владельца, 64 свежие попытки, два endpoint,
128 больших кадров, подпись RSA-4096 длиной 512 байт, два обычных TLS 1.3 tickets и заголовок
ServerHello на границе/выше предела. Локальное принятие байтов не подтверждает обработку другой стороной.

Обычные сертификаты и ровно два намеренно открытых тестовых server key находятся в
[каталоге fixtures](../../fixtures/transport/tls/README.ru.md); [provenance](../../fixtures/transport/tls/provenance.json)
фиксирует генерацию, свойства и ожидаемые результаты. Проверки CLI сертификатов отдельно от выполнения runtime.
Частные ключи CA не входят в этот каталог.

| Случай | Реальная граница доказательств |
| --- | --- |
| Зашифрованный намеренно превышенный/повреждённый CertificateVerify | Только анализ исходников; native-сценарий не выполнен, недостижимость не утверждается |
| Максимальный/превышенный/повреждённый NewSessionTicket | Только исходный предел; два обычных полученных tickets не проверяют этот максимум |
| Потолок CertificateRequest 65 536 байт | Только исходники; профиль без клиентского сертификата не выполняет этот предел |
| Допустимый P-384 ServerKeyExchange ровно 617 байт | Максимум выведен по исходникам; native RSA-4096/X25519 имеет меньший обмен |
| TLS peer с ECDSA-аутентификацией | Не выполнен; допуск P-256/P-384 фабрикой — более узкая проверка |
| Полное произведение PSS hash/MGF/salt/encoding | Отдельные native-ограничения и анализ исходников; не исчерпывающий перебор |
| `SSL_write` WANT_READ/WANT_WRITE | Достижимость и сохранение retry tuple обоснованы исходниками; native socket backpressure — другая проверка |
| Полный корпус partial-record/claimed-body EOF | Не выполнен; обычный прерванный handshake/EOF не заменяет такой корпус |
| Сложные ASN.1/SPKI, fuzzing, allocator/provider/RNG hooks | Вне области обычных conformance-тестов |

Независимое критическое ревью текущей политики условно одобрило исходники при завершении итоговых
проверок. Подготовка касается двух окружающих DRBG (primary/private) и трёх DRBG отдельного контекста
(primary/public/private), сохраняя проверки READY/provider/CTR-DRBG/AES-256/DF. Дополнительное условие
предварительного прогрева окружающего public DRBG не вводится.
Состав SDK, условия приложения, ресурсная метрика и исключение фиксированных кадров остаются
условными контрактами. Ни native-тест, ни инструментированный вызывающий код не доказывает RSS,
жёсткий срок или санитайзерную квалификацию неинструментированного SDK.

Обновлённый пакет проверен после изменения политики: 57 файлов на каждой ОС, физический перенос
с сохранением всех хэшей и отсутствием исходного prefix, свежая сборка независимого потребителя
и четыре успешных TLS 1.2/1.3 запуска. На каждой ОС выполнены два `find_package`, проверены
24 установленных qd-заголовка и 15 imported archives; прямые targets — `qdcxx_tls`/`qdcxx_quote`.
В компиляции потребителя нет SDK/Asio/test-заголовков или fallback к дереву сборки/исходников.
`/MT` и неправильный SDK отвергнуты при configure без сборки workload. Linux использует
ASan+UBSan с LSan OFF; SDK не инструментирован. Все четыре итоговых профиля регрессии прошли: 58/58 с JSON и 57/57 без JSON на каждой ОС.
Проверка сгенерированной справки учитывается отдельно. [Сборка TLS](../../../docs/CPP-BUILD.ru.md#tls-source-profile-cpp-build-ru)
задаёт включение компонента и квалифицированный SDK.

Исторические [наблюдения выполнимости](VALIDATION.ru.md) и [TCP-проверки](TCP-VALIDATION.ru.md)
сохраняют свои исходные границы. Внешний сервер, reconnect, полный фасад подписок, throughput,
RSS и жёсткое время этой страницей не подтверждаются.

## Внутренний тестовый сервер

Тестовый `qdcxx_tls_test_peer` вызывается родительским
[помощником `TlsTestPeer`](tls_test_peer.hpp) и не устанавливается как пользовательская утилита.
[Точка входа](tls_test_peer_main.cpp) принимает отдельный `--help`, отсутствие аргументов либо
`--control ABSOLUTE_OWNED_FILE`. Справка без аргументов и по ключу одинакова и не начинает файловый I/O,
инициализацию TLS или сетевую работу. Недопустимые аргументы дают 2 до работы. Допустимый запуск
с control читает ограниченный родительский двоичный control-v4 (совместимый control-v2 также принимается) и обслуживает одно подключение
`127.0.0.1:0` с явно заданными обычными PEM-файлами, явной тестовой версией TLS, байтовыми сценариями и сроками.
Поиска тестовых файлов нет.

Пределы: 4 MiB на отдельный байтовый сценарий (начальная запись, ожидаемое чтение, ответ), 4 096 байт UTF-8 на путь, 128 KiB на PEM-файл и 1..60 000 ms
на тайм-аут. Значения API по умолчанию: TLS 1.3, чистое close_notify, пустые начальная запись и ответ, отсутствие
ожидаемого чтения, нулевые задержки, 5 000 ms на запуск/handshake/чтение/запись, 15 000 ms на всё время
жизни и 250 ms на кооперативную остановку родителем. Режимы закрытия: чистый, внезапный TCP EOF
и удержание; задержки handshake/чтения задаются явно. Содержимое сертификатов/ключей, байты приложения
и форматированный текст ошибок SDK не печатаются и не включаются в отчёты.

После handshake сервер сначала пишет `initialBytes`, затем выдерживает необязательную задержку
чтения, читает точное ожидаемое число байтов и пишет ответ. Пустое значение `initialBytes` по умолчанию
сохраняет прежнюю последовательность чтение/ответ. Начальная запись и ответ допускают суммарно
не более 8 MiB исходящих данных; каждый сценарий отдельно ограничен 4 MiB. Это позволяет проверить
двухфазный обмен challenge/response без повторного подключения.

В POSIX вызывающая сторона сохраняет возможность ожидания своего дочернего процесса: `SIGCHLD`
не должен быть `SIG_IGN`, флаг `SA_NOCLDWAIT` исключён, другие потоки/обработчики не должны забирать
завершение этого процесса. Известная несовместимая настройка до запуска даёт `PROCESS_START`.
Предусловие действует всё время жизни владельца; помощник не меняет глобальную настройку сигналов.

Код 0 означает обычное завершение сценария/остановки или успешный вывод справки; 1 — ошибку
control/TLS/I/O/срока либо вывода справки; 2 — недопустимые аргументы. Родитель владеет точным дочерним
процессом и уникальным временным каталогом, пишет двоичные данные управления/сценария и читает
только числовые поля отчёта. Побочные действия дочернего процесса: один loopback-listener, замена
числового `report`/`report.next` и опрос маркера остановки. Родитель ждёт конечный кооперативный срок,
после чего может завершить только свой процесс и удалить точные собственные файлы. Он не ищет чужие
процессы и не удаляет корневой каталог вызывающей стороны рекурсивно. Принудительное завершение
не означает законченный сценарий TLS. Control содержит синтетические тестовые данные; открытые
учётные данные не передаются через argv/окружение или диагностические журналы.

Ревью исходников/API помощника и проверки CLI/собственного процесса отделены от тестов рабочего
TLS runtime. Проверки исходников/CLI и завершения собственного child имеют отдельные результаты.
Итоговая регрессия включает helper; результат только helper не считается проверкой рабочего TLS runtime.

Текущий родитель пишет control-v4; child принимает также v3 и v2. V3 добавляет слово политики после
close mode, V4 — число начальных TLS 1.3 tickets 0..2; по умолчанию 0, для других версий требуется 0.
V2 выбирает MODERN. CBC_ONLY/P521_ONLY/SHA1_ONLY принадлежат только отрицательному тестовому серверу.
TLS 1.0/1.1 разрешают только MODERN; CBC_ONLY/SHA1_ONLY — только TLS 1.2. Security level 0 действует
локально в legacy/SHA-1 test peer; рабочий клиент сохраняет строгий профиль TLS 1.2/1.3.
Report-v2 содержит 21 числовое слово: magic, port, version, bytes read/written, ready, accepted,
handshake, expected-match, close-notify, completed, timeout, failed, SNI-present, SNI-localhost,
cipher suite, group, signature-hash NID, ticket count, signature scheme и signature byte count.
Флаги SNI не содержат имени; метаданные подписи не выводят её содержимое. Совместимость control
не означает совместимость со старым 15-словным report reader.

## Остаточное ограничение тестовой инфраструктуры

В одном прежнем Windows-прогоне 64 сессий все runtime-проверки завершились, но агрегат завершения
одного тестового дочернего процесса сообщил сбой. Причина неизвестна; исправление причины не заявляется.
Добавленная числовая диагностика различает будущие исходы завершения процесса, не ослабляя проверку.
На итоговых исходниках все четыре профиля регрессии, отдельный прогон 64 сессий и ограниченный
параллельный прогон двух процессов по 64 сессии прошли без воспроизведения. Это остаётся ограничением
доказательств тестовой инфраструктуры, а не доказательством отсутствия дефекта. Повторение требует
разбора нового числового результата до дальнейшей квалификации.
