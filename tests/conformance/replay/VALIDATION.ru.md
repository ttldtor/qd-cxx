# Проверка офлайн-воспроизведения

[English version](VALIDATION.md). Английская версия является нормативной.

## Реализованная граница

Необязательная библиотека `qdcxx_replay` предоставляет синхронный `replayTape` для неизменяемой
допущенной записи. Вызывающая сторона выбирает `IMMEDIATE` или `RELATIVE`, задаёт независимые
конечные бюджеты разбора, работы, callbacks, часов и ожиданий и владеет observer, опросом отмены и
монотонными часами/ожиданием. Библиотека сохраняет generic records и исходное время по wire-порядку;
команда CLI, файловый доступ, транспорт, фоновые задачи и реализация реальных часов не добавлены.

Движок использует новый reader и требует фактического исчерпания байтов и reader finish для
подтверждения чистого EOF. Результат ошибочного frame не доставляет его завершённый префикс.
Relative scheduling применяется только к непустым data frames с присутствующими timestamp; пустые
кадры не меняют anchors, high-water elapsed и проверки диапазонов. Ссылки callback на записи
истекают при возврате. Внешние эффекты прежних callbacks не откатываются. Эти правила поведения и
времени жизни описаны в [контракте офлайн-воспроизведения](../../../spec/protocol/OFFLINE-REPLAY.ru.md).

## Выполненные целевые проверки

Итоговые Windows MSVC 19.42 x64 Release-сборка и целевой CTest прошли: один target, 9 случаев /
1 303 assertions. Тест выполняет все 24 документированных replay-сценария, использует native
writer/admission, сравнивает девять Java RAW timestamp/cursor наблюдений и охватывает все восемь
точных типов полей. Для fixture независимо рассчитан ledger в 31 единицу работы: семь попыток frame, две попытки record, два обхода layout, 13 опросов движка, три чтения часов, одно ожидание и три попытки observer.
Три намеренные мутации не прошли соответствующие проверки: доставка ошибочного префикса (2 случая /
3 assertions), планирование пустых кадров (1 / 13) и принятие преждевременного `READY` (1 / 1).
Итоговая проверка форматирования прошла для трёх изменённых C++-файлов.

Независимая целевая Windows MSVC-проверка также прошла replay target (9 случаев / 1 303 assertions).
Отдельный Windows-потребитель сначала не скомпилировался без защиты макросов, затем собрался и
запустился после определения `NOMINMAX` до Windows-заголовков и отмены `RELATIVE` перед replay-
заголовком. Это подтверждает только данную последовательность подключений, но не гарантирует
совместимость для произвольного порядка Windows-заголовков. Исходная неудачная сборка и исправленная
проверка сохранены в архиве.

## Полные проверки

Полная Windows MSVC x64 Release-сборка и CTest прошли: 51/51 тест за 311,19 секунды. Также
успешно сконфигурированы и собраны три Windows production-only Release-профиля с выключенными
testing и JSON: replay ON при всех tools OFF; replay ON со всеми тремя inspection/writer tools ON;
replay OFF при всех tools OFF. Итоговая запись профилей подтвердила отсутствие `_deps` во всех
трёх и наличие `qdcxx_replay` только при включённой опции.

Общая проверка форматирования C++ прошла для 100 файлов. Doxygen 1.18.0 завершился успешно и создал
страницы API replay; файл предупреждений пуст. Настройка `EXTRACT_ALL` означает, что пустой файл
предупреждений не доказывает полноту всей API-документации.

Linux Debug ASan/UBSan CTest прошёл 51/51 на Ubuntu 24.04 / WSL2 с GCC 13.3 за 869,98 секунды (конфигурация, сборка, CTest). Также прошли Linux production-only Release-профили: replay ON/tools OFF, replay ON/все три tools ON и replay OFF/tools OFF. Проверки артефактов подтвердили отсутствие `_deps` во всех профилях и наличие библиотеки/target replay только при включённой опции; см. сводку Linux-профилей. В сборке replay OFF появилось существующее предупреждение GCC `-Wstringop-overflow` в `src/core/wide_decimal.cpp:68`; сборка завершилась успешно.

Не заявлены macOS, интеграция с реальными часами, replay CLI, транспорт, гарантированное ограничение
времени пользовательских callbacks, враждебная конкурентная мутация или совместимость со всем
форматом tape. Callback и ожидание должны быстро возвращаться по контракту; движок не может
ограничить callback, который зависает навсегда.
