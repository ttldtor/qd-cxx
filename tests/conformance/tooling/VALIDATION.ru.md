# Валидация переносимых средств разработки

[English version](VALIDATION.md). Английская версия является нормативной.

## Область и статус

QDCXX-028 реализует переносимые native-инструменты разработки; проверка выполнена.
Фактический исходный HEAD: `9b4f8ddf5786f71ac5f6d2305a0215a84b86b4b4`, изначально чистое рабочее дерево и пустой staged diff;
Исходный снимок сохраняет первоначальные хеши файлов.
Это проверка и самопроверка. Независимое ревью/приёмка остаются открытыми.

Итоговые повторные проверки исходников и целевые проверки исправлений завершены, как описано ниже;
ссылки на итоговые результаты аудита сохранности при передаче приведены в разделе аудита.
Прежние отказы отделены от исправленных повторов.

## Решения реализации

- Автономный `tools/dev/Bootstrap.cmake` собирает native tools независимо от корневых production-целей,
  doctest и готового logger. Исключение первой сборки записывает UTC-границы фаз и отдельные исходные потоки.
  Последующие измеряемые этапы используют `qdcxx-run-utc`.
- Logger получает владение процессами до исполнения, передаёт native argv без оболочки, переопределяет
  только дочерний `TZ` и отдельно декодирует/вычитывает оба потока. Закрытый наблюдатель отслеживает выход
  корневого процесса независимо от EOF потоков и записи в получателей. Единый пятисекундный срок очистки
  действует до завершения EXIT и закрытия журнала; отмена начинается через четыре секунды, оставляя одну
  секунду для подтверждения очистки. Native-запись журнала исключает повтор буферизованного вывода из
  деструктора. Диагностика ошибок использует внутреннюю непосредственную native-запись с попыткой в пределах
  100 мс и последующим немедленным завершением процесса с исходным кодом; полный stderr не может снова
  запустить неограниченное ожидание после остановки watchdog. Очистка Linux перечисляет принадлежащую
  сессию через `/proc` и использует pidfd для отправки сигналов и ожидания без гонок, сохраняя PID корневого
  процесса как устойчивый идентификатор сессии. Эти вспомогательные средства остаются внутренними для tooling.
- CMake formatter использует неизменённый точный конвейер 0.83.0 → 20.1.8 и конфигурации. Каждый входной
  файл получает отдельный временный каталог с исходным basename: clang-format использует это имя для
  приоритета соответствующего заголовка. JSON-выбор и декодирование имён Git сохраняют сложные имена.
- Существующий image guard получает явный режим `--deny-interpreters`; исходный интерфейс по-прежнему
  запрещает только Python. Новые точные перечни выводятся из этой матрицы. Production-only сборки не входят
  в `tools/dev` и не получают doctest; production-библиотеки не связываются с этими инструментами.

## Исходные проверки и доказательства регрессий

[Покрытие](COVERAGE.ru.md) и [coverage.json](coverage.json) сохраняют 157 первоначальных обязательств и
четыре регрессионные проверки R5 и одну регрессию форматтера, всего 162. Валидация отвергает удаление каждой именованной записи, включая
все 17 offline и 9 human имён мутаций. Старые проверки logger на Windows
и Linux, а также все
28 необязательных Windows setup/formatter-проверок выполнены
до замены. Эти намеренные исторические PowerShell-проверки находятся вне нового дерева с запретом интерпретаторов.

При проверке исходников воспроизведены и исправлены семь проблем:

1. Открытый, но не читаемый console pipe мог скрыть выход корневого процесса: red.
   Наблюдатель остаётся активным даже при выводе завершающего EXIT.
2. POSIX FIFO-журнал всё ещё мог блокировать flush у `ofstream`: red.
   Теперь журнал использует собственную native неблокирующую запись POSIX; Windows — отменяемую native-запись.
   Целевые наборы промежуточных исходников Windows и
   Linux повторяют исходную проверку, все три реальные мутации logger
   с обязательной диагностикой и восстановленную исходную проверку. Linux дополнительно проверяет `/dev/full`
   и реальный FIFO; Windows проверяет фактическую ACP 1252 с native Unicode argv и путями.
3. Пронумерованные временные basename меняли сортировку соответствующего заголовка. Неизменённый старый
   formatter прошёл проверку исходного inspector, тогда как
   восстановленный ошибочный driver не проходит новую проверку порядка заголовков.
   Исправленные formatter-наборы Windows и Linux
   проходят проверки реальных инструментов, пяти настоящих мутаций driver и восстановленной исходной версии.
4. Полный stderr мог блокировать сообщение об ошибке после остановки watchdog обработчиком исключения:
   Windows red, Linux red.
   Теперь внутренний worker пытается напрямую записать native-диагностику не дольше 100 мс; немедленный
   выход 1 или 2 сохраняет установленный результат ошибки/неверных аргументов без повторов из деструктора
   или flush потока. Целевые повторные наборы
   Windows и Linux;
   завершаются EXIT 0; результаты последующих полных профилей приведены ниже.
5. Linux-потомок с `setpgid` оставался в принадлежащей сессии, но переживал EXIT 0:
   red. Теперь очистка сканирует `/proc` для этой сессии и использует pidfd
   signal/wait с устойчивым PID корневого процесса, охватывая потомков, переходящих в другую группу
   процессов внутри той же сессии. Отказ при отсутствии возможностей
   возвращает 1 до исполнения команды; целевой Linux-набор завершается
   EXIT 0. Эту целевую исходную проверку дополняют результаты полных профилей ниже.
6. Завершающие аудиты матриц Windows/Linux, тесты которых прошли, упали на traces размером около 1 МБ:
   regex stack overflow на Windows и segmentation fault на Linux. После удаления повторяющегося regex
   валидация выявила разделение списка CMake с потерей точек с запятой в путях образов. Теперь auditor
   проверяет скалярные значения UTF-8 по отдельности и обратимо кодирует метасимволы списка при обходе записей trace.
   Регрессионные проверки Windows и Linux
   проходят большие UTF-8/специальные пути, неверные данные и восстановленную исходную проверку.
   Прежние неуспешные журналы сохранены.
   Дополнительная малая трасса выявила ошибочный разбор буквального POSIX backslash как разделителя Windows;
   имя файла теперь выделяется по синтаксису пути образа. Итоговые проверки под guard на
   Windows и Linux
   включают этот случай и буквальные метасимволы процентов/списка.
7. Переданное вызывающей стороной cache-значение `-DtempRoot` было видно ранней очистке ошибки форматтера,
   что позволяло удалить каталог вызывающей стороны: Windows red,
   Linux red. Теперь driver перекрывает cache-значение пустым
   внутренним состоянием и очищает только созданный им временный каталог. Исправленные formatter-наборы
   под guard на Windows и Linux
   проходят все пять мутаций driver и восстановленные исходные проверки. Итоговый общий Check проходит
   все 77 C++-файлов на Windows и Linux.
   Покрытие отвергает все 162 мутации отсутствующей записи на Windows
   и Linux; соответствующие аудиты трёх traces и их
   отрицательные проверки проходят на Windows и
   Linux. Последнее исправление затрагивает только CMake tooling;
   C++-исходники всех семи профилей компиляторов неизменны.

Первый повтор итоговых исходников Windows прошёл 39/40 наборов: новый аудит большой трассы превысил
30-секундный таймаут дочернего процесса под отладчиком Windows. Отдельное
воспроизведение под guard завершилось так же.
Лимит процесса аудита теперь равен 180 секундам; данные, требования отклонения и пятисекундный
контракт очистки logger не изменены. Повтор под guard прошёл; полные проверки Windows перезапущены
в `windows-recheck-b`. Ранние профили Linux прошли более строгий 30-секундный лимит; последующие
профили и итоговые аудиты трасс используют обновлённый harness. C++ исходники logger сохраняют
тот же зафиксированный снимок.

Более ранние журналы промежуточных исходников сохраняют этот статус. Они включают первоначальный отказ
песочницы при поиске Windows SDK, исходную ошибку необязательной загрузки, неверный путь к кэшу doctest и
ошибки кавычек в командах. Последние разделяли незаключённые в кавычки PowerShell-значения `-D`;
порожденные артефакты тестов/сборок выявлены и удалены либо изолированы под `.work`, включая удаление

Эти попытки не являются итоговыми успешными проверками.
Исторические доказательства, fixtures, formatter/dependency locks и исходники Java не переписывались.

Первая Windows Debug матрица под guard прошла 39/40 наборов: перебор удалений карты покрытия превысил
внешний таймаут harness 180 секунд (сохранённый отказ).
Теперь предел целого набора — 600 секунд (180 секунд на дочерний запуск logger suite); проверки срока R5

Повторные запуски под guard на Windows и
Linux для промежуточных исходников отвергают все тогдашние 159 удалений.
Два последующих дополнения R5 довели перечень до 161, затем регрессия форматтера — до 162;
прежние доказательства не переобозначаются.
Windows-матрица перезапущена
в новом каталоге `windows-final-b`; неуспешные доказательства не перезаписаны.
Тот Windows CTest использовал четыре параллельных исполнителя; Linux-матрица была последовательной.
Ранние прошедшие Linux-профили и Windows Debug использовали прежний эквивалентный
обход карты. Целевые повторы и последующие профили проверяют итоговый обход; точные команды/таймауты

## Запрет интерпретаторов и аудит доказательств

Отдельные guard-проверки работают вне другого debugger, поскольку tracers не могут вкладываться.
Тридцать проверок на каждую ОС проходят на Windows и
Linux: семь алиасов через absolute/PATH/потомков, подавляющих ошибку,
два пути реальных интерпретаторов теми же тремя способами, fake formatter с запуском PowerShell,
разрешённая и восстановленная исходные проверки. `inventory.json` каждого каталога задаёт точные
корневые процессы и ожидаемые запреты. `.python-only.tsv` с исходной политикой намеренно остаётся вне
более строгого перечня и проверяет обратную совместимость. Запрещённый интерпретатор не исполняется;
намеренные попытки записываются как DENIED.

Отрицательные проверки аудита Windows и Linux
удаляют каждый обязательный control trace и отвергают пустые, лишние, malformed, wrong-root, relative-image,
forbidden-image, missing-LF, extra-tab, CRLF, BOM и invalid-UTF-8/UTF-16 traces, затем восстанавливают
исходную проверку. Каждая итоговая матрица выводит собственный точный trace-перечень и повторяет удаление
каждого обязательного файла. Прежние количества Q027 49/42 trace-файла не используются как ожидания.

После исправлений auditor аудит Windows-матрицы прошёл точный
перечень из 42 traces и каждую отрицательную проверку отсутствующего файла;
аудит Linux-матрицы прошёл точный перечень из 38 traces и
соответствующие отрицательные проверки. Оба включают мутации содержимого и восстановленные исходные
проверки. Они проверяют сохранённые traces прежних матриц и не заменяют последующие повторные проверки
исходников или итоговый аудит передачи.

Итоговые результаты аудита сохранности/фильтров передачи:
Windows и Linux.
Исторический аудит сохранности проверял полный
перечень изменений, защищённые исходные хеши, пробельные ошибки изменённых файлов и относительные ссылки.
Для исходных доказательств действует адресный `-text`; только конкретные raw-пути с фактической
whitespace-диагностикой получают `-whitespace`. Проверки clean/smudge используют `core.autocrlf=true`

причина, а не доказанная операция staging. Итоговые аудиты выполняются после фиксации документов с
`GIT_OPTIONAL_LOCKS=0`; сохранённая неуспешная попытка не является положительным результатом.

## Ограничения и передача

- Обязательные окружения — Windows x64 и native Linux x86_64 под Ubuntu WSL. Используются native Linux
  executables, а не Windows tools через WSL. Другие дистрибутивы/архитектуры Linux не проверены.
- ASan/UBSan и LSan разделены: ptrace-запуски задают `ASAN_OPTIONS=detect_leaks=0` и
  `LSAN_OPTIONS=detect_leaks=0`; они не доказывают покрытие LeakSanitizer.
- Очистка принадлежащей сессии на Linux требует Linux 5.4+, читаемый `/proc`, доступные pidfd open/signal/wait
  и возможность ожидать потомков при текущей обработке `SIGCHLD`. Отсутствие возможностей приводит к отказу
  до исполнения потомка. Резервный POSIX-путь вне Linux не квалифицирован этими Linux-результатами.
- Для macOS выполнено только изучение исходников: POSIX-код изолирует Linux subreaper/pidfd-вызовы, но компилятор,
  очистка/reaping групп процессов и runtime-поведение не проверены и не блокируют работу.
- POSIX signal exit потомка отображается в `128 + signal`; обработанная отмена logger возвращает 1.
  Отделённые POSIX sessions, принудительное завершение logger и непрерываемый kernel/device I/O — явные
  ограничения. POSIX FIFO-журнал требует существующего читателя. Журналы текстовые и не являются
  сохраняющими байты захватами inspector.
  Срок реализации — пять секунд; проверки времени допускают 0,5 секунды на планирование
  (0,6 секунды для намеренно задержанной внедрённой ошибки). Проверки зависшего вывода подтверждают
  фактический выход корня до проверки очистки и проверяют, что управляемые потомки больше не работают.
- Имена файлов с CR/LF и буквальной обратной косой чертой POSIX в имени source отвергаются до
  форматирования; последние не поддерживаются грамматикой путей CMake. Принудительное завершение CMake
  находится вне обрабатываемой очистки.
- Image denial — доказательство свойств процесса разработки, а не sandbox против переименованных/встроенных
  враждебных интерпретаторов. Unicode-результаты средств разработки не расширяют Unicode-поддержку inspector.
  Java tooling, остальные ручные Python-аудиты/генераторы, production-код/настройки и отслеживаемый байткод
  сохраняют прежние границы.

Ни одно утверждённое требование намеренно не сокращено.
