# Авторская верификация QDCXX-027

[English](VALIDATION.md). Английская версия является основной.

Границы реализации: QDCXX-027 — инструменты разработки без Python.
Исходный HEAD — `dcccd0242252cadb674f4970cc723fbf113bed53`, рабочее дерево было чистым.
Это авторская верификация, включая самопроверку; независимое ревью и приёмка ожидаются.

Этот отчёт сохраняет исходные прогоны реализации. Текущие хеши исходников, строгий аудит трасс,
проверки Windows-1252 и повторные прогоны затронутых наборов для замечаний #1/#2 приведены в
проверке исправлений ревью. Прежние журналы и снимки хешей неизменны.
Передача Unicode теперь проверяется тестовым помощником с нативными аргументами; представимость путей
production CLI на Windows по-прежнему зависит от активной кодовой страницы. Проверка неудобного пути
настоящего инспектора сохраняет пробелы и точки с запятой, используя ASCII.

Неизменённые Python-инструменты запускались с `PYTHONDONTWRITEBYTECODE=1` и явным `-B` при прямом вызове.
Offline negatives отвергли все 17 мутаций и восстановили полный baseline.
Отдельный human baseline охватил 84 human-сценария, 72 прежних TSV-сценария,

доказательством полноты: исходные скрипты не учитывают в этих счётчиках некоторые запуски.

Сравнение старого и нового и поимённая таблица
используют точные временные мутации новой реализации. Совпали стадии отказа всех 17 offline-мутаций;
байты всех 9 human-мутаций равны исходным выражениям, отказ которых выполнен в baseline.
Запись новых мутаций дополнительно проверяет отказ адаптера
при изменении только exit. Каждый финальный полный CTest повторяет все мутации и полностью
восстановленные offline/human-наборы. [Покрытие](COVERAGE.ru.md) сопоставляет грамматику, сравнение байтов,
чанки, Java-наблюдения, ошибки CLI и ветви I/O.

## Решения реализации

- CMake читает неизменённые JSON-manifest с конечными ограничениями адаптера и сохраняет точные
  границы аргументов, включая пустые строки, точки с запятой и Unicode. Тестовый C++ проверяет сырые
  файлы и выбрасывает исключения при ошибках также в Release. Ожидаемые JSON-строки передаются через
  hex-to-binary, поскольку текстовая запись CMake на Windows добавила бы CRLF. Наблюдаемые stdout/stderr
  никогда не нормализуются.
- Имена `offline_inspection_cli` и `human_inspection_cli` сохранены. Явно добавлены три проверки:
  `inspection_checker_contract`, `inspection_cli_negatives`, `inspection_process_contract`.
  Прежние наборы аргументов и injected-I/O сохранены. Реальный заранее закрытый stdout проверяется
  без аргументов, с help, TSV и human на обеих ОС; отсутствие executable и таймауты — ошибки harness.
- `Run-Utc.ps1` требует PowerShell 7.4+, сохраняет порядок строк внутри каждого потока, замену ошибок
  UTF-8, универсальные переводы строк и последний фрагмент; TZ меняется только у дочернего процесса.
  Порядок между независимыми потоками и захват сырых байтов не гарантируются. Worker входит в Windows job
  или Unix session до запуска команды; ошибки console/log завершают принадлежащих ему потомков,
  даже когда основной процесс уже вышел. Намеренно отделённые Unix sessions вне этой границы владения.
- Windows setup использует прежний lock, проверяет хеши новых и кешированных архивов и все пути до
  распаковки, отвергает links/reparse paths, публикует проверенный временный каталог с rollback.
  Повторная распаковка проверенного кеша восстанавливает повреждённые executable. Pip и новые пакеты
  не нужны. Эти Windows EXE не доказывают получение нативных форматтеров Linux.
- Запрет Python отслеживает образы всего дерева процессов: Windows debug stops при создании и Linux
  ptrace exec stops проверяют разрешённый путь до исполнения. PATH aliases, настоящий абсолютный
  interpreter и потомок, чей родитель подавляет ошибку, должны дать exit 97 и доказательство `DENIED`.
  Это проверка рабочего пути, не sandbox против намеренно переименованного или встроенного Python.

Каждый вариант конфигурирует свежий кеш с TRUE для `CMAKE_DISABLE_FIND_PACKAGE_Python`, `Python2`,

Использованные команды воспроизведения (для повтора необходимы свежие run tags):

```powershell

```

Внутри WSL, из `/work/qd-cxx`:

```sh
.work/python-migration-pwsh/pwsh -NoProfile -File tests/conformance/python-migration/Verify-NoPython.ps1 -Guard .work/python-migration-linux-guard -DoctestSource .work/linux-debug/_deps/doctest-src -PythonControl /usr/bin/python3 -RunTag final-b
```

Windows guard предварительно собран в прежнем CMake-дереве MSVC Release; Linux guard — командой
`g++ -std=c++23 tests/conformance/no_python_guard.cpp -o .work/python-migration-linux-guard`.
Хеши бинарных guard и разрешённые инструменты сохранены в финальных `environment.json`.
GCC ASan+UBSan использует non-PIE и `detect_leaks=0`: LeakSanitizer не может исследовать процессы
под ptrace. AddressSanitizer и UndefinedBehaviorSanitizer включены; проверка утечек не заявляется.

## Записанные ошибки и ограничения

Первые configure baseline завершились ошибкой из-за разбитого аргумента пути doctest / доступа к SDK
из sandbox, затем из-за сохранённого неверного пути: первый,
повтор. Свежий
configure с корректными кавычками и доступом к SDK прошёл.
Первый ручной вызов Linux logger guard не передал аргумент команды
guard; это ошибка harness, не успешный тест.
Первый configure Linux-матрицы завершился ошибкой:
несколько результатов `Get-Command` превратились в одну строку executable. Исправлен выбор первого
нативного приложения; финальный свежий запуск — `linux-final-b`. Доказательства ошибок сохранены без изменений.
На ранних этапах также не прошли ограниченная загрузка с пустым кешем и параллельная пересборка helper;
настоящая загрузка setup и пересобранные helpers затем успешно проверены. Эти попытки не являются результатами приёмки.

После успешных четырёх полных Windows-профилей первый production-only configure в `windows-final-a`
завершил CMake, но guard ждал принадлежащего запуску потомка компилятора `vctip.exe`. Этот процесс
верификации остановлен; его job завершил собственные оставшиеся процессы.
Незавершённый журнал configure сохранён.
Теперь Windows guard завершает оставшихся отслеженных потомков после выхода основного процесса и
дочитывает debug exit events. Регрессия с 30-секундным потомком
завершилась примерно за две секунды без оставшегося процесса. Свежий полный Windows-запуск — `windows-final-b`;
он использует параллелизм CTest 4 с теми же полными наборами. Записанный Linux-запуск использовал
последовательный CTest; политика исполнения Linux guard неизменна. Правка guard прошла закреплённые Format и Check.
Свежая пересборка Linux guard из окончательного исходника воспроизвела
точный SHA-256 бинарника, использованного завершённой Linux-матрицей.

Production/API/wire/schema не менялись; новые Python-исходники/зависимости, изменения Java-исходников,
новые Java captures и анализ частного tape отсутствуют. CTest использовал прежние Java-derived fixtures;
Java Verify не повторялся. Остальные Python negatives примитивов/протокола, JSON-валидация,
старые аудиты доказательств и генераторы остаются обязательными в [реестре миграции](../../../docs/PYTHON-MIGRATION.ru.md).
Сохранённая в CPP-BUILD ручная Python-команда явно отмечена как неперенесённая.

## Сохранность, самопроверка и передача

Аудит передачи подтверждает побайтовую сохранность всех 4004 защищённых
исходных файлов и индекса владельца. HEAD остаётся `dcccd0242252cadb674f4970cc723fbf113bed53`;
SHA-256 индекса — `33322613B5F77CBC535C6E869BA707574F389B843BAD602D894ADDE800A69460`.
Исходные хеши определяют CMake/C++/PowerShell-файлы до исправлений ревью.
Аудит матрицы проверяет все 23 комбинации configure/build, числа применимых
тестов, расписания/exit всех 156 именованных сценариев и 72 именованных legacy TSV-сценария в каждом запуске
с QTP, отсутствие sanitizer diagnostics и образов Python, кроме намеренных контрольных отказов.
Аудит проверяет whitespace изменённых и неотслеживаемых авторских файлов, взаимные/относительные ссылки,
Git filters сырых файлов и их whitespace attributes. По фактической диагностике Git исключения whitespace
потребовались до исправлений ревью для 88 конкретных сырых путей; отказ на whitespace авторских файлов остаётся включённым.
Выполненный аудит сохранности:

Исторический аудит сохранности записывал Git objects только в игнорируемый изолированный каталог и пропускает каждый
новый сырой файл доказательств через Git clean/smudge с `core.autocrlf=true`.
Индекс и object database владельца не записываются. Сырые пути имеют scoped `-text`;
исключения whitespace заданы только конкретным сырым файлам, где такие пробелы действительно есть.
Внесённый дефект конечных пробелов в авторском Markdown должен отвергаться.
Исторические сырые доказательства никогда не нормализуются.

Итоговый diff, включая неотслеживаемый код и документы, проверен на границы и корректность.
Проверки повторного использования/качества/эффективности выявили семь необязательных упрощений;
исправлений корректности среди них не было. Общий parsing добавил бы allocation или связанность;
короткие повторные преобразования и неиспользуемые exports не оправдали новой абстракции;
для regex/poll не измерено узкого места; manifest установленного кеша ввёл бы новый протокол доверия/кеширования.
Эти предложения отложены. Отдельная проверка harness привела к явному закреплению компилятора,
контролю подавленной ошибки потомка и очистке logger после выхода основного процесса;
всё включено в выполненные финальные проверки. Это авторская самопроверка.
