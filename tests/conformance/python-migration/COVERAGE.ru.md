# Покрытие проверок без Python

[English version](COVERAGE.md). Английская версия нормативна.

## Зафиксированный контракт (U1)

Исходный HEAD: `dcccd0242252cadb674f4970cc723fbf113bed53`. Рабочее дерево было чистым.
Метаданные baseline, SHA-256 всех отслеживаемых файлов,
инвентарь CTest и карта именованных сценариев
сохранены до переноса. Карта перечисляет все 72 offline и 84 human случая, фактические уникальные
размеры порций, коды выхода, аргументы и предполагаемые компоненты замены. Счётчики не определяют
покрытие: исторические скрипты не учитывают часть запусков процессов в итоговых числах.
Исторические скрипты, манифесты, captures и отслеживаемый bytecode остаются неизменными.

## Именованные мутации и стадии отклонения

`inspection_cli_negatives.cmake` создаёт временные входы и требует нужную стадию отклонения.
Посторонняя ошибка процесса не считается успешной отрицательной проверкой.

- Точное offline сравнение: `value`, `symbol`, `local-id`, `name`, `complete-count`.
- Валидация ожидаемого TSV: `offset`, `row-type`, `row-arity`, `number-syntax`, `hex-syntax`,
  `missing-complete`, `double-complete`, `trailing-row`.
- Приём манифеста: `empty-selection`.
- Семантическое Java сравнение: `java-value`; структура Java наблюдения: `java-unknown`, `java-completion`.
- Точное human сравнение: `label`, `value`, `escape`, `escape-lookalike`, `completion-count`,
  `missing-completion`, `double-completion`, `trailing-output`, `frame-offset`.

После каждой группы мутаций восстановленные baseline должны проходить. Это контракт покрытия
до переключения; выполненные проверки и ограничения описываются в [валидации](VALIDATION.ru.md), а не выводятся из счётчиков.

## Инструменты разработки и проверка запрета Python

- `Test-RunUtc.ps1`: успех/выход 37/отсутствующий executable, пустые аргументы и пробелы/Unicode/semicolon/
  кавычки/backslash, только дочерний TZ с проверкой родителя в том же процессе, CR/LF/CRLF/неверный UTF-8/
  BOM/последние фрагменты, по 5000 строк на поток, недоступный журнал, реально закрытая консоль и ограниченная
  очистка при работающем или уже завершившемся основном процессе. В Linux дополнительно проверяется `/dev/full`.
- `Test-SetupCpp.ps1`: 28 именованных проверок, включая настоящие закреплённые архивы с пустым/прогретым кешем,
  восстановление повреждённого EXE, неверные хеши кеша/загрузки, прерванную загрузку, отсутствующий executable,
  опасные пути/разделители/drive/UNC/ADS/device, ZIP links/reparse entries, дублирование/конфликт распаковки,
  junction файловой системы, сохранность прежней установки, неверные версии и Format/Check/отказ без записи/идемпотентность.
- `inspection_process_contract`: четыре случая с заранее закрытым stdout настоящего процесса (без аргументов,
  help, TSV, human), строгий код/диагностика, отсутствующий executable и timeout дочернего процесса с 256 KiB
  stderr. Stderr сохраняется в сырой файл; блокирующее чтение pipe вне предела времени отсутствует.
- `Verify-NoPython.ps1` и `qdcxx_no_python_guard`: свежие кеши, запрещённое обнаружение Python в CMake,
  сохранённые применимые имена CTest, отсутствие отключённых тестов, все комбинации опций и именованные
  профили компиляторов. Остановки создания Windows debugger и Linux ptrace exec проверяют разрешённые ОС
  пути executable до выполнения их кода, включая потомков и абсолютные пути. Намеренные проверки alias/
  абсолютного пути/потомка должны возвращать 97 и записывать DENIED. Это ограниченная проверка workflow,
  а не универсальная защитная среда для переименованных или встроенных runtime. Production-only сборки
  не обнаруживают и не загружают doctest.
  Windows-контроль `guard-orphan` также требует быстрого завершения живого потомка после выхода основного процесса.
- `Audit-Handoff.ps1` требует точный перечень трасс существующей матрицы: 49 Windows и 42 Linux,
  включая все configure/build, применимые inventory/test и контроли запрета/инструментов разработчика.
  Он отклоняет пустые или ошибочные записи, неверный UTF-8, относительные пути образов, неверные корневые
  образы, выполнение Python и отсутствующие/неверные запреты. `Test-HandoffAudit.ps1` изменяет изолированные
  копии; проверка исправлений ревью фиксирует результаты и границы аудита сохранённых доказательств.
- `Compare-Legacy.ps1` предназначен только для сравнения со старым путём: запускает неизменённый исторический
  Python checker на точных временных мутациях замены, фиксирует все 17 стадий отклонения и проверяет
  побайтовое равенство 9 human-мутаций историческим выражениям. По назначению он вне перенесённого пути;
  он не заменяет запуск неизменённого исторического human baseline.
