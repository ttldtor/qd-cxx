# Офлайн-приёмка шлюза Kraken

[English version](README.md). Английский текст нормативный.

Стенд запускает четыре процесса на IPv4 loopback. Синтетический WSS-источник передаёт
ticker, шлюз публикует TICKER Quote, а два независимых приложения подписываются по QTP.
Один потребитель использует установленный C++ Feed SDK, второй — Java QD из ревизии
в [upstream.lock](../../../upstream.lock). WSS-источник использует
[синтетические сертификаты](../../fixtures/transport/tls/README.ru.md). Внешняя сеть не нужна.

Нативный клиент получает начальный снимок. Затем снапшот получает только что подключённый
Java-клиент, а первое обновление доставляется обоим. Стенд обрывает соединение
с источником, проверяет переподписку с новым идентификатором запроса и ждёт свежего снимка.
Контрольное обновление, посланное до снимка, не должно появиться в трассе шлюза и у обоих
потребителей. Нативный клиент продолжает получать данные после выхода Java-клиента.
Цены и объёмы имеют точно представимые тестовые значения. Сырые значения нативного
потребителя также должны совпасть с опубликованными значениями шлюза. Оба клиента
проверяют нулевые временные поля, последовательность, наносекундный остаток и коды бирж.
Шлюз должен завершить ожидающие публикации, освободить обоих клиентов и успешно завершиться.
Этот прогон проверяет локальный сценарий. Прогон с живым Kraken выполняется отдельно.

Соберите шлюз по [руководству](../../../tools/kraken/README.ru.md).
Подставьте установленные префиксы Feed SDK и Beast SDK, квалифицированный префикс
OpenSSL и classpath собранной закреплённой Java QD в [команды запуска](README.md).
На Windows используйте PowerShell с настроенным окружением x64 MSVC 19.42.
Профиль сборки использует Ninja, `Release` и `MultiThreadedDLL` (динамический CRT).
На Linux используйте Ninja и GCC 13 в профиле `Debug` с ASan/UBSan и флагами
компиляции и линковки из английской версии. Настройки запуска санитайзеров также
приведены там. Требуется JDK 21 или новее. Разделитель classpath на Windows — `;`.
Шлюз работает 12 секунд, каждое ожидание стенда ограничено 15 секундами.
Стенд инициализирует JVM перед запуском шлюза. Под WSL используйте classpath на файловой
системе Linux.
Потребуется новый каталог `LOGS`. Супервизор завершает собственные процессы и сохраняет
их stdout и stderr. Успех отмечается строкой `PASS`, ошибки проверки и таймаут дают
ненулевой код.

Для отдельного конечного потребителя достаточно собрать Feed-клиент с
`-DORG_TTLDTOR_QDCXX_KRAKEN_TEST_PEER=OFF` и передать ему адрес шлюза и
интервал наблюдения. Формат строк и команда приведены в [английской версии](README.md).
