# Проверки текста событий

[English version](EVENT-TEXT-VALIDATION.md). Английская версия является основной.

Статус: квалификация UTC/fixed и именованных контекстов для всех пяти поддерживаемых типов событий. Итоговые проверки пакетов прошли; независимое ревью API/контекстов/времени жизни ещё ожидается. Отчёт не означает выпуск.

В целевых проверках ошибки не обнаружены. [Provenance](../fixtures/event-text/provenance.json) связывает текущие Java sources/classes, harness/launcher и captures. [Установленный consumer](event_text_consumer/CMakeLists.txt) отдельно компилирует каждый установленный заголовок проекта до заголовков ОС и проверяет UTF-8 пример и long-текст Summary. ## Интеграция общего провайдера именованных зон

Фактический Java-корпус содержит 182957 наблюдений: прежние 181661 и ещё 1296 строгих наблюдений для восьми именованных зон. Отдельные запуски Java 8 и Java 25 для этих профилей побайтно совпали. MSVC 14.42 Release /MD прошёл шесть целевых проверок; GCC 13.3 Debug ASan/UBSan с LSan — пять применимых. Тесты сравнивают полный UTF-16 событий и граничные моменты после уничтожения исходного дескриптора данных и строк ID, затем параллельно используют копии и перемещения контекстов. Принятое числовое ядро и заголовок double formatter не изменены.

Целевой процесс Summary на GCC сначала достиг прежнего лимита 30 секунд при холодном запуске backend; после применения того же лимита 120 секунд, что у основного oracle-теста, он прошёл за 44,26 секунды. Установленный именованный consumer использует этот же лимит. Это ограничения отдельных проверок, не синхронного публичного API.

Проба с настоящими макросами min/max Windows SDK воспроизвела ошибку шести вызовов numeric_limits в serial_field_type.hpp. Скобки только вокруг этих имён исправили ту же единицу трансляции. event_text.hpp также скомпилировался после Windows.h с активными min/max, без NOMINMAX. Публичный заголовок макросы не подавляет.

Первичная генерация документации прошла: 710 связанных страниц и 2664 ресурса. Среди 35 существующих предупреждений повторяющихся якорей нет диагностик EventText/ADR-0011.

| Фактический Java-эталон | Capture, затем Verify прошли для итогового корпуса 182957 строк, 14 явных профилей и трёх локалей; различий fixture нет |

Фактические кеши производителя проверены на backend/feed ON/ON и OFF/OFF. В графе выключенного backend нет исходников date-провайдера; UTC/fixed-контексты и типизированная ошибка недоступной именованной зоны работают. Именованные consumers инициализируют только явный установленный/перемещённый каталог данных. Поиск зоны хоста не используется.

Проверка всех заголовков устанавливает их самостоятельность до заголовков ОС. Она не доказывает совместимость каждого необязательного Client-заголовка с Windows-first: существующее имя ProgressKind::CALLBACK конфликтует с макросом CALLBACK из Windows SDK. В этой задаче нет переименования Client API или подавления макросов. Итоговое независимое ревью отделено от авторских проверок.
