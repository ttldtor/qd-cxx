# Авторская валидация реализации RAW/MESSAGE

[English version](VALIDATION.md). Английская версия является основной.

Исходный HEAD: `c1654f2dbb5163917b848d1b84b17dfb9d0999fc`.
Проверки ниже выполнены 2026-09-22 UTC. В перечисленных успешных проверках ошибок не обнаружено.
Это авторские проверки, отдельно от независимого ревью.
Реализация готова к независимому ревью; независимая приёмка не заявлена.

## Доказательства до реализации

[Валидация](../../../fixtures/protocol/raw-tape/VALIDATION.ru.md) закреплённого Java содержит два
чистых захвата, 94 сценария / 284 точных артефакта, десять отклонённых мутаций, полный отрицательный
Verify и последующий Verify неизменённой базы. Шесть сценариев используют настоящий producer path
FileWriter или DXEndpoint/TapeConnector/FileWriterHandler; остальные входы явно помечены
diagnostic-wire. [Контракт](../../../../spec/protocol/RAW-TAPE.ru.md) установлен до C++.
Последующая проверка повторно сравнила все 284 артефакта
чистого захвата B с ожиданиями репозитория. Это не ещё одна чистая сборка upstream.

## CLI, отрицательные проверки и исправление по ревью

359 запусков CLI до/после сравнили точные байты stdout, stderr
и коды выхода с дорефакторинговыми исполняемыми файлами, собранными из исходного checkout. Tape-входы
охватывают прежние quote/tape fixtures с обоими локальными профилями, TSV/human и версиями диагностики;
также включены QTP help/no-argument/invalid-argument и неверный профиль tape.
Tape help намеренно исключён из побайтового сравнения до/после, поскольку описывает новый параметр.
Текущее равенство no-argument/standalone-help проверяется CTest. Исполненный
скрипт сравнения также проверяет пропущенный и явный legacy в tape-запусках.
Существующие QTP CTest-наборы покрывают его успешные прежние входы.

Первоначальные 13 отклонённых CLI-мутаций и база прошли проверку.
Затем независимое ревью показало, что тестовый компаратор принимал перенос записи между двумя
кадрами с одинаковым timestamp. Production reader не изменён. Теперь компаратор требует заданное
генератором количество в одну запись на кадр для 29 выбранных CLI fixtures независимо от фактического
вывода, а CMake и PowerShell изменяют эту принадлежность кадру. Итоговый
запуск с 14 мутациями отклонил все мутации и принял обе неизменённые
базы Quote и timing. CMake теперь содержит восемь отклоняемых мутаций вывода.

После этого изменения только теста пересобран лишь затронутый компаратор. Затронутый CLI-набор
повторно прошёл во всех семи конфигурациях: MSVC Debug,
MSVC Release, ClangCL Debug,
ClangCL Release, GCC Debug,
GCC Release, ASan+UBSan.
Прежние запуски 20 наборов не переименованы в запуски после исправления.

Ранняя проверка CLI при разработке обнаружила преобразование переводов строк Windows в CMake
`file(WRITE)`. Теперь фактический вывод процесса захватывается через `OUTPUT_FILE`; мутации явно
используют UNIX newlines. Грамматика LF для CLI остаётся строгой; только CRLF захваченных Java
артефактов интерпретируется как переводы строк producer.

## Инвентаризация, сохранность и передача

Сгенерированный self-test инвентаризации прошёл, включая
каждый префикс кадра, неизвестные envelopes/типы, поздние descriptions, malformed/truncated framing/descriptions
и исчерпанные бюджеты. [REAL-TAPE-GAPS](../../../../docs/REAL-TAPE-GAPS.ru.md) содержит отдельное частное
наблюдение: структурно перечислены 1 280 envelopes, 48 descriptions и 349 fields. Дополнительные
полные типы 10/40/72/88 и Profile остаются неподдерживаемыми. Ограниченный replay закреплённого Java
остановился на бюджете доставки 1 000 000 записей; счётчик — 1 000 001 с первой отклонённой лишней
попыткой. Он не завершился и не установил ошибку совместимости.
Байты частного tape, символы, значения событий, хеши и сырые захваты replay остаются только локально
в игнорируемом `.work`.

Закреплённые Java Format и затем Check охватили 15 sources; итоговый Java Check прошёл.
Закреплённые Uncrustify 0.83.0, затем clang-format 20.1.8 Format и
Check охватили 51 C++ файл; исправление ревью отформатировано и
итоговый полный Check прошёл. Проверка сохранности
подтвердила все 1 594 дотасковых fixture/lock-файла по исходным хешам.
Итоговые проверки документации/ссылок/пробелов и списка файлов сохранены в аудите передачи.

Проверки упрощения reuse/quality не нашли полезных изменений. Предложение эффективности перенести
проверку неверного режима перед ограниченным построением схемы рассмотрено, но не принято: этот
путь ошибочной конфигурации не оправдывает отдельный helper и изменение приоритета исключений.
 Отклонений от границ задачи и новых семантических
догадок нет. Остальные типы, флаги, сжатие, сессии, адаптеры, планирование replay и транспорт
исключены. Полная поддержка частного tape не заявлена.
