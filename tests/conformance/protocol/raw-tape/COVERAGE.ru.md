# Покрытие ограниченной реализации RAW/MESSAGE

[English version](COVERAGE.md). Английская версия является основной.

Это карта реализации QDCXX-023, а не заявление об общей поддержке tape.
[RAW-TAPE](../../../../spec/protocol/RAW-TAPE.ru.md) задаёт измеренную политику и вывод;
[покрытие Java](../../../fixtures/protocol/raw-tape/COVERAGE.ru.md) отделяет production tapes от
diagnostic-wire проб. Схема default composite Quote не изменена. Размножение RAW на callbacks
10/15/20 в Java сравнивается через callback 15 как проекцию одной wire-записи без
переписывания ID входных сообщений и потери replay/sequence timing.

## Требования и исполняемые доказательства

| Требования | Покрытие |
| --- | --- |
| R1, R2 | 94 Java-сценария / 284 артефакта; шесть producer-сценариев и отдельно помеченные diagnostic-wire входы. C++ сравнивает неизменённые production tapes S/R/E и default Quote; только точные типы 2/8/56/120. Матрица дескрипторов различает отсутствующий, пустой, null, hs и неизвестный opt; время и send-list проверяются до приёмки данных. |
| R3 | Отсутствующий timestamp и явный ноль; пустой envelope и heartbeat с отсутствующим/нулевым content; повторяющееся/убывающее время, heartbeat на EOF, время через descriptions и data, упаковка/насыщение на границах int64, точный sequence и отображённое event time отдельно от бизнес-времени Quote. |
| R4, R6 | Локальный профиль и режим tape независимы. Оба профиля, режима, формата и версии диагностики; строгий TSV-парсер версии 3, точные побайтовые сравнения и коды старого режима, равенство default/explicit legacy, регрессии QTP, проверки help/аргументов/отсутствия входного IO. |
| R5 | Независимость от разбиения, владение значениями после уничтожения входа/reader, отсутствие состояния между readers, терминальные ошибки, точные позиции примитивов, атомарная публикация heartbeat/descriptions, завершённые префиксы, пропуск неизвестных records/fields только с известной шириной, конечные нулевые/точные/превышенные бюджеты metadata/data/перестроения/вывода. |
| R7 | Сгенерированные ограниченные self-tests инвентаризации и только агрегатный частный отчёт в [REAL-TAPE-GAPS](../../../../docs/REAL-TAPE-GAPS.ru.md); неподдерживаемые data непрозрачны, malformed framing/descriptions останавливают перечисление без ресинхронизации. |

## Наборы C++

- [raw_tape_tests.cpp](../../raw_tape_tests.cpp): десять doctest-сценариев сравнивают все выбранные
  значения записей Java, порядок полей, символы, флаги, проецируемое время callbacks и отображение
  default Quote. Проверяются целые, побайтовые и смешанные входные порции, точные границы, неуспешные
  append-only descriptions, сброс символов, время жизни reader и счётчики бюджетов. Намеренные
  мутации полей/времени/порядка обязаны провалить семантическое сравнение.
- [raw_tape_io_tests.cpp](../../raw_tape_io_tests.cpp): три doctest-сценария проверяют оба профиля,
  TSV/human, версии диагностики, временные строки, насыщенные/отсутствующие/нулевые metadata,
  точные/недостаточные/нулевые бюджеты вывода, внедрённые ошибки read/write/flush и отклонение
  неверного режима до файлового IO.
- [raw_tape_cli.cmake](../../raw_tape_cli.cmake) с
  [raw_tape_cli_tests.cpp](../../raw_tape_cli_tests.cpp): 29 принимаемых Java-сценариев проходят
  строгий полный разбор TSV и упорядоченное сравнение значений/времени/envelope. Процессные проверки
  порций, профилей, режимов, аргументов, missing/empty/malformed/unsupported файлов и лимитов вывода
  дополняют IO-тесты. Отдельный [negative runner](Test-Negatives.ps1) отклоняет 14 мутаций и принимает
  неизменённые базы; CMake-набор также внедряет восемь некорректных вариантов вывода. Эти 29 выбранных
  fixtures содержат ровно одну запись в каждом RAW-кадре по построению `RawTapeOracle.production/connector/focused`.
  Компаратор требует это ограничение независимо от фактического вывода и отклоняет перенос записи
  между кадрами с одинаковым временем. Reader с несколькими записями проверяется отдельно в его наборе.

Production targets остаются независимыми от doctest, файлового IO и представления. Существующий
type-15 `decodeStreamData` сохраняет контракт; явный type-5 `decodeRawData` разделяет измеренную
реализацию payload. Фиксированное владеющее состояние времени ограничено отдельно от накопленного
`timingEvents`, списывающего каждую попытку явного heartbeat или RAW data message, даже если
позднее примитив завершится ошибкой. Нулевой лимит по умолчанию значим; инструмент задаёт конечный лимит.

## Ограничения и передача

Более широкая приёмка Java для options дескриптора/расширений heartbeat сохранена как доказательство
и не расширяет политику C++. Ненулевые event flags, другие полные типы, отображение Profile, сжатие,
FIELD/NONE timing в новом режиме, замена сессии, транспорт и планирование replay исключены.
Полная структурная инвентаризация частного файла не является полным семантическим replay; его Java
replay остановился на бюджете доставки, а типы 10/40/72/88 остаются неподдерживаемыми в C++.

[проверка](VALIDATION.ru.md) содержит выполненные конфигурации, числа, команды и ограничения.
Независимая приёмка завершена в этих границах; её новые проверки отделены
от изменённых прогонов и не доказывают общей совместимости tape.
