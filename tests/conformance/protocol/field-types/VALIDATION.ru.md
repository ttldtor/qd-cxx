`task/qdcxx-024-field-types`. Все даты ниже и сохранённые логи — UTC, 2026-09-22.
Начальные наблюдения закреплённой Java и [FIELD-TYPES](../../../../spec/encoding/FIELD-TYPES.ru.md)

## Выполненная матрица компиляторов и production

Оба необязательных инспектора включены во всех семи тестовых конфигурациях; выполняются все 25
CTest-наборов, включая 20 неизменённых и пять новых для типов полей. MSVC 19.42.34444 и ClangCL 19.1.5
используют Visual Studio 17 2022, x64, Windows SDK 10.0.26100.0. GCC 13.3.0 запускается в Ubuntu-24.04 WSL.
CMake — 4.4.2; закреплённый doctest 2.4.12 берётся из существующих проверенных кешей.

Санитайзеры используют `-fsanitize=address,undefined -fno-omit-frame-pointer -fno-pie` и linker `-no-pie`;
PIE executables с санитайзерами и другие ОС/архитектуры не проверялись. Последняя правка только
уточнила исключение версии 4 в tape help; все шесть CLI-наборов повторены в шести обычных
конфигурациях компиляторов. Сборка с санитайзерами включает этот финальный help. Соседние
`*-build.log`, `*-configure.log` и `*-final-cli-test.log` сохраняют точные команды и результаты.

Все четыре GCC Release комбинации `BUILD_TESTING=OFF` для QTP/tape инспекторов прошли configure/build;
ни в одной нет каталога `_deps` или записей Python/doctest в кеше. Их
`prod-<QTP>-<TAPE>-configure.log` и build logs содержат фактические команды. Новые production-зависимости
и Python scripts не добавлялись. Существующие Python launchers/process regression tests неизменны.

## Oracle, стиль и отрицательные проверки

[Авторская проверка Java](../../../fixtures/encoding/field-types/VALIDATION.ru.md) фиксирует два чистых
upstream captures с побайтовым совпадением всех 82 артефактов, 17 отклонённых мутаций, полный
отрицательный Verify и последующий неизменённый baseline Verify. Java Format, затем Check охватили
16 исходников закреплённым formatter на OpenJDK 23.0.2; oracle исполнялся на Zulu JDK 8. Главный автор
повторно сверил текущие хеши всех четырёх oracle tools и 82 артефактов с финальными Verify metadata:
provenance audit. После этого oracle source не менялся.

C++ Format, затем Check прошли для 57 файлов: Uncrustify 0.83.0, затем clang-format 20.1.8:
Format, Check. Первая проверка
форматирования потребовала ещё одного прохода pipeline для пустой строки в test helper;
финальная проверка чистая. Имена, Doxygen, владение, арифметика бюджетов и границы задачи также
проверены вручную.

Пять новых наборов охватывают шесть сценариев значений, десять tape-сценариев, семь I/O-сценариев,
двенадцать мутаций primitive reader и двенадцать мутаций полного вывода. После каждого отрицательного
набора проверяется неизменённый baseline. CLI comparator независимо определяет ожидаемую группировку
по исходным envelopes и Java STREAM callbacks, включая записи в разных кадрах с одинаковым временем.
Ранние отказы comparator при разработке относились к ожиданиям descriptor и callback batching;
ожидания исправлены по исходным доказательствам до успешной матрицы, без изменения fixtures.

Red-проверки до реализации продемонстрировали отсутствие char-array API, отклонение новой схемы
и CLI-профиля. Начальный smoke-прогон старых 20 наборов использовал существующую MSVC Release сборку;
он не считается заново собранным baseline. Доказательство регрессий — полная финальная матрица.
Настройка сборки потребовала выхода из Windows sandbox для обнаружения SDK; первоначально неверный
аргумент пути и последующая проблема аргументов WSL inline shell исправлены в командах запуска,
а не в production-поведении.

Все 1982 прежних fixture/lock файла сохранили SHA-256:
исходные хеши, audit.
Исторические captures, upstream.lock и expectations не переписывались. Частный tape не читался.
Новые доказательства сгенерированы офлайн; live endpoint не требовался.

## Итоговые границы и передача

Список изменённых файлов, включая новые, — [changed-files.txt](changed-files.txt).
Source manifest определяет проверенные исходники реализации/тестов;
completion audit фиксирует ссылки, whitespace и пустой staged diff.
Исходные доказательства сохранены как получены, без trimming ради правил Markdown whitespace.
Staging, коммит, push, PR и работа над следующей задачей не выполнялись.

Реализация добавляет точную поддержку полей и фиксированный диагностический профиль без полного
Profile adapter. Отклонений от границ и блокирующих семантических вопросов в этой ограниченной задаче
нет. Обработка отказов выделения памяти проверена чтением кода, без внедрения отказов; generated
evidence не доказывает совместимость произвольной схемы или полного частного файла. В перечисленных
успешных проверках ошибок не обнаружено; это не утверждение об отсутствии всех семантических ошибок.

`ce-compound` рассмотрен и пропущен: неочевидное различие primitive/message и начисление временного
владения уже сохранены в нормативном EN/RU-контракте и coverage. Дублирующее learning не добавило бы
долговечных сведений. Независимое ревью остаётся отдельным этапом.
