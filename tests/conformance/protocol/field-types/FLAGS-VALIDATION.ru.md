# Проверка флагов событий и времени удаления

[English version](FLAGS-VALIDATION.md). Английская версия является основной.

Отчёт квалифицирует явную политику событий STREAM/NONE из
[STREAM-DATA](../../../../spec/protocol/STREAM-DATA.ru.md#catalog-event-metadata), BINARY_CATALOG_V1
с переданной схемой и маски опций символов0/1. Прежние режимы и трёхаргументные функции payload
RAW/STREAM принимают только нулевые флаги. Семантика collector, время FIELD, другие семейства,
файлы без заголовка и новый формат вывода не входят в это изменение.

## Проверки C++ и намеренные различия

`protocol_event_flags` проверяет все 64 подмножества, неизвестные биты до ID/времени/выходной
работы, проекцию физических старших битов, различие нуля и отсутствия времени удаления,
произвольные логические позиции пары/одного 64, null defaults строк/байтов, неиндексные/неизвестные/
нулевые по числу полей записи, sentinel, состояние сообщений, неверные префиксы и точные позиции
усечения со владеющим префиксом. Проверяются нулевые/меньшие/точные/превышенные бюджеты
payload/записей/значений/выхода, пределы около size_t, нулевой wireFields при локальных defaults
и ошибки выделения до первого успеха. Владеющие значения и provenance переживают уничтожение
контекста/reader и поколения равных описаний.

Нативное сравнение читает реальные файлы composer и все шесть записей FileWriter, сопоставляет
каждое исходное STREAM-значение с Java, объединяя физические long-слоты в логические 64,
и отдельно потребляет исходные файлы через TapeReader. Сохранены полная неизменённая схема
TimeAndSale и её фактические lookup-метаданные.

Сохраняются прежние проверки символов/stream/индексных сессий и общего/Profile formatter.
Старые форматы отклоняют ненулевые флаги и любой заданный removalTime, включая0, до построения
строки даже при выходном бюджете0. Число байтов явного нулевого префикса сохраняет прежний вывод.
Числовые metadata SymbolValue по умолчанию нулевые, порядок агрегата сохранён. Реальное
автоматическое преобразование tape-write отклоняет removalTime; исходный view/API writer
не меняется, BINARY_FIELDS_V1 остаётся только для чтения на границах writer/admission.

Явная функция политики отдельно названа `decodeStreamDataWithEventPolicy`; исходные
decodeStreamData/decodeRawData остаются без перегрузок. Полная Windows-сборка выявила
неоднозначность старого использования адреса функции при первоначально предложенной
перегрузке. Новое имя исправляет совместимость исходников без изменения прежних вызовов;
неиспользуемый API политики RAW не добавлен. Конечные авторские focused-проверки MSVC 14.42
Release прошли 8/8 в 17:13:44UTC, включая неизменённый event_mapping_contract.
Uncrustify0.83.0 затем clang-format20.1.8 прошли Format и Check; контракты заголовков описывают
приоритет политики, владение, defaults и ошибки.

C++ намеренно сохраняет владеющий завершённый префикс при усечённом удалении; наблюдаемый буфер
текущего сообщения Java отбрасывается. Допустимые в Java неизвестные опции/биты остаются выбранными
отказами UNSUPPORTED. Это ограниченная совместимость wire-значений без collector, recovery и
идентичности доставки ошибок.

исправленных исходниках, отдельно скопированных Windows/Linux бинарных файлах и реальных
текущих производственных файлах. Дополнительные проверки покрыли все 49 сочетаний типов пары

захватов/повторов/публичных эталонов и реальных classpath; Java повторно не выполнялась,
