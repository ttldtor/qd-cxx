# Владеющие байтовые, строковые и объектные поля: проверка

[English version](OBJECT-VALIDATION.md). Английская версия нормативная.

Выполнено 2026-10-30 UTC для явно выбранного обычного расширения BINARY_FIELDS_V1
типами 9/137/233/249, доступного только для чтения.
[Контракт полей](../../../../spec/encoding/FIELD-TYPES.ru.md) задаёт точные значения,
независимые от отображения грамматики и логические ограничения ресурсов.
[Манифест захватов](../../../fixtures/encoding/field-types/object-captures.json)
содержит итоговые хеши исходников оракула, среды исполнения и состава classpath,
а также хеш каждого исходного захвата обеих закреплённых ревизий.
Частный tape и исполнение объектов Java не используются.

## Выполненные наблюдения производственных путей

QD3.355 `0ddc0a09779fb61d74cc0b37c6449ff47dcb715f` и QD3.356
`f71e4cb390d1586f2d4e3a83d9b9067e3326ef19` произвели по 49 исходных артефактов:
48 файлов захватов компоновщика с явно заданными типами и FileWriter и одну таблицу
из 803 строк (801 наблюдение и две строки обрамления). Два захвата каждой ревизии
на итоговых исходниках с заранее собранным classpath точно совпали с проверенными
ожидаемыми результатами. Закреплённая базовая ревизия также прошла настоящий полный
регламентированный Verify с чистой сборкой всего реактора, включая неизменённые
82 корневых и 25 скалярных артефактов и 49 новых объектных артефактов. Захваты текущей
ревизии используют её ранее квалифицированные закреплённые классы; это не второй
Verify с чистой сборкой всего реактора. Среда исполнения — Zulu8u422, куча 128MiB,
тайм-аут 30s; JDK форматтера — отдельный OpenJDK23.0.2.

| Поверхность | Наблюдений на ревизию | Значение |
| --- | --- | --- |
| BinaryQTPComposer с явно заданными типами |24 | Четыре точных wire ID, null/empty/content, STREAM и RAW |
| FileWriter/FileReader |24 | Фактические локальные типы 9/137/249; запрошенный 233 использует локальный 9 |
| BinaryQTPParser |324 | Обработчики известных и неизвестных полей, оба семейства данных |
| Дополнительные привязки парсера |186 | Неизвестные записи и повторяющиеся цели |
| Производственный FieldReader поверх BufferedInputPart |162 | Точные значения полей и контрольных маркеров, ошибки и исследование байтов |
| Вспомогательные ограниченные примитивы |81 | Результат примитива и позиция отдельно от наблюдения сообщения |

Три обратных вызова RAW порождены одной записью в wire-потоке. Только захваты
компоновщика с явно заданными типами доказывают wire233; его FileWriter использует
фактическую идентичность 9 класса ByteArrayField. Наблюдения MarshalledObjField
вызывают только getBytes. Известный 249 проецирует compact INT; неизвестные объекты
Java вместо этого используют массивы байтов с длиной LONG. Известный 137 проверяет
UTF, а пропуск неизвестных объектов Java — нет. Универсальный C++ намеренно применяет
точную грамматику INT для 249 и проверку UTF для 137 даже при пропуске. Эти различия
проверены и не скрыты за утверждением о совместимости с локальными преобразованиями
Java или со всем DataScheme.

Захваты покрывают null/empty/неинтерпретируемые байты, байты известной сериализованной
строки и произвольные неизвестные теги, содержимое длиной 4096 байтов, отрицательные
длины, длины с ненулевыми старшими 32 битами, избыточные и усечённые кодировки длин,
конечные префиксы тела, BMP, дополнительные символы, CESU, непарные суррогаты и
избыточные кодировки UTF, недопустимые продолжения и диапазоны, разрыв последовательности
объявленной байтовой длиной и фактическое отсутствие продолжения. Повреждённый разрыв
может вызвать исследование следующих байтов до ошибки; учёт позиции отражает реальное
исследование. Явные курсоры с временными метками делают RAW-файлы детерминированными
без нормализации. Строки наблюдений используют явный LF без BOM, сохраняя хеши исходных
захватов при действующей текстовой политике fixtures. Достаточность ограниченного
резерва кодовых единиц UTF доказана на арифметических границах INT32_MAX и SIZE_MAX
перед добавлением одной или двух единиц; для демонстрации границы не выделяется
многогигабайтная память.

Регламентированный компаратор проверяет конечные наборы файлов, строк, канонических
проекций и все байты. Все 28 намеренных мутаций отклонены, затем неизменённый базовый
набор дал PASS. Пять новых мутаций проверяют null/empty, байты полезной нагрузки,
исследование UTF, завершение и фактическую локальную идентичность. Исторические
протоколы захватов не меняются.

## Выполненные исходные проверки C++

На зафиксированных исходниках прошли целевая сборка Windows MSVC19.42 Release и
четыре проверки CTest: `field_type_java_values`, `field_type_java_tape`,
`object_field_owned_values` и `field_type_inspection_io`. Это исходные проверки,
а не независимое ревью.

Тесты читают каталоги обеих закреплённых ревизий через настоящие контейнеры FileWriter
и кадры компоновщика с явно заданными типами, используя размеры порций 1/7/65536.
Универсальные канонические значения, контрольные маркеры и исследование байтов
обработчиками известных полей совпадают с производственными наблюдениями.
Пути неизвестных полей и записей и повторяющихся целей проверяют неизменные точные
грамматики. Дополнительные случаи покрывают прежний смысл агрегатов и профили,
недопустимые вручную смешанные полезные нагрузки, значения по умолчанию, глубокое
владение после разрушения источника, контекста, схемы и reader, равенство RAW/STREAM,
границы работы и хранения zero/L-1/L/L+1, работу при пропусках и заменах без возврата
бюджета, смешанный учёт единиц 10/137, пики old+temporary/completed+current+temporary,
внедрённый отказ выделения памяти и сохранение завершённого префикса, терминальный
учёт нескольких кадров и ранний отказ OutgoingLayouts для режима только чтения.
Универсальный форматтер версий 4/6/7 отвергает все новые идентичности полезной
нагрузки, включая null/empty; полезная нагрузка не теряется молча.

Закреплённый Uncrustify0.83.0, затем clang-format20.1.8 прошли Format/Check для
13 изменённых файлов C++. Общие Java Format/Check прошли для 31 файла;
производственные проверки итоговых исходников выполнены после форматирования.
Doxygen завершился с нулевым числом байтов предупреждений. На итоговых исходниках
Windows x64 MSVC 19.42 Release и Linux x64 GCC 13.3 Debug ASan/UBSan прошли все
54 проверки CTest каждый. Обнаружение утечек было отключено; квалификация
LeakSanitizer не заявляется. На обеих платформах прошли производственные профили
BUILD_TESTING=OFF для минимальных библиотек, инструментов/replay с JSON OFF и
инструментов/replay с JSON ON. Wire CLI с JSON OFF прошёл проверку; получения
тестового фреймворка в производственных профилях и необязательных зависимостей
при JSON OFF не было. JSON ON использовал явно переданные существующие исходники
simdjson.

Независимое критическое ревью обнаружило превышение резерва кодовых единиц STRING,
проверило исправление с проверкой перед добавлением и доказательства для
INT32_MAX/SIZE_MAX без выделения памяти; скопированные тесты значений, tape,
владения и форматтера на Windows прошли. Его финальная повторная проверка LF
подтвердила захваты, хеши исходников и скопированные тесты tape и форматтера.
Финальные Java Format/Check прошли для 31 файла без дальнейших изменений исходников;
запуск Doxygen на итоговых заголовках дал ноль байтов предупреждений при включённом
EXTRACT_ALL, что само по себе не доказывает полноту документации членов.

## Ограничения

Эти наблюдения квалифицируют конечную обычную универсальную проекцию полей.
Прежние профили и грамматики контейнеров сохраняют точность; допуск исходящих
данных и поддержка их производства через replay не расширены. Индексные схемы,
замена описаний, более широкие флаги, семейства и политики контейнеров, грамматика
вывода, адаптеры событий, семантика объектов Java, транспорт и полная совместимость
частного tape остаются вне изменения. Логические ограничения исключают ёмкость
и служебные данные аллокатора и RSS. Равенство исходников или целостность сохранённых
артефактов не является независимо повторённым наблюдением времени исполнения.
