# Дополнительные типы полей: покрытие conformance

[English version](COVERAGE.md). Английская версия является основной.

[Контракт FIELD-TYPES](../../../../spec/encoding/FIELD-TYPES.ru.md) задаёт точное явно выбираемое
объединение типов, владеющие значения, границы primitive/message и правила начисления работы.
Авторские тесты непосредственно читают [неизменённые Java expectations](../../../fixtures/encoding/field-types/expected).
[Java coverage](../../../fixtures/encoding/field-types/COVERAGE.ru.md) различает исходную доставку
production FileWriter/FileReader, пробы production parser и прямые примитивы. Диагностический обход
не используется как доказательство доставки событий. Выполненные конфигурации и ограничения — в [VALIDATION](VALIDATION.ru.md).

| Требование | Исполняемые доказательства |
| --- | --- |
| R1 точная политика/binding | `field_type_java_values` проверяет все идентификаторы -1..256 для обоих прежних профилей и нового объединения; `field_type_java_tape` проверяет точные mismatches и неизвестные поддерживаемые поля/записи. |
| R2 nullable владеющий UTF-16 | Тесты значений читают все 9 writer, 219 reader и 324 integer наблюдения; точно сравниваются null, empty, суррогаты, неканонические кодировки, префиксы, статусы и потребление. Прямые результаты переживают уничтожение input/context. |
| R3 исходные значения и типы скаляров | Signed low-int32 проекция 40/72/88, включая более широкие compact-long формы, сохраняет полные теги. Некорректные вручную созданные значения и новые теги отклоняются в каждой позиции Quote. |
| R4 production-доставка | Исходные mixed и неизменённые полные Profile tapes проходят STREAM и RAW при подаче целиком, побайтово и смешанными блоками. Все 16 логических полей Profile сохранены несмотря на физические Java VOID tails. Ещё 27 успешных диагностических tapes проверяют defaults, повторы, пропуски, широкие значения и выравнивание следующего sentinel. |
| R5 ограниченная работа/владение | Нулевые, точные и недостаточные лимиты байтов/единиц; повреждённые допущенные строки; пропущенные/повторные/неудачные попытки; одновременное хранение старой и новой строки; накопленные tape-бюджеты; счётчики работы отдельно от сохранённых значений. |
| R6 атомарные префиксы и вывод | Повреждённая строка третьей записи сохраняет две завершённые записи с точными смещениями/счётчиками. Отклонённое добавленное описание сохраняет прежний контекст. Проверяются терминальные feed/finish, разделение timing, изоляция readers, каждый выходной байтовый порог, short writes, исключения I/O и оба отказа flush. |
| R7 просмотр только полей | Фиксированная диагностическая схема, явная версия 4, независимая Java STREAM-проекция, отдельные поле SEQUENCE и heartbeat eventTimeSequence; без отображения бизнес-события Profile. |
| R8 регрессии | При обоих инспекторах включены все 20 прежних CTest-наборов и пять новых. Проверяются прежние профили/форматы и exit behavior; расширяется только документированный tape help. |

`field_type_inspection_cli` сравнивает полный TSV и human stdout обоих режимов с независимо
построенными ожиданиями. Исходные Java-строки полей и tape envelopes задают идентичность, порядок,
принадлежность кадрам и timing; группировка никогда не берётся из фактического вывода инспектора.
Три одиночные wire-записи занимают три исходных data frame, включая RAW-кадры с одинаковым временем.
Java callback batching/fanout проверяется отдельно; wire-записи представляет только STREAM-проекция.
Comparator проверяет все байты descriptor/frame/record/timing/marker/completion, а не только значения.

Двенадцать CLI-мутаций охватывают изменённые units, null/empty, tag, raw, пропуск поля/записи,
дублированную/неизвестную строку, число колонок, раннее/повторное completion и перенос между кадрами
с одинаковым временем. Двенадцать мутаций primitive fixtures охватывают bytes, units, nullability,
raw, tag, consumption, неизвестные строки, колонки, дубликаты, пропуск и completion. Каждая мутация
обязана реально изменить вход и вызвать отказ сравнения; затем проверяется неизменённый baseline.
Отдельные Java negatives охватывают 17 мутаций и полный отрицательный, затем baseline Verify.

Семь I/O-сценариев проверяют оба формата и режима. Предварительная проверка целой строки не позволяет
ресурсному отказу записать её часть; физический отказ I/O может оставить префикс. Финальный flush
может отказать после записи completion, поэтому обязателен exit 0. Тесты escaping включают controls,
суррогатные пары и одиночные суррогаты. Преобразование отказов выделения памяти реализовано и
проверено чтением кода; внедрение отказов allocator не выполнялось.

Java может восстановиться на следующем кадре или преобразовать несовпадающие поля; ограниченная
C++-политика намеренно отклоняет mismatches и становится терминальной. Эти случаи проверяют
документированный отказ, не приравнивая Java recovery к C++ acceptance. Не покрыты дополнительные
serial identities, индексированные схемы, compression, flags, transport, полное отображение Profile
и частный tape, который не читался. Стандартные события-свидетели SHORT_STRING/SEQUENCE остаются вне
измеренного покрытия реальных схем; их точные доказательства полей синтетические.
