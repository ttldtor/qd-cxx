## Изменения и обоснование

- `SerialType` именует три реализованных базовых типа; `FieldRepresentation` — реализованные
  селекторы представления. Селекторы являются альтернативами, а не независимыми флагами.
- `SerialFieldType` сохраняет имена, базовый тип int32 и значения 2/8/10/40/56/72/88/120;
  определения теперь составлены из именованных компонентов. Входные raw ID остаются int32.
- Маски и функции извлечения сохраняют неизвестные старшие биты. Составление ID не проверяет
  допустимость пары. Проверка точного ID в `supportsSerialType` остаётся нормативной для схемы
  и binding; switch перечисляет каждый полный тип один раз без повторяющихся приведений/сравнений.
- Диагностическая схема tape использует общий enum полных типов вместо собственного списка чисел.
  Независимые числовые ожидания сохранены в conformance-тестах для обнаружения случайного изменения ID.
- Декодер/структура значений, владение, бюджеты, форматы вывода, Java-инструменты и эталоны неизменны.

Основание: [FIELD-TYPES](../../../../spec/encoding/FIELD-TYPES.ru.md), включая закреплённые Java-маски
и определения компонентов. Новых гипотез о Java-семантике или захватов нет.

## Исправление P2 — 2026-09-23 (UTC)

Независимое ревью `a3d9c20db589a5730703f3a2c55bfb14a06961e5` относительно указанного выше baseline
выявило один пробел тестов P2: проверки полных ID и декомпозиции числовых входов не закрепляли
значения enum представлений напрямую. Это дополнение добавляет шесть прямых проверок underlying-значений
в [field_type_value_tests.cpp](../../field_type_value_tests.cpp): PLAIN=0x00, SHORT_STRING=0x20,
TIME_SECONDS=0x30, SEQUENCE=0x40, DATE=0x50 и WIDE_DECIMAL=0x70. Ожидания — независимые литералы,
не вычисленные через production-константы, маски или составление ID. Прежние проверки полных ID,
декомпозиции и профилей сохранены. Production-код, Java tooling и fixtures неизменны.

### Новые выполненные проверки исправления

Это проверки автора исправления, отдельно от исторических проверок рефакторинга ниже и от
предшествующего независимого ревью. Повторное независимое ревью этого исправления не проводилось.

- Закреплённые Format, затем Check прошли для изменённого C++ теста (Uncrustify 0.83.0, затем
  clang-format 20.1.8).
- Инкрементальная сборка MSVC Release, целевой `field_type_java_values` (1/1) и полная регрессия
  CTest (25/25) прошли; оба инспектора включены.
- Инкрементальная сборка GCC Debug ASan+UBSan в WSL, тот же целевой тест (1/1) и полная регрессия
  CTest (25/25) прошли; оба инспектора включены.
- Mutation test использовал отдельную копию `git archive` коммита `a3d9c20` с обновлённым тестом
  и отдельную сборку GCC 13.3.0 Debug/Ninja без санитайзеров. Повторно использованы имеющиеся исходники
  закреплённого doctest. Целевой тест неизменённой копии прошёл. Затем только в скопированном заголовке
  `SHORT_STRING = 0x20` заменён на `0x28`. Отдельная проверка при компиляции по-прежнему подтверждала
  полный `SerialFieldType::SHORT_STRING == 40`. Цель успешно собралась и упала ровно на новой проверке
  селектора: `CHECK(40 == 32)`, при 15 845 успешных assertions и одном неуспешном.
- Восстановление скопированного заголовка сначала сохранило его старую дату, поэтому Ninja использовал
  мутированный бинарник и первый повтор снова упал. `--clean-first` пересобрал изолированную цель,
  восстановленный тест прошёл (1/1), завершив pass–fail–pass. Общий рабочий заголовок не подвергался
  мутации; его SHA-256 остался `9B3880E92121DD048B201AB34B33A5707D16E9A6A22AE8A921BC444D2C01ACF7`.
- Итоговая самопроверка diff, относительных файловых ссылок и концевых пробелов прошла для изменённых
  файлов, включая EN/RU пару отчёта; индекс остался неизменным.

Локальные доказательства находятся в `.work/field-representation-p2-20260923T130039Z/logs/` (игнорируются,
не включены в коммит): `msvc-{build,target,regression}.log`, `gcc-{build,target,regression}.log`,

Логи используют UTC. Изолированный configure выдал только существующее предупреждение об устаревшей

P2 исправлено и локально проверено, повторное независимое ревью не выполнено. Полная матрица платформ,
production-only сборка, повторный захват Java и инъекция отказа аллокатора не запускались; частный tape

## Историческая проверка автора

До реализации существующий MSVC Release `field_type_java_values` прошёл. После добавления нового
теста, но до production-изменений, сборка этой цели завершилась ошибками отсутствующих объявлений
`SerialType`, `FieldRepresentation` и функций. После реализации тест прошёл.

Новые проверки независимо проверяют все восемь полных ID и их компоненты, все 256 однобайтовых ID,
неизвестные старшие биты, знаковые границы, неподдерживаемые пары компонентов и constexpr-вычисление.
Существующие исчерпывающие проверки профилей (от -1 до 256), значений и Java fixtures сохранены.

Инкрементальная пересборка MSVC Release и все 25 наборов CTest прошли, включая отрицательные проверки
fixtures и прежние CLI-проверки tape/QTP. Три изменённых C++ файла прошли закреплённый Format pipeline.
Инкрементальная пересборка GCC Debug ASan+UBSan и все 25 наборов также прошли в WSL.
Production-сборка GCC Release (`BUILD_TESTING=OFF`, оба инспектора ON) успешно пересобрана.
Первая попытка использовать этот Linux-каталог из Windows CMake завершилась ошибкой пути
Linux-генератора в кэше; правильный запуск через WSL затем прошёл. Кэш ради обхода ошибки не переписывался.
Format с последующим неизменяющим Check прошли для всех трёх изменённых C++ файлов.

Три проверки упрощения без изменений файлов (повторное использование, качество, эффективность)
не нашли необходимых изменений в diff заголовка/теста. Автор также проверил замену enum в инструменте
и итоговый diff. Независимое ревью этого дополнения было недоступно. Независимая приёмка не заявляется.

Повторены только эти две тестовые конфигурации и одна production-конфигурация, не исходная матрица
семь/четыре. Java captures не перезапускались: Java, wire-семантика и ожидания неизменны. Инъекция отказа
аллокатора, дополнительные платформы и проверка частного tape не заявляются.
Нового Python-кода и зависимостей нет; существующие CLI-тесты использовали прежние Python-скрипты.
