## Сначала Java

[Java-проверка](../../../fixtures/events/mapping/VALIDATION.ru.md) фиксирует 21 изолированный JVM-сценарий,
две чистые сборки/captures с 135 побайтно одинаковыми артефактами, 14 отклонённых мутаций, полный
отрицательный Verify и последующий положительный Verify. Production delegates/FileWriter/FileReader,
прямые граничные пробы и наблюдения разрешения источников отмечены отдельно. Контракты предшествовали production C++.
Full24/full137 сохранены как отрицательные случаи; совместимый XML использует явный full10 без ослабления
неизменённых default/dxlink случаев. Блокеров приёмки, требующих расширить разрешённую область, не возникло.

Основной автор проверил текущие hashes шести oracle tools и всех 135 expectations по metadata последнего
положительного Verify: аудит provenance. Финальные Java Format
и Check прошли для 17 исходников закреплённым google-java-format 1.36.1 на JDK 25.0.1; прежний oracle
formatter использовал JDK 23.0.2, исполнение oracle — JDK 8. Format,
Check. Форматирование не изменило ни один хешируемый Java-исходник.

## Бюджеты, вывод и сохранность

Подробный лог наборов фиксирует точные числа. Два configured oracle теста
выполнили 68 335 assertions по прямым наблюдениям и обоим chunk schedules.
Общий helper содержит 10 случаев/135 assertions, Profile — 6/137, Quote — 9/54 245, включая исторические
файлы. Profile IO содержит четыре случая/266 assertions после проверки совместимости агрегата. Строгие
configured-fixture проверки отклоняют 13 мутаций; CLI сравнивает шесть полных выводов и отклоняет 84
мутации. Примеры вывода сохраняют оба режима/формата и wire omission.
Ошибка первого flush и ошибка финального flush после completion — разные тесты; один текст completion
не подтверждает успех. Бюджет output отклоняет полную пару raw/event до её первой записи.

Аудит прежнего вывода сравнивает stdout/stderr/exit bytes 18 вызовов с
заново собранной базой до реализации и прогоном 25 наборов. Оба снимка сохранены в
`evidence/legacy-before/` и `evidence/legacy-after/`. Все прежние CLI-наборы также входят в финальную матрицу.
Исторический аудит проверяет 2188 исходных fixture/lock файлов по
начальным hashes; все идентичны. Частный tape не читался.

Закреплённые Uncrustify 0.83.0, затем clang-format 20.1.8 Format/Check прошли для всех 66 обнаруженных C++ файлов;
новый test helper header форматировался и проверялся отдельно. Format,
Check. Вручную также проверены имена, Doxygen, точные identities, владение,
порядок ошибок, конечная арифметика, прежнее поведение и границы изменённых файлов.

Проверки разработки выявили ошибки построения тестов до финальной верификации: лишний diagnostic symbol
byte, неизменяющую числовую мутацию, ожидаемое число omitted-wire полей и невалидную отрицательную схему.
Тесты исправлены по исходным доказательствам. Самопроверка усилила проверку final flush и добавила защиту
формы полей formatter. Исполнение Windows SDK/Python потребовало sandbox elevation; ошибочные параметры
запуска исправлены. Ни одна из неудачных попыток не учитывается как PASS.

## Границы передачи

Реализация U1–U5 завершена в назначенном подмножестве. Новые API владеют привязанными к схеме выборами
и точными значениями событий; новая схема не может молча повторно использовать старый контекст. Копии
и перестроения неизменяемых wire snapshots сохраняют исходный local context. Generic extra/custom values доступны.
Загрузка источников, полная совместимость настроек, полный dxlink, дополнительные identities, indexed/regional
events, wire coercion, сжатие, ненулевые QTP flags, transport и replay scheduling остаются отдельными работами.
Независимое ревью открыто;

Нетривиальные выводы о моменте чтения конфигурации, различиях absent/default и владении контекстом уже
сохранены в двуязычных нормативных контрактах.
Аудит документов охватывает whitespace изменённого/untracked авторского
Markdown, взаимные языковые ссылки и локальные relative targets. Raw evidence не нормализовались.
Source hashes определяют проверенные исходники.
