# Покрытие conformance офлайн-инспекции

[English version](COVERAGE.md). Английская версия является нормативной.

[Контракт](../../../../spec/protocol/OFFLINE-INSPECTION.ru.md),
[CLI](../../../../docs/QTP-INSPECT.ru.md), [результаты](VALIDATION.ru.md),
[доказательства Java](../../../fixtures/protocol/offline-inspection/COVERAGE.ru.md).

Process-level [checker](../../check_offline_inspection.py) сравнивает точные stdout, stderr
и exit status с [72 спроектированными случаями](../../../fixtures/protocol/offline-inspection/designed.json).
Каждый случай использует побайтовое, разделённое и полное/больше файла чтение размерами
1,2,3,7,16,4096 и размер-файла+1 (без повторов). Для 116-байтового production-composed потока
дополнительно используются все размеры 1..117 и 4096; вывод побайтно одинаков, семь локальных
записей совпадают с независимыми Java callback observations. Проверяется разбиение чтений файла,
не callback batching и не timing.

| Поверхность | Выполненное покрытие |
| --- | --- |
| Интеграция | Несколько начальных description/data кадров; heartbeat до/между/после; message-local символы; remapped ID; target/skip/duplicate targets; недостающие поля; неизвестные локальные и zero-field записи. |
| Пустой вход | Пустой файл, только описания, только heartbeat, пустое описание и пустой data; содержательное покрытие из этого не выводится. |
| Первая ошибка | Data до описаний; повторные/пустые описания после data; повторные ID внутри/между кадрами; явный ноль/unknown/PART/ticker; non-8 поля, включая неизвестные имена; ненулевые flags; неописанные ID; усечённые payload/конечный кадр/префикс; завершённый префикс до ошибки; последующий кадр не обрабатывается. |
| Смещения | Неканонические length/type при успехе и усечении; точные границы кадров, разные consumed/error позиции и вычисленные абсолютные позиции. |
| Ресурсы | Точные/нулевые/превышенные input, frame, число кадров, общие description/action/name, record/field/value/symbol/output бюджеты; минимумы per-message; пропуски/повторные цели списываются между сообщениями. |
| Запуск | Отсутствующие/повторные/неизвестные аргументы, неверные/отрицательные/переполненные числа, несовместимые пределы хранения, help, отсутствующий файл, каталог как нечитаемый файл и реальный закрытый stdout pipe. |
| Переносимые инъекции | Ошибка чтения до входа и при точном нулевом входном лимите; ошибка чтения после завершённого вывода; отказ write; ранний отказ flush; отказ flush completion; неисправный stderr; output stream с включёнными исключениями. |
| Независимая схема | Интеграция вызывается с отдельно валидированной локальной S без полей вместо встроенного адаптера, сохраняя потребление wire S.v. |

[offline_io_tests.cpp](../../offline_io_tests.cpp) задаёт детерминированные ошибки streambuf
отдельно от тестов реального executable subprocess. Физические частичные записи нельзя откатить;
неуспешный финальный flush даёт ненулевой exit, даже если complete дошла до приёмника.
Частичная декодированная запись намеренно не выдаётся. Тесты бюджетов записей в
[stream_data_tests.cpp](../../stream_data_tests.cpp) проверяют списанные попытки, пропуски,
повторные цели, ошибки примитивов, точные/исчерпанные лимиты и неизменность прежних результатов/позиций.
Дополнительная инъекция ошибки чтения после нового частичного заголовка длины проверяет, что
индекс/начало нового кадра заменяют предыдущий выданный кадр в диагностике.
Сохранение счётчиков при ошибке аллокации проверено по общим путям возврата в исходнике;
инъекция отказа allocator не заявляется.

Валидатор отклоняет неизвестные строки, неверное число ячеек, numeric/hex syntax, порядок,
пустую выборку, отсутствующую/повторную completion и семантические несовпадения.
[Negative checker](../../check_offline_negative.py) отклоняет 17 временных мутаций значений,
символов, ID, имён, смещений, типов/числа ячеек строк, синтаксиса, completion, выборки и Java
observations; затем проходит неизменённый baseline. [Proof](negative-proof.json). Ожидания неизменны.

Все шесть прежних suites остаются регрессионными проверками во всех семи тестовых профилях.
Не покрываются полный протокол, importer/transport/dynamic-session, ненулевые flags, огромные
аллокации, точный RSS, 32-bit платформа, performance или универсальный Java exception/callback parity.
Это авторские проверки; независимое ревью ещё требуется.
