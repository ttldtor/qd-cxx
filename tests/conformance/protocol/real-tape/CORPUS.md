# Real-tape corpus qualification

[Русская версия](CORPUS.ru.md). English is authoritative.

The [portable manifest](../../../fixtures/protocol/real-tape/corpus.tsv) references existing,
unchanged generated bytes by SHA-256. Paths resolve from the repository root. `mixed-raw`
contains supported full field types; `unsupported-identities` retains full types 24/137 as
explicit unsupported C++ witnesses. These are field/profile evidence, not real-market recordings.
Their production provenance remains in the [field corpus](../../../fixtures/encoding/field-types/CAPTURES.md)
and [writer corpus](../../../fixtures/protocol/tape-write/CAPTURES.md).

Run [Check-Inventory.ps1](../../../../tools/upstream/raw-tape-oracle/Check-Inventory.ps1) with
`-UpstreamRoot $lockedUpstream -JavaHome $oracleJdk -WorkDir $privateWorkDir`.
The launcher checks every manifest hash and runs the structural inventory for each input.
It also runs generated assertions for opaque unknown kind 117, unsupported full type 255,
late descriptions, every truncated frame/description prefix, malformed headers and finite limits.
Unknown types remain inventory observations; a complete structural walk never accepts a payload.

For the owner-controlled sample, add `-PrivateFile $privateTape -ReplayDeliveryLimit 10000000`
and optionally `-Inspector $tapeInspector`. Only ignored output under repository `.work` is allowed.
The sample is opened read-only and hashed before/after. Its bytes, paths, symbols and detailed logs
must not enter this manifest or public captures. An unavailable sample is an explicit local gap;
portable checks still run without it.

Production replay uses unchanged locked FileReader/DXFeedScheme, automatic format/time/compression,
MAX_SPEED, one literal filename, no cycle/resync, 128 MiB heap and 30 seconds per process by default.
The delivery limit counts callback fanout. `replay-observed` counts attempted deliveries, including
the first rejected one; `accepted-deliveries` excludes it. STREAM_DATA is a one-wire-record
projection for this RAW sample, not a count of distinct business events.

`returned-byte-match` requires normal return, zero corruption callbacks and processed bytes equal
the physical file size. Review stderr as well: FileReader can log and swallow I/O errors. Compressed,
paired and sequence inputs are not qualified by this predicate. C++ observations use the named
`oracle-field-types-v1`/`default-quote-v1`/`default-profile-v1` local profiles and `raw-message-v1` mode, with unchanged finite defaults;
a failure identifies that profile's first stage, not compatibility with every caller-supplied schema.

See [aggregate results and ranked gaps](../../../../docs/REAL-TAPE-GAPS.md). Whole-file C++/Java
value/order equality remains a separate milestone; inventory counts and Java return do not prove it.

The manifest also pins unsupported-message (C++ exit 4, type stage) and truncated-heartbeat (exit 5, heartbeat stage). With Inspector supplied, all declared C++ exits are checked. The unsupported-identities input returns 4 at binding/TYPE even with an unmapped record; its full types are not accepted.

`returned-byte-match` is a neutral observation, not source/container classification or a complete
semantic decode claim. Compressed output length can equal physical input size: generated checks
replay 4,096 zero marker bytes both plain and as a small gzip padded to 4,096 bytes. Production
FileReader returns with zero corruption callbacks and 4,096 processed bytes for both. The launcher
requires the same neutral token for both, so byte equality never establishes an uncompressed source.

Manifest fields cpp_stage/cpp_reason pin negative diagnostics (- means unspecified); cpp_emitted/cpp_processed pin positive completion counts. The mixed positive requires 3 mapped and 3 processed records. Failures must have one matching diagnostic and no completion.
