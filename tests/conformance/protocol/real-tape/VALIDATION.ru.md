## Профили и источники истины для сравнения

`BINARY_CATALOG_V1` сохраняет 19 документированных конечных full field ID,
поколения wire-схемы, sender/local ID, порядок записей, владеющие символы и
payload, flags и removal metadata. См.
[проверку полей](../field-types/VALIDATION.ru.md) и
[проверку dispatch](../field-types/DISPATCH-VALIDATION.ru.md).

`SELF_CONTAINED_SEGMENTS_V1` владеет конечным явным списком вхождений, закрывает
каждый открытый источник и проверяет завершение parser, sidecar и container до
единственного итогового результата. Однородная политика времени задана явно:
NONE, MESSAGE, FIELD, LONG или TEXT. Через API контейнеры могут различаться;
CLI выбирает один вид контейнера данных и один вид контейнера companion на весь
запуск. См. [контракт последовательности](../../../../spec/protocol/TAPE-SEQUENCE.ru.md).

Профиль сопровождаемого компаратора полного файла намеренно уже: один несжатый
источник MESSAGE, ordinary-схемы, точные типы 2/8/10/40/56/72/88/120, нулевые
flags, отсутствие FIELD/removal metadata. Проверяются все 27 ячеек output9,
identity источника, полный список ресурсов, source-end и итоговые суммы.
Более широкие семейства времени и значений отвергаются явно. Остальные ячейки
каталога подтверждаются именованными production fixtures и native-проверками;
ordinary-корпус не является доказательством для этих ячеек.

Истина для сырого timestamp MESSAGE — фактический production heartbeat callback.
Packed time читается из Java `RecordCursor`; event milliseconds вычисляются
production-проекцией `TimeSequenceUtil`. Эффективное время в узком профиле
выбирает внешний cursor либо ноль при нулевом packed time. Это отдельные
наблюдения и вычисленные проекции. Отдельный digest времени с числом записей
не позволяет заменить новую проверку времени прежним digest схемы/значений.
Фактический Java protocol descriptor обязан объявить точное `message` или
`MESSAGE` до первой попытки чтения записи; принудительная настройка FileReader
сама по себе этого не доказывает.

Инструментированный поток наблюдает физический EOF, открытия/закрытия и ошибки
I/O. Второй проход настоящего FileReader с буквальным именем файла обязан дать
ту же полную проекцию. Физический EOF и счётчики закрытия этого второго прохода
отдельно не инструментируются. Corruption callbacks должны быть нулевыми;
числа mapped wire-записей и STREAM-проекций должны совпасть без пропуска значений.

Используйте [Compare-RealTapes.ps1](Compare-RealTapes.ps1) с
`-SourceProfile self-contained-segments-v1 -TapeMode raw-message-v1` и явным
`-OracleProfile baseline` либо `current`. Значение baseline по умолчанию сохраняет
прежнюю проверку lock. Нужны заранее собранные чистые source classes, JDK 8,
конечные ограничения heap/времени/вывода дочерних процессов и неизменность
hash входа, исходников и classpath. Upstream не собирается и не изменяется.
Весь исходный вывод, зависящий от данных, остаётся приватным.

Native source checks воспроизводятся в настроенном дереве сборки:

```powershell
ctest --test-dir $buildDirectory --output-on-failure `
  -R '^(protocol_field_time|sidecar_.*|compressed_input|source_format|tape_sequence_admission|source_sequence_.*)$'
```

Полные наборы выше дополнительно включают все прежние тесты. Проверка источника
с тремя миллионами записей отличает логические resource charges от RSS процесса;
это проверка конечного потокового чтения, не benchmark пропускной способности.
Маркер результата предварителен до flush и успешного завершения процесса.

macOS, live follow/cycle, неявный поиск файлов, произвольные ZIP-архивы,
смешанные политики времени CLI, десериализация объектов и дополнительные
адаптеры событий остаются вне утверждения. Логические счётчики ресурсов не
измеряют RSS.
