## Выполненные проверки

Первичный чистый Capture создал кандидаты для обоих точных producer. Затем чистый Verify
окончательных исходников прошёл по документированной
[команде](../../../../../tools/upstream/real-tape-corpus/README.ru.md#требования-и-запуск):
baseline 3.355 с commit `0ddc0a09779fb61d74cc0b37c6449ff47dcb715f` и current 3.356 с commit
`f71e4cb390d1586f2d4e3a83d9b9067e3326ef19`. Свежий официальный `git ls-remote` подтвердил последний
HEAD и master; отдельная копия определила release tag `qd-qds-3.356`. Текущий
`Tools Help Connect` вернул exit 0 без подключения. Исходная locked-копия и `upstream.lock`
остались неизменными.

Размеры исходных QTP для обеих выбранных версий: 121 байт (`compact-none`), 258 (`quote-none`),
299 (`quote-message`), производный negative — 297 байт. Наблюдения используют канонический
UTF-8/LF. Каждый окончательный Verify использовал probe heap 128 MiB, timeout процесса 15 секунд,
Maven heap 512 MiB и timeout сборки 600 секунд. Положительных timeout не было. Это настройки
пределов, а не измерения пикового RSS. Для потоков runner проверяется лимит 8 MiB с документированным
превышением из-за интервала опроса.
Нативный runner владеет Windows job до старта Java; deadline включает завершение root, drain
потоков и завершение payload. Принудительное завершение runner закрывает job, с ожиданием
подтверждения не более пяти секунд. UTC-логи объединяют декодированные stdout/stderr Java; это
не отдельные сырые потоки Java. Тесты справки используют отдельное перенаправление дочерних
потоков прямо в файлы.

Одного Capture недостаточно для продвижения эталонов. Переносимые артефакты скопированы
неизменными, затем повторно сгенерированы свежим Verify с окончательными хешами исходников
Java/launcher. Полные логи и metadata окончательных исходников сохранены отдельно от
исследовательских попыток сборки.

## Ограничения и ревью

В этих именованных положительных проверках ошибки не обнаружены. Отрицательные parser errors
и timeout — намеренные наблюдения. Проверки используют production FileWriter/FileReader и
полную генерацию стандартного Quote, а не диагностический decoder. Class-файлы сообщают
`QDS-UNKNOWN`; provenance устанавливают commit identity и хеши контролируемой сборки.

Production-код C++ и регистрации CTest в этой единице не менялись; применимая регрессионная
проверка — Java/PowerShell workflow. Рабочие режимы Windows явно требуют существующий нативный
UTC runner и отклоняют неподдерживаемую платформу до работы с путями/исходниками/файлами.
Справка переносима. Нативные интеграционные результаты Windows/Linux относятся к отдельным
отчётам. Запуск этого workflow в Linux/macOS, POSIX-очистка потомков, произвольное декодирование tape,
равенство значений/порядка C++, business conversion parity, контейнеры, sidecars и split sources
не подтверждены. Необязательное получение live demo не реализовано и не запускалось. Полные
логи и приватные записи не публикуются. Произвольные Unicode-пути установки JDK/Maven/исходников
не квалифицированы. Родительский общий corpus inventory и исторические
доказательства не меняются.

Это исходные проверки. Независимое ревью — отдельное условие; данный отчёт его не подтверждает.

## Чтение фикстур нативными инструментами

2026-10-30 нативные инспекторы Windows Release и Linux Release при JSON OFF
полностью прочитали четыре compact/Quote NONE фикстуры двух закреплённых
producer: по три mapped/processed записи в каждой. Полный вывод версии 7
побайтно совпал между платформами. Это подтверждает данные переносимые входы;
PowerShell launcher producer остаётся квалифицированным только на Windows,
а приёмка MESSAGE и более широкого набора семейств сообщений остаётся отдельным
ожидающим выполнения контрактом.

Итоговые Format, затем Check всех 30 Java-файлов репозитория прошли с закреплённым
форматтером и JDK 23.0.2; байты исходников Java не изменились.
