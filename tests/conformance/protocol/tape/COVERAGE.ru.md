# Покрытие conformance tape reader

[English version](COVERAGE.md). Английская версия является основной.

[Контракт reader](../../../../spec/protocol/TAPE-READER.ru.md), [контракт CLI](../../../../docs/TAPE-INSPECT.ru.md),
[Java-доказательства](../../../fixtures/protocol/tape-reader/COVERAGE.ru.md). Это проектные ожидания C++,
не совпадение жизненного цикла/позиций Java. Семь reader-кейсов выполняют 18 061 утверждение в итоговом
прямом MSVC Debug-запуске. Два IO-кейса проверяют внедрённые ошибки и безопасное представление;
процессные проверки выполняет CMake. Десять прежних наборов включены во все полные профили матрицы.

| Область | Выполненное покрытие |
| --- | --- |
| Исходная tape | Точные семь локальных ID, символов и значений в локальном порядке из неизменённой constrained.qtp, поздние ID, Unicode/крайние числа, записи без полей; все разбиения на две порции и целиком/1/2/3/7/17 байт |
| Java-входы / политика C++ | Все 51 исходный вход целиком/1/5/13 байт; явные ожидаемые категории, одинаковые завершённые префиксы и позиции frame/accepted/payload consumed/error во всех расписаниях |
| Дескриптор | Обязательные/отсутствующие/пустые/null и неизвестные/повторные свойства, диагностическая version, ограничения opt/time/send/receive, отрицательные счётчики, magic, хвостовое расширение и усечение полного сообщения |
| Неизменяемое состояние | Ошибки синтаксиса и повторного ID в кандидате сохраняют адрес прежнего контекста и содержимое планов; новый ID не появляется; последующие feed принимают ноль |
| Жизненный цикл данных | Работа пропуска неизвестной записи, E без полей, сброс repeat между сообщениями, усечённая текущая запись после одной завершённой, терминальная ошибка и собственные результаты после уничтожения reader |
| EOF/маркеры | Пустой/только заголовок/без заголовка/без footer, отклонение explicit-zero, данные после маркера (девять записей), усечённые байты после маркера; идемпотентный finish |
| Позиции | Неканонические двухбайтовые длина/тип с фактическим началом payload 4/концом 60; независимые утверждения для повреждённого пустого заголовка/счётчика и усечённого файла; остальные расписания сравнивают точные позиции |
| Ресурсные границы | Ноль/точно/на единицу меньше для входа, body, frames, описаний, actions, отдельного/общего имени, построения, обработанных/выданных записей, wire-полей, значений, собственных/отдельных/state единиц символов, свойств/элементов/байтов/единиц/общего текста дескриптора, data payload/остаточного symbol span; переполнение конфигурации frame |
| Повторное использование | Прежние schema/binding/primitive/symbol/data-наборы сохраняют независимые проверки бюджетов схемы, ширины/переполнения чисел, повторных целей/пропущенных полей, неподдерживаемых типов/флагов и владения |
| Вывод/IO | TSV по умолчанию и явный human, одинаковый вывод при разных порциях, экранирование controls/bidi/одиночного surrogate в version, предварительный бюджет строки, точный/недостаточный бюджет, внедрённые ошибки read/write/flush, /dev/full в Linux |
| Процессный контракт | Без аргументов равно отдельному help; отсутствующие/повторные/неизвестные/переполненные/отрицательные аргументы, нулевая порция, отсутствующий файл; исходный constrained успешен, default/TEXT явно отклонены, исходный truncated завершается ошибкой |
| Целостность эталонов | Отдельная строгая PowerShell-валидация строк/точное сравнение отклоняют десять мутаций, включая пустое покрытие; полный отрицательный и базовый чистый Java Verify |

Нет заявлений об инъекции аллокатора, экстремальной памяти, производительности, других архитектурах,
default Quote, default RAW_DATA TapeConnector, сжатии/временных sidecar, транспорте, импортере и общих
sessions. Позиции примитивов — политика C++; отбрасывание Java callback-batch/продолжение не копируются.
Успешный EOF не подтверждает полноту записи. [Выполненная валидация и логи](VALIDATION.ru.md).
