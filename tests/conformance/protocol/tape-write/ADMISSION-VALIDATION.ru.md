# Валидация допуска и офлайн-перезаписи QDCXX-034

[English version](ADMISSION-VALIDATION.md). Английская версия является нормативной.

## Реализованная граница

`qdcxx_protocol` предоставляет `admitTape` и move-only `AdmittedTape` в
`qd/protocol/tape_admission.hpp`. Допуск копирует полную последовательность байтов вызывающей стороны
в пределах конечного лимита входа, проверяет её новым reader `RAW_MESSAGE_V1` до явного завершения,
валидирует каждое описание, включая неиспользуемые записи, и строит полный точный исходящий inventory.
Token возвращается только после успешного завершения всех проверок. Он владеет точными исходными
байтами, descriptor, проверенными schema/layouts и limits; moved-from token становится неактивным.
Ошибочный результат reader не допускает даже завершённый префикс записей, декодированная история
не сохраняется.

`AdmissionLimits` раздельно задаёт limits reader, limits layout, дополнительную невозвратную работу,
одновременные логические scratch bytes и единицы UTF-16. Ledger допуска учитывает копии сохраняемых
schema records, fields и lookups, а также хранилище источника, описаний, binding и candidate-объектов.
Лимиты описывают логическое владение, а не metadata/capacity allocator и не точный предел heap.
Внутренние буферы кадров и pending reader остаются в отдельно ограничиваемой области `TapeLimits`.
Строгий допуск отклоняет неоднозначные или непредставимые descriptors и запрещает sender ID
`INT32_MAX`; перенумерации идентификаторов нет.

Необязательная CLI `qdcxx-tape-write` по умолчанию выключена и обрабатывает только полностью
допущенный источник. До чтения tape она загружает явно выбранный встроенный профиль или схему из
необязательного native JSON. Исходник читается до физического EOF и закрывается до допуска и до
создания временного файла вывода. Второй проход с новым reader объединяет исходные позиции envelopes
с ограниченными writer chunks. Публикация создаёт назначение только после проверенных записей,
завершения reader/writer, flush и close, используя временный файл в той же директории и create-only
публикацию через hard link. Существующие и появившиеся в гонке назначения отклоняются. Overwrite и
rename fallback отсутствуют.

## Выполненные записанные проверки

Архив исходных данных, результатов, Java observations и выбранных логов доступен в
архиве доказательств допуска; `snapshot.tsv` и `inventory.tsv`
фиксируют ревизии исходников и точные байты каждого файла архива.

Замороженная реализация допуска прошла Format и Check через Uncrustify 0.83.0, затем clang-format
20.1.8. Изолированная Windows MSVC 19.42 x64 Release-сборка целевого компонента прошла. Тест допуска
прошёл 6 cases / 1 388 assertions с генерацией вывода и 6 / 1 384 без неё. Сгенерированный B34 witness
содержит 128 записей и измеренный пиковый логический scratch допуска 9 479 единиц; проверены границы
0, 9 478, 9 479 и 9 480 единиц. Независимые ledger cases охватывают descriptor-only tape со schema,
содержащей 0, 1 и 3 fields, и точную формулу границы. Отдельные мутации, удалявшие учёт копий schema
fields или менявшие преобразование ошибки allocation reader, ожидаемо провалили assertions;
восстановленная реализация прошла.

записанные проверки CLI охватили production-сборки MSVC Release с включённым и выключенным JSON при
`BUILD_TESTING=OFF`; конфигурация без JSON не загружала simdjson. Регрессия CLI проверила все 38
параметров help/defaults и грамматику чисел, пять native corpus inputs, точные канонические перезаписи,
стандартные Quote/Profile, отказы конечных лимитов входа/выхода, существующие/совпадающие назначения,
Unicode paths и нормализацию overlong compact integer до 61 байта вывода. Ошибка Windows argument
bridge для входного файла с буквальным именем `--output` была воспроизведена, исправлена и повторно
проверена свежим native запуском. CLI и изменённые C++ файлы прошли необходимый pipeline форматирования.

Независимое целевое ревью Windows MSVC 19.42 x64 Release прошло сборку и 3/3 теста CTest:
admission 6 cases / 1 384 assertions, filesystem 12 / 437 и CLI-проверки help, всех 38 параметров,
отказов, Quote/Profile перезаписей и Unicode paths. Ревью независимо закрыло overlong sender и
регрессию входного пути `--output` после исправления CLI. Проверенные им хеши совпали с замороженными
итоговыми файлами. Это целевое ревью, не полная матрица проекта.

## Приёмка полного проекта

Итоговая Windows MSVC x64 Release-сборка прошла, полный CTest
прошёл **50/50** тестов за 285,37 секунды.
Также прошли отдельные Windows production-only Release-сборки с `BUILD_TESTING=OFF` и JSON OFF:
одна с tools OFF, другая с включёнными QTP inspection, tape inspection и tape-write. Проверки
фактических конфигураций и зависимостей
показали, что ни один профиль не получил дополнительных зависимостей.
Итоговая проверка C++ форматирования 97 файлов
прошла.

Закреплённый production Java FileReader принял пять итоговых CLI-перезаписей: 18 STREAM records,
54 callback projections, 152 rows и ноль ошибок parser. Точные входы, нормализованные результаты,
Java observations, provenance и исходные логи сравнения
находятся в архиве. Целевые Linux GCC ASan+UBSan file-boundary тесты прошли: 12 cases / 436 assertions.
Итоговый полный Linux Debug прогон
прошёл **50/50** под Ubuntu 24.04 / WSL2 с GCC 13.3, AddressSanitizer и
UndefinedBehaviorSanitizer. CTest указал 865,93 секунды; интервал команды в журнале —
2026-10-11T23:23:12.960Z–23:38:14.459Z. Оба Linux production-only Release-профиля собрались с JSON OFF: минимальный с tools OFF и с QTP inspection, tape inspection и tape-write ON. Итоговые проверки подтвердили отсутствие `_deps` в обоих профилях; см. архивные журналы Linux dependency gate и профиля с tools. В обеих сборках GCC выдал существующее предупреждение `-Wstringop-overflow` в `src/core/wide_decimal.cpp:68`; команды завершились успешно.
Независимое ревью не запускало Linux, JSON ON, Java oracle или полный набор проекта самостоятельно.

Doxygen завершился с кодом 0, создал страницу API допуска и пустой файл предупреждений. В настройках
включён `EXTRACT_ALL`, чтобы включить свободные функции; пустой файл и сгенерированный HTML не
подтверждают полноту всей API-документации. См. архивные
лог Doxygen и
файл предупреждений.

Не заявлены проверки macOS, Windows-пути с изолированным surrogate, замены родительской директории
враждебным процессом, публикации при враждебных конкурентных изменениях или сохранности после сбоя
питания/процесса. Логические scratch limits не включают overhead/capacity allocator, а измерение B34
не является универсальным ограничением heap.
