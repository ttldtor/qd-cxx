# Покрытие читаемого инспектора

[English version](COVERAGE.md). Английский документ является основным.

Это спроектированная политика представления, не новые доказательства Java wire.
[Designed manifest](../../../fixtures/protocol/human-inspection/designed.json) содержит 84 точных случая:
69 проекций исторических CLI-сценариев (три специфичных для TSV бюджета вывода заменены проверками
байтовых границ human) и 15 явных Unicode-входов. Восемь прежних suites и все исторические ожидания
неизменны. Два новых suites — `human_inspection_cli` и `human_inspection_injected_io`.

| Область | Выполненное покрытие |
| --- | --- |
| Представление | Заголовок/профиль, имена/ID/фактические offsets кадров, включая неканонические заголовки, локальный порядок S.v и R.y/R.x/R.z, пропуски/дубли/нулевые defaults, пустые символы, записи без полей, точный итог. |
| Unicode | ASCII, кириллица, supplementary scalars и границы ширины UTF-8, одиночные high/low и переставленные суррогаты, буквальные подобия escape, кавычки/обратные косые черты, все C0/DEL/C1, разделители строк/абзацев, все указанные bidi controls, разложенный и составной текст. Строгое декодирование UTF-8 и отсутствие сырых небезопасных controls. |
| Разбиение/ошибки | Размеры чтения 1/2/3/7/16/4096 и file-size+1; точные завершённые префиксы, unsupported/malformed/sequence/resource ошибки, прежний stderr, семь новых ошибок использования формата и help, реальный закрытый stdout pipe. |
| Регрессия TSV | Все 72 исторических designed CLI-сценария сравнены с исходными точными stdout/stderr/exit для default и explicit tsv при чтении 1/7/4096; также сравнен исходный Java-composed файл. Прежний CLI suite по-прежнему проверяет 624 запуска и семь Java-записей. |
| Учёт вывода | Точные байтовые лимиты и нехватка бюджета на каждом начале/конце строки для всех 25 успешных сценариев без дополнительных аргументов; без частичных логических строк. Различия расширения UTF-16 до четырёх/шести байт, стоимость заголовка/итога учтены. Большой экранируемый символ с малым бюджетом и максимальный бюджет size_t. |
| Интеграция утилиты | Независимая схема использует field[0]/field[1] вопреки порядку aliases; локальные имена экранируются так же; отсутствие полей отличается от пустого символа; специальная глобальная числовая локаль, максимальный счётчик uint64. |
| Инъекции I/O | Первая запись, flush до итога и финальный flush, с исключениями потоков и без них. Точный прежний stderr и ненулевой exit даже после доставки байтов итога. Это переносимые streambuf-тесты, отдельно от реального процесса с закрытым pipe. |
| Отрицательная верификация | Девять human-мутаций: метка, значение, escape, буквальное подобие escape, счётчик/удаление/дублирование итога, лишняя строка и offset кадра; неизменный baseline. Повторены прежние 17 мутаций/baseline без изменения старого proof. Ошибка форматирования отвергнута без перезаписи, baseline и идемпотентность двух этапов проходят. |

[Валидация](VALIDATION.ru.md) содержит команды, логи, измеренные лимиты и хеши. Генератор fixtures
требует новый каталог и никогда не вызывается CTest-верификацией. Точные сравнения читают сохранённые
designed expectations; верификация сравнивает хеши до/после и не утверждает C++-вывод как эталон.
Новый Java capture не требовался: используются прежние доказательства штатного composer/parser.
Не заявлены новые wire-семантики, инъекции allocation failure, огромные ресурсы/гарантия RSS, 32-bit,
tape/compression/time-file, protocol descriptors, importer, transport, динамические сессии,
конверсии, расширенные поля, timing или общая совместимость dxFeed.
