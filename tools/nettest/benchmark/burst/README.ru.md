# Синтетический корпус всплеска

[English version](README.md).

`Corpus.ps1` создаёт воспроизводимую нагрузку для одного предлагаемого
всплеска из синтетических сообщений. Профиль по умолчанию распределяет 625 000
сообщений за 100 мс и ограничивает полезную нагрузку UDP 1 472 байтами.
Расписание описывает целевую нагрузку независимо от фактического времени
отправки. Данные подготавливаются до измерений, сетевые операции не выполняются.

```powershell
pwsh -NoProfile -File tools/nettest/benchmark/burst/Corpus.ps1 -Mode Generate -Directory .work/burst-input
pwsh -NoProfile -File tools/nettest/benchmark/burst/Corpus.ps1 -Mode Validate -Directory .work/burst-input
```

`-Help` и `-HelpRu` описывают параметры, значения по умолчанию, ограничения,
коды выхода и работу с файлами. Generate требует новый каталог. Validate читает
параметры из манифеста, проверяет хеш и воспроизводит каждый заголовок, каждый
байт полезной нагрузки и каждое запланированное смещение. Ошибки генерации и
проверки завершают команду с ненулевым кодом.

`Measure-Clock.ps1 -Directory .work/burst-input -Output .work/burst-clock.json`
проверяет и загружает корпус до запуска таймера. Отчёт содержит число
датаграмм и сообщений внутри окна и всего, а также p99 и максимальное
опоздание в наносекундах. Планировщик активно ожидает и расходует CPU. Этот
замер охватывает локальные часы и планировщик, без передачи по сети или QTP.

## Бинарный формат

`manifest.json` содержит идентификатор `qdcxx-synthetic-burst-v1`, число
сообщений, окно в миллисекундах, ограничение полезной нагрузки, seed, цикл
размеров, расписание, число сообщений и датаграмм, суммы байтов, минимальный и
максимальный размеры нагрузки, размер файла и SHA-256 файла `corpus.bin`.

Все целые значения `corpus.bin` беззнаковые и записаны в little-endian.
Заголовок файла занимает 16 байт и содержит ASCII `QBURST01`, 32-битное число
сообщений и 32-битный предел полезной нагрузки UDP. Далее до конца файла идут
записи датаграмм. Каждая содержит восьмибайтное запланированное смещение в
наносекундах, четырёхбайтную длину нагрузки UDP, четырёхбайтное число сообщений
и указанное количество байтов нагрузки.

Каждая нагрузка начинается с ASCII `QDP1`, 32-битного номера датаграммы и
восьмибайтного номера её первого сообщения. Нумерация начинается с нуля.
Размеры сообщений циклически выбираются из 24, 40, 64 и 80 байт по формуле
`(ordinal + seed) % 4`. Сообщение начинается с двухбайтной полной длины и
восьмибайтного номера. Для остальных байтов начальное 32-битное беззнаковое
состояние равно `seed ^ ordinalLow32 ^ ordinalHigh32 ^ 0x9e3779b9`. Для каждого
байта последовательно выполняются `state ^= state << 13`, `state ^= state >> 17`
и `state ^= state << 5` с усечением до 32 бит после каждого обновления. Младший
байт состояния становится очередным байтом сообщения.

Сообщения последовательно упаковываются в датаграмму, пока следующее не
превысит предел нагрузки. Смещение датаграммы равно целой части произведения
номера первого сообщения на длительность окна в наносекундах, делённого на
общее число сообщений. Все сообщения этой датаграммы получают одно целевое
время отправки. Последняя датаграмма может быть короче. Корпус содержит один
всплеск. Программа воспроизведения может повторять его с отдельно заданным
периодом и должна показывать фактические времена отправки, опоздавшие и
неотправленные датаграммы.
