# Проверка TimeAndSale/STREAM на C++-приёмнике

[English version](NATIVE-VERIFIER.md).

Режим --verify-stream в Record NetTest проверяет одну подписку IBM с
физической схемой TimeAndSale по умолчанию. Сначала запустите источник.
На обеих машинах используйте один и тот же бандл схемы.

~~~powershell
# Машина источника. Укажите адрес её тестового интерфейса.
qdcxx-nettest p --bundle C:/path/to/default --address SOURCE_IPV4 --port 7301 --record TimeAndSale --contract stream --symbol IBM --instances 1 --duration 10 --rate 100000 --batch 32
# Машина потребителя. Укажите доступный адрес источника и больший таймаут.
qdcxx-nettest c --bundle C:/path/to/default --address SOURCE_IPV4 --port 7301 --record TimeAndSale --contract stream --symbol IBM --instances 1 --duration 30 --verify-stream
~~~

ACTIVE означает первую проверенную запись. Когда источник закроет
соединение штатно, приёмник напечатает RESULT и отдельное десятичное
CHECKSUM. При успешном прогоне оба процесса завершаются с кодом 0, written
источника совпадает с delivered потребителя, в журнале есть контрольная
сумма. Приёмник проверяет поля и последовательность во время чтения. Метки
времени исключены из контрольной суммы для сравнения повторов с одинаковым
доставленным префиксом. Совместимость отдельно сверяется с Java QD на том
же сценарии Record NetTest.

На двух свободных машинах зафиксируйте хеши сборок и схемы, ОС, процессоры,
скорости сетевых интерфейсов, маршрут и RTT TCP. Физический
[сетевой замер](windows/README.ru.md) выполните отдельно. Сохраните оба
вывода со счётчиками generated, composed, written, wireRecords и delivered,
CPU и память по процессам и счётчики NIC. Для оценки задержки между машинами
измерьте смещение и погрешность синхронизации часов. Таймаут CLI и окно
RESULT имеют другие определения, чем односторонняя задержка.

Приёмник отслеживает переход через 22-битную границу по полному порядковому
номеру записи. Предел прогона — 3 600 000 000 записей. В этом режиме клиент
не отправляет heartbeat. Источником служит синтетический Record NetTest.

## Замеры этапов источника

Флаг --profile-producer печатает отдельную строку PROFILE. generationNs,
composeNs и writeNs суммируют длительность генерации пакетов записей,
композиции кадров DATA и отдельных вызовов записи в сокет по монотонным
часам. Отчёт считает созданные пакеты, кадры, попытки записи, WOULD_BLOCK
и частичные записи. Вызовы измерителя времени могут влиять на темп при
малом пакете. Для абсолютной скорости повторите предложение с обычными
настройками и сравните отчёты точной доставки. Простой, служебный трафик
подписок и работа потребителя находятся за пределами этих сумм.
