# Бандл NetTest для Windows

[English version](README.md).

Бандл выполняет ограниченный синтетический прогон QTP и сохраняет результат
каждого потребителя Java QD 3.357. Запускайте его на Windows x64, когда другая
нагрузка на машину минимальна. В составе находятся среда Java 21, JAR-файлы QD,
оба нативных источника, необходимые библиотеки Microsoft C++ и схема Record.
В бандл можно включить PowerShell 7. Иначе установите PowerShell 7.2 или новее
и добавьте `pwsh.exe` в PATH.

Откройте PowerShell в распакованном каталоге и выполните:

```powershell
.\run.cmd -OutputDirectory .\results\run-1 -ProducerKind Event -Contract stream -Clients 4 -Rates 1000,10000,100000 -Duration 10
```

`run.cmd -Help` показывает параметры без запуска замера. Каждый прогон
содержит один источник и заданное число процессов Java. По умолчанию используется
IPv4 loopback. Режим Event поддерживает STREAM и TICKER. Режим Record сейчас
поддерживает одного потребителя STREAM. Размер пакета равен единице.
При расчёте общей скорости учитываются доставки каждому потребителю.

Скорость источника задаётся в записях в секунду. Скорость сетевого канала этот
параметр не настраивает. Предлагаемое число записей за прогон должно помещаться
в 22-битную последовательность. При высокой нагрузке источник может принять
меньше номинального числа записей. Сверяйте поля каждого источника и потребителя
вместе с общей скоростью доставки.

Каталог результатов должен быть новым. Он содержит `baseline.json` с нагрузкой
CPU перед прогонами, доступной памятью и скоростями адаптеров, папку каждого
прогона и `summary.csv`. В папке прогона сохраняются `result.json`, сырые
замеры процессов и потоков, `sampling.json`, `metrics.prom` и stdout/stderr. `-SampleIntervalMs 100` задаёт номинальный интервал опроса (10..10000 мс). JSON разделяет последнюю наблюдаемую живую память active, выборочные пики, пики ОС за время жизни и интервалы CPU наблюдаемых потоков. Имена необязательны, роли потоков не назначаются. Задержка, доставка, CPU и память каждого
потребителя представлены в `result.json`. STREAM сверяет каждую ожидаемую
запись у каждого клиента. TICKER сохраняет последнее значение ключа, поэтому
промежуточные обновления могут объединяться, а последнее значение проверяется.

Точность метки указывается в результатах. Записи Event передают наносекунды,
когда схема поддерживает это поле. Точность зависит от часов платформы и их
разрешения. Для замеров между машинами нужно отдельно проверить синхронизацию
часов.
Гистограмма задержек использует интервалы по 1 микросекунде от -10 до 100 мс
и по 1 миллисекунде за этими пределами. Вывод в наносекундах не означает,
что разрешение измерения составляет наносекунду.

Для определения пропускной способности Event укажите `-Pacing yield`.
В этом режиме ожидание следующей записи и повторные попытки уступают
процессор планировщику, поэтому источник может занять дополнительное ядро.
Для сопоставления с исходными замерами используйте режим `sleep`.
Число повторов зависит от того, как часто источник проверяет доступность очереди.

## Мониторинг

Опциональную панель можно запустить через Docker Compose из каталога бандла:

```powershell
docker compose -f .\dashboard\docker-compose.yml up -d
.\run.cmd -OutputDirectory .\results\with-metrics -ProducerKind Event -Contract stream -Clients 4 -Rates 1000,10000 -Duration 30 -PushgatewayUrl http://127.0.0.1:9091
```

Grafana доступна по адресу <http://127.0.0.1:3000>, панель называется
**qd-cxx NetTest**. Адрес Prometheus — <http://127.0.0.1:9090>. После каждого
прогона стенд публикует снимок показателей, Prometheus считывает его каждые
пять секунд. Подробные данные сохраняются в JSON и CSV. `metrics.prom` точно совпадает с публикуемым снимком; CPU gauge содержит приращения за интервал отсчётов, панель использует их напрямую. Интервалы потоков могут различаться, недоступные наблюдения обозначены NaN, а не нулём. Следующий прогон заменяет снимок job. Если закреплённые
образы отсутствуют, Docker скачает их. Остановка выполняется командой:

```powershell
docker compose -f .\dashboard\docker-compose.yml down
```

Данные Prometheus и Grafana после остановки остаются в именованных томах Docker.

## Физическая сеть

Loopback проверяет путь QTP на одной машине. Для измерения физической сети
используйте отдельно полученный `iperf3` на обеих машинах, запишите скорость
адаптеров и сохраните результаты с обеих сторон. Например:

```powershell
# Принимающая машина
iperf3.exe -s
# Передающая машина
.\link.cmd -Iperf C:\path\iperf3.exe -Server RECEIVER_ADDRESS -OutputDirectory .\results\link -TargetsMbps 100,1000,0 -Duration 30 -Adapter Ethernet
```

По умолчанию обёртка проверяет одно TCP-соединение. Положительный target задаёт
предлагаемую скорость в Мбит/с, а `0` запускает TCP без ограничения скорости
источника. Для UDP укажите `-Protocol udp` и положительные target. Параметр
`-Parallel` задаёт число потоков, target применяется к каждому. Необязательный
`-Adapter` сохраняет счётчики адаптера до и после прогона, маршрут выбирает ОС.
Убедитесь, что версия iperf3 поддерживает `-b` и записывает в JSON показатели
отправителя и получателя в `end.sum_sent` и `end.sum_received`. Для UDP также
нужны потери и джиттер получателя в `end.sum_received`. Управляемые ограничения ширины
канала и задержки требуют отдельного сетевого эмулятора или настройки shaping.
Сохраняйте его настройки вместе с результатами.

Прогон QTP и физический сетевой тест измеряют величины в разных единицах.
Синтетическая запись не является измеренным сообщением OPRA. Текущий источник
принимает не более 1 000 000 записей/с и менее 2^22 записей за прогон. В
уведомлении OPRA от апреля 2026 года для теста июля указаны 625 000 сообщений
за 100 мс на выходную линию, что соответствует 6,25 млн/с в этом интервале.
Текущие пределы источника не позволяют воспроизвести эту нагрузку одной линии.
[Уведомление OPRA](https://cdn.opraplan.com/documents/notices/OPRA_Capacity_Test%20Reminder_041126.pdf)

## Сборка бандла

Разработчик запускает `Create-Bundle.ps1 -Help` в репозитории и передаёт пути
к собранным программам, соответствующим схеме и provenance, JAR QD 3.357,
лицензии QD, распространяемым DLL Microsoft C++ и JDK 21. Утилита `jlink`
создаёт уменьшенный образ Java с `javac` для сборки включённого проверяющего
класса. Чтобы включить PowerShell 7, задайте `-PowerShellDirectory`.
Манифест содержит SHA-256 хеши входных файлов стенда. Каталог назначения
создаётся заново.
