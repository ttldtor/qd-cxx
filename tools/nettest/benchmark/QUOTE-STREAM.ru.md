# Стенд синтетических котировок Quote STREAM

[English version](QUOTE-STREAM.md). Английская версия является нормативной.

[Определения метрик](METRICS.ru.md) задают границы передачи и доставки, требования
к часам, округление гистограммы и измерение ресурсов процессов.

Соберите `qdcxx_quote_stream_nettest` с включённым публичным Feed API.
Инструмент публикует физические записи Quote через коллектор STREAM.
Параметры задают порт, число записей, предлагаемый темп в записях/с и размер
пакета (1–8). Нулевой темп позволяет публиковать по мере локального приёма.
Сначала запустите издателя.
Добавьте `--stream-bytes ЦЕЛЬ ПРЕДЕЛ` после четырёх параметров, чтобы
включить байтовые лимиты STREAM. ЦЕЛЬ задаёт порог закодированных полезных
данных, ПРЕДЕЛ — размер полного QTP-кадра в байтах. Без этого параметра
используется прежний профиль. ПАКЕТ генератора независим от обоих лимитов.
`--clients N` задаёт число получателей от 1 до 8. `--pending-records N`
задаёт число входных ячеек, а `--delivery-bytes N` — байтовое окно выдачи
для каждого получателя.

~~~sh
qdcxx-quote-stream-nettest 7300 250000 50000 8
javac -cp "$QD_CLASSPATH" -d classes tools/nettest/benchmark/StreamReceiver.java
java -cp "classes:$QD_CLASSPATH" StreamReceiver 127.0.0.1:7300 IBM quote-stream ns probe
~~~

Например, `qdcxx-quote-stream-nettest 7300 250000 50000 8
--stream-bytes 8000 65536` позволяет сравнить байтовый режим с теми же
вызовами генератора по восемь записей.

В Windows разделяйте элементы classpath точкой с запятой. Укажите classpath
QD 3.357. После `READY` издателя дождитесь `PROBE_RECEIVED` от каждого
получателя. Если кто-то ещё не подтвердил спрос, отправьте `PROBE` для
повтора. Отправьте одну команду `GO` для начала замера. После `RESULT`
запишите ожидаемое число записей с переводом строки в stdin каждого
получателя.
Другой издатель может дождаться `COUNT_REACHED N` и закрыть соединение.
Получатель проверит итоговое количество после закрытия, включая лишние
записи.

Синтетическая запись использует IBM, цену bid равную порядковому номеру с 1,
цену ask на единицу выше, биржи B и A, размер ask равный 2. Время bid и ask
содержит секунды по общей монотонной шкале. Размер bid хранит остаток
микросекунд плюс 1. Номер 0 зарезервирован для пробной записи. Для этого
формата нужны общие часы машины, например QPC у проверенных инструментов
Windows. Гистограмма показывает время от генерации до приёма в Java.
Учитывайте отрицательные выборки и проверьте общую шкалу перед сравнением
p99. Получатель сверяет все восемь полей Quote и точный порядок.
Поля `sourceIngressFrames` и `sourceIngressRecords` считают целые исходные события
и записи, принятые коллектором STREAM, включая пробные записи. Счётчики читаются
после обработки очереди, за пределами измеряемого времени публикации. Их соотношение
и размер порции генератора показывают, как готовые публикации объединяются перед
обработкой коллектором. Эти счётчики описывают вход отдельно от сетевых кадров.

Поле издателя `streamFrames` содержит число полностью отправленных кадров
STREAM DATA по всем клиентам, включая пробные кадры. Вычтите `probeFrames`
для числа измеряемых кадров. `probeRecords` учитывает пробные записи,
опубликованные до `GO`. В байтовом режиме
`maxFrameRecords` и `maxFrameBytes` показывают максимальные число записей и
размер среди полностью отправленных кадров STREAM DATA. `failedFrames`
показывает число ошибок сборки кадра, приведших к закрытию клиента.
Эти счётчики издателя дополняют проверку доставки получателем.

Команда получателя `--self-test-quote-stream` проверяет корректные и
повреждённые записи через локальный коллектор Java QD STREAM. При определении
предела учитывайте только точные доставки. Сравнивайте темп издателя и
получателя, записывайте размер пакета, CPU и память каждого процесса.
Перед сравнением проверьте количество, поля, порядок и p99 для каждого
получателя.

## Эталонный издатель на Java QD

Скомпилируйте издателя и используйте того же получателя с Java QD 3.357
в classpath. Запустите издателя и получателя в разных терминалах.

~~~sh
javac -cp "$QD_CLASSPATH" -d classes tools/nettest/benchmark/QuoteStreamPublisher.java tools/nettest/benchmark/StreamReceiver.java
java -cp "classes:$QD_CLASSPATH" QuoteStreamPublisher 7300 250000 50000 8
java -cp "classes:$QD_CLASSPATH" StreamReceiver 127.0.0.1:7300 IBM quote-stream ns probe
~~~

Параметр `--clients N` задаёт максимум подключений Java-сервера (по умолчанию 1);
N — положительное целое число. Запустите столько же получателей.
Java-издатель слушает на loopback, ждёт подписку на точный символ и запись
Quote и передаёт физические записи через `QDDistributor.process`,
переиспользуя `RecordBuffer`. После `READY` отправляйте `PROBE` по мере
необходимости, пока каждый получатель не сообщит `PROBE_RECEIVED`, затем
отправьте `GO`. После `RESULT` передайте ожидаемое число каждому получателю.
Когда все сообщат `COUNT_REACHED N`, отправьте `CLOSE` издателю. Дождитесь
завершения всех процессов и проверьте результат каждого получателя.

При сравнении чередуйте порядок издателей. В каждом раунде используйте одну
сборку получателя, одинаковое число записей, символ, темп и размер пакета
API. Размер пакета ограничивает один вызов API. Коллектор STREAM и писатель
QTP могут формировать кадры другого размера. При нулевом темпе фиксируйте
измеренную скорость точной доставки. При заданном темпе отдельно проверяйте,
удержал ли издатель этот темп.
