# Сравнение раздачи Event STREAM

[English version](FANOUT.md).

`Measure-EventFanout.ps1` запускает источник Event и потребителей Java QD 3.357
с подпиской IBM TimeAndSale/STREAM у каждого клиента. По умолчанию сравниваются
пакеты публикации из одной и восьми записей с 1, 2, 4 и 8 клиентами. Прогоны
идут последовательно. Каждый клиент подтверждает пробную запись до замера,
затем проверяет последовательность и поля каждой принятой записи.

```powershell
pwsh -NoProfile -File tools/nettest/benchmark/Measure-EventFanout.ps1 `
  -Program $eventNettest -Java $java -Classpath $qd357Classpath `
  -OutputDirectory $newLogDirectory -Rate 1000 -Duration 10 -Repeats 3
```

Параметры и пределы приведены в `-Help`, русская справка доступна через
`-HelpRu`. Укажите новый каталог результатов. Команда создаёт процессы
источника и потребителей, по умолчанию открывает TCP loopback, компилирует
Java-проверку с помощью JDK и сохраняет stdout, stderr, `result.json` и
`process-samples.csv` каждого прогона. `-ListenAddress` выбирает конкретный
локальный IPv4.

В `-Clients` можно передать различные значения от 1 до 8, в `-Batches` — 1
или 8, в `-Pacing` — `sleep`, `yield` либо массив из обоих режимов. По
умолчанию используется sleep. Yield предназначен для измерения предельной
нагрузки и может занимать дополнительное ядро. Повторы приёма между этими
режимами напрямую не сопоставимы, поскольку частота проверки очереди
различается. На каждом чётном повторе порядок размеров пакета обращается.
Rate задаёт предлагаемое число записей источника в секунду.

В `summary.csv` одна строка соответствует одному прогону. `admittedRecords`
считает записи источника, `deliveredRecords` — проверенные клиентские доставки,
а `sentDataFrames` — завершённые кадры DATA для всех клиентов.
`dataFramesPerDeliveredRecord` делит число кадров на число доставок. Результат
каждого клиента сохранён в `result.json`. `worstClientP95Ns` — максимум p95
отдельных клиентов. Шаг гистограммы в центральном диапазоне составляет 1 мкс.
Возраст записи вычисляется по системным часам на одном хосте и может быть
отрицательным. Точность аппаратных часов отдельно не калибровалась.

CPU измеряется по выборкам во время активной фазы и суммируется по процессам
потребителей. Сумма их выборочных пиков working set или private commit
складывает отдельные пики, которые могут приходиться на разные моменты. Для
сопоставимых результатов запускайте прогон без другой нагрузки. Тесты на общей
машине проверяют корректность стенда без порога скорости.

`-Help` и `-HelpRu` не запускают нагрузку. Успешная проверка возвращает ноль,
ошибка параметров, компиляции, процесса, сети, проверки или записи — ненулевой
код. Дочерние процессы завершает внутренний runner. Каталог результатов и
журналы сохраняются и при ошибке.

Скорость источника считает принятые записи за секунду заданного окна публикации. Скорость доставки включает записи из разгрузки очереди и делится на длительность того же окна.
