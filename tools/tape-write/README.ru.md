# Офлайн-нормализация tape

[English version](README.md). Английская версия нормативна.

`qdcxx-tape-write` реализует [строгое офлайн-переписывание](../../docs/TAPE-WRITE.ru.md).
Утилита допускает целую поддерживаемую запись RAW/MESSAGE, воспроизводит исходную
последовательность конвертов новым reader и ограниченным writer и публикует новое назначение.
Байты источника, имена, полные идентификаторы полей, raw-значения и различия времени
сохраняются семантически; кодирование примитивов может нормализоваться. Живое соединение не открывается.

## Сборка и вызов

```text
cmake -S . -B build -DORG_TTLDTOR_QDCXX_BUILD_TAPE_WRITE=ON
cmake --build build --config Release --target qdcxx_tape_write
qdcxx-tape-write --input quote.qtp --output quote-normalized.qtp --tape-mode raw-message-v1 --profile default-quote-v1
qdcxx-tape-write --input input.qtp --output normalized.qtp --tape-mode raw-message-v1 --schema schema.json
```

Утилита необязательна и по умолчанию отключена. Нативный JSON закрыто подключается только при
`ORG_TTLDTOR_QDCXX_BUILD_SCHEMA_JSON=ON`; иначе `--schema` возвращает LOADER_DISABLED
до I/O схемы и tape. Production-библиотеки остаются независимыми от JSON и файлового I/O.
Поддерживаемые встроенные схемы: `oracle-sre-v1`, `default-quote-v1`, `default-profile-v1`
и `oracle-field-types-v1`; их прежние точные локальные профили сохраняются.
Вызов без аргументов и отдельный `--help` выводят одинаковую справку без открытия файлов.
Успех не выводит сообщений; родитель назначения должен существовать, а конечная запись — отсутствовать.

## Конечная конфигурация

Справка перечисляет все **38** конечных опций и точные значения по умолчанию: 31 опцию
tape/admission/writer из [TAPE-WRITE](../../docs/TAPE-WRITE.ru.md) и семь прежних
[опций нативной схемы](../../spec/schema/NATIVE-JSON.ru.md).
Значения — отдельные беззнаковые десятичные ASCII-токены; ноль имеет смысл, повтор опций
и переполнение являются ошибками вызова. Владеющая конфигурация разрешается один раз до файлового I/O.

Счётчики reader и admission независимы для предварительной проверки и нового прохода композиции.
Второй проход сканирует проверенные ID описаний без выделения копий имён и проверяет бюджеты
временных контейнеров sender-ID/record-view/type-8 до роста. Типизированные значения
и символы заимствуются только на время текущего вызова writer, до освобождения владеющего
результата feed. Завершённый префикс записей ошибочного результата reader не попадает в вывод.

Общий бюджет посещений текста writer — проверенная сумма `--max-descriptor-units`
и `--max-description-name-units`. Admission отдельно ограничивает текст дескриптора и удерживаемые
имена layout. Сравнение, измерение, копирование и кодирование writer расходуют этот общий бюджет,
поэтому повторные посещения могут исчерпать его раньше бюджетов удерживаемого текста. Лимиты
байтов/units descriptor-string также применяются к UTFString-именам writer; `--max-name-units`
layout остаётся отдельным. Переполнение при выводе общего бюджета даёт resource exit 6.

Физическая файловая работа имеет отдельные выведенные конечные бюджеты: `4*N+68` для чтения
источника/схемы и `2*N+68` для вывода, с проверенной арифметикой и соответствующим лимитом байтов `N`.
Они покрывают передачу байтов, худший случай положительного продвижения по одному байту,
копирование при ограниченном росте чтения, до 64 попыток создания исключительного имени
и проверенные операции завершения. Удерживаемые нативные пути ограничены 4096 нативными units.
В Windows токены опций используют проверенное преобразование UTF-8 без ANSI code page;
операнды путей после проверки аргументов сохраняют исходные нативные UTF-16 units.
CLI-регрессия проверяет Unicode-пути; выполнение с изолированным суррогатом в пути не проверялось.

## Завершение и ошибки

Полная загрузка схемы предшествует проверке алиасов и физическому EOF/проверенному закрытию входа.
Строгий admission предшествует исключительному созданию временного файла в каталоге назначения.
Каждый целый chunk writer записывается с проверкой частичного продвижения; завершение reader,
завершение writer, flush и close предшествуют публикации hard link только с созданием.
Существующее или появившееся назначение отклоняется. Перезапись и запасной rename отсутствуют.
Удаляется только временный файл, полученный в исключительное владение.

Ошибки используют [описанные категории exit](../../docs/TAPE-WRITE.ru.md)
и LF-диагностику без содержимого входа. При ошибке очистки временного файла после публикации
назначение остаётся валидным, а `published=1` сопровождается ненулевым exit. Дополнительная
ограниченная строка очистки использует `owned-native-path-hex` для точных нативных байтов пути
без внедрения управляющих символов. Защита от враждебной замены родителей и устойчивость
к аварии/отключению питания не обещаются.

Нативная CLI-регрессия: [tape_write_cli.cmake](../../tests/conformance/tape_write_cli.cmake).
Она проверяет справку, все 38 defaults и грамматику чисел, порядок отказа loader-OFF,
переписывание полных Quote/Profile, все пять нативных случаев корпуса при включённом JSON,
нормализацию overlong compact-int, Unicode-пути, существующее/совпадающее назначение
и конечные отказы ввода/вывода.
Фактическая приёмка платформ, production-сравнение Java и проверки файловых ошибок
представляют отдельные доказательства верификации.
