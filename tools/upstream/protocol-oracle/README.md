This independently authored Java driver invokes locked QD 3.355. Nine fresh-JVM cases cover only [COVERAGE.md](../../../tests/fixtures/protocol/COVERAGE.md). No upstream code or resources are copied. Generated byte/descriptor observations are factual captures; the external MPL-2.0 source remains external. No sockets, C++ implementation, extra harness dependencies or upstream test-suite results are involved.

## Driver and instrumentation

P01/P03/P04 use `BinaryQTPComposer(scheme,true)` and a fresh `BinaryQTPParser` with retained `ChunkedInput`. Schemes use DefaultScheme/DefaultRecord, CompactIntField (serial ID 8), PentaCodec, no object/time fields, default options and no field replacers. P01 has two ABC records (11,22)/(33,44), then another data frame (55,66). All other publishers use (11,22); subscriptions use ABC. Callback cursors are serialized immediately into immutable strings before upstream reuses buffers. Parse positions, pending bytes, calls and errors remain in exact captures. Descriptions do not have an application consumer callback; the diagnostic wire reader exposes them using upstream primitive readers.

P05's driver lives in `com.devexperts.qd.qtp` to access the package-private factory/connection. It creates and starts a real MessageAdapterConnection via its factory, feeds the peer's Java-composed description/subscription through `processChunks`, and obtains replies through `retrieveChunks`. The production connection constructs its actual ConnectionQTPParser/Composer; no requested layout is injected or simulated. Peer R ID 1 maps to publisher R ID 0. A minimal MessageAdapter supplies a RecordBuffer, observes incoming subscriptions and intentionally emits no DESCRIBE_PROTOCOL. Reflection sets only `nextHeartbeatTime` and `bytesToNextHeartbeat` to Long.MAX_VALUE before retrieval. Thus scheduled heartbeat/clock bytes and EndpointId are absent by construction, not stripped from captures. Time marks still run internally but these data records serialize no time metadata. Transport notifications, adapter state before close, and explicit teardown close are recorded. This is not negotiation, timing, auth, concurrency or reconnect evidence.

Each request variant uses a fresh connection before the writer's first use. A peer parser observes the reply with its requested local scheme; a separate audit parser with x,y,z exposes delivered/omitted raw slots. Neither audit parser chooses the outgoing layout. `none` has a peer z scheme but sends no request. Zero-field and absent-z-only requests are separate stimuli.

## Artifacts and comparison

`cases.json` lists cases; programmatic inputs are identified by the Java source hash. Raw stdout/stderr is retained. Normalization changes **only CRLF to LF**. Exact `.tsv` expectations preserve wire hex, frame boundaries, scheme/field metadata, lookup probes, chunk schedules, ordered callback contents/counts and pending-byte observations. `.semantic.tsv` expectations are a separate projection: ordered records with replay scope, without callback grouping, chunk timing or transport notifications. For P01 only whole-input semantics enter this projection; Java independently requires every split and bytewise replay to equal that sequence. Exact batching differences remain visible and verified in the original capture.

Rows use escaped TSV (`\\N` null; escaped slash/tab/CR/LF). A record value is message type, local ID, name, symbol and ordered raw-slot values with the field's formatted value in parentheses. `parse.end` columns are cumulative bytes supplied, total consumed, available pending bytes, cumulative record count, callback count and error count. `frame` offsets are start-inclusive/end-exclusive. A `complete` row and process exit code guard truncated runs. Future C++ comparisons should use semantic expectations separately from Java batching evidence.

Metadata records command arrays/cwd, upstream identity/cleanliness, JDK/Maven, tool and harness bytecode hashes, cases hash, ordered classpath/content hashes, build-cache jar inventory and normalization. The schema-oracle environment inspector is reused (and hashed) for JDK/JAXP, relevant properties and service resource/provider inventory. The runtime has the same 12 source-built class directories as schema-oracle. No XML/property overlays are loaded; programmatic records report their mapping classes. Ambient JVM injection is rejected. Environment metadata and build logs retain machine paths and are not semantic goldens.
