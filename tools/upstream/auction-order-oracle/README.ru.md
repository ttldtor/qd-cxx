# Бинарный оракул для OTC и дисбаланса

[English](README.md).

Программа сохраняет исходные значения курсора и типизированные свойства с помощью
`BinaryQTPComposer`, `BinaryQTPParser`, `OtcMarketsOrderDelegate` и
`OrderImbalanceDelegate` из ревизии в [upstream.lock](../../../upstream.lock).
В профилях по умолчанию, tiny-decimal, целочисленном и полной книги заявок используются
стандартные записи. В отдельной проверке опущены все необязательные поля дисбаланса.
В шести некорректных определениях опущено по одному обязательному полю события, каждое
из этих определений должна отклонить фабрика.

Проверяются беззнаковое представление индекса OTC, флаги удаления и снапшота, знаковые
время и плата за доступ к котировке, границы числовых представлений, зарезервированные
коды флагов, точные источники и отсутствие имени маркетмейкера. Бинарные фикстуры
записаны с опцией `hs`. Профиль этих фикстур не согласует время FIELD, поэтому время
события Java равно нулю.

Справку `Invoke-Oracle.ps1 -Help` или `-HelpRu` можно открыть без рабочих входов.
Для проверки [происхождения сохранённых байтов](../../../tests/fixtures/auction-order/provenance.json) укажите
собранную закреплённую версию QD, JDK 8 и регистратор времени проекта.

```powershell
pwsh -File tools/upstream/auction-order-oracle/Invoke-Oracle.ps1 -Mode Verify `
    -Upstream C:/qd-reference -JavaHome C:/jdk8 -Logger C:/tools/qdcxx-run-utc.exe `
    -RunDirectory .work/auction-order-verify
```

Проверка выполняется офлайн в новом каталоге и сравнивает байты TSV и QTP в UTC и
Pacific/Honolulu. Режим Capture обновляет кандидаты фикстур и сведения об их
происхождении. Режим Verify сравнивает результаты и записывает отчёт в рабочий каталог.
