# Форматирование C++

[English version](CPP.md). Английская версия является нормативной.

[Контракт стиля](../../docs/CPP-STYLE.ru.md) применяется к C++ проекта.
[Format-Cpp.cmake](Format-Cpp.cmake) выполняет **Uncrustify 0.83.0 → clang-format 20.1.8** с
неизменёнными корневыми конфигурациями. Нужны CMake 3.25+ и нативные исполняемые файлы точных версий;
для автоматического поиска нужен Git. Переносимый путь не требует Python или PowerShell.
Получение форматтеров отделено от запуска: драйвер не скачивает инструменты и не подменяет версии.

```text
cmake -DUNCRUSTIFY=/absolute/path/to/uncrustify -DCLANG_FORMAT=/absolute/path/to/clang-format -DMODE=Format -P tools/format/Format-Cpp.cmake
cmake -DUNCRUSTIFY=/absolute/path/to/uncrustify -DCLANG_FORMAT=/absolute/path/to/clang-format -DMODE=Check -P tools/format/Format-Cpp.cmake
```

Заключайте целые аргументы `-DNAME=value` в кавычки, если пути содержат пробелы или метасимволы оболочки.
На Windows используйте нативные Windows-программы, на Linux — нативные Linux-программы.
[Инструкции инструментов разработки](../dev/README.ru.md) содержат исполнимые примеры для обеих платформ,
bootstrap нативного UTC logger, явный способ подготовки Linux и зафиксированное происхождение инструментов.
macOS не проверена; анализ переносимости исходников не доказывает поддержку сборки или выполнения.

`MODE` по умолчанию равен `Check`. Необязательный `FILES` задаёт путь к UTF-8 JSON-массиву, а не списку через точку с запятой:

```json
["tools/dev/run_utc.cpp", "src/a name;example.cpp"]
```

Передавайте его как `-DFILES=/absolute/path/to/files.json`. Пути могут быть относительно репозитория или абсолютными.
Необязательный `ROOT` выбирает корень изолированного репозитория для детерминированных тестов;
обычно он определяется по расположению драйвера. В корне должны быть обе неизменённые конфигурации.
Все выбранные исходники проверяются до запуска любого форматтера. Пробелы, Unicode, точки с запятой и
одноимённые файлы в разных каталогах сохраняются как отдельные пути. Имена с CR/LF отклоняются до
форматирования, в том числе при поиске через Git; они не могут незаметно обрезать выбранный набор.
POSIX-имена с буквальным обратным слешем тоже отклоняются до запуска инструментов: грамматика путей
CMake 3.25 трактует этот символ как разделитель. Разделители Windows-путей остаются поддержанными.

Автоматический поиск включает tracked и nonignored new файлы из `include/` (`*.hpp`), `src/`
(`*.cpp`), `tests/conformance/` (`*.cpp`), а также `tools/qtp-inspect/`, `tools/tape-inspect/`, `tools/tape-write/`,
`tools/dev/`, `tools/subscribe/`, `examples/subscriptions/`, `examples/feed_quote/`, `examples/event_text/` и `examples/ipf_live/` (`*.cpp`, `*.hpp`).
Git C-quoted имена декодируются до отбора.
Сегменты каталогов `upstream`, `generated` и `fixtures` исключаются. Явный manifest допускает
`.cpp` и `.hpp` в этих корнях и `.work/` для намеренных контрольных примеров; другие корни/расширения отклоняются.
И лексический, и разрешённый путь исходника должны оставаться в допустимых корнях вне защищённых сегментов.
Поэтому symlink/junction не обходит ограничения исходников. Symlink исполняемого файла форматтера допускается;
разрешённый исполняемый файл по-прежнему должен сообщать точную закреплённую версию.

Драйвер отклоняет отсутствие инструментов/конфигураций, неверные версии, ненулевые коды форматтеров,
диагностику Uncrustify с warning/error/unknown/invalid и любую непустую диагностику clang-format.
Каждый исходник проходит обе стадии на отдельной временной копии; байты сравниваются, а `Check`
никогда не перезаписывает оригиналы. `Format` публикует файл только после успеха обеих стадий;
ошибка следующего файла не отменяет уже завершённые файлы. Собственные временные копии удаляются при
успехе и обрабатываемых сбоях, включая прерывание процессов форматтеров. Внешнее принудительное завершение
самого CMake-драйвера не входит в эту гарантию очистки. Общий корень `.work/` никогда не удаляется при очистке.

[Переносимые проверки форматтера](../../tests/conformance/tooling/format.cmake) охватывают настоящие закреплённые инструменты,
обнаружение расхождения без записи, идемпотентность, ошибки диагностики и выхода, поиск имён, защищённые
aliases и намеренные мутации настоящего драйвера. [Текущая проверка](../../tests/conformance/tooling/VALIDATION.ru.md)
фиксирует выполненные профили и ограничения отдельно от исторических результатов. Форматтеры не проверяют
все требования к именованию, namespace, самостоятельности заголовков и содержательному Doxygen; они требуют ревью.

## Необязательное получение на Windows и историческая обёртка

[Setup-Cpp.ps1](Setup-Cpp.ps1) остаётся необязательным удобством Windows x64 с требованием PowerShell 7.4+.
Он скачивает точные архивы из [cpp-tools.lock.json](cpp-tools.lock.json), проверяет SHA-256 до
распаковки и хранит всё в игнорируемом `.work/`. Архив/hash Uncrustify взяты из официального
GitHub release 0.83.0; wheel/hash clang-format — из metadata выпуска 20.1.8 на PyPI.
Упаковка wheel не добавляет runtime-зависимость от Python или pip. Глобальной установки нет.

```powershell
pwsh -NoProfile -File tools/format/Setup-Cpp.ps1
```

Setup использует только lock репозитория и `tools/format/.work/`; альтернативного lock нет.
Загрузки временные и проверяются до публикации в cache. Каждый архив, включая warm-cache,
проверяется по hash до распаковки в новый staging. Отклоняются абсолютные/обходные пути ZIP, alternate
data streams, Windows device/неоднозначные имена, дубликаты и link/special/reparse entries;
существующие filesystem reparse points тоже отклоняются. Публикуются только установки с ожидаемым
исполняемым файлом. Сбой распаковки сохраняет прежнюю установку; временные staging и загрузки
удаляются при сбое. Windows-архивы не предоставляют нативные Linux-программы.

Необязательный [Format-Cpp.ps1](Format-Cpp.ps1) и исторический
[setup_cpp.py](setup_cpp.py) сохраняют прежние интерфейсы. PowerShell-обёртка
не получает автоматически новую область поиска `tools/dev/`. Её исторические
[setup checks](../../tests/conformance/python-migration/Test-SetupCpp.ps1) охватывают враждебные архивы,
cold/warm Windows acquisition и поведение обёртки; cold-cache запуск требует сети.
Первоначальная [проверка форматирования](../../tests/conformance/encoding/VALIDATION.ru.md) остаётся исторической.
Java formatting и oracle provenance из [README](README.ru.md) остаются отдельными и неизменными.

Portable driver и необязательная PowerShell-обёртка дополнительно допускают только каталог
examples/ipf_live для live IPF sample; остальные example roots сохраняют прежнюю область.
Явные Format/Check используют ту же закреплённую pipeline и неизменные корневые configs.
