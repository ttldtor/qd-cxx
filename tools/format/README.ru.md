# Стиль Java и автоматическое форматирование

[English](README.md). Английская версия является основной.

Java-код репозитория следует [Google Java Style](https://google.github.io/styleguide/javaguide.html).
[google-java-format](https://github.com/google/google-java-format) — основной автоматический
форматтер в стандартном режиме Google: отступ блока 2 пробела и предел 100 колонок с исключениями
из руководства. Режим AOSP не используется. [.editorconfig](../../.editorconfig) задаёт базовые
настройки редактора, но не заменяет форматтер. AGENTS.md передаёт инструкции
будущим сессиям, а [CONTRIBUTING.md](../../CONTRIBUTING.md) описывает проверки перед review.

## Команды

Нужны PowerShell 7.4+, Git и JDK 21 или новее. Из корня репозитория:

```powershell
$formatterJdk = 'C:/Program Files/Microsoft/jdk-21.0.4.7-hotspot'
pwsh -File tools/format/Format-Java.ps1 -Mode Format -JavaHome $formatterJdk
pwsh -File tools/format/Format-Java.ps1 -Mode Check -JavaHome $formatterJdk
```

По умолчанию выполняется `Check`: он перечисляет файлы, которым нужно форматирование, и завершается
ошибкой, не меняя Java-исходники. `Format` переписывает исходники; после него должен пройти `Check`.
Ту же команду Check можно использовать в CI. Без `-JavaHome` wrapper использует JAVA_HOME, а если
переменная не задана — java из PATH. JDK 8 отвергается с явным сообщением: JDK форматтера отделён
от JDK 8 закреплённого oracle QD. Глобальный JAVA_HOME, Git hooks, настройки IDE, production
dependencies и конфигурация сборки upstream не меняются.

## Воспроизводимость инструмента и область действия

[google-java-format.lock.json](google-java-format.lock.json) закрепляет версию **1.36.1**, URL
официального release asset и SHA-256. При первом запуске wrapper скачивает jar в игнорируемую
`.work/` и проверяет хеш до исполнения. Кешированный jar также проверяется при каждом запуске.
Несовпадающая загрузка или кеш отвергаются. Для скачивания нужна сеть; последующие запуски используют
проверенный локальный кеш. Обновление форматтера требует явного изменения lock, затем Format, Check
и затронутых проверок.

Поиск файлов: `git ls-files --cached --others --exclude-standard -- '*.java'`. Включаются отслеживаемые
и новые неигнорируемые Java-файлы репозитория. Каталоги captures, expected, target и `.work`
исключены. Внешний checkout закреплённого Java QD находится вне этой области. Эталоны не форматируются.
Нельзя использовать плавающую версию форматтера IDE как окончательную проверку.

Форматтер управляет расположением кода и imports, но не проверяет весь стиль или семантику.
Остальные правила руководства проверяются при review, включая именованные packages, явные imports,
обязательные управляющие блоки и имена. Unicode escapes сохраняются там, где задают исходные входы
oracle. Все три harness перенесены: schema и encoding теперь используют package `qdcxx.oracle`,
protocol сохраняет `com.devexperts.qd.qtp` для доступа к upstream package. Launchers используют
соответствующие полные имена классов. Исключений из стиля для этих harness не вводится.

## Provenance oracle после правок исходников

Форматирование меняет хеш исходника и может менять отладочные данные байткода. Выполняйте Format
до финальных capture. После изменения harness или launcher повторяйте затронутые Verify и сохраняйте
фактические новые метаданные и логи. Нельзя вручную подменять хеш в исторических метаданных или менять
эталоны только ради форматирования. SchemaOracle также служит инспектором окружения для protocol и
encoding, поэтому его изменение затрагивает все три цепочки provenance.

При этом переносе прежние schema/protocol evidence сохранены как неизменная история; новые
доказательства Verify находятся в evidence. Четыре текущих capture encoding обновлены
двумя независимыми чистыми сборками и отрицательным/положительным Verify. Все существующие эталоны
неизменны. Точные проверки и ссылки — в [валидации](VALIDATION.ru.md).
