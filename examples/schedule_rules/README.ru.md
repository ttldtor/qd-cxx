# Пример правил расписаний

[English version](README.md). Английский текст является основным.

Полный консольный клиент создаёт явный календарный контекст, получает `XNYS()` через
`Schedule::getInstance` и выводит владеющие имя/timezone identity. Результат закреплённого baseline:

```text
NYSE    America/New_York
```

Разделитель — одна табуляция. Metadata фиксированного примера — ASCII; приложение сохраняет нативные
владеющие результаты UTF-16 либо кодирует их для собственного слоя отображения.

Включите `ORG_TTLDTOR_QDCXX_BUILD_SCHEDULE=ON` и `ORG_TTLDTOR_QDCXX_BUILD_EXAMPLES=ON`, соберите target
`qdcxx_schedule_example`. Выбор compiler/profile описан в [сборке C++](../../docs/CPP-BUILD.ru.md).
Для этого parser-примера не нужны Java, date/tz SDK или runtime-подключение. Установленное приложение
линкует `qdcxx_schedule` после `find_package(qdcxx CONFIG REQUIRED COMPONENTS schedule)`.

`qdcxx-schedule-example --run` запускает пример. Без аргументов и с отдельным `--help` выводится
одинаковая EN-справка; `--help-ru` выводит RU-справку. Справка не создаёт контекст и не запускает
parser. Внешние данные/credentials не принимаются. `--run` использует встроенные defaults и обычные
`ScheduleLimits`, выделяет только владеющие объекты в памяти, не обращается к файлам/сети.
Exit 0 означает успех/справку, 1 — операционную ошибку/вывод, 2 — неверные аргументы.

[main.cpp](main.cpp) содержит полный исходник и необходимую обработку ошибок.
[Руководство приложения](../../docs/SCHEDULE-RULES.ru.md) описывает именованные части, типизированные
defaults, пределы, владение и конкурентные обновления поколений. Запросы Day/Session по моменту и
фильтры — отдельные возможности; пример показывает разобранные правила и metadata.
