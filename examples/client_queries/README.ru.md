# Запросы клиентских снимков

[English version](README.md). Отдельное приложение запрашивает последний Quote, дневные Candle и снимок Order источника DEFAULT, затем строит локальный стакан. Вывод различает состояния покрытия, включая TRUNCATED. Источник должен поддерживать выбранные символы, историю и источник заказов; пустой результат не подтверждает права доступа. SDK отклоняет snapshot-запросы к tape.

Соберите каталог против установленного пакета qdcxx с Feed:

```powershell
cmake -S . -B build "-DCMAKE_PREFIX_PATH=$prefix"
cmake --build build
ctest --test-dir build --output-on-failure
.\build\qdcxx-client-queries.exe --run demo.dxfeed.com:7300
```

Без аргументов, с `--help` или `--help-ru` выводится справка без runtime и сети. `--run HOST:PORT [HISTORY_HOST:PORT [FROM_MS TO_MS]]` создаёт два endpoint SDK, использует обычный TCP и общий таймаут десять секунд; по умолчанию адрес HISTORY совпадает с первым; отказы выводятся явно, оба endpoint закрываются. По умолчанию период — последние 24 часа; необязательные знаковые FROM_MS и TO_MS задаются вместе как включительные Unix-миллисекунды. Код 0 означает, что владеющие результаты запросов получены и оба endpoint достигли CLOSED или FAILED с финальной статистикой и без активного native соединения и истечения срока; он не обещает drain непрерывного потока без потерь. FAILED сохраняет диагностику закрытия; код 0 не означает чистое транспортное завершение. Фактические drain, gap и диагностика неидеального закрытия выводятся в stderr. Код 1 означает отказ запроса, ошибку источника до закрытия или истечение срока закрытия; 2 — неверные аргументы. Файлы не создаются, учётные данные не сохраняются. Доступность источника и права определяются извне. Для NTV и других именованных native Order источников нужен явно заданный пользовательский реестр событий.
