# Смешанные рыночные события

[English version](README.md)

Автономная программа использует установленную цель `qdcxx_feed`. Она подписывается
на Quote, Trade и Order, производные от Quote, выводит события и итоговые счётчики
доставки и соединения. Ожидание выполняется без цикла опроса в приложении.
Для `AAPL` программа получает композитные Quote и Trade, а для Order явно выбирает
источник `COMPOSITE`. Индексированный селектор `AAPL&Q` выбирает региональную Quote
и сторону `REGIONAL_BID` региональных делегатов Order. Стандартный маршрут Trade
сохраняет точное написание символа. В середине интервала пример добавляет `MSFT`
с тем же композитным источником. Локальное принятие изменения не подтверждает получение сервером.

Для сборки из корня репозитория нужен установленный пакет qd-cxx с компонентом
feed и совместимая конфигурация компилятора и runtime.

```text
cmake -S examples/feed_market -B build/feed-market -G Ninja -DCMAKE_PREFIX_PATH=/path/to/qdcxx -DCMAKE_BUILD_TYPE=Release
cmake --build build/feed-market
build/feed-market/qdcxx-feed-market --help-ru
build/feed-market/qdcxx-feed-market --run --duration-ms 10000
```

В Windows используйте настроенный терминал компилятора и путь
`build/feed-market/qdcxx-feed-market.exe`. Для установленного пакета с TLS при
конфигурации может понадобиться квалифицированный OpenSSL, как описано в
[руководстве по сборке](../../docs/CPP-BUILD.ru.md). Программа использует обычный
TCP. Параметр `--address HOST:PORT` выбирает совместимый источник. Данные demo
могут приходить с задержкой или отсутствовать из-за доступа, разрешений и часов
торгов. Доступность региональных Quote и Trade зависит от источника. Установленное
соединение не гарантирует события каждого выбранного типа и источника.

Без аргументов и при `--help` программа выводит английскую справку без создания
SDK runtime и сетевого подключения. `--help-ru` выводит русскую справку. Код 0
означает получение хотя бы одного события и завершение локального drain, 1 — ошибку
или отсутствие событий, 2 — неверные аргументы, 130 — прерывание. Интервал задаётся
в пределах 2–600000 мс, по умолчанию 10000 мс. Ctrl+C инициирует завершение.
Программа создаёт потоки SDK и обработки сигналов и сетевое соединение. Входные
файлы не изменяются. `deliveredAvailability` и `readBytesAvailability` содержат
числовые значения `core::StatisticAvailability`, `desiredSelectors` отражает
локальное число селекторов, а `readBytes` — число байтов транспорта. Эти счётчики
показывают локальное состояние и не подтверждают получение на другой стороне.

Приложение вызывает `find_package(qdcxx CONFIG REQUIRED COMPONENTS feed)` и
использует публичные заголовки. Его можно скопировать вместе с CMake-файлом и
кодом обработки сигналов в другой проект. Контракты endpoint, обработчиков и
статистики описаны в [руководстве Feed API](../../docs/FEED-API.ru.md).

Пример выводит сохранённую диагностику endpoint в stderr, включая ошибки транспорта, замеченные после успешного завершения локальной доставки.

## Проверка без публичного demo

В сборке репозитория с включёнными Feed, примерами и тестами выполните:

```text
cmake --build build --config Release --target qdcxx_feed_market qdcxx_feed_market_tests
ctest --test-dir build -C Release -R "^feed_market(_help)?$" --output-on-failure
```

Тест запускает локальный QTP-стенд на временном loopback-порту и проверяет точные
запросы подписки, добавление MSFT, семь заданных событий и итоговые счётчики
доставки. Публичный источник данных и DNS-запросы не нужны. Для числового адреса
`127.0.0.1` пример задаёт параметр резолвера локально. Фиксированные записи и
значения заданы в [исходнике теста](../../tests/conformance/feed_market_tests.cpp).
